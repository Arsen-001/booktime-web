# PWA — приложение для телефона

Статус на 25.09.2026: веб-версию **можно поставить на телефон как приложение** (иконка на
домашнем экране, standalone-окно без адресной строки браузера). Service worker, офлайн-кэш и
пуш-уведомления **не включены** — бэкенда нет, присылать пуши неоткуда, а SW без реального
API только рискует закэшировать моковые данные и сбивать с толку. Ниже — что уже сделано и что
понадобится дальше.

## Что сделано

- `src/app/manifest.ts` — генерирует `/manifest.webmanifest` (Next 16, файловая конвенция
  `app/manifest.ts`, см. `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/manifest.md`).
  Имя и подпись берутся из `common.app.name` / `common.app.tagline` (`messages/ru/common.json`) —
  сменится имя продукта (сейчас рабочее «BookTime», см. комментарий в `src/shell/Logo.tsx`) — манифест
  подхватит само. Манифест **не переключается по языку** (единственный экземпляр, `lang: 'ru'`) —
  для будущей локализации манифеста понадобится `generateMetadata`-подобный маршрут через
  `NextRequest`/cookie языка (сейчас файловая конвенция `manifest.ts` таких данных не получает).
- `display: 'standalone'`, `theme_color: '#4f46e5'` (`--primary`, палитра «Б — Индиго»),
  `background_color: '#f7f7fb'` (`--bg`, светлая тема — цвет заставки при запуске).
- `public/icons/` — иконки, сгенерированы из знака `Logo.tsx` (плашка `bg-primary` + буква «A»
  `primary-contrast`) скриптом на `sharp` (SVG → PNG), не закоммичен — при смене логотипа
  перегенерировать вручную тем же приёмом (rsvg через `sharp`, см. историю правки):
  - `icon-192.png`, `icon-512.png` — `purpose: any` (со скруглением, как плашка в `Logo.tsx`).
  - `icon-maskable-192.png`, `icon-maskable-512.png` — `purpose: maskable`, без скругления,
    знак — в безопасной зоне (центральный круг 80% холста), чтобы не срезался круглой/квадратной
    маской Android.
  - `apple-touch-icon.png` (180×180) — для `metadata.icons.apple` в `layout.tsx` (iOS не читает
    `purpose: maskable`, скругление накладывает сама ОС).
- `src/app/layout.tsx`: `metadata.manifest`, `metadata.icons`, `metadata.appleWebApp` (`capable:
  true` — открывается с домашнего экрана как отдельное окно, без Safari UI) и `viewport.themeColor`
  раздельно на светлую/тёмную тему (`prefers-color-scheme`; сам манифест — один цвет, тему
  переключателя приложения — `data-theme` на `<html>` — манифест не видит).
- Безопасные зоны: `viewport.viewportFit: 'cover'` уже стоял в `layout.tsx` до этой правки —
  экран рисуется под чёлку/жесты, а не обрезается по ней; отступы под неё — забота компонентов
  `src/shell/**` (`env(safe-area-inset-*)`), этот файл их не переопределяет.

## Проверка

```bash
bash scripts/ensure-dev.sh
curl -s http://localhost:3710/manifest.webmanifest | head -c 500   # манифест отдаётся, JSON валиден
curl -sI http://localhost:3710/icons/icon-512.png | head -3        # иконки отдаются статикой
```
Chrome DevTools → Application → Manifest — должен показать имя, иконки, `display: standalone`,
без ошибок. На телефоне (Android/Chrome) — баннер «Добавить на главный экран» появляется сам,
когда манифест валиден и иконки — правильных размеров (уже выполнено).

## Понадобится дальше

### Пуш-уведомления (наше решение — напоминания только пушем)
1. Backend: эндпоинт для хранения `PushSubscription` на пользователя (сейчас нет ни бэкенда, ни
   модели пользователя вне мока — `src/domain/core.ts` живёт в браузере).
2. Service worker (`public/sw.js` или через `next-pwa`/ручная регистрация в
   `src/app/register-sw.ts`, `'use client'`) с обработчиком `push` и `notificationclick` —
   **не заводить, пока нет бэкенда**, иначе он закэширует моковые ответы `src/api/request.ts` и
   будет врать про «офлайн работает», хотя данные ненастоящие.
3. VAPID-ключи, запрос разрешения `Notification.requestPermission()` в момент, когда это уместно
   пользователю (не на первом экране — правило раздела notify, см. `messages/*/notify.json`), и
   ре-подписка при истечении `PushSubscription`.
4. iOS: push через Web Push работает **только у поставленного на экран PWA** (Safari 16.4+,
   `display: standalone` уже настроено) — обычная вкладка Safari пуши не получит.
5. Раздел `notify` (`src/app/biz/notifications/**`) — источник шаблонов и правил, с ним пуш и
   согласуется по текстам; сама регистрация — фундамент (`src/app/**`, `src/lib/**`), т.е. просьба
   в `qa/requests/notify.md`, когда бэкенд появится.

### Обёртка в магазины (Capacitor / TWA) — позже
- **Android — TWA (Trusted Web Activity):** обёртки не требуется писать код — генератор
  [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) берёт готовый `manifest.webmanifest`
  (он уже есть) и домен, добавляет `assetlinks.json` на сервер (подтверждение владения доменом) —
  нужен только реальный домен вместо `localhost:3710`.
- **iOS — нет TWA-аналога:** пришлось бы либо Capacitor (WebView-обёртка, нужен Xcode-проект и
  Apple Developer аккаунт), либо остаться на «установка через Safari» (то, что уже работает
  сейчас) без публикации в App Store.
- **Capacitor** (кросс-платформенно, ближе к «настоящему» приложению — доступ к камере/пушам
  нативно): добавляет нативные проекты `ios/`, `android/` поверх текущего Next-статического
  экспорта или через `capacitor-community/next-js`. Это НЕ делается в рамках текущего репозитория
  без решения — нужен отдельный проект/подпапка и `npx cap init`, что меняет `package.json`
  (фундамент) → просьба в `qa/requests`, не самостоятельная правка раздела.
- Оба варианта требуют настоящий домен и HTTPS (сейчас — `localhost:3710`), т.е. имеют смысл
  после деплоя.

## Не путать

- Манифест ≠ офлайн-режим. Без service worker страница по-прежнему требует сеть при каждом
  открытии — это ожидаемо для текущего состояния (мок живёт в `localStorage`, а не в кэше SW).
- `theme_color` в манифесте — это цвет системной "хром"-рамки на Android при **установленном**
  PWA; `viewport.themeColor` в `layout.tsx` — цвет строки состояния браузера при обычном заходе
  (обновляется вместе с темой оформления). Это разные механизмы, оба настроены.
