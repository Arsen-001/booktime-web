## 3. Какие уведомления есть

Типы Altegio 1–88 (F-05-004) берём по смыслу, но каналы — наши. Предлагаю таблицу событий сервера (каждое
событие — строка в исходящей очереди `notifications`):

### 3.1 Клиенту (пуш + лента)

| Событие | Когда | F |
|---|---|---|
| Запись создана (сразу) | запись клиента в статусе `scheduled` | F-05-024, F-00-092 |
| Запись ждёт подтверждения мастера | статус `awaiting_confirmation` | F-00-067 |
| Мастер подтвердил / отклонил | смена статуса | F-00-067 «клиент получает пуш о решении» |
| Ждём предоплату, осталось N минут; окно освобождено без оплаты | `awaiting_prepayment`, истечение `hold_until` | F-00-097 |
| Мастер получил предоплату | `master_confirmed_at` | F-00-097 |
| Напоминание о визите | за X часов (X не решён, 00 «Открыто» №25) | F-00-120 |
| Запись изменена / перенесена мастером | перенос, смена мастера или времени | F-05-027, F-00-184 |
| Мастер отменил — с кнопкой «выбрать другое время у того же мастера» | `cancelled_by_master` | F-00-100 |
| Мастер задерживается на N минут | «Задерживаюсь» | F-00-059 |
| Освободилось окно из листа ожидания | отмена/перенос подходящей записи | F-00-101, F-00-102 |
| Серия: запись переехала с выходного | повторяющаяся запись попала на выходной/отпуск | F-00-064 |
| «Понравилось? ★» | после «пришёл» | F-00-116 |
| «Пора снова» | прошло `repeat_interval_days` после визита «пришёл» | F-00-119 |
| Новость салона/мастера | мастер отправил новость | F-00-114 |
| Появился мастер, которого вы искали | в районе зарегистрировался мастер нужной сферы | F-00-112 |
| Поздравление с днём рождения | в день рождения, только клиентам с приложением | F-00-187 |
| «Мастер теперь в салоне …» | подписанный мастер перешёл в салон | F-00-043 (предл.) |
| Ответ поддержки | ответ в обращении | F-00-182 |

**Не шлём клиенту** (как Altegio, F-05-043): о записи, внесённой мастером в журнал без согласия клиента на
пуши от этого бизнеса — открытый вопрос (§7 №3); при смене клиента в записи; при создании серии групповых
событий; о «не пришёл» после начала визита.

### 3.2 Бизнесу (пуш в приложение бизнеса + колокольчик)

| Событие | Кому | F |
|---|---|---|
| Новая запись клиентом / заявка на подтверждение (подтвердить или отклонить **прямо из пуша**) | мастер; админ салона | F-00-067, F-05-044/049 |
| Клиент перенёс / отменил | мастер; админ | F-05-046/047/051/052 |
| Клиент нажал «Я оплатил» | мастер | F-00-097 |
| После конца записи: «пришёл · сумма / не пришёл» в 1–2 нажатия из пуша | мастер | F-00-127 |
| Домашняя запись мастера в часы смены | админ салона (имя клиента не передаём) | F-00-047, P3 |
| «Попросить перезвонить» с номером клиента | мастер (у салона — админ) | F-00-106, F-00-105 |
| Откройте окна на следующую неделю (воскресенье) | мастер в режиме `busy` | F-00-055 |
| График кончается | владелец/админ | F-02-040 |
| Товар ниже минимума; срок годности подходит; день замены оборудования | владелец | F-00-137, F-00-140, F-00-141 |
| Подписка: за 7, 3, 1 день; не прошла оплата; заморожено | владелец | F-00-023, F-00-024 |
| Проверка: одобрено / отклонено с причиной (+ монеты вернулись) | автор материала | F-00-170 |
| Идея сделана | автор идеи | F-00-009 |
| Приглашение в салон | приглашённый мастер | F-00-042 |

Сотруднику имя и телефон клиента в тексте пуша — только если у него есть право на телефоны (утечка Altegio
F-10-093 у нас закрыта, `03` P5).

## 4. Устройство отправки

```
событие в транзакции записи  →  строка notifications (outbox, статус queued, send_at)
                                        │
                     воркер очереди ────┤ берёт готовые (send_at ≤ now), по одному получателю:
                                        │   1. проверки «не слать»: клиент приглушил новости,
                                        │      тип выключен у бизнеса, нет токенов, тихие часы (предл.)
                                        │   2. текст по шаблону на языке получателя (ru/hy/en)
                                        │   3. отправка во все токены получателя; мёртвые токены гасим
                                        │   4. копия в inbox_items (ленту)
                                        └── статус sent / failed, попытки с паузой, ключ дубля
```

- **Ключ дубля** `(тип, объект, получатель, версия)`: повторная обработка не шлёт второй пуш.
- **Отложенные** (напоминание, «пора снова», день рождения) — строки с будущим `send_at`. При переносе или
  отмене записи отложенные по ней строки гасятся в той же транзакции.
- **Настройки действуют на будущие записи** (F-05-009) — у нас не повторять: напоминание считается от
  текущей настройки в момент отправки (предл.), это проще и понятнее мастеру.
- Язык: клиенту — язык его приложения (`users.locale`), а не «один на локацию», как у Altegio (F-04-228).
- Журнал отправок для бизнеса (F-05-107): по `notifications` бизнеса, с маскировкой телефонов.

## 5. Лимит новостей: 3 в неделю

| Вопрос | Предложение | Статус |
|---|---|---|
| «Неделя» — календарная (пн–вс по Еревану) или скользящие 7 дней | календарная: понятно мастеру («осталось 1 новость до понедельника») | (предл.) |
| На кого лимит | на **бизнес** (салон), не на мастера: «до 3 пушей в неделю на салон» | решено |
| Что считается | отправленная новость (одна новость = один пуш каждому подписчику) | (предл.) |
| 4-я новость | не уходит пушем, но видна в ленте подписчиков и на странице салона; «отправить пушем за монеты» — предл. (F-00-027, 00 «Открыто» №8) | открыто |
| Поводы, которые предлагает приложение (новый товар «показывать клиентам», новая услуга, новый мастер, проверенный диплом, горящее окно) | тоже новости, тоже в лимите | (предл.) |
| Кто получает | только подписчики ❤ и не приглушившие новости | решено |
| Новость проходит проверку? | «всё новое — ручная проверка до показа» (F-00-168) касается и текста новости → новость уходит после одобрения; из шаблона и одобренных фото — сразу (F-00-169) | вывод, подтвердить |

Реализация: `news_posts.week_key = '2026-W39'`; при отправке — `SELECT count(*) … FOR UPDATE` в транзакции, чтобы
два администратора одновременно не отправили 4-ю.

«Рассылка своим клиентам» (F-00-199, массовые пуши F-04-039/040) — у нас это та же новость подписчикам;
рассылки не-подписчикам — только платным продвижением (предл.). Решения нет.

## 6. Вход по коду

### 6.1 Поток

```
1. POST /v1/auth/code        { phone, channel: whatsapp|telegram|sms, purpose: client|business }
   → сервер нормализует номер, проверяет пределы, создаёт otp_requests (хэш кода), отправляет
   ← 204 (всегда одинаково — не выдаём, есть ли такой пользователь)

2. POST /v1/auth/verify      { phone, code, name?, consent? }
   → проверка хэша, срока, попыток
   → клиент: users по телефону есть → вход; нет → создать users + app_profiles (нужны name и consent, F-14-008)
   → бизнес: должен быть staff с этим телефоном (или приглашение); иначе — «зарегистрировать бизнес»
   ← { accessToken, refreshToken, user, memberships[] }

3. Запись, начатая до входа, создаётся сразу после проверки кода, без повторного ввода (F-00-032)
```

Сейчас: `sendLoginCode` ничего не шлёт, `verifyLoginCode` принимает только `0000` (`src/api/client.ts`).

### 6.2 Каналы кода

| Канал | Как (не проверено, кроме цены Telegram) | Плюсы | Минусы |
|---|---|---|---|
| Telegram | Telegram Gateway API — код приходит от служебного аккаунта Telegram | $0.01 за код (проверено 23.09); сам проверяет, есть ли у номера Telegram | нет Telegram у номера — не доставит |
| WhatsApp | WhatsApp Business Cloud API, шаблон категории «аутентификация» | в Армении WhatsApp у всех (по памяти) | нужна проверка бизнеса в Meta, шаблон утверждается; цена для Армении не найдена |
| SMS | местный или международный агрегатор | доходит на любой номер | дороже; агрегатор не выбран |

Порядок по умолчанию (предл.): клиент выбирает WhatsApp или Telegram; кнопка «Не пришёл код? Получить SMS»
появляется через 60 секунд.

### 6.3 Защита

| Правило | Значение (предл.; решение — 00 «Открыто» №24) |
|---|---|
| Длина кода | 4 цифры (удобно пожилым, F-00-124) при строгих пределах ниже; 6 — если хотим запас |
| Срок жизни | 5 минут |
| Попытки ввода | 5 на один код, потом новый код |
| Повторная отправка | не раньше чем через 60 с; не больше 5 кодов на номер в час и 10 в сутки |
| С одного адреса | не больше 20 кодов в час (защита от накрутки счёта за коды) |
| Хранение | только хэш кода; сам код — нигде, в логах тоже |
| Номер | только `+374…` на старте? — открыто (иностранные туристы-клиенты) |

### 6.4 Сессии

- Токен доступа — 15 минут; токен обновления — 60 дней, меняется при каждом использовании; украденный
  старый токен обновления гасит всю цепочку (предл.).
- Сессия привязана к устройству; список устройств и «Завершить все сеансы» (F-10-125).
- Отключение администратора и снятие доступа мастера — отзыв сессий сразу (F-00-040).
- Администратор: логин + пароль, при первом входе смена пароля (F-00-034); восстановление — только через
  владельца (у администратора нет своего номера для кода — предл.).

## 7. Открытые вопросы уведомлений и входа

1. За сколько часов напоминать о записи; можно ли клиенту выбрать (F-00-120; у Altegio клиент выбирает в
   виджете, F-05-083).
2. Тихие часы для новостей и «пора снова» (например, 21:00–10:00) — предл.
3. Получает ли пуш клиент, которого **мастер** записал в журнал по номеру, если у номера есть приложение:
   это полезно (напоминание), но выдаёт, что номер есть в базе салона (F-00-130). Предлагаю: не слать, пока
   клиент сам не записывался к этому бизнесу через приложение; мастеру — кнопка «Пригласить в приложение»
   (F-00-130 «мастер зовёт старую базу приглашением»).
4. Нужен ли каскад клиенту вообще, если пуш выключен (F-05-007 ❓) — по решению «только пуш» ответ «нет».
5. Длина и срок кода, повторная отправка, иностранные номера (00 «Открыто» №24).
6. Один вход для клиента и мастера с переключателем (F-00-036).
7. Новость проходит ручную проверку до отправки или сразу (§5).
8. Четвёртая новость за монеты — да/нет, цена.
