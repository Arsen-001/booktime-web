# 03 · Права и приватность

Сейчас права проверяет **только интерфейс**: `PermissionGate` прячет кнопки, `useCan()` читает персону из
cookie, а функции `src/api/*` ничего не проверяют. Вся моковая база лежит в браузере целиком — любой может
открыть DevTools и прочесть чужих клиентов. На сервере каждое правило ниже проверяется **в запросе**, а не на
экране; экран лишь не показывает недоступное.

---

## 1. Кто есть кто

| Персона мока | На сервере | Как входит |
|---|---|---|
| `guest` | нет сессии | — |
| `client` | `users` + `app_profiles` | телефон + код в WhatsApp/Telegram (F-00-032) |
| `individual` | `staff` роли `owner` в бизнесе `kind = individual` | телефон + код (F-00-033) |
| `owner` | `staff` роли `owner` в салоне | телефон + код |
| `admin` | `staff` роли `admin` + `staff_logins` | логин и пароль от владельца, смена при первом входе (F-00-034) |
| `master` | `staff` роли `master` в салоне | телефон + код; в салон — по приглашению с согласием (F-00-042) |
| `network` | владелец сети = `owner` в каждом филиале + `network_users` | телефон + код |
| `platform` | `platform_team` (один проверяющий, F-00-168; «несколько проверяющих с отдельными входами» — снято) | телефон + код + список разрешённых номеров |

Один человек может быть сразу клиентом и мастером (F-00-036 «один вход с переключателем» — не решено).
Модель это допускает: сессия принадлежит `user`, а «в какой роли и в каком бизнесе я сейчас» — выбор
`business_id` в заголовке запроса, который сервер сверяет с членством.

## 2. Как сервер решает «можно ли»

```
разрешено(сессия, действие, объект) =
      у сессии есть членство staff в объекте.business_id со status = active
  И   действие ∈ эффективные_права(staff)
  И   объект в области видимости (свои записи / свои клиенты / свои филиалы)
  И   ограничение по времени не нарушено (правка прошлых записей, F-10-099)
  И   бизнес не заморожен для этого действия (§5)
```

**Эффективные права** = шаблон роли (сейчас `PERSONA_PERMISSIONS` в `src/config/permissions.ts`) + галочки
владельца (`staff_permissions`, F-00-039). У владельца — всё, и снять с себя он не может. Снятая галочка
действует **со следующего запроса** (F-00-039 «снятая галочка сразу скрывает раздел»): права не кладём в
долгоживущий токен, а читаем при каждом запросе (из кэша на несколько секунд со сбросом при изменении).

**Отключение администратора** (F-00-040): `staff.status = disabled` + отзыв всех его `sessions` в той же
транзакции → следующий запрос получает `401`.

### 2.1 Список прав

Сейчас 28 прав. У Altegio в локации 211 галочек (F-10-076…089: журнал 8, окно записи 31, финансы 36,
товары 39, сотрудники 8, услуги 12, уведомления 2, настройки 10, клиентская база 26, отчёты 25, лояльность 8,
лицензия 1, онлайн-запись 1, отдельные 4). По правилу «один в один» полный список нужен, но решение
пользователя про список галочек открыто (00, «Открыто» №13). Предлагаю:

- сервер хранит права **строками с точкой** (`journal.create`, `clients.phones.card`), неизвестное право —
  «нет доступа»;
- 28 нынешних остаются корнями групп; мелкие права Altegio добавляются как дочерние (`journal.edit` →
  `journal.create`, `journal.move`, `journal.edit_past`); право-родитель без детей = все дети (так экраны
  продолжают работать без переделки);
- зависимости прав (F-10-073) сервер проверяет сам: без `journal.view` право `journal.create` не даёт ничего.

Уже просили раздельные права (`qa/requests/journal.md`): «Создавать записи» и «Перенос записи» отдельно от
`journal.edit` (F-01-024, F-01-031, F-01-178, F-01-179).

## 3. Правила приватности (P1–P12)

Каждое правило — обязательная проверка сервера и автотест. Колонка «Где держим» говорит, **в каком месте кода
сервера** правило живёт, чтобы его нельзя было обойти другим экраном.

| № | Правило | Решение | Где держим на сервере | Тест |
|---|---|---|---|---|
| **P1** | **CRM мастера клиенту не видна никогда** | решено (F-00-010, F-00-130) | Клиентские маршруты (`/v1/me/*`, `/v1/public/*`) физически не читают таблицы `clients`, `client_*`, `fin_ops`, `payroll_*`, `booking_status_history`. Отдельный слой данных «клиентское представление записи» с белым списком полей: время, мастер, место, услуги, цена по прайсу, статус, предоплата | Пользователь с номером, который есть в CRM салона (с заметками, суммами, неявками), вызывает все `/v1/me/*` и `/v1/public/*` — ни одно поле CRM не приходит; мастер у него не появляется в «Мои мастера» |
| **P2** | **Чужие имена в календаре не видны** | (предл., F-00-010, F-00-065) | Клиенту календарь не отдаётся вовсе — только **список свободных окон** (`04`). Сотруднику чужого бизнеса — только `busy_blocks.visibility_label`. Мастеру без `journal.others` — чужие записи салона как «занято» | Ответ `/v1/public/.../slots` не содержит ни одного `booking_id`, имени, телефона; перебор всех дат не восстанавливает, чья запись |
| **P3** | **Администратор видит «занято дома» без имени** | решено: «домашняя запись видна администратору»; «без имени и суммы» — предл. (F-00-046) | Журнал салона берёт занятость мастера из `busy_blocks` по `person_key`: блоки чужого бизнеса приходят как `{from, to, label: 'home'\|'visit'\|'busy'}` без `booking_id`, клиента и суммы | Админ салона открывает журнал дня, где у мастера домашняя запись: видит закрытый отрезок «дома», в ответе нет ни клиента, ни суммы, ни услуги |
| **P4** | **Выгрузка клиентов закрыта по умолчанию** | предл. (F-00-039 «выгрузка клиентов у нового администратора выключена», F-10-096) | Право `clients.export` не входит ни в один шаблон, кроме владельца; каждая выгрузка — запись в `data_exports` и `audit_events`; файл отдаётся по одноразовой ссылке с коротким сроком; владельцу уходит уведомление «администратор выгрузил N клиентов» (предл.) | Админ без галочки получает `403` на `/export`; после включения — файл и строка в журнале выгрузок |
| **P5** | Телефон клиента виден только с правом | 1:1 (F-04-202, F-10-092) | Маскировка **в сериализаторе** всех ответов, где есть телефон или email клиента: журнал, карточка, списки, отчёты, лист ожидания, журнал изменений, уведомления сотруднику. Без права — `+374 •• ••• •12` | Перебор всех маршрутов кабинета под мастером без права: ни одного полного номера. Утечки Altegio (F-10-093: email в детализации, телефон в тексте уведомления сотруднику, телефон в истории записи) у нас закрыты |
| **P6** | Точный адрес мастера на дому — только после подтверждённой записи | предл. (F-00-077) | `staff_workplaces.address_private` и «как войти» отдаются только в карточке **своей** записи со статусом `scheduled`/`client_confirmed`; до этого — район | Клиент без записи или с записью «ждёт подтверждения» адреса не получает |
| **P7** | Расстояние до мастера на дому округляется (~1 км) | предл. (F-00-077, F-00-109) | Поиск «рядом» для мест `home` возвращает расстояние, округлённое вверх до 1 км, и сортирует по округлённому | Серия запросов из разных точек не сходится к дому ближе чем на 500 м |
| **P8** | Местоположение клиента не храним | предл. (F-00-109) | Координаты приходят в запросе поиска и не пишутся ни в базу, ни в логи (маскирование в логах запросов); спрос пишется по району | В логах и таблицах нет координат клиентов |
| **P9** | Адрес клиента при выезде — только мастеру и только после подтверждения | предл. (F-00-080) | `bookings.client_address_private` отдаётся только мастеру этой записи (не администратору, не в отчёты) и только при подтверждённом статусе | Админ салона не видит адрес выезда мастера |
| **P10** | Поставщик ничего не получает о мастерах | решено (F-00-164) | Отчёт рекламодателю — только суммы показов и нажатий по дням; никаких id бизнесов; реклама поставщика — только тем, кто сам включил «получать предложения» | Отчёт по объявлению не содержит ни одного бизнеса |
| **P11** | Просьба клиента «удалите мои данные» | решить нам (F-10-159) | Обезличивание: имя → «Удалённый клиент», телефон → хэш, заметки/файлы/комментарии стираются; записи и деньги остаются с обезличенным клиентом (для отчётов бизнеса) | После обезличивания номер нигде не находится, отчёты сходятся |
| **P12** | «Ваша ссылка — только ваша»: по ссылке салона нет чужих сторис, рекламы, «похожих» | решено (F-00-006) | Публичные маршруты страницы бизнеса не зовут рекламу и сторис; в ответе только этот бизнес | — |

Дополнительно, из решений:

- **Замороженный бизнес клиентам не виден** (F-00-024): каталог, поиск, публичная страница, окна — фильтр
  `status = active` на сервере (сейчас он есть в `listCatalog` и `getPublicBusinessData`, но только в браузере).
- **Мастер «только мои клиенты»** (F-00-065): не виден в каталоге и поиске; окна видят только клиенты, у кого
  с ним была запись; чужой по ссылке может только подать заявку (предл.). Сейчас мок просто скрывает его из
  каталога и публичной страницы.
- **Ссылка «моя запись без входа»** (F-03-098): у Altegio по пересланной ссылке кто угодно отменяет запись
  (F-05-022). Предлагаю: хэш 128 бит, храним только его SHA-256, ссылка даёт **просмотр и отмену**, но не
  перенос и не данные клиента; срок жизни — до конца визита + 7 дней (предл.).
- **Клиент в чёрном списке** (F-04-056, F-00-189): онлайн-запись отклоняется на сервере с нейтральным текстом
  «Мастер сейчас не принимает онлайн-записи — позвоните», без слова «чёрный список» (предл.).
- **Запросы по чужому `id`**: сейчас `getBooking(bookingId)`, `confirmBookingByClient`, `markPrepaymentPaid`
  в `src/api/client.ts` принимают любой id. На сервере — только свой (`bookings.app_user_id = me`), иначе
  `404` (не `403`, чтобы не подтверждать существование).

## 4. Скрытие по сфере — не права

«У стоматолога нет палитры» (F-00-145) — это не безопасность, а набор функций. Сервер хранит
`businesses.sphere_ids` и отдаёт список функций (`src/config/spheres.ts` → таблица/конфиг). Проверять на сервере
стоит только то, что создаёт данные (например, нельзя включить выбор оттенка у услуги сферы без `palette`) —
чтобы не копить мусор.

| Состояние бизнеса | Кабинет | Клиенты |
|---|---|---|
| `active` | всё | видят |
| отсрочка 3 дня после конца оплаты (предл.) | всё + плашка «оплатите» | видят |
| `frozen` | вход есть; можно смотреть данные, оплатить, выгрузить; **нельзя** создавать новые записи? — открытый вопрос (00 «Открыто» №5) | не видят в каталоге, поиске, по ссылке; уже сделанные записи — открытый вопрос |
| `left` (ушёл) | только выгрузка на срок хранения | не видят |

## 6. Безопасность входа (кратко; подробно — `05`)

- Код входа: хэш в базе, 5 минут жизни, 5 попыток, повторная отправка через 60 секунд, дневной предел на номер
  и на адрес (предл.; длина и срок — открытый вопрос 00 №24).
- Пароль администратора: argon2id, блокировка после 5 неверных, смена при первом входе (F-00-034).
- Сессии: короткий токен доступа + длинный обновляемый; «Завершить все сеансы» (F-10-125).
- Журнал входов с устройством (F-10-106).
- Опасные необратимые действия (удалить сотрудника, базу клиентов) — ввод одного и того же слова во всех
  разделах (F-10-155, наш вывод); всё обратимое — «Отменить» 5 секунд (F-00-061), которое сервер реализует как
  окно отката (`05`/`02`).
