## 1. Пять правил

1. **Сначала дело, потом объяснения.** Лучший первый вход — когда объяснять нечего: на визите мы уже завели услуги,
   часы, фото и позвали мастеров (F-00-176). Подсказка нужна там, где человек иначе застрянет, а не везде.
2. **Один обучающий слой за раз.** Порядок: приветствие (один раз) → по кнопке тур (1 раз) → дальше только
   чек-лист и тихие подсказки. Никогда два окна подряд без действия человека; тур не стартует сам поверх
   открытого окна — `useTour` ждёт, пока закроются Modal/Sheet (в том числе WelcomeDialog), `when` нужен только для
   «пока грузятся данные».
3. **Тур — не больше 3–4 шагов**, и только на экране, где человек будет работать каждый день (журнал, свой
   календарь, наша «Подключить салон»). Каждый шаг — одна мысль: заголовок-действие + одна фраза.
4. **Галочки считаются по данным, а не по нажатиям.** «Услуги добавлены» = в базе есть хотя бы одна услуга.
   Тогда чек-лист не врёт, если шаг сделан другим путём или сделан нами на визите.
5. **Показывается один раз — и всегда можно повторить.** Закрытое крестиком и пройденное запоминается
   (у каждой демо-персоны свой первый вход). Повтор: кнопка «Как это работает» у экрана с туром и
   «Показать подсказки снова» в настройках / профиле.

Не больше **одного** HintBanner и **одной** Beacon-точки на экран. Гостю по ссылке салона — никаких туров
и окон: запись за секунды (F-00-004).

## 2. Роли: путь первых 5 минут

Сокращения ниже: **W** — WelcomeDialog (приветствие), **T** — Tour, **C** — ChecklistCard, **H** — HintBanner,
**E** — EmptyStateHint, **B** — Beacon, **?** — HelpTip, **V** — VisibilityCard («видно ли в каталоге»),
**P** — PermissionPrimer (своя карточка перед системным разрешением), **I** — InviteCard (приглашение мастера),
**S** — ShareLinkCard (своя ссылка с «Копировать / Поделиться»), **O** — OneTimeChoice (разовый выбор окном, потом тихая строка),
**N** — NextStepCard («Готово → что дальше»), **PB** — PreviewBanner («Так видят клиенты» над своей публичной страницей).
В скобках — id для `useOnce` / компонента.

### 2.1 Владелец салона (`owner`)

**Как приходит.** Обычно — после нашего визита: мы в «Подключить салон» завели название, сферу, точку, фото,
услуги из шаблона, часы и отправили приглашения мастерам (F-00-176). Реже — сам: регистрация бизнеса
(F-00-035) → быстрый старт.

**Чек-лист «Первые шаги салона»** (раздел settings, `/biz/onboarding`; компактно — над журналом до завершения):

| # | Шаг (заголовок) | Сделано, когда (по данным) | Ведёт на | Кнопка |

| 3 | Пригласите мастеров | ≥ 1 мастер принял приглашение (ждёт — Badge «Ждёт ответа», `waiting`) | `/biz/staff` | «Пригласить» |
| 4 | Добавьте фото салона | ≥ 1 фото (на проверке — Badge «На проверке», F-00-170) | `/biz/online/page` | «Добавить фото» |
| 5 | Отметьте, где вы | сохранена точка «📍 Я сейчас на месте работы» (F-00-075) | место работы в `/biz/online` | «Отметить» |
| 6 | Поделитесь своей ссылкой | ссылку копировали/делились хотя бы раз | `/biz/online` | «Скопировать ссылку» |

Подпись чек-листа говорит про каталог (F-00-072): «Осталось 2 шага — и салон появится в каталоге». Если профиль
**не виден в каталоге** (нет услуг, окон или фото) — это главное, что владелец должен понять за 3 секунды.
Когда всё сделано: «Салон готов принимать записи» + «Открыть журнал»; крестик скрывает чек-лист навсегда.

Необязательные (в конце, не считаются в «готов»): «Добавьте администратора — первый бесплатно» (F-00-016),
«Включите напоминания клиентам» (notify). В коде — `optional: true` у шага: пунктирный кружок, в кольцо и «Осталось N» не
входит; когда обязательное сделано, необязательные остаются под поздравлением. Считать «сколько осталось» для подписи,
`ChecklistPill` и скрытия — только `checklistProgress(items)` (одна формула на экран, таблетку и компактный вид).

**Сам без визита.** Регистрация (settings): тип «Индивидуал / Салон» → сфера → название и телефон → промокод
(только здесь, F-00-020) → **быстрый старт в 3 шага** (Stepper, «Шаг N из 3», F-15-017): услуги из шаблона
галочками → мастера (салон — приглашения по номеру; индивидуал — пропуск, мастер он сам) → часы недели с
готовыми вариантами (10–20 по умолчанию для нашего рынка — решает settings). Потом журнал + тот же чек-лист.
Бесплатного месяца нет (F-00-019) — не обещать его на экранах самостоятельной регистрации.

Тот же вход, но стартовый экран — **мой календарь**, а не журнал салона.

«Переход к сотруднику», фильтры по должностям; «Делить запись по ресурсам» — только если ресурсы есть. У него один человек — он сам;
салонные инструменты на первом экране отодвигают его неделю за край и выглядят как чужой продукт. Признак — `Business.kind === 'individual'`.

### 2.3 Администратор салона (`admin`)

Входит логином и паролем, которые выдал владелец (F-00-034). Настраивать салон — не его задача, поэтому
**чек-листа настройки нет**.

1. Первый вход — «Придумайте свой пароль» (предл. F-00-034; экран staff/settings).
2. Приветствие «Вы администратор {салон}»: 3 пункта — записывать клиентов, искать клиента по номеру, что
   владелец открыл (строится из `useCan`: деньги, телефоны клиентов, отчёты). **W** (`staff.welcome.admin`)
3. Тур журнала — тот же `journal.intro` (у каждой персоны свой «видел»).
4. Там, где права нет, — не пустота, а `PermissionGate` с понятным `fallback` («Попросите владельца открыть
   доступ») — это тоже подсказка.

### 2.4 Мастер салона (`master`)

Приходит по **приглашению** по номеру (F-00-042), вход в салон — только с его согласия (предл.).

1. Вход по номеру → экран приглашения **I** (`InviteCard`): «{Салон} приглашает вас в команду» — кто пригласил, что
   увидит салон (записи в часы смены), что остаётся вашим (домашние клиенты, F-00-044/045). «Принять» / «Отказаться»,
   под кнопками — «Выйти из салона можно в любой момент». Экран строит staff (маршрут приглашения — его).
2. Приветствие «Вы в команде {салон}» — ваш календарь, ваши клиенты, «Закончил раньше» / «Задерживаюсь».
   **W** (`staff.welcome.master`)
3. Тур своего календаря, 3 шага: «+ запись» · «Закончил раньше» → горящее окно (F-00-058) · «Задерживаюсь»
   (F-00-059). **T** (`journal.masterIntro` или `schedule.masterIntro` — у кого экран).
4. Короткий чек-лист «Ваш профиль» (3 шага): проверьте свои часы · добавьте фото работ (6 мест) · проверьте
   свои услуги и цены. **C** (`staff.masterProfile`).
5. Мастер ещё и индивидуал (F-00-045) — **H** «Домашние записи видит администратор салона» (F-00-046), один раз.
6. **k4:** у мастера в журнале одна колонка — он сам: фильтры (вид, статусы, шаг, перерыв, ресурсы) — в «⋯»/Sheet, его день — сразу под
   «Сегодня ‹ ›» (сейчас сетка начинается на 1 250 px и тур «Закончил раньше / Задерживаюсь» показать не на чем).

### 2.5 Клиент без приложения по ссылке салона (`guest` на `/b/[slug]`)

**Никаких туров и окон.** Страница сама объясняет себя: только этот салон — без рекламы, соседей и чужих
сторис (F-00-006); главное действие «Записаться» у большого пальца.

- Над услугами — одна строка-обещание (не баннер): «Запись онлайн — без установки и паролей» (F-00-007).
- На шаге данных — **?** рядом с «Код придёт в WhatsApp или Telegram»: «Почему не SMS?» (F-00-032).
- Нет окон — **E** не «Пока пусто», а «Свободного времени на эти дни нет» + «Показать другие дни» и
  «Сообщить, когда появится» / лист ожидания (F-00-102).
- **Бизнес ещё не опубликован** (черновик, `status: 'draft'`) — не «Страница не найдена», а спокойное **E** «{Салон} скоро откроет онлайн-запись»
  без наших ссылок и каталога. Сотрудник этого бизнеса на той же странице видит **PB** tone="notReady" с путём «Закончить настройку».
- После записи, на экране подтверждения — **H** tone=info: «Напомним за день — в приложении BookTime» + «Установить»
  (напоминания только пуш, F-00-120). Один раз (`online.installAfterBooking`, scope 'global').

### 2.6 Клиент приложения (`client`, и `guest` в приложении)

Смотрит без входа (F-00-031) — вход только в момент записи.

- Главная: сверху «Что ищете?» и «Свободно сегодня рядом». Перед системным запросом геолокации — **P**
  (`PermissionPrimer id="client.geoPrimer"`): «Показать, кто свободен рядом?» · «Разрешить» → системный запрос ·
  «Выбрать район»; отказ — `state="denied"` со спокойным текстом, не ошибкой (иначе браузер спросит «в лоб», человек
  откажет, и «рядом со мной» не работает никогда).
- Гость: одна **H** (`client.browseWithoutLogin`, scope 'global'): «Смотрите без входа — войти попросим
  только при записи».
- **Поправка k2** (правило пользователя «пустое состояние у всего», CONVENTIONS §0.3): блоки с данными человека
  («Ближайшие записи», «Мои мастера») не прячем, а показываем компактный EmptyState **с действием** («Найти мастера»).
  Прячем только служебные места, которые не про человека: рекламное место, пустая лента сторис, серые кружки-заглушки
  — если там нечего показать, блока нет. Надписи «Здесь будет реклама салонов» на виду у клиента быть не должно.
  Пустые экраны — **E**:
  «Мои записи» → «Здесь будут ваши записи» + «Найти мастера»; «Избранное» → «Нажмите ❤ на странице мастера —
  он появится здесь и будет присылать новости» (F-00-113); «Мои мастера» — после первого визита (F-00-118).
- Первый раз на странице мастера — **B** на ❤ (`client.favoriteBeacon`), гаснет после первого нажатия.
- В профиле — «Крупный шрифт» (F-00-124) и «Показать подсказки снова» (`ReplayHintsButton`).

### 2.7 Наша панель при визите (`platform`)

Здесь человек — мы сами, учить интерфейсу не надо; нужно **не забыть шаг и уложиться в 10 минут**.

- `/platform/connect` — мастер из 7 шагов (Stepper): название и сфера → я на месте → фото → мастера → услуги →
  часы → промокод. Над ним — ориентир времени («≈ 10 мин»), черновик сохраняется на каждом шаге («Начатые
  подключения» — продолжить).
- Финал — не тост, а **экран передачи владельцу**: «Салон подключён и виден в каталоге» + что сказать и
  показать: вход по номеру, ссылка и QR, бесплатный месяц до {даты} (F-00-019), что владелец увидит при входе
  (его приветствие и чек-лист — §2.1). Кнопка «Записать визит» → учёт визитов (F-00-177). Ссылку салона показывать той же
  **S** ShareLinkCard, что владелец увидит у себя, — узнаёт её с первого взгляда.

## 3. Подсказки на пустых экранах (кабинет)

Пустота первого входа ≠ пустота фильтра. Первый вход — **EmptyStateHint** (что здесь будет, 2–3 шага, одна
кнопка). «Ничего не нашлось по фильтру» — обычный **EmptyState** со «Сбросить фильтры».

## 4. Короткие туры (≤ 3–4 шагов)

| id | Экран | Кто | Шаги | Запуск |
|---|---|---|---|---|
| `journal.intro` | `/biz/journal` | owner, admin, network | Новая запись · листать дни · колонка мастера | после «Показать, что где» в приветствии; повтор — «Как это работает» |
| `journal.masterIntro` | свой календарь в журнале | master | + запись · Закончил раньше · Задерживаюсь | после приветствия мастера |
| `schedule.quickTools` | `/biz/schedule` | individual, master | Открыть весь день · провести пальцем · как на прошлой неделе | autoStart при первом заходе |
| `platform.connectIntro` | `/platform/connect` | platform | шаги мастера · черновик · экран передачи | autoStart, `scope: 'global'` |

Другие экраны обходятся без туров: там хватает понятной раскладки, EmptyStateHint и **?**.

Кнопка повтора у каждого экрана с туром — **одна и та же** `TourButton` (ghost, значок «?», подпись «Как это работает»),
в `PageHeader actions` левее главного действия; на телефоне в тесной шапке — `iconOnly`. `fresh={!tour.seen}` ставит
тихую точку, пока тур не видели. Сам тур не стартует поверх открытого окна или шторки — `useTour` ждёт, пока их закроют
(в том числе WelcomeDialog), поэтому «приветствие → тур» работает без ручных `when`.

## 5. Что показывается один раз и как повторить

| Что | Один раз? | Как повторить |
|---|---|---|
| WelcomeDialog | да, и «Позже» тоже запоминается | «Показать подсказки снова» (настройки, профиль клиента) |
| Tour | да (пройден или пропущен) | кнопка «Как это работает» рядом с заголовком экрана (`tour.start()`) |
| ChecklistCard | пока не скрыт крестиком; сам исчезает, когда всё сделано и скрыт | `/biz/onboarding` показывает полный чек-лист всегда |
| HintBanner с `id` | да, после крестика | «Показать подсказки снова» |
| HintBanner без `id` | нет — пока верно условие (нет окон, нет точки) | — |
| Beacon | гаснет после первого нажатия | «Показать подсказки снова» |
| PermissionPrimer с `id` | до «Разрешить» или «Выбрать район / Не сейчас» | «Показать подсказки снова»; отказ браузера — `state="denied"` (не спрашиваем снова, объясняем, где включить) |
| VisibilityCard, InviteCard, ShareLinkCard | всегда, пока верно условие (не виден / приглашение не принято / ссылка есть) | — |
| OneTimeChoice с `id` | окно — само один раз, пока не выбрано; «Позже» / крестик тоже запоминаются | тихая строка «Режим: … · Изменить» всегда на экране |
| EmptyStateHint, HelpTip | всегда, пока пусто / по нажатию | — |

Память — `localStorage`, ключ `bp.onb.<персона>:<вид>.<id>` (вид: `tour.`, `welcome.`, `hint.`, `checklist.`,
`beacon.`, `choice.`). id пишем как `<раздел>.<что>`: `journal.intro`, `online.linkIsYours`. У пустого бизнеса
(`?demo=owner&empty=1`, `?demo=individual&empty=1`) персона в ключе — `owner-empty` / `individual-empty`: свой первый вход.

## 6. Как разделу пользоваться компонентами

Импорт — прямо из файла: `import { Tour } from '@/ui/onboarding/Tour'`. Тексты — из словаря раздела (`useT`),
кнопки «Далее / Назад / Готово / Закрыть» подставляются сами из `common`/`ui`.

### Тур по экрану

```tsx
const t = useT('journal');
const tour = useTour('journal.intro', { autoStart: false });   // autoStart: true — сам при первом заходе
// …в разметке — метки целей:
<Button data-tour="journal-add" leftIcon={<Plus />}>{t('add')}</Button>
<DaySwitcher data-tour="journal-day" />
// …где-то рядом с заголовком — повтор:
<Button variant="ghost" size="sm" leftIcon={<CircleHelp />} onClick={tour.start}>{t('howItWorks')}</Button>
<Tour
  {...tour.props}
  steps={[
    { id: 'add', target: '[data-tour="journal-add"]', icon: <CalendarPlus />, title: t('tour.add.title'), body: t('tour.add.text') },
    { id: 'day', target: '[data-tour="journal-day"]', title: t('tour.day.title'), body: t('tour.day.text') },
    { id: 'col', target: '[data-tour="journal-column"]', side: 'top', title: t('tour.col.title'), body: t('tour.col.text') },
  ]}
/>
```

- Нет цели на экране (ещё грузится, скрыта на телефоне) — шаг покажется карточкой без подсветки; цель появится —
  подсветка переедет к ней. Держите `when={!q.isLoading}` в `useTour`, чтобы тур не начинался на скелетоне.
- Метка цели — `data-tour="<раздел>-<что>"`. Кнопка есть и в мобильной, и в десктопной раскладке — ставьте на обе,
  подсветится видимая.
- Телефон: карточка внизу у большого пальца, цель плавно подводится в центр экрана.

## 9. Как проверить первый вход

1. Пустой бизнес: `?demo=owner&empty=1` или `?demo=individual&empty=1` (обратно — `?empty=0`). У него своя память подсказок, поэтому
   приветствия, туры и «спросить один раз» покажутся, даже если на живом салоне вы их уже закрыли.
2. Замер: `node scripts/measure.mjs --routes /biz/journal,/biz/online --persona owner-empty,individual-empty --device phone`.
3. Вопрос к снимку телефона: «понятно ли за 3 секунды, что здесь делать?» — главное действие и объяснение должны быть **на первом экране**
   (до 844 px), а не под фильтрами и настройками, которыми пока нечего делать.
4. Повтор подсказок в том же браузере — «Показать подсказки снова» (профиль клиента, витрина) или `resetOnboarding()` в консоли; пока
   «Сбросить демо-данные» их не сбрасывает (§7, №2).
