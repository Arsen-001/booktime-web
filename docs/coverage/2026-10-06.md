# Охват ТЗ: интерфейс и сервер, 06.10.2026

Сверка ТЗ (`booking-research/functional-map/`, 2896 функций в файлах 00–16) с кодом сайта (`booking-platform`, ветка
develop) и сервера (`booktime-backend`). Вопрос: что работает у настоящего салона в режиме `api`, а что держится только
на моке или на заглушке. Код не правился.

## 1. Как считали

1. **В интерфейсе** — у функции есть метка `data-f` в `src/**` (`node scripts/fids.mjs`).
2. **На сервере** — скрипт на TypeScript AST (лежит в скретчпаде, в репозиторий не добавлен) прошёл по всем
   экспортам `src/api/**`. Функция считалась «серверной», если в ней есть ветка `isApiMode()`. Функции-склейки
   получали статус тех функций, которые они вызывают. Дальше для каждого файла с `data-f` (вместе с его хуками и
   компонентами на два уровня вглубь) собирался список вызовов `src/api`. Чтение зеркала (`coreList`, `readCore`) и
   служебные `…Tx` / `…Sync` за мок не считались. Похожие на мок ветки, которые экран сам закрывает проверкой
   `isApiMode()` (например, `startIntroTrial`), разобраны руками и тоже не считались.
3. **Сервер правда отвечает** — все сегменты адресов из `src/api/*.server.ts` сопоставлены с декораторами маршрутов
   NestJS (1369 маршрутов). Адресов, которых нет на сервере, не нашлось.
4. **Ограничение подхода:** «на сервере» значит, что экран ходит на сервер и сервер хранит данные. Это ещё не значит,
   что правило выполняется или сообщение доходит до человека. Такие места искались отдельно, по сервисам сервера
   (раздел 3.2). Их нашлось много, поэтому колонку «На сервере» нужно читать как верхнюю границу.
5. Решения со статусом «снято (не делаем)» в 00 своих F-номеров не имеют, поэтому из счёта ничего не вычиталось.
   Около 45 функций Altegio относятся к другим странам: Украина, ОАЭ, Бразилия, Россия, Pagar.me, Яндекс,
   медицинские сферы. Их нет ни в одном списке ниже: для Армении они не нужны.

Как читать колонки:
- **Частично** — экран функции вызывает хотя бы одну функцию, которая в режиме api пишет или читает браузерную базу.
  Почти все такие случаи сводятся к трём источникам:
  - «Найти окно → предложить» и напоминания о заявках (`src/api/journal-offers.ts`);
  - статус чат-партнёра (`getChatPartnerStatus`);
  - журнал операций с данными (`logDataOperation`).

  Из-за них в «частично» попали и соседние функции журнала, размеченные в тех же файлах: сами по себе они работают
  через сервер.
- **UI без своего запроса** — экран читает данные через общее зеркало ядра (`useCoreList`) или получает их от
  родителя. Это формы клиента, фильтры, справочные экраны. Отдельной серверной части им не нужно.
- **Нет в UI** — 9 функций:
  - F-00-028, F-00-029, F-00-030 — отложены или не решены владельцем;
  - F-06-182, F-07-100 — Бразилия;
  - F-07-111 — правило «включили политику → убрать конфликтующие настройки предоплаты». Скорее всего, не нужно:
    предоплату настраивают в одном месте (решение 01.10);
  - F-01-161, F-16-164, F-16-165 («изменить или удалить заявку листа ожидания») **на деле сделаны**:
    `WaitlistForm` → `updateWaitlistEntry`, `WaitlistBoard` → `removeWaitlistEntry`, сервер `PATCH/DELETE
    …/waitlist/:id`. Не хватает только меток.

**Метки только на скрытых элементах.** 63 функции размечены лишь пустыми `<span data-f hidden />` или

## 3. Что не работает у живого салона

### 3.1. Только мок в режиме api (проверено по коду)

### 3.3. Проверено от экрана до базы — работает

- **F-01-121, восстановить удалённую запись.** `RecordsScreen` → `restoreDeletedBooking` → `journal.server.ts::restoreBooking`
  → `POST bookings/:id/restore` → `BookingsService.restore`: срок из `deletionRestoreWindowDays`, повторная проверка
  занятости, коды `restore_expired` и `restore_slot_taken`.
- **F-04-135, объединение дублей.** Меню карточки → `clients.server.ts` → `POST clients/merge`.

- **F-00-098 и F-00-071, поздняя отмена и счётчик неявок.** На сервере `noShowCount` увеличивается: снята проблема
  B14 из `docs/backend/07-mock-only.md`.
- **F-00-079, выезд всегда с подтверждением.** `rules.ts`: `workplace === 'visit'` → `awaiting_confirmation`.
- **F-00-045, двойная запись невозможна, в том числе между двумя бизнесами одного мастера.** `person_locks` +
  `busy_blocks` в `availability/occupy.ts`.
- **F-04-056 / F-00-189, чёрный список.** `client_blocked` при онлайн-записи.
- **B2, код перед записью из веба.** `POST public/b/:slug/code` + `otp.verify`.
- **F-00-059, «Задерживаюсь».** `POST bookings/:id/delay`. **F-00-058, «Закончил раньше».** `finishEarly`.
- **«Предложить другое время»** (известная ошибка из `qa/full-test-0930/final-api.md`) **исправлена**: сервер сверяет
  время с `freeSlots`.

`docs/backend/07-mock-only.md` (25.09) во многом устарел: большая часть пунктов S, B, K и P теперь сделана на сервере.

## 5. Для сведения

- `scripts/fids.mjs` считает только наличие метки. Скрытые метки и функции, которые хранятся, но не действуют
  (п. 3.2), он не видит. Если считать охват по критериям «Готово, когда», стоит отмечать `[x]` только после
  проверки в режиме api.
- Число отправляемых серверных типов уведомлений растёт (`kinds.ts`). Каталог экрана (`notify-type-registry.ts`,
  29 + 2 типа) стоит разметить флагом «отправляется», чтобы экран и журнал показывали правду (пп. 3–4 таблицы).
- Скрипт анализа лежит вне репозитория. Если его нужно повторять, его стоит перенести в `scripts/` рядом с
  `fids.mjs`, например как `fids.mjs --server`.
