Задача: 24 функции раздела `schedule`, не имевшие `data-f` в коде. Без тестов/замеров (решение
пользователя 26.09.2026) — только сборка, затем `tsc`/`eslint` по затронутым путям и
`node scripts/fids.mjs --area schedule`.

## Метод

По каждой функции сначала искал существующую реализацию (часто под ЧУЖИМ F-id — экран уже построен
в journal/settings/network/online/client/notify для их собственных функций, но совпадает с описанием
из `02-slots-schedule.md` 1:1) и добавлял `data-f="F-02-0NN"` рядом с уже стоящим id (вложенный
`span`/доп. `data-f` в том же узле). Только для двух функций писал новый код: месячный календарь
загрузки (F-02-038, экран пуст в коде совсем) и настоящая проводка «своих типов нерабочих дней сети»
в панель графика/таблицу (F-02-011 — тип `custom:${string}` уже был объявлен в домене, но нигде не
читался: `dayTypeById` для него молча возвращал «Рабочий день», то есть свой нерабочий тип рисовался
как обычный рабочий — поймано и исправлено).

## partial (3 — по-настоящему не построено, причина)

- **F-02-022** «Платный сотрудник — тот, кто стоит в графике» — лицензионная модель мест
  (paid/free seat) в коде вообще отсутствует ни в staff, ни в billing/settings: нет поля,
  нет расчёта. Сама справка Altegio (см. блок ТЗ) прямо противоречит себе в том, какие роли
  бесплатны без графика — решать это нужно владельцу продукта, а не сборщику молча. Не строил.
- **F-02-036** «Перерыв из пустого места журнала» (выбор Запись/Событие/Перерыв по тапу на пустую
  ячейку) — сейчас клик по пустой ячейке в `DayGrid.tsx` сразу зовёт `onCreate` (окно записи), без
  промежуточного выбора. Файл `DayGrid.tsx` в момент работы был занят параллельным сборщиком
  (harness прислал уведомление о параллельной правке во время сессии) — структурная правка
  обработчика клика в общем, активно редактируемом файле журнала оставлена, чтобы не создавать
  конфликт с чужой правкой. Нужно точечно доделать отдельным проходом, когда файл не занят.
- **F-02-063** «Технический перерыв через Excel» — в разделе «Услуги» вообще нет операций «Выгрузить
  в Excel / Загрузить из Excel» (ни для одной колонки), это отдельная инфраструктура (генерация и
  парсинг XLSX, лимит 500 строк), а не одна колонка `techBreak`. Строить одну колонку без остального
  экспорта/импорта значило бы создать нерабочий фрагмент. Не строил — нужно как отдельная функция
  каталога услуг (владеет `services`, не `schedule`).
