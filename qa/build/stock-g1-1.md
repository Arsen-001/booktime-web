## Что сделано (проверено вживую: tsc, eslint, console-clean на затронутых экранах)

**Касса склада (F-00-138, F-08-057, F-08-070, F-08-073) — один узел, четыре F-id:**
- Добавлен мост `stock → finance`: `recordStockFinanceOperation()` (`src/api/stock.ts`) находит кассу по
  локации и складского товара, находит статью `goodsSale`/`goodsPurchase` через
  `readArea('finance').itemBySystemKey`, зовёт `finance.recordOperation()` (единственная точка записи кассы —
  по документации самого `finance.ts`: «одна бизнес-операция — один вызов»). Обратная сторона —
  `finance.cancelOperation()`.
- `createSaleOperation`: продажа с `paid: true` теперь пишет доходную операцию в кассу суммой строк +
  доп.строк (абонементы/сертификаты), способ оплаты (`cash`/`card`/иначе `other`), партнёр — клиент, если
  указан. Id операции кассы сохраняется в новом поле `OperationDoc.financeOperationId`.
  (F-00-138, F-08-070)
- `cancelSaleOperation`: если у отменяемой продажи была касса — вызывает `cancelFinanceOperation`, выручка
  снимается тем же путём, каким finance умеет отменять операции. (F-08-073)
- `createIncomeOperation`: приход с `paid: true` пишет расходную операцию (закупка) в кассу. Добавлено поле
  `IncomeInput.paymentMethod?` (по умолчанию `cash` — UI формы прихода это поле не выставляет, это **assumed**
  упрощение, форма пока не даёт выбрать способ оплаты прихода — только «Оплачено» да/нет). (F-08-057)
- `updateOperationDoc` (галочка «Оплачено» у уже созданного прихода): переключение false→true заводит кассовую
  операцию, true→false — отменяет её. Правка суммы строк у уже оплаченного прихода кассу пока НЕ пересчитывает
  (**partial**, см. ниже). (F-08-057)

**F-08-028 — archiveGood/archiveGoods не проверяли techCards:**
- `archiveGood` теперь бросает `ApiError('good_in_use')`, как уже делал `deleteGood`.
- `archiveGoods` возвращает `{ archived, skipped }` вместо `void`; пропущенные (used in techCards) не
  архивируются молча. `GoodFormScreen` уже был готов показать причину (`goodForm.archiveFailedInUse` —
  ключ существовал и ждал этой правки, только не срабатывал). `StockCatalogScreen.archiveSelected` обновлён
  под новый ответ, добавлен ключ `catalog.bulk.archivedSkipped` (ru/en).

**F-08-092/F-08-076 — поле «Код» подписано optional, но отказывало без него:**
- `ExtraModal` (`SaleFormScreen.tsx`) больше не блокирует добавление сертификата/абонемента без кода —
  генерирует код автоматически (`randomCode()`), когда тип требует код и продавец его не ввёл. Подпись
  «необязательно» теперь правдива для продавца: поле реально не обязательно вводить руками.

**Нарушения решений (текстовые, ru/en):**
- Калька из Altegio `operations.notFoundTitle` («По данным критериям данные не найдены») →
  «Ничего не нашли» (в стиле остальных `notFoundTitle` раздела).
- Заголовки страниц «Складские операции» / «Технологические карты» (и подписи в help-виджете) переименованы
  в «Приход и расход» / «Техкарты» — вслед за уже переименованным меню (`nav.operations`/`nav.techCards`);
  то же для en (`title` → `Stock movements`, вслед за `nav.operations`).
