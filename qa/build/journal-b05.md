## Что построено

**Настройки → `/biz/journal/settings`** (новая страница, ссылка из `SettingsHub` и подпункт меню
«Настройки журнала», право `settings.manage` — видно владельцу/сети/индивидуалу, как требует ТЗ
«Роль: владелец»):
- «Основные настройки»: тип записи (F-01-167, три плитки + «по сфере»), вид журнала и должность/ресурс
  по умолчанию (F-01-170), «показывать занятые ресурсы у сотрудников» (F-01-169, настройка).
- «Записи и визиты»: первая строка блока (F-01-171), интервал склейки визита (F-01-172, поверх уже
  существовавшего `visitIntervalMin`), «разделять запись по ресурсам» (F-01-174, перенесено из шапки
  журнала в постоянное место), «показывать лист ожидания» (F-01-155).
- «Технические перерывы»: правило суммы/максимума (F-01-175, перенесено из шапки) + общий перерыв
  после записи, минут (F-01-175, новое поле, применяется к новым записям).
- «Работа с клиентами»: разрешить онлайн-запись поверх «Не пришёл» (F-01-173) — реально меняет
  `computeOverlap`/`computeResourceFree` в `api/journal.ts`, не только хранит галочку.
- «ФИО клиента» (F-01-176): ссылка на существующий тумблер клиентов (F-04-046) + свой тумблер
  «Отчество» (хранится, поле в формах пока не выведено — см. «Не доделано»).
- «Настройки из справки» (F-01-177): решено, где живёт каждая — период планирования графика (раздел
  `schedule`) и число мест в групповой записи (раздел `services`), с прямыми ссылками.
- «Чат с клиентом» (F-01-165, F-01-166): демо-переключатель «подключена ли интеграция» + всплывашка
  о новом сообщении (F-01-165, рабочая, с автосбросом через 4 с) + «сохранять лидов из чата» —
  переиспользует `clients.getAutoSaveChatLeads`/`simulateChatLead` (F-04-016, уже был построен как
  временный заменитель) вместо дублирования.
- «Права доступа» (F-01-178, F-01-179): выбор сотрудника-администратора, вкладки «Журнал записей» (8
  прав) / «Окно записи» (31 право), каждый тумблер сохраняется сразу.

**Права — `src/areas/journal/lib/rights.ts`** (временный слой поверх грубых `journal.*`/`clients.*`,
тот же паттерн, что `src/areas/clients/lib/rights.ts`): `useJournalBlockRights()` и `useWindowRights()`
дают умолчания по персоне (owner/network/individual — все права; admin/master — из ТЗ), override по
`staffId` из настроек, грубые права фундамента всегда сильнее, если они строже. Реально включено в UI:
- **F-01-085**: кнопка «Сохранить» и корзина в окне записи блокируются по `canEditBooking`/
  `canDeleteBooking` (статус + оплаченная сумма) — `BookingWindow.tsx`.
- **F-01-115**: перетаскивание/растягивание в сетке — `journal.reschedule` × `reschedule`-право
  (`JournalScreen` → `canResize`); отдельно от прав окна — «Изменять сотрудника и время»/«длительность»
  блокируют соответствующие поля в `LeftZone` (`lockSchedule`/`lockDuration`), а не всё окно целиком.
- **F-01-154**: быстрые плитки левой панели (`JournalSidebar`) гасятся по `stock.edit`/`finance.edit`/
  `services.view`/`stock.view`; кнопка статистики (`DaySummaryButton`) — по `showStatistics`.
- **F-01-178**: `viewStaffScope` сужает список видимых колонок сотрудников (`staffForView`),
  `historyLimit` блокирует правку записи за пределами окна (`useIsBeyondHistoryLimit`), `showPhones`
  маскирует телефон в блоке сетки (`BookingBlock`, `maskPhone()`), `showWaitlist` × настройка
  управляют плиткой листа ожидания.
- **F-01-179**: `clientAccess` прячет всю правую зону клиента (с сообщением «нет прав»),
  `createClientInWindow` — поля нового клиента, `clientDropdown` — подсказки поиска,
  `showPhones` — маска телефона в окне, `createBookings`/`editBookings`/`editArrivedPaid`/
  `deleteBookings`/`deleteArrivedBookings`/`deletePaidBookings` — уже перечислены выше.
- **F-01-180**: `historyLimit` + статус/оплата вместе гасят Сохранить/Удалить у записей вне окна
  прошлого (`beyondHistory` в `BookingWindow`).

**Прочее:**
- **F-01-036**: источник `'external'` уже существовал в ядре и виден в «Записях» как обычная запись —
  добавил только `data-f`; проверка «без телефона — отклонить» требует правки `createBooking` в
  фундаменте (`api/core.ts`) — не мой путь, запрос в `qa/requests/journal.md`.
- **F-01-192**: кнопка «Дублировать» (иконка) в шапке окна записи у сохранённой записи — новая
  `duplicateBooking()` в `api/journal.ts`: статус сбрасывается на «Ожидание», оплата и депозит не
  переносятся (как в справке 360426), состав услуг/товаров копируется, открывает копию сразу.
- **F-01-184/185**: отдельного мобильного приложения в проекте нет — по решению «один макет на все
  телефоны» тот же адаптивный журнал и окно записи на 390×844 покрывают создание записи и работу с
  визитом (статус, товары, оплата, удаление) — уже было построено в b01–b03, в эту пачку добавил только
  `data-f` и проверил измерителем на четырёх персонах.
- **F-01-219**: записи клиента с удалённой (мягко) карточкой не теряются структурно — `deletedAt`
  не убирает клиента из `core.clients`, поэтому окно записи и «Записи» находят его по id как раньше;
  добавил `data-f` на `RecordsScreen`, отдельной логики не потребовалось.

## assumed (додумано)

- Права блока «Журнал записей»/«Окно записи» — тонкие ключи (8+31) не в `config/permissions.ts`, а в
  своём слое `lib/rights.ts` с override по `staffId` в своём срезе (просьба в `qa/requests/journal.md`).
- `viewStaffScope` — упрощение «все / только свои» без «выбранных сотрудников» из ТЗ (там ▾-список).
- `historyLimit` — добавил опцию «3d», которой нет в ТЗ буквально (шаг между 1d и 7d), для более
  плавного демо; остальные значения — 1d/7d/1m/3m/6m/unlimited — как в ТЗ.
- F-01-176 «Фамилия» — не дублирую состояние клиентов, а ссылаюсь на их тумблер; отдельные поля
  Фамилия/Отчество в форме окна записи и в карточке клиента не выведены (см. requests).
- F-01-177 — «период планирования» и «число мест» не строю как настройки здесь (они принадлежат
  `schedule`/`services`), только объясняю и даю ссылку — читаю это как решение вопроса ТЗ «где живёт».
- Чат с клиентом (F-01-165/166) — интеграции нет физически, добавил демо-переключатель «подключена ли
  интеграция», как и раньше делали другие пачки для похожих внешних систем.
- F-01-192 «Дублировать» — кнопки в оригинале не нашли (ТЗ ❓), сделал иконку-кнопку в шапке окна
  сохранённой записи по описанию из справки (копия без политики оплаты и депозита).
