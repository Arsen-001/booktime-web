## assumed (додумано)

- Обязательность полей формы типа карты: ТЗ отмечает ❓ (не проверяли пустое). Сделал обязательным только «Название»
  (как в списке акций/карт b01) — остальные поля со значениями по умолчанию можно сохранить пустыми/нулевыми.
- «Товары» (F-06-026, F-06-035, product scope) — у раздела нет каталога товаров (он у `stock`), поэтому ограничение
  на товары — это только режим («Все»/«Не для товаров»/«Некоторые» — последний вариант без реального выбора
  конкретных товаров, только режим сохраняется). Просьба заведена не была — сочтено, что каталог товаров придёт
  из `stock` позже и это скорее интеграционный вопрос b05/владельца, а не блокирующая просьба.
- «Тип бонуса» на шаге 3 условного вида (F-06-040) — по ТЗ это поле есть, но что оно значит, не описано (❓ в ТЗ) —
  сделал его тем же переключателем процент/сумма, что и у типа скидки (наиболее естественное толкование в контексте
  «скидка на n-ю услугу»).
- «Продано»/«Оплачено» (F-06-048) считаю по `Booking.status === 'arrived'` как «визит состоялся» — в ядре нет явного
  статуса «оплачено полностью», `arrived` — ближайшее по смыслу (клиент пришёл, услуга оказана).
- Лимит применения (F-06-027) «если заданы оба — действует меньшее» (❓ в ТЗ) — сохраняю оба числа как есть, сам
  расчёт лимита при оплате — задача движка оплаты (b04/finance), не форма.
- Reference-локации акции (F-06-036 `locationIds`) — пустой список читаю как «во всех локациях сети» (естественное
  значение по умолчанию для новой акции без выбора).
