# Отчёт сборщика · clients · пачка b03

Работа с клиентом: история визитов, отметка «пришёл · сумма», визиты задним числом, сводка CRM,
неявки и долги, массовые действия, клиент в окне записи.

## Что построено

**Экраны/маршруты:**
- `/biz/clients/[clientId]` — новые вкладки «История визитов» (`HistoryTab.tsx`, фильтр
  все/неоплаченные/в долг, фото визита, ссылка на запись), «Статистика» (`StatsTab.tsx`, график
  выручки по месяцам, любимые услуги/мастера), «Звонки» (`CallsTab.tsx`, 🔒 демо — телефонии нет),
  «Файлы» (`FilesTab.tsx`, загрузка/скачивание/удаление); строка «Посетители» и бейдж «Должник» в
  карточке; кнопка «Пригласить в приложение» (F-00-130) для клиентов без `appUserId`; кнопка
  «Посмотреть визиты с долгом», переключающая вкладку+фильтр.
- `/biz/clients` — кнопка «Добавить визит» (шапка), новый quick-фильтр «Неявщики» (F-04-157),
  массовые действия по «Действиям» и по `BulkActionBar` (сообщение / PUSH мобильный / PUSH Altegio.me
  / категория / удалить), три модалки (`BulkMessageModal`, `BulkCategoryModal`, `BulkDeleteModal`).
- `/biz/clients/summary` — новая «Сводка CRM»: выручка/клиенты/визиты за период, разбивка по
  мастерам (выручка + часы), блок «Ждут отметки» с инлайн «Пришёл·сумма» / «Не пришёл».
- `src/areas/clients/extensions/BookingWindow.tsx` — вклад в окно записи (хост `bookingWindow`):
  мини-карточка клиента, категории, «Данные сети» (визиты/неявки/продано/баланс), правка примечания
  без выхода из записи.
- `AddVisitSheet.tsx` — визит задним числом (F-00-129): с карточки клиента (клиент фиксирован) и со
  списка (поиск существующего клиента ИЛИ создание нового прямо в форме, имя+телефон).

**API/домен/сток:** `src/domain/clients.ts` (история визитов, файлы, посетители, звонки, сводка CRM,
`PastVisitInput`), `src/mock/slices/clients.ts` (версия 4: `files`, `invitedAt`,
`manualVisitPayments`, `categoryColors`, `calls` — с сидом звонков/файлы пустые для честного
пустого состояния), `src/api/clients.ts` (`listClientVisits`, `listDebtVisits`, `addPastVisit`,
`listFiles/addFile/deleteFile`, `listVisitors`, `inviteToApp/getInvitedAt`, `getCrmSummary`,
`listPendingMarks`, `markVisitArrived/markVisitNoShow`, `bulkSendMessage/bulkPushMobile/
bulkAddCategory/bulkDeleteClients`, `listCalls`, `updateClientNote`).

**Попутно почищено (в своих файлах):** `createClient`/`updateClient`/`deleteClient` читали/писали
mock-базу вне `request()` (нашёл через консольное предупреждение `[mock-db]` при прогоне сценария
«добавить визит новому клиенту») — обернул в `request()`, поведение не поменялось, предупреждение
пропало.

## assumed (додумано)

- Источник записи `BookingSource` не имеет значения «внесено вручную мастером» — использовал
  ближайшее по смыслу `'phone'`; предложил в `qa/requests` завести отдельное значение, если ядро
  сочтёт нужным.
- Оплата по визиту (частично оплачено / оплачено / в долг) нигде не хранится по-настоящему (только
  клиентский агрегат «Оплачено»); для визитов, добавленных вручную, храню в своём срезе
  (`manualVisitPayments`), для визитов из журнала — считаю полностью оплаченными при статусе
  «пришёл» (это единственный источник правды, который есть сейчас).
- Слово подтверждения массового удаления — «УДАЛИТЬ» (капс), по аналогии с удалением услуги, раз
  справка не даёт точного слова для клиентов (см. F-04-042 «⚠ добавлено проверкой 2»).
- Цвет новой категории (F-04-041) хранится как индекс токена `chart-N` в `ClientsState.categoryColors`
  — полноценный справочник категорий (с цветом на бейдже) достроит b04.
- «Данные сети» (F-04-094) показывает данные ТЕКУЩЕЙ локации, не по всей сети — сеть филиалов ещё
  не тянет данные клиента по всем локациям одним запросом; при появлении такого API — переключить.
- Демо-звонки (F-04-079) сидятся детерминированно от хэша id клиента (как остальные срезы раздела),
  видны при `h % 4 === 0`.
