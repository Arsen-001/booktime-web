# Пачка b04-fix1 — финансы: починка дефектов измерителя (F-07-076, F-07-094, F-07-078, F-07-156)

Сборщик чинил конкретные дефекты, найденные измерителем на пачке b04 (онлайн-платежи, предоплата,
фискализация), а не пересобирал весь пакет из 29 функций заново.

## Готово

- **F-07-076 · Раздел «Онлайн-платежи»** — у каждой из трёх карточек способов (`OnlinePaymentsScreen.tsx`)
  добавлена кнопка «Как это работает?» (иконка `HelpCircle`), открывающая `Modal` с описанием и примером
  именно для этого способа (`online.howItWorks.<link|widgetPrepayment|onlineSales>.{title,description,example}`
  в `messages/{ru,en}/finance.json`). Раньше такого элемента не было вообще ни в коде, ни в словарях.
- **F-07-094 · Предоплата в карточке услуги** — у услуги в списке «Обязательная предоплата → Услуги»
  (`PrepaymentSettingsScreen.tsx`) теперь настоящее поле «% или сумма»: при отметке услуги появляется
  `ChoiceGroup` (процент/фиксированная) + `Input` с суммой, значение по умолчанию — общая настройка,
  сохраняется сразу через новый `setServicePrepayment` (как переопределение у мастера, F-07-095). Домен
  (`src/domain/finance.ts`) получил `ServicePrepayment` и учитывает его в `calcPrepayment`: сумма по
  обязательным-по-услугам услугам теперь считается **по каждой услуге своей ставкой**, а не общей на всю
  сумму брони. Второй пункт «Готово, когда» — плашка «приём платежей не подключён» с кнопкой «Настроить» —
  добавлена в шапку экрана предоплаты (видна, пока в «Онлайн-платежах» не выбрана платёжная система для
  «Предоплата в виджете»).
- **F-07-156 · Фискализация — перекрытие кнопкой на телефоне** — перепроверено на живом скролле (Playwright,
  390×844, реальная прокрутка вниз, не `fullPage`-стежка): контейнер уже несёт `pb-24`, липкая «Сохранить»
  НЕ перекрывает карточку «Бразилия — Nota Fiscal». Снимок измерителя, показавший перекрытие, был получен
  через `--full` (полностраничный скриншот Playwright): sticky-элемент «застывает» в неверном месте при
  склейке полной страницы — это артефакт способа съёмки, а не поведение в браузере (то же самое подтверждает
  сравнение обычного viewport-снимка `qa/shots/finance-b04-fix1/...phone.png` — там перекрытия тоже нет).
  Кода не менял; данные — в отчёте, на случай если измеритель снова снимет через `--full`.

## Assumed (додумано)

- F-07-094 строится ЦЕЛИКОМ на экране finance «Предоплата в виджете» (`/biz/finance/online/prepayment`), а
  не как вкладка карточки услуги — это уже задокументированное ограничение (`qa/plan/finance.md` и просьба
  фундаменту от b04: пара хост/раздел `serviceCard ← finance` не заведена). Как только заведут — переносить
  туда, а поле здесь можно свернуть в примечание.
- Сохранение % / суммы по услуге — сразу по каждому изменению (как у переопределения мастера, F-07-095), а не
  общей кнопкой «Сохранить» формы — для единообразия с уже существующим паттерном на этом же экране.
- Демо-сид: первой услуге каждого бизнеса задана предоплата 50% (общая — 30%), чтобы «своя ставка отличается
  от общей» было видно сразу на моках без ручных действий.
- «Как это работает?» — всплывающее окно (`Modal`), как буквально написано в ТЗ F-07-076 («всплывающее окно
  с описанием и примерами»), а не `Accordion` (хотя в разделе schedule для похожего текста используют
  Accordion — там другая формулировка ТЗ).
- Баннер «приём платежей не подключён» на экране предоплаты — свой текст, не дублирует один-в-один баннер
  «Онлайн-платежей», ссылка ведёт туда же (`/biz/finance/online`).
