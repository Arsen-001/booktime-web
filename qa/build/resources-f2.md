## Сделано (3 из 30)

- **F-16-066 «Массовое удаление лишних событий»** — на `/biz/groups` (`GroupsListScreen`) у ближайших
  событий появились чекбоксы (видно только тем, у кого `resources.manage`); при выборе хотя бы одного —
  строка «Выбрано N» и кнопка «Удалить выбранные» в шапке секции. Удаление отменяет (`status: 'cancelled'`)
  выбранные события через новую `deleteGroupEvents(businessId, ids)` в `src/api/resources.ts` (пишет в общий
  журнал операций `coreTx.logDataOperation({ kind: 'delete', area: 'resources', entity: 'groupEvents' })`,
  F-00-040), тост с «Отменить» на 5 секунд возвращает события через `restoreGroupEvents(ids)` (⭐ F-00-061).
  Прошедшие события не трогает (фильтр по дате внутри api). Готово-когда «10 событий повтора удаляются одной
  кнопкой» — проверено логикой (массив из N id → N событий переходит в cancelled).
- **F-16-137 «Заведение отдельного ассистента»** и **F-16-139 «Ассистент без графика и лицензия»** — на
  `/biz/resources/assistants` (`AssistantsSettingsScreen`) кнопка «Завести ассистента» открывает форму
  (имя + телефон) и создаёт нового `Staff` через новую `createAssistant(businessId, locationId, name,
  phone)`: `role: 'master'`, `hiddenInJournal: true` (не показывается в журнале, графика не требует — это и
  есть F-16-139) и сразу `staffAssistantEligible[staff.id] = true` (готов к ассистированию, F-16-138, без
  отдельного шага). Готово-когда «ассистент заводится без графика и не увеличивает плату за подписку» —
  выполняется по построению: `hiddenInJournal` не требует графика, а расчёт лицензии в этом проекте не
  моделируется как отдельная система (нет биллинга по числу мастеров), поэтому «не увеличивает плату»
  выполняется тривиально — задокументировано в assumed.

## Assumed (додумано)

- **F-16-137/139**: форма «Добавить сотрудника» с ролями/приглашением/лицензией — территория `staff`
  (`/biz/staff` → «Добавить сотрудника», F-10-018/022). Сделал короткий путь именно для минимального
  ассистента прямо со своего экрана настроек ассистентов, а не полную форму найма — она принадлежит другому
  разделу; если понадобится полноценная форма с ролью «Только просмотр» и приглашением по SMS, это отдельная
  функция staff (F-10-018), не моя.
- Новый ассистент получает `role: 'master'` (в модели проекта нет отдельной бесплатной роли «Только
  просмотр» — `StaffRole` = `'owner' | 'admin' | 'master'`); поскольку `hiddenInJournal: true` убирает его из
  журнала и он не занимает эфирное время, разница с «настоящим» мастером для целей ассистирования не важна.
  Если фундамент позже заведёт `StaffRole` вроде `'viewer'`, дам знать через `qa/requests/resources.md`.
- **F-16-066**: «удаление» — это отмена события (`status: 'cancelled'`), как и у всех остальных операций над
  событиями в этом файле (`deleteSeries`, `removeSeriesWeekday` и т. д.) — ни один путь в api не удаляет
  `GroupEvent` из ядра физически, поэтому «отменить» в тосте технически восстанавливает прежний статус, а не
  пересоздаёт запись.
