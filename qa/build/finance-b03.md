## Что построено

**Баланс клиента (F-07-055/057)** — `src/areas/finance/extensions/ClientCard.tsx` (вклад «Деньги» в
хост `clientCard`, `/dev/ext/clientCard/finance`): «Продано / Оплачено / Баланс» из визитов «Клиент пришёл»
и ручных операций на клиента (`getClientMoneySummary`, `computeClientMoneySummary` в `src/domain/finance.ts`);
«Визиты с долгом» с фильтром «Все / Неоплаченные / Счётом в долг» (`listClientDebtVisits`).

**Личный счёт клиента — отмена и возврат (F-07-064/070)** — там же: список пополнений с кнопкой «Отменить»
(`cancelClientAccountTopUp`, убирает деньги и со счёта, и из кассы — операция пополнения теперь связана
`operationId`, добавлено в сид `mock/slices/finance.ts`); «Вернуть часть» — расходная операция статьёй
«Возврат» (новый системный ключ `refund`, `SYSTEM_ITEM_KEYS`) уменьшает счёт и кассу без искажения выручки
(`refundClientAccountPartial`).

**Ограничения счетов клиентов (F-07-065)** — по нашему решению кабинет один и на вебе, и в приложении, поэтому
ограничение «только в вебе» не переносим; счёт открывается/пополняется/списывается везде, где есть вкладка
«Оплата» (уже верно из b02).

**Возвраты в окне визита (F-07-066/067)** — `src/areas/finance/extensions/BookingWindow.tsx`: кнопка «Полный
возврат» в шапке списка платежей одним действием отменяет все активные платежи визита с указанием причины
(`refundBookingFull`, оборачивает уже готовый `removeBookingPaymentLine` по каждой строке + сохраняет причину
в примечание); частичный возврат — существующая связка «корзина у строки → скидка по акции → оплатить заново»
(из b02) подтверждена как рабочая цепочка F-07-067.

**Напоминание о предоплате при отмене (F-07-074)** — там же: если запись отменена и предоплата (F-00-097) была
оплачена, а платежи ещё активны — жёлтый баннер-напоминание с кнопкой «Полный возврат».

**Ручной штраф клиенту (F-07-075/175)** — блок «Деньги» карточки клиента: кнопка «Оштрафовать клиента» —
статья «Списание штрафа», касса, комментарий (`chargeClientPenalty`); штраф не связан с записью-неявкой,
не трогает зарплату сотрудника (партийный тип — клиент, а не сотрудник).

**Взаиморасчёты с сотрудником (F-07-159…162)** — новый экран `/biz/finance/settlements`
(`src/areas/finance/SettlementsScreen.tsx`, заменил заглушку): выбор сотрудника (мастер видит только себя —
`payrollOwnStaffOnly`), лента начислений/выплат с балансом (`settlementBalance`), «Создать расчётную
ведомость» за период (⭐ демо-упрощение — сумма из визитов «Клиент пришёл» за период, полных схем зарплаты нет
— `createSettlementSheet`), «Выписать премию/штраф», «Внеочередное начисление» (`createSettlementEntry`),
«Выдать зарплату» (`payoutSalary` — расходная операция статьёй «Зарплата персонала» + строка выплаты) с
отменой выплаты (`cancelSalaryPayout` — возвращает сумму и в кассу, и в баланс), удаление ведомости/премии/
штрафа убирает начисление (`deleteSettlementEntry`). Мастер без прав на начисление видит только чтение (кнопки
скрыты). Новый домен `SettlementEntry`/`settlementEntrySign`/`settlementBalance` в `src/domain/finance.ts`.

**Нефискальный чек (F-07-147/148/158)** — `/biz/finance/settings` (`src/areas/finance/SettingsScreen.tsx`,
заменил заглушку): формат печати (А4/80мм/58мм), поля клиента, 9 реквизитов, «налог по каждой позиции»,
доп. информация, комментарий, НДС ОАЭ «уже включён в цену» с расчётом `vatIncludedInPrice` (цена/(100+ставка)
×ставка — при 105 и 5% даёт 5, проверено). Печать — новый маршрут `/biz/finance/receipt/[bookingId]`
(`src/areas/finance/ReceiptScreen.tsx`): показывает услуги, способы оплаты, итог, комментарий по настройкам;
кнопка «Скачать чек» отдаёт файл `.html` (не настоящий PDF — см. assumed). Ссылка на чек из вкладки «Оплата»
окна записи ведёт сюда вместо страницы операции.

**Онлайн-кассы, ККМ (F-07-151)** — карточка-заглушка в настройках («Скоро», как у самого Altegio — интеграция
недоступна); право `canManageKkm` заведено в модели прав на будущее.

**Права раздела «Финансы» (F-07-166…168)** — ⭐ демо-набор `FinanceRights` (`src/domain/finance.ts`): доступ ко
всем/выбранным кассам, глубина просмотра/создания назад, редактирование/удаление/выгрузка/баланс/контрагенты/
статьи, права окна записи (оплата, оплата со счёта, правка цены услуги, удаление оплаченной записи, статистика
дня), права денег клиента (счета, лояльность без кода, штрафы политики), «только свои взаиморасчёты». Редактор
— в `/biz/finance/settings` (выбор сотрудника → тумблеры, `getFinanceRights`/`saveFinanceRights`). Применено:
`OperationsScreen` (кассы, глубина, баланс, кнопка «Новый платёж»), `AccountsScreen` (баланс касс скрыт «•••»),
`BookingWindow` (корзина у оплаченной строки, «Полный возврат»), `FinanceAccessGate` (мастер по адресу
`/biz/finance/settlements` без `finance.view`, если есть `payroll.view`).
