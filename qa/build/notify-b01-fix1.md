# notify · b01 · починка дефектов (fix1)

Дата: 25.09.2026. Чиню 4 дефекта измерителя (b01-m0) по пачке b01 «Каркас раздела и главные экраны».

## Что починил

### F-05-001 (major) — прямой заход по URL обходил право `notify.manage`
Меню скрывало пункт «Уведомления» у персон без права, но каждая страница `/biz/notifications/**`
не проверяла право сама — прямой адрес открывал полный доступ (подтверждено прогоном persona=master).

Добавил `src/areas/notify/NotifyAccessGate.tsx` — компонент-гейт (`useCan('notify.manage')` +
`PermissionGate fallback="message"`) и обернул им все `page.tsx` раздела, где функции по ТЗ требуют
роль «владелец, администратор»: `/biz/notifications` (+ `/channels`, `/channels/email`, `/channels/sms`),
`/mailings`, `/mailings/new`, `/log`, `/types/[typeId]` (+ `/templates`).

**Не тронул `/biz/notifications/inbox`** — по ТЗ (F-05-061 «все пользователи кабинета», F-05-062
«сотрудник, администратор») это личная лента уведомлений (колокольчик), а не настройки рассылок;
гейтить её правом `notify.manage` было бы новым дефектом — мастер должен видеть свои уведомления о записях.

Проверено прогоном `measure.mjs --persona master` по всем 8 гейтнутым маршрутам: `data-f: 0` везде
(контент не рендерится, показывается «нет прав») — при первом прогоне два маршрута дали случайный 500
из-за параллельной пересборки dev-сервера другим агентом (`src/api/core.ts`, я его не трогал), повторный
прогон в одиночку — 0 ошибок консоли. Owner-прогон (`--persona owner`) — доступ по-прежнему полный.

### F-05-096 (major) — не было фильтра «получал/не получал рассылку за период»
Добавил в `NewMailingScreen.tsx` пару Select'ов «Получал рассылку» (Неважно / Получал(и) / Не получал(и))
+ «За период» (30/90/180 дней), с реальной фильтрацией:
- `ReceivedMailingFilter` в `AudienceFilter` (`src/api/notify.ts`);
- `Mailing.recipientClientIds` (`src/domain/notify.ts`) — кто фактически получил рассылку, чтобы будущий
  фильтр мог их найти;
- `createMailing` теперь сам считает получателей через `audienceClients(businessIds, filter)` (а не
  доверяет счётчику с экрана) и пишет их id в `recipientClientIds` — заодно чинит и рассинхрон из F-05-092
  ниже одним и тем же изменением;
- сид (`src/mock/slices/notify.ts`) — у двух исторических рассылок каждого бизнеса тоже проставлены
  `recipientClientIds`, чтобы фильтр было на чём проверить сразу после первого входа.

Проверено сценарием `measure.mjs --scenario`: выбор «Получал(и)» → счётчик получателей меняется (было 20+,
стало 4) — фильтр реально режет аудиторию, не просто текст на экране.

### F-05-092 (minor) — метка «Получатели» врала для push-канала
`audienceLabel()` читала сырое состояние чекбокса `onlyWithApp`, а не то, что реально уходило в фильтр —
для push-каналов «только с приложением» форсируется всегда (`filter.onlyWithApp`), но если чекбокс никто
не трогал, в истории писалось «Вся база». Поменял источник на `filter.onlyWithApp` — метка теперь всегда
совпадает с примененным фильтром; заодно добавил в неё кусок про «получал/не получал рассылку за N дней»,
когда фильтр F-05-096 применён.

### F-05-079 (minor) — «Брендированное приложение» наезжало на select на телефоне
`TypeDetailScreen.tsx`, блок «Отправка уведомлений»: строка была `flex flex-wrap items-center` с
`flex-1`-лейблом и `w-56`-select — на телефоне длинная подпись переносилась на 2 строки и второй строкой
залезала под select/кнопку «Подключить». Сделал строку `flex-col` на телефоне и `sm:flex-row` от `sm:`,
select — `w-full sm:w-56`. Проверено снимком `/biz/notifications/types/2` (тип с `brandedApp` в каналах,
самая длинная подпись) на 390×844 — подпись и поле теперь на раздельных строках, без наложения.

## assumed

- Право `notify.manage` гейтит только «настроечные» экраны раздела (типы/каналы/рассылки/журнал), но не
  `/inbox` (личная лента, доступна всем по ТЗ F-05-061/062) — решение по ТЗ, не додумано.
- «Получал рассылку за период» смотрит только на `recipientClientIds` **тех рассылок, что были записаны
  под тем же `businessId`**; сетевая рассылка (`network: true`) в моке пишется только в массив
  `mailings[businessId]` главной локации — для филиалов сети её «получатели» этим фильтром пока не видны
  (при новой рассылке по сети история о прошлой сетевой рассылке в разрезе конкретного филиала не всплывёт).
  Точный контракт «одна рассылка — одна запись на филиал или общая» не описан в ТЗ явно; если понадобится
  точнее — дублировать запись `Mailing` по каждому businessId сети при отправке (правка в `createMailing`).
- Период фильтра — фиксированные 30/90/180 дней (в ТЗ период не уточнён численно, просто «получал
  sms-рассылку (период)» + пример «в январе или в марте»); если нужны произвольные месяцы/даты —
  дополнительный DatePicker, не делал, чтобы не раздувать b01-фикс.
- «Напомнить через WhatsApp» у недоставленных в журнале беру номер master'а из `Staff.phone` записи,
  привязанной к `LogMessage.staffId`; если у сообщения `staffId` не проставлен (часть служебных типов —
  F-05-130) — кнопка не показывается, это осознанно (звонить/писать не от кого).
