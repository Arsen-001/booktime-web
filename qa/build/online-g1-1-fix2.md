# online — g1-1-fix2: починка дефектов после проверки g1-1

Чинил 30 F-id, найденных измерителем в доделке g1-1 (4 block-бага + 15 «функции нет» + 11 из основной проверки).

## Что сделано

### Настоящие баги (block/major) — LinkSettingsScreen

- **F-03-069 (block, «Любой специалист» не переключается)** — при ручной проверке в браузере переключатель
  на самом деле переключается по реальному клику (`aria-checked` меняется на `true`, проверено `read_page`/JS
  напрямую); похоже на ложное срабатывание автопрогона из-за задержки мока (150–1200мс) без ожидания ответа.
  На всякий случай сделал переключатель устойчивым к этому в принципе: заменил ad-hoc `await
  updateBusinessRules(...); refetch()` на `useApiMutation` с `optimistic()` (как в `GroupBookingSection`) —
  теперь `aria-checked` меняется СИНХРОННО по клику, без ожидания круга мока. Перепроверил живым кликом —
  `aria-checked` становится `true` мгновенно, без задержки.
- **F-03-016 (block, порядок шагов не сохраняется) + F-03-014 (major, 4 разные кнопки «Сохранить»)** —
  настоящая причина одна: `StepsSection` и `DesignSection` держали своё состояние и свою кнопку «Сохранить»
  отдельно от нижней sticky-кнопки и её `dirty`; правка порядка шагов не помечала общий `dirty`, поэтому общая
  кнопка оставалась disabled, а свои кнопки секций не были связаны с ней. Переписал `LinkSettingsScreen.tsx`:
  всё редактируемое состояние ссылки (основное + шаги + дизайн, включая изображение первого экрана) поднято в
  родительский компонент, `StepsSection`/`DesignSection` стали чистым представлением (value/onChange, без
  своих кнопок), единственная кнопка «Сохранить» внизу шлёт один общий patch и включена только когда
  `dirty && !mismatch && colorValid`. Проверено в браузере: стрелка «вниз» у шага → кнопка становится активной
  → «Сохранить» → reload → порядок сохранился; на странице ровно одна кнопка «Сохранить» (`document.querySelectorAll` → 1).
- **F-03-001 (minor, зона нажатия «?» <44px)** — `HelpHint` использовал `IconButton size="sm"` (40px); заменил
  на `size="md"` (44px, счётчик project-rule «зоны нажатия ≥44px»).

### Функции, которых не было (F-03-036, 039, 040, 041, 042, 043, 046, 048, 052)

Построены как новые секции существующих экранов `online` (без выхода за пределы путей раздела — подробности
и явное разграничение с F-03-068/108/124/128/131/136, которые остаются за другими разделами, — в
`qa/requests/online.md`, запись «g1-1-fix2»):

- **`/biz/online/widget` → «Другие каналы записи»** (SectionCard): свой API с демо-ключом (генерация/пересоздание/
  отзыв, F-03-036), Instagram/Facebook Book Now (F-03-039), Google Reserve (F-03-040, недоступно в Армении —
  переключатель заблокирован с бейджем), Яндекс.Карты (F-03-041, бейдж «только с оплаченной лицензией»), 2GIS
  (F-03-042, недоступно), партнёрские каталоги Earlyone/DOQ.kz (F-03-043), сторонние боты/витрины (F-03-046).
  Подключение — демо (переключатель меняет своё состояние в срезе `online`, реального похода на площадку нет),
  явно подписано в описании секции.
- **`/biz/online/widget` → «Мобильные приложения»** (F-03-048): ссылки на свои iOS/Android приложения (сохраняются
  одной кнопкой) + блок «Брендированное приложение» с условиями и кнопкой «Отправить заявку на консультацию»
  (демо, ставит метку времени, показывает подтверждение).
- **`/biz/online/requests` → «Кого позвать»** (F-03-052) — НЕ демо, рабочая логика: свободные окна на 3 дня
  вперёд считаются тем же `computeFreeSlots`, что и виджет; клиент подбирается по «обычно ходит в это время»
  (была запись к этому мастеру в тот же час ±1ч за 90 дней) или «пора снова» (услуга ≥21 день назад, новой ещё
  нет); «Пригласить» одним нажатием создаёт запись в журнал приглашений с готовым текстом и убирает окно из
  списка кандидатов (перепроверено вручную: слот 15:00 пропал из списка сразу после приглашения, приглашение
  появилось в «Отправленные приглашения» и пережило reload).

Новые сущности — в своём домене: `IntegrationConnection`/`ApiCredentials`/`MobileAppLinks`/`SlotInvite` в
`src/domain/online.ts`; срез `src/mock/slices/online.ts` (version 9→10); API — `listIntegrations`,
`setIntegrationConnected`, `generateApiKey`/`revokeApiKey`, `getMobileAppLinks`/`updateMobileAppLinks`/
`requestBrandedAppConsult`, `getSlotCandidates`/`inviteToSlot`/`listSlotInvites` в `src/api/online.ts`.
i18n: новые ключи `widget.channels.*`, `widget.mobileApp.*`, `requests.whoToInvite.*` в `messages/{ru,en}/online.json`
(hy не пишем — правило проекта, только en+ru пока формулировки не устоялись).

data-f статически (охват `scripts/fids.mjs`) — там, где рендер шёл через `.map()`, литеральные строки не
попадали в статический скан регулярки; переписал на явные литералы на каждом `<li data-f="F-03-…">`.
