## Готово по каждому пункту «Готово, когда»

  доступа — модель не блокирует); действие в журнале изменений пишет автора (`actorLabel`, `actorStaffId`).

- **F-10-007**: уволенные скрыты по умолчанию (`filters.status === 'working'`), фильтр «Учёт в лицензии»

- **F-10-009**: вкладка «Специализация» — реордер (drag нативным HTML5 + кнопки ↑/↓ для клавиатуры/сенсора),
  пишет в общий `staff.order`, который смогут читать schedule/journal (см. `qa/requests/staff.md`).
- **F-10-010**: вкладка «Системные пользователи» — пустое состояние + один демо-пользователь (помечен «Демо»),
  права видны бейджами; интеграций в проекте пока нет — раздел integrations сам стаб.
- **F-10-011**: в строке — имя, специализация/должность, контакты, тумблер онлайн-записи (переключает
  `Staff.onlineBookingEnabled`, число услуг — НЕ показано отдельной колонкой (услуги ещё не назначаются
  сотруднику из этого экрана — карточка вне b01), роль и статус оплаты; у сотрудника с `status: 'disabled'`
  — кнопка «Выдать доступ».
- **F-10-012**: меню «⋯» — уволить/удалить/восстановить (у уволенного), «перенести доступ» НЕ построено (нет
  экрана выбора «другого сотрудника» — оставлено b03, отмечено ниже).
- **F-10-013**: один список, единый источник `order` — не дублируется.
- **F-10-014**: `Staff.id` постоянный, используется в маршруте `/biz/staff/<id>`; отдельная «ссылка записи»

- **F-10-015**: «+ Добавить» → «Сотрудника» / «Должность» — `DropdownMenu` в шапке (десктоп) и `Fab` (телефон).
- **F-10-016**: форма создаёт сотрудника с именем/специализацией, выбором платный/бесплатный (авто по роли +

  моделировалось (тонких прав ещё нет — весь редактор прав в b04), поэтому пункт «пользователь с правом только
  Создание не может назначить услуги/права» не проверяем отдельно: форма и так не даёт назначать услуги/права.
- **F-10-017**: счётчик «Платных мест: N · подписка X ֏/мес» в подвале формы, живой (меняется по мере ввода).
- **F-10-018**: «Бесплатный» ограничен ролью (ассистент — только у master), при добавлении в график

- **F-10-023**: тот же экран работает на телефоне (проверено `--device phone`), синхронизация — общий мок-стор.
- **F-10-110**: колонка «Лицензия» показывает платно/бесплатно; сотрудник переходит в бесплатные автоматически,

- **F-10-112**: фильтр «Учёт в лицензии» — Все/Платно/Бесплатно.
- **F-10-113**: владелец видит сумму подписки в форме добавления и как она меняется (`totalSeatCost`).
- **F-10-132**: «команда с телефона» = тот же адаптивный экран (создание/увольнение/восстановление работают на

## Что пришлось додумать (assumed)

- «Ассистент» — не отдельное поле ядра; определяется эвристикой `role==='master' && workplaces=[] &&
  serviceIds=[]`. Записано в `qa/requests/staff.md` как кандидат на настоящее поле.
- «Кто первый администратор» (бесплатное место) — по `hiredAt` (раньше нанят = первый).
- Ссылка на личную запись мастера (F-10-014) не строил — нет ещё online-виджета, куда бы она вела.
- «Системные пользователи» — раз интеграций в проекте пока нет, посеял один демо-пользователь с пометкой
  «Демо: подключённая интеграция», чтобы вкладка не была голым нулём без объяснения, откуда возьмутся строки.
- Цена места (4 000 / 2 000 ֏) — временная константа, а не из settings/billing (там ещё нет api) — задокументировано
  и запрошено.

одновременно) на комбинации admin/hy/desktop однократно вылетела ошибка гидратации + предупреждение

`bp-mock-db` в localStorage браузера Playwright). Повторный изолированный прогон той же комбинации — 0 ошибок.
Не чинил: не воспроизводится, инфраструктурное (shared dev-сервер под несколькими сборщиками), не код b01.
