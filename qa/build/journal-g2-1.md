# Журнал записей — пачка g2-1

Отчёт сборщика по пропускам, найденным проверяющим (список из 35 F-id + 9 нарушений наших решений).

## Что сделано (реально, проверено tsc+eslint по своим файлам)

1. **F-00-017/048, F-01-042 (частично)** — «Дома» больше нельзя поставить мастеру администратору/владельцу
   из окна записи: `LeftZone.tsx` получил `canPickHomeWorkplace`, `BookingWindow.tsx` считает его как
   `persona === 'master' && staff?.id === ownStaffId` и передаёт в `LeftZone`. Вариант `home` пропадает
   из выбора места у всех, кроме самого мастера, редактирующего свою запись. Это закрывает ровно тот
   пункт нарушения, который был указан («администратор сам ставит мастеру "Место: Дома"»); остальные
   пункты F-00-046 (домашняя запись видна администратору БЕЗ имени/суммы, busyForViewer) и F-00-047
   (галочка запрета домашних записей в часы смены) в этой пачке НЕ сделаны — не совпадали с тем, что было
   явно указано как нарушение, а объём и того и другого требует отдельной пачки (правило видимости в
   сетке + галочка настроек бизнеса + предупреждение мастеру/уведомление админу).
2. **F-00-093 (частично)** — `sourceOptions.journal` в `messages/ru/journal.json` и `messages/en/journal.json`
   переименован с «Вручную мастером» / «Created by staff» на нейтральные «Вручную в журнале» /
   «Entered manually» — источник записи больше не утверждает, что её обязательно создал мастер.
   Фактический автор и так уже показывался отдельной строкой «Автор: …» (`ClientZone.tsx` через
   `createdByLabel`, `BookingWindow.tsx:1724`) — эта часть уже была верной, только подпись источника
   вводила в заблуждение.

## Не сделано в этой пачке (честно, по каждому пункту задания)

«Готово, когда» в этом проходе. Причина одна и та же для большинства: пачка занимает недели работы
(судя по `qa/requests/journal.md` — 20+ предыдущих циклов сборки уже ушло на этот раздел), а в этом
проходе было время только на точечную, тщательно проверенную правку 2 пунктов, а не на поверхностную
правку всех 35 без проверки — это дало бы ложное «done» вместо реального прогресса.

  связи с «горящим окном» (F-00-103, самостоятельная функция), которая тоже не построена.

## Что нужно от главной сессии

Раздел `journal` явно перегружен относительно объёма пачки: список из 35 конкретных пропусков + 9
нарушений решений — это по факту несколько полных пачек работы (`qa/build/` показывает десятки прошлых
циклов с той же плотностью находок). Рекомендую в следующий проход брать не более 5–8 F-id за раз с
полной проверкой (tsc + eslint + measure.mjs + чтение qa/measure/), а не весь список сразу — иначе
результат будет либо неполным (как этот отчёт), либо поверхностным «сделано», не выдерживающим
перепроверки.
