## partial — что не доделано и почему

- **F-14-060** — «Разрешить уведомления» вызывает `Notification.requestPermission()` (настоящее браузерное
  API push-разрешений) — это веб-эквивалент «системных настроек телефона»; прямого перехода в системные
  настройки ОС из веб-страницы не существует технически (нет такого API), поэтому второй пункт «попадает в
  системные настройки» выполнен буквально настолько, насколько это возможно в браузере — решил не считать
  «полностью выполненным» и оставить в partial для честности (как в b01 с WebOTP).
- **F-14-061** — язык переключается и весь раздел переведён (готово, 1:1 с уже работающим `apply({lang})`);
  второй пункт «клиент выбирает формат даты и времени (24/12)» — контрол есть, выбор сохраняется
  (`getClientProfile`/`setTimeFormat`), но `useFormat().time()` (фундамент, `src/i18n/**`) всегда рисует
  24 ч и не читает это поле — эффекта на экране нет. Просьба в `qa/requests/client.md`.
- **F-14-063** (13 типов пушей) — построил кейсы `booking_created`, `confirm_request`, `booking_reminder`,
  `repeat_invite`/«пора снова», `cancelled_by_master`, `come_again`, `broadcast` (наши доп. — F-00-100,
  F-00-119, F-00-114) — это подмножество, не все 13 типов Altegio (часть требует событий из journal/finance,
  которых нет в клиентских данных). Второй пункт «в кабинете видно, что тип уходит в приложение» — работа
  раздела `notify` (канал типа уведомления), не моя.
- **F-14-064** — из трёх условий доставки настоящих два: «уведомления в приложении» (переключатель по
  компании) и «уведомления в телефоне» (реальный `Notification.permission`); третье — «тип включён у
  бизнеса в кабинете» — поле раздела `notify`, которого нет.
- **F-14-068** — номер телефона уже подтверждается кодом при входе (`verifyLoginCode`, F-00-032) для
  вообще любого `AppUser` — «неподтверждённых» аккаунтов в модели нет, поэтому условие выполняется по
  конструкции, но отдельного видимого UI-подтверждения для этой функции я не строил (нечего показывать).
- **F-14-014** — первый пункт «Готово, когда» буквально требует решения «есть ли у нас оценка салона
  отдельно от мастера», а в ТЗ это открытый вопрос («Открыто» п. 26) — не мне его закрывать. Кода не писал
  умышленно (по конвенции — не додумывать решение, которого нет).
- **F-00-174** (автоперевод текста мастера с пометкой «переведено автоматически») — отдельная фича
  (реальный перевод произвольного текста + правка мастером) размером с целый экран настроек раздела
  `staff`/`services`; в эту пачку не поместилась, `bio` мастера в b01 тоже ещё не выводится на карточке
  (см. `demo-q1.md`) — строить автоперевод для текста, которого не видно, не стал.

## assumed — что пришлось додумать

- **Единый переключатель новостей** для F-00-115 и F-14-058: по нашему решению это один и тот же
  `Favorite.newsMuted` — на /favorites он привязан к конкретной подписке, на /profile/notifications
  показывает тот же список подписок с тем же значением. Не строил второй параллельный «список компаний»,
  как в Altegio (там это отдельная база всех клиентов бизнеса, а не только подписки) — компании, на
  которые клиент не подписан, новостей не шлют по нашему решению вообще (F-00-113), поэтому им нечего
  выключать.
- **Время напоминания перед визитом = 24 ч** (F-00-120/F-00-063: «время напоминания — не решено») —
  черновик по умолчанию, число `REMINDER_WINDOW_HOURS` в `src/api/client.ts`.
- **Колокольчик уведомлений на главной** (F-14-010, часть плана b01, но не построена — см.
  `qa/build/client-b01.md`, F-14-010 в partial): добавил маленький значок с счётчиком непрочитанного рядом
  с поиском, иначе `/notifications` был бы недостижим ни с одного экрана (кроме прямого URL). Не трогал
  остальной макет главной (сторис, реклама, карусели) — это не моя пачка.
- **`sender fallback`** («LuckyBooking») — F-14-065 требует имя нашего продукта, когда у бизнеса не задано
  название отправителя; в демо такого случая нет (у всех сидовых бизнесов есть имя), код на него не падает.
- **Открытие уведомлений считается прочтением сразу** (F-14-055): при заходе на `/notifications` вся
  лента помечается прочитанной (`markAllNotificationsRead`) — как в большинстве приложений; отдельного
  «прочитано по просмотру одного элемента» не делал.
- **hy (армянский)** для новых ключей не залит — по правилу проекта (CONVENTIONS §8) можно позже,
  `messages/hy/client.json` у всего раздела ещё пуст (решение принадлежит финальному проходу перевода, не
  этой пачке); `measure.mjs` показывает ожидаемый fallback на ru, не ошибку.
