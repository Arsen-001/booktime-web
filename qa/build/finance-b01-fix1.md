# finance — b01 · починка 1 (по замерам измерителя)

Пачка b01, дефекты из первого прохода измерителя — 6 штук (4 major, 1 minor формально, но список
просил править и minor). Ниже — что сделано по каждому и честная сверка с «Готово, когда» из ТЗ.

## Что починено

### F-07-007 · Справочник статей по умолчанию (major)
Набор статей приведён 1:1 к таблице ТЗ: 13 системных статей с точными названиями/типами
(«Закупка материалов», «Закупка товаров», «Налоги и сборы», «Оказание услуг», «Прочие доходы»,
«Прочие расходы» и т.д. — `src/mock/slices/finance.ts` → `SYSTEM_ITEMS`, ключи —
`src/domain/finance.ts` → `SYSTEM_ITEM_KEYS`). «Аренда» осталась в сиде отдельной ПОЛЬЗОВАТЕЛЬСКОЙ
статьёй (`system:false`) поверх системных 13 — демонстрирует F-07-008, не подменяет системный набор.
`src/api/finance.ts` (`transferFunds`) и все места сида, ссылавшиеся на старые ключи (`rent`,
`purchase`, `utilities`, `advertising`, `other`), переведены на новые (`materialsPurchase`,
`otherExpense` и т.д.) — cross-area зависимостей на старые ключи не было (проверено grep).

**Готово, когда:**

- [ ] постоянный номер статьи для загрузки из Excel — не показан нигде в UI (не было в дефекте, не трогал)

### F-07-011 · Список операций: колонки и переходы (major)
Добавлены все недостающие колонки: **№ документа**, **Услуга/Товар**, **Комментарий**, **Автор**,
**Остаток в кассе**, кликабельная ссылка **Визит**. Реализация:
- `Operation` получил `docNumber?`/`lineLabel?` (`src/domain/finance.ts`), сид проставляет их у
  оплат визита (номер — 9-значный детерминированный из id визита; строка услуги — имена услуг визита).
- «Остаток в кассе» — новая чистая функция `accountRunningBalances` (`src/domain/finance.ts`):
  берёт ВСЕ операции кассы (не только страницу с фильтрами) в хронологическом порядке и считает
  баланс после каждой; `OperationsScreen` тянет отдельный неотфильтрованный запрос только для этого.
- «Автор» резолвится в имя сотрудника через `useCoreList('staff', …)`, `createdBy: 'system'` →
  «Система».
- Клик по дате в блоке «последние 5 дней» на «Счетах и кассах» теперь долетает до списка: экран
  операций научился читать `?from=&to=` и подставлять период (было только `?new=1`).

**Готово, когда:**
- [ ] оплата визита с двумя услугами даёт ДВЕ строки с одним номером документа — у нас архитектурно
  ОДНА операция на визит (не по строкам услуг), это решение было в исходном b01, не в этом дефекте;
  правка требует переделать создание операций визита построчно — отдельная, более крупная задача
- [x] клик по дате открывает операцию, клик по визиту — окно визита
- [x] в колонке «Способ оплаты» у оплаты визита стоит фактический способ (было верно и раньше)

### F-07-001 · Страница «Счета и кассы» (major)
Добавлены все недостающие элементы:
- блок «Остатки по дням» — 5 последних дней, каждая дата кликабельна → открывает операции этого дня;
- график «Выручка / Расходы» — по дням за 2 недели (`recharts` `BarChart`, `ChartCard` из `@/ui`);
- две круговые диаграммы «Доходы по статьям» / «Расходы по статьям» — топ-5 + «Остальные», доля от
  месяца; используют `ChartCard`'s `autoEmpty`, так что на пустых данных graph НЕ рисует ось с
  «01.01.1970» — просто пустое состояние (это специально проверено ТЗ-пунктом).

При отладке поймал и починил гонку ключей React (`Cell key={entry.name}` дублировался, пока
`itemsQ` ещё грузится и все строки временно называются «—») — теперь ключ берётся по `itemId`.
Также поймал ложную тревогу: диаграммы выглядели «обрезанными» на скриншоте — это была анимация
монтирования recharts (доигрывает до ~1.9 с), не баг; на статичном кадре после анимации — полный круг.

**Готово, когда:**
- [ ] «Сейчас в кассе»/«Доходов за месяц» растут без перезагрузки после оплаты — не трогал этот путь,
  логика была в b01 и её не касается текущий дефект
- [x] клик по дате в «последние 5 дней» открывает операции кассы за этот день
- [ ] пользователь без права «Доступ к балансу» не видит сумм остатков — такого права ещё нет нигде
  в `src/config/permissions.ts`; это часть F-07-166 (права блока «Финансы»), не построена никем
- [x] пустая касса показывает пустой график без мусорных дат
- [ ] (доб. пров. 2) домашняя запись мастера не попадает в кассы салона — не проверял, вне дефекта

## assumed (додумано)

- «Круговая диаграмма Доходы/расходы» из ТЗ (одна фраза, два смысла) — сделал ДВЕ отдельные диаграммы
  (доходы и расходы раздельно), а не одну составную: так читается однозначнее и совпадает с текстом
  «какую долю дохода ИЛИ расхода даёт статья».
- «Поиск по номеру документа открывает ровно этот документ» — реализовано как фильтр списка (как и
  везде в разделе — операции, контрагенты), а не автопереход при точном совпадении; после фильтра
  документ — один клик.
- Номер документа оплаты визита — детерминированный 9-значный код из id визита (нет реального
  генератора номеров документов в проекте); контент-заполнение «visit-документов» — по booking.services.
- «Аренда» в сиде переведена из статьи-подмены в полноценную пользовательскую статью (не системную) —
  чтобы не терять пример «свой расход», но и не нарушать «1:1 состав системных 13».
- Fallback: `/biz/finance/reports` и `/biz/finance/settings` сделаны такими же заглушками, как уже
  существовавшие «Методы оплаты»/«Взаиморасчёты» — раздел их ещё не строил, дефект был только про
  ОТСУТСТВИЕ пункта меню/страницы, не про полноту функциональности.
