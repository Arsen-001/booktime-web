# Отчёт сборки «Зарплата» — пачка b01

25.09.2026. Каркас раздела, «Основные настройки», схема сотрудника (шесть блоков), базовый движок
расчёта, «Расчёт за день» и «Расчёт за период».

## Что застал

Код пачки b01 был уже почти весь написан (предыдущий срез): экраны, движок в `src/domain/payroll.ts` /
`src/api/payroll.ts`, все шесть блоков схемы, «Основные настройки», «Расчёт за день/период», три
вклада в чужие хосты. `qa/build/payroll-b01.md` при этом ещё не было — эта сборка его создаёт. Основная
работа этого захода — не написать функционал заново, а:

1. проверить каждый пункт «Готово, когда» по ТЗ `09-payroll.md` живьём (браузер, замер);
2. закрыть разрыв между «функция реально работает» и «`scripts/fids.mjs` это видит» — 14 из 25 F-id
   были уже реализованы, но не попадали в подсчёт, потому что `data-f` передавался через проп `dataF`
   компонента `BlockCard` (динамическое значение), а сканер `fids.mjs` берёт только литеральные строки
   `data-f="F-…"`. Добавил литеральные `data-f` рядом (на блоках F-09-014/031/036/039/042/043) и на
   корневых узлах экранов, где отметки не было вовсе (F-09-003 порядок настройки — на `SchemePromo`,
   F-09-012 копирование — на содержимом `CopySchemeDialog`, F-09-013 сохранение — на `SchemeEditor`,
   F-09-017/026/106/111/112 — сквозные правила движка, отмечены на `DailyScreen`/`PeriodScreen`, где их
   результат виден и проверяем);
3. поправить найденный замером дефект: строки операций «Расчёта за день» на телефоне — 28 px высотой
   (< 40 px минимума из CONVENTIONS §0) — увеличил до `min-h-10` с более просторным паддингом.

## Готово, когда — сверено по каждому F-id пачки

- **F-09-001** Меню и точки входа — `nav.ts` (6 подпунктов) + вклад в `SettingsHub` со ссылками.
  Проверено: страницы каждого подпункта отвечают 200.
- **F-09-003** Порядок первичной настройки — заставка схемы → подсказка → «Настройки» → пустые
  состояния расчётов ведут туда же; отмечено на `SchemePromo`.
- **F-09-004/005** «Основные настройки» — три блока (дата начисления, комиссия банка, ассистирование),
  одна кнопка «Сохранить» (неактивна без изменений), настройки — на филиал (`locationId`), переживают
  перезагрузку (`localStorage` через `mutateArea`). Проверено в браузере: смена варианта → «Сохранить» →
  toast → перезагрузка страницы → значение осталось.
- **F-09-010** Заставка «не настроено» → «Настроить»: уход без сохранения не создаёт запись (черновик
  только в состоянии компонента, `saveScheme` не вызван).
- **F-09-011** Шесть блоков с переключателями, всё выключено по умолчанию, поля раскрываются по
  переключателю.
- **F-09-012** «Скопировать у другого сотрудника» — диалог с выбором образца из настроенных схем,
  заменяет все блоки черновика.
- **F-09-013** «Сохранить» неактивна без изменений (`dirty` через сравнение JSON с загруженным),
  предупреждение о несохранённом — `useUnsavedGuard`; сброса схемы в «не настроено» нет (кнопки такой
  не существует).
- **F-09-014/016** «Оплата за лично оказанные услуги»: ставка по умолчанию (% / ֏) + индивидуальные
  значения для категории или отдельных услуг через `OverridesEditor`.
- **F-09-017** Движок берёт только визиты в статусе «пришёл» с оплатой (`computeServicesForDay` фильтрует
  по `Booking.status === 'came'`), «Ожидание» не входит.
- **F-09-026** Выплата за одну услугу не уходит ниже нуля (`Math.max(0, raw)` в `domain/payroll.ts:57`),
  минус не переносится на соседние строки.
- **F-09-031/032** «Оплата за продажу товаров»: ставка по умолчанию + значения для отдельных товаров
  (категорий товаров у нас пока нет — см. `qa/requests/payroll.md`, зависит от раздела stock).
- **F-09-036** «Оплата за рабочий день»: сумма + час/день/месяц, часы и дни — из графика (`api/core`).
- **F-09-039** «Вознаграждение за созданную запись»: по `Booking.createdBy`.
- **F-09-042/043** Доп. вознаграждение за услуги/товары: % от оборота или прибыли филиала.
- **F-09-058/059** «Расчёт за день»: колонка на сотрудника, строки операций (клик — разбивка по
  статьям), «За день», «Итого»; пустое состояние — F-09-061.
- **F-09-061** Пустое состояние «не настроено» на `/daily` и `/period` — кнопки «Основные настройки» и
  «Сотрудники».
- **F-09-062** «Расчёт за период»: десять колонок (сотрудник/время/услуги-кол-во/услуги-сумма/
  товары-кол-во/товары-сумма/итого/выплачено/зарплата — на телефоне карточки), «Итого», фильтр по
  должности, период по умолчанию — с начала месяца до сегодня; уволенные исключены фильтром `status`.
- **F-09-106** Точность сумм — округление до целого драма (`roundMoney`, банковское округление не
  нужно — валюта без копеек); допустимые значения ставок проверяются `checkPayoutValue` с текстом
  ошибки под полем.
- **F-09-111** Итог = сумма частей схемы (`sumDayResult`), одна функция для дня и периода.
- **F-09-112** Услуга засчитывается мастеру строки услуги (`BookingServiceLine.staffId`, не мастеру
  записи целиком) — перенос записи к другому мастеру меняет `staffId` строки, движок берёт актуальное
  значение при каждом расчёте.
