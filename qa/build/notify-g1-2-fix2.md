### F-05-118 · Тариф SMS по сети — ✅ done (закрыт своим черновиком)
Раньше блокировалось отсутствием общего понятия «баланс уведомлений» (F-05-115 не построен нигде в
проекте). Вместо того чтобы продолжать ждать, реализовали как временный, явно помеченный 🔒-черновик в
своих путях (по правилу CONVENTIONS.md §1: «пока просьба не выполнена — обходитесь своими путями»):
- `NETWORK_SMS_RATE_AMD = 25` ֏ и `NETWORK_SMS_BALANCE_SEED_AMD = 3000` — `src/domain/notify.ts`.
- `NotifyState.networkSmsBalanceAmd: Record<Id, number>` (ключ — id главной локации сети,
  `Network.mainBusinessId ?? businessIds[0]`) — `src/mock/slices/notify.ts`, версия среза 7 → 8.
- `createMailing` (`src/api/notify.ts`) считает стоимость сетевой SMS-рассылки, сверяет с балансом
  главной локации, при нехватке бросает `Error('notify/network-sms-insufficient-funds')`, при отправке
  списывает с баланса.
- `NewMailingScreen` показывает посчитанную стоимость и остаток на балансе живьём (было — голая
  текстовая подсказка без цифр), кнопка «Отправить» блокируется при нехватке средств, тост объясняет
  причину.
Проверено сценарием `qa/scenarios/notify-network-sms-rate.json` (подключить SMS → перейти в новую
рассылку → SMS + «По всей сети») → `qa/shots/scenarios/biz-notifications-channels-sms__network-nails-ru-light-phone__network-sms-rate.png`:
«Стоимость рассылки 2 625 ֏, на балансе главной локации 3 000 ֏», получателей 105.
Когда в settings/finance появится настоящее поле баланса — перенести значение туда, записано в
`qa/requests/notify.md` (arch-a1 правило №7, «поле появилось в ядре — черновик убрать»).

### F-05-043 · Когда уведомления не уходят — ⏳ частично
`node src/areas/notify/lib/run-tests.mjs` — 16 тестов, все проходят (реальные ассерты через встроенный
`node:test`, НЕ печать). Уточнение к прошлой записи «vitest не установлен, прогнать физически нельзя»:
это верно только для `npm test` (корневой `package.json`, вне пути notify) — у раздела уже есть свой
рабочий прогон, тесты реально исполняются. Сводный список ТЗ (F-05-043) — 17 пунктов «когда НЕ шлём»;
16 тестов покрывают часть из них (типы 8, 75, 73, 72, 55, 4, 1, смена клиента, массовое удаление,
«Оплатить»). Не покрыты: тип 6/20 (отзыв позже интервала), тип 16 (отмена скидки), тип 19 (окончание
графика), лист ожидания, режимы «Не беспокоить»/«В самолёте» — потому что движок `liveLog.ts` эти
сценарии вообще не реализует (не наша функция в этой пачке), тест на них был бы пустой проверкой
несуществующего кода. **Не в done** (требует либо построить недостающую логику, либо ТЗ явно пометить
«ждёт реализации»).
