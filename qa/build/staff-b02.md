## Готово по каждому пункту «Готово, когда»

- **F-10-024**: карточка открывается (2-колоночная раскладка, как принятый в проекте паттерн `ClientCardScreen`)
  со всеми 8 вкладками (9-я, «Доступ», — вне b02, см. b03) и кнопками «Уволить»/«Удалить навсегда» (в меню «⋯»)
  и «Сохранить»; закрытие с несохранёнными правками (Escape, переход по ссылке меню) спрашивает НАШ диалог
  (`ConfirmDialog` через `useUnsavedGuard`), не системное окно, страница не виснет — проверено чтением кода

## Что пришлось додумать (assumed)

- Карточка — 2-колоночная раскладка на всю страницу (как `ClientCardScreen`), не буквальная выезжающая справа
  панель из Altegio — тот же паттерн уже принят проектом для клиентов (единообразие, CONVENTIONS §0).
- «Настройки» (F-10-034/035/036/037/098) физически частично живут во вкладке «График работы» (уже построено
  schedule) — моя «Настройки» содержит только то, чего больше нигде нет (F-10-037, «Внешний ID»), со ссылкой,
  куда ушла остальная часть, чтобы владелец её не искал.
- «Ассистент/владелец» для вкладки «Настройки» (F-10-037 роль «владелец») — гейт `persona === 'owner' |
  'network' | 'individual'`, как и в других разделах (`clients/lib/rights.ts` и т. п.).
- Юр. поля без формато-специфичной проверки (паспорт/ИНН/страховой) — ТЗ само отмечает ❓ по формату.
- «Внешний ID» и «Доступен для ассистирования» — новые поля своего среза (`staff.cardSettings`), не ядра;
  не просил у фундамента, т. к. это данные, нужные только карточке staff.
- Переименование должности каскадится на уже назначенных сотрудников (раньше — только на новых), закрывает
  часть просьбы №1 из b01 (полноценная ссылка по id всё ещё не заведена).
