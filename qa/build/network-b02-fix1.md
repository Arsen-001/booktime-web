## Что почищено

### 1. F-11-041 · block · Поиск в базе клиентов сети не фильтрует

**Реальная причина другая, чем в отчёте измерителя.** Измеритель верно локализовал баг «в текстовом поле/
его привязке к `applied.query`», но сам механизм (`SearchInput` → `draft.query` → `runSearch` →
`setApplied` → `useApiQuery` с ключом `JSON.stringify(applied)`) оказался исправен — проверено логами:
`filters` в `listNetworkClients` приходили верно (`{"query":"zzz…","sort":"name"}`).

Баг жил в самой функции фильтрации `listNetworkClients` (`src/api/network.ts`):

```ts
r.phone.replace(/\D/g, "").includes(q.replace(/\D/g, ""))
```

Когда запрос — любое имя без цифр, `q.replace(/\D/g, "")` даёт `""`, а `"любая строка".includes("")` в JS
всегда `true`. Через `||` это условие перебивало проверку по имени и email — фильтр пропускал **все**
строки при любом непустом запросе без цифр (то есть почти всегда).

Правка: телефон сравнивается только если в запросе реально есть цифры (`qDigits && …`).

Перепроверено Playwright (`node scripts/…`, скрипт временный, удалён):
- запрос `zzzzznonexistentxyz` (без цифр, заведомо нет совпадений) — было 105/105 строк, стало 0.
- запрос `Ани` (реальное имя) — 6 из 105 строк, список сузился корректно.

### 2. F-11-076 (и через него F-11-064…070, F-11-078) · major · Экспорт из аналитики — неверный автор/тип

`src/areas/network/analytics/AnalyticsReports.tsx`, общий хук `useExport()` для всех вкладок аналитики:
- `authorName: t("clientCard.title")` — переводился заголовок карточки клиента сети вместо имени
  текущего пользователя. Исправлено: как в `ClientsScreen.tsx` — `useCurrent()` → `staffId` →
  `useCoreGet("staff", staffId)` → `meQ.data?.name`.
- параметр `kind` принимался, но отбрасывался (`void kind`) — `exportNetworkClients` в `src/api/network.ts`
  жёстко писал `kind: "clients"` для любой вкладки. Добавлен необязательный параметр `kind?: "clients" |
  "records" | "staff"` (по умолчанию `"clients"`, чтобы `ClientsScreen.tsx` не ломался без правки — там же
  теперь и передаётся явно), `useExport` пробрасывает реальный `kind`.
- `ExportLogScreen.tsx` подставлял `r.kind` («clients»/«records»/«staff») в перевод как есть — на русском
  экране был виден сырой технический токен. Добавлены ключи `clients.exportKind.{clients,records,staff}`
  в `messages/{ru,en}/network.json`, строка журнала теперь переводит `kind` через них.

Перепроверено Playwright: экспорт со вкладки «Сотрудники» аналитики → в «Журнале выгрузок» строка
`Сотрудники · 6 строк · Гоар Арутюнян` (было `clients · 1 строк · Карточка клиента сети`). Экспорт из
самой клиентской базы (`ClientsScreen.tsx`) — работал верно и раньше, не трогался по сути, только добавлен
явный `kind: "clients"`.
