## Что исправлено

- **F-08-036 (major + minor)** — `TechCardsScreen`: добавлена строка поиска («Поиск по названию или
  комментарию», фильтр на клиенте по названию услуги, имени мастера и названиям расходников строк —
  у техкарты нет своего поля «название»/«комментарий», см. assumed) и пустое состояние «Ничего не нашли».
  Строка списка теперь показывает состав техкарты: «расходник (склад) · количество с единицей» под именем
  мастера, как в макете ТЗ.
- **F-08-037 (major)** — у строки техкарты появилось поле «Склад» (`TechCardLine.warehouseId` в
  `src/domain/stock.ts`; выбор склада в форме `TechCardFormScreen`, список складов из `listWarehouses`).
  Автосписание (`ensureAutoWriteoffs` в `src/api/stock.ts`) теперь группирует строки визита по складу из
  строки техкарты и создаёт складскую операцию на каждый использованный склад (раньше все расходники
  всегда списывались с единственного склада типа «для списания», игнорируя склад строки).
- **F-08-096 (major)** — блок «Запрет операций при нехватке остатка» в настройках склада — теперь рабочий
  чекбокс «Ограничено», сохраняется в `StockSettings.forbidOnShortage` через `updateStockSettings`
  (поле в домене уже было, но API и экран его не принимали/не показывали). Сама проверка на нехватку при
  продаже/списании/перемещении (F-08-099) — отдельная, не входящая в этот список функция, оставлена как есть.
- **F-08-097 (major)** — добавлен третий алгоритм себестоимости «Брать из настроек товара»
  (`CostMethod = 'lastPurchase' | 'average' | 'fromGoodSettings'`); при этом методе приход больше не
  перезаписывает `good.costPrice` — себестоимость остаётся той, что задана в карточке товара.
- **F-08-063 (major)** — панель продажи товара (и все места, где показывается название склада: операции,
  инвентаризация, техкарты, склад-список) больше не показывает жёстко русское «Товары»/«Расходники» в
  EN-локали. Добавлен `src/areas/stock/warehouse.utils.ts` (`warehouseLabel`/`warehouseNameLabel`) — два
  системных дефолтных склада идут через `stock.warehouseDefault.{writeoff,sale}` (en/ru), склад, который
  владелец переименовал сам, показывается как есть (пользовательские данные не переводим).

## assumed (додумано)

- У `TechCard` в домене нет своих полей «Название»/«Комментарий» (спецификация Altegio их описывает) —
  карточка идентифицируется парой «услуга × мастер». Поиск сделан по названию услуги, имени мастера и
  названиям расходников строк вместо «название/комментарий» техкарты — ближайший рабочий эквивалент на
  имеющихся данных. Заведение отдельных полей «название»/«комментарий» у техкарты — вне списка чинимых
  дефектов, не трогал.
- По умолчанию склад строки новой техкарты — склад типа «для списания» (совпадает с логикой автосписания
  до этой правки); если такого нет — первый склад локации.
- Когда расходники одной услуги в разных строках техкарты указывают разные склады, `ensureAutoWriteoffs`
  теперь создаёт отдельный документ списания на каждый склад визита (а не один документ с одним складом,
  как раньше) — у вкладки визита «Списание расходников» (F-08-043, вне этой пачки) есть код, читающий один
  документ на бронирование; при одном складе на техкарту (обычный сегодняшний сценарий и весь текущий мок)
  поведение не меняется, при нескольких складах в одной техкарте вкладка визита должна научиться сводить
  несколько документов — оставил как открытый пункт, не в списке дефектов этой пачки.
- Название дефолтного склада «для продажи» на EN — «Goods» (не «Products»), чтобы не путать с «Products»
  из меню (каталог товаров) — свободный перевод, не F-id.
