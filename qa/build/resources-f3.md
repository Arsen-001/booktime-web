## Построено — F-16-150…165 (лист ожидания, `/biz/waitlist`)

Экран `WaitlistScreen.tsx` уже существовал (пачки b01/f1/f2, там же F-16-149/159/160/163), но полной формы
заявки, фильтров и правки/удаления не было. Достроил в своих путях:

- **F-16-150** «Форма заявки: клиент» — имя и телефон обязательны; ввод телефона ищет клиента через
  `findClientByPhone` (уже есть в `@/api/core`), при совпадении — ссылка «Уже есть клиент: Имя», клик
  подставляет имя в поле.
- **F-16-151** «Форма заявки: услуги» — мультивыбор `EntityMultiPicker` (было и раньше), список без
  групповых и пакетных услуг (F-16-033/135, тоже уже было).
- **F-16-152** «Форма заявки: сотрудники» — добавил мультивыбор чипами: «Любой специалист» (по умолчанию)
  или несколько конкретных. Потребовало сменить `WaitlistEntry.staffId?: Id` на `staffIds: Id[]`
  (`src/domain/resources.ts`, `src/api/resources.ts`, сид `src/mock/slices/resources.ts` — везде мой
  путь). Обновил демо-данные: заявка `wl_nuri_2` теперь ждёт любого из двух мастеров.
- **F-16-153** «Форма заявки: предпочтительные дни и время» — заменил заглушку `wishes: []` настоящим
  билдером как в journal-панели: «+ Добавить день и время», чекбокс «Любое время в течение дня», внутри
  дня — «+ Добавить время» (несколько интервалов). Прошлые даты блокирует `DatePicker` (`min={today()}`).
  Потребовало расширить `WaitlistWish` необязательным `intervals?: {from,to}[]` (обратно совместимо —
  старые записи с одним `time` не сломаны). Демо: `wl_nuri_1` теперь на второй день имеет два интервала.
- **F-16-154** «Комментарий, кнопки, результат» — комментарий, «Отмена» / «Создать заявку», тост
  «Заявка добавлена в лист ожидания» — было раньше, оставил, добавил `waitlist.form.updated` для правки.
- **F-16-155** «Фильтр по статусу» — чипы «Активная» (по умолчанию) / «Срок истёк» / «Закрытая».
- **F-16-156** «Фильтр по дате и «пропавшая» заявка» — Select «Все» (по умолчанию) / «На сегодня». ⭐
  наше решение уже встроено в дизайн: раз дефолт — «Все», новая заявка никогда не «пропадает» из-за
  фильтра даты (баг Altegio из ТЗ структурно невозможен, не нужен обходной путь после создания).
  Упрощение: у нас нет «дня, открытого в журнале» (это отдельная standalone-страница, не часть сетки
  журнала) — третий вариант Altegio «На выбранную дату» не воспроизводил дословно, это ⭐/assumed.
- **F-16-157** «Сортировка» — «На ближайшее время» (по умолчанию, без даты — в конце) / «Сначала новые» /
  «Сначала старые» — по `createdAt`.
- **F-16-158** «Поиск» — по имени и последним цифрам телефона, работает вместе с фильтрами (все совместно
  в одном `filter`).
- **F-16-161** «Записать»: режим выбора слота — не строил day-grid pick-mode (это сетка journal, чужой
  файл `JournalScreen.tsx`, трогать нельзя). Кнопка «Записать» передаёт `waitlist=<id>`, `date`, `staff` в
  `/biz/journal?new=1&...` — сигнатура именно та, что описана в «Стыках» плана раздела
  (`qa/plan/resources.md`: «окно записи открывается по адресу с waitlist=<id>»).
- **F-16-162** «Окно записи из заявки и закрытие» — моя часть готова: `closeWaitlistEntry(id, bookingId)`
  уже был в `api/resources.ts` (пачка b01/b02). Сама интеграция «после сохранения записи journal зовёт
  нашу closeWaitlistEntry» — это правка journal (в её собственном окне записи), не моя; она уже записана
  как открытая просьба в `qa/requests/resources.md` («journal: вызвать markWaitlistBooked после сохранения
  записи из заявки»). Дублировать эту просьбу не стал.
- **F-16-164** «Изменение заявки» — добавил `updateWaitlistEntry(id, patch)` в `api/resources.ts`; в UI —
  пункт «✎ Изменить» в меню «⋯» карточки (только для активной/просроченной — у закрытой пункта нет, как
  в ТЗ), открывает ту же форму, предзаполненную.
- **F-16-165** «Удаление заявки» — было (`removeWaitlistEntry`), но кнопка была видна только у закрытой/
  просроченной. Добавил «🗑 Удалить» в меню «⋯» для активной тоже. ⭐ наше решение по ТЗ (F-00-061,
  черновик): вместо диалога «вы уверены?» — заявка сразу скрывается, тост с «Отменить» 5 секунд
  (`setTimeout` + `clearTimeout`), реальный `removeWaitlistEntry` летит только если не отменили.
