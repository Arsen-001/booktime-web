# Клиенты и CRM · b04 · починка дефектов (fix1)

Пачка b04 «Категории, программа лояльности локации, импорт и выгрузка, дубли и удаление» — почин дефектов,
найденных измерителем. Все 7 дефектов из списка (2 major, 5 minor) исправлены.

## Что сделано

### F-04-107 · Фамилия при импорте из телефонной книги (major)
`src/areas/clients/components/PhoneBookImportModal.tsx`: контакт с раздельными полями (`givenName`/`familyName`)
теперь передаёт их в `createClient` отдельными полями `name`/`lastName`, а не склеенной строкой. Контакт с одним
полем (`fullName`) по-прежнему целиком уходит в «Имя», фамилия не заполняется — так по логике F-04-107.

### F-04-111 · Категория клиента в окне записи (major)
`src/areas/clients/extensions/BookingWindow.tsx`: блок категорий сделан всегда видимым (с подписью «Категории:») —
раньше он был скрыт целиком при пустом списке тегов, из-за чего измеритель на демо-клиенте без тегов решил, что
категория не показывается вообще. Теперь пусто показывается как «Без категории», узел помечен `data-f="F-04-111"`.

### F-04-137 · Журнал изменений клиента (major, ⭐ наше решение)
Реализован с нуля — раньше такого узла не было вовсе:
- `src/domain/clients.ts` — тип `ClientChangeLogEntry` (+`ClientChangeAction`).
- `src/mock/slices/clients.ts` — состояние `changeLog: Record<businessId, entry[]>` (по бизнесу, не по клиенту —
  чтобы запись об удалении не пропадала вместе с самим клиентом); `version: 7` (реcид).
- `src/api/clients.ts` — `logChange()` + `listClientChangeLog()`; вызовы из `updateClient` (сравнивает поля до/после,
  пишет список изменённых), `deleteClient` (пишет `deleted`), `mergeClients` (пишет `merged`).
  `updateClient`/`deleteClient`/`mergeClients`/`bulkDeleteClients` получили необязательные `actorId`/`actorName`.
- `src/areas/clients/components/ChangeLogCard.tsx` — новый компонент: заголовок, пустое состояние, список
  «автор + время + что изменилось» (перевод названий полей — через `switch`, не через таблицу, т.к. `t()` в
  проекте типизирован компилятором и не принимает динамическую строку).
- `ClientCardScreen.tsx` — секция вставлена во вкладку «Карточка клиента» между историей комментариев и кнопкой
  «Удалить»; передаёт `staffId`/`t('card.you')` как автора при сохранении/удалении/объединении.
- `messages/{ru,en}/clients.json` — ключи `changeLog.*`, `bookingWindow.categories`/`noCategories`.
- Проверено сценарием measure.mjs (правка примечания → запись «Вы — Изменено: Примечание» появляется сразу и
  переживает полную перезагрузку страницы — 9/9 шагов сценария прошли).

### F-04-130 · Выгрузка базы: без права — пункта нет (minor)
`src/areas/clients/ImportExportScreen.tsx`: секция «Выгрузка в Excel» теперь скрыта целиком при отсутствии права
`clients.export` (раньше — задизейблена кнопка + текст-пояснение). Соответствует «Готово, когда»: «у сотрудника
без права кнопки нет».

### F-04-177 · Загрузка остатков счетов (minor, ⭐ наше решение «обсудить»)
Свою форму Altegio не строит (только через менеджера), наше предложение — через импорт клиентов уже
технически работало (колонка `balance` уже была в `ImportColumnTarget` и обрабатывалась в `applyImportRow`), но
была не видна пользователю: добавил `Balance` в шаблон CSV (`TEMPLATE_HEADER`) и пояснение в комментарии кода.
Решение остаётся «обсудить» с владельцем (в ТЗ явно помечено так) — assumed ниже.

### F-04-002 · Поиск по цифрам телефона (minor, вне пачки)
`src/areas/clients/ClientsListScreen.tsx`: поиск теперь параллельно сравнивает цифры запроса с цифрами номера
без форматирования — «777888» находит «+374 93 777 888».

### F-04-109 · Дубль категории разным регистром (minor)
`src/mock/slices/clients.ts`: ключ `categoryColors` был `Постоянный` (заглавная), а тег в сиде (`mock/seed/clients.ts`,
фундамент — не мой файл) — `постоянный` (строчная). Разный регистр давал два «разных» пункта в справочнике
категорий. Поправил ключ на `постоянный`, чтобы совпадал с реальным тегом. Проверено скриншотом
`/biz/clients/categories` — один пункт «постоянный», 12 клиентов.

## Заодно (найдено при чтении соседних замечаний, до 30% времени пачки)

`qa/measure/clients/core-rules.md` №2 и `qa/measure/clients/arch-a1.md` №7 (major, ранее не отмечены) —
**удаление клиента было жёстким** (`coreRemove`), хотя поле `Client.deletedAt` уже есть в ядре. Это напрямую
касалось функции, которую я и так переписывал для журнала изменений (F-04-137), поэтому довёл до конца:
`deleteClient`/`mergeClients` (дубль) теперь пишут `deletedAt` вместо `coreRemove`; фильтр `!c.deletedAt` добавлен в
`listClientRows`, `getClientRow`, `listCategoryOptions`, `listCategories`, проверки дубля телефона в
`createClient`/`updateClient`, поиск `keep`/`dup` в `mergeClients`. Проверено отдельным Playwright-пробником
напрямую (не через `measure.mjs --scenario`: его `goto` без `?demo=...` в query уводит в чужой демо-бизнес, где
может случайно существовать client с тем же `cl_00N`, — так получил обманчивый «клиент не удалился» на первых
попытках): удалённый клиент по прямой ссылке теперь отдаёт ErrorState «Не удалось загрузить», а его номер
телефона освобождается для нового клиента.

`qa/measure/clients/arch-a1.md` №4 и №12 — отмечены как уже исправленные (телефон/выгрузка по праву — на экране
уже так было; поиск по цифрам — сделал в этой пачке для F-04-002); ⏳ `assertCan(...)` внутри самих api-функций
и вынос поиска в общую с journal функцию — оставлены на потом, отмечено в файлах с обоснованием.

## assumed (додумано)

1. **F-04-107**: контакт с одним полем ФИО (`fullName`) не пытаемся разбить эвристикой на слова — только явные
   раздельные поля контакта (`givenName`/`familyName`) уходят в разные поля базы, как буквально требует «Готово,
   когда».
2. **F-04-111**: для наглядности добавил подпись «Категории:» и текст-заглушку «Без категории» вместо того, чтобы
   скрывать блок при пустом списке — иначе визуальная проверка отличить «есть функция, но у клиента нет тегов» от
   «функции нет вообще» не может.
3. **F-04-137**: журнал — по бизнесу (`businessId`), не по клиенту, чтобы запись об удалении не исчезала вместе с
   удалённым клиентом; на экране карточки клиента показываю только его собственные записи (фильтр по `clientId`
   на чтении). Отдельного общего экрана «Журнал изменений по всем клиентам» не делал — не было в списке дефектов.
   Не пишу в журнал `created` (создание клиента) — по прямому тексту ТЗ: «Создание клиента не пишется в
   „Изменения данных“» (F-04-061); тип действия `created` в перечислении оставлен на будущее (например, для
   импорта), но никто его сейчас не эмитит.
4. **F-04-177**: реализация «остатков через импорт» — числовая колонка, которая прибавляется и к «Продано», и к
   «Оплачено» (баланс счёта = разница), а не отдельный тип операции — минимальное приближение, вопрос помечен
   «обсудить» в самом ТЗ, окончательная форма ждёт владельца.
5. Мягкое удаление (заодно, выше) не трогает `listClientVisits`/`inviteToApp`/подписи `clientId→name` в списках
   визитов — эти вызовы либо работают только для уже открытой (не удалённой) карточки, либо намеренно показывают
   имя удалённого клиента в исторических записях (записи и платежи остаются, F-04-137 «Готово, когда»).
