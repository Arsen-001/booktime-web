# journal · g3-1 fix1 (25.09.2026)

Чиню дефекты измерителя по доделке g3-1. Список: F-01-006 (block), F-01-029 (major), F-01-181 (major),
F-01-156 (minor), F-01-033 (minor).

## Починено (мои пути)

### F-01-029 — карточка статуса теперь открывается наведением
`src/areas/journal/components/BookingBlock.tsx`: кнопка-значок статуса у `Popover` была только `onClick`.
Popover переведён на управляемое состояние `open`/`onOpenChange`; кнопка получила `onMouseEnter` (открыть
через 150 мс — гасит мигание при пролёте курсора), `onMouseLeave`/`onBlur` (закрыть через 200 мс),
`onFocus` (открыть сразу — клавиатура). Клик оставлен рабочим (тач, клавиша Enter/Space) — таймер сразу
гасится, чтобы клик не спорил с уже начатым закрытием. Обёртка над содержимым карточки тоже гасит таймер
закрытия по `onMouseEnter`, чтобы можно было довести курсор до кнопок внутри карточки, не потеряв наведение.
Содержимое карточки не трогал — измеритель подтвердил, что оно верное.

### F-01-181 — отчёт «Записи» дополнен до полного набора фильтров ТЗ
Сам файл `RecordsScreen.tsx` уже содержал почти всё «Готово, когда» просит (фильтр «Отменённые», карандаш
открывает окно записи, колонки клиент/время/специалист/услуга/сумма/автор+дата/источник/статус, «Удалить
выбранные», «Операции с Excel» — импорт/экспорт с историей). Стартовый комментарий файла был устаревшим
(«вне этой пачки, F-01-181…183») ещё с более ранней версии — обновил его на актуальное описание, это и
объясняет находку измерителя (не читавшего код ниже комментария). Добавил три фильтра, которых
действительно не хватало из «Поля и варианты»: источник (все/онлайн/офлайн — `ONLINE_SOURCES` = app/link/
widget), статус оплаты (все/оплачено полностью/не оплачено — по `extras.paidAmount` относительно
`booking.total`), категория записи (все + список `getBookingCategories()`, подпись через
`bookingCategoryLabel`). Пустое состояние при активном любом из фильтров теперь показывает «Ничего не
нашли» со сбросом всех четырёх фильтров разом. Ключи `records.filter.source*/paid*/category*` добавлены в
`messages/ru/journal.json` и `messages/en/journal.json`.
Не добавлял (не входит в «Готово, когда», за рамками этой пачки, зафиксировано ниже как assumed):
фильтры по дате создания/визита отдельными полями (SegmentedControl+DatePicker), поиск по имени/телефону
клиента текстовым полем, «Сотрудник с доступом» (кто создал), «с услугами / без услуг», постраничность
25/50/100 и счётчики «Найдено N» / «Показаны 1–N из N», колонка «Локация» (сетевой список). Список в
ТЗ большой и часть пунктов ортогональна проверенным «Готово, когда»; если владелец хочет 1:1 полностью —
отдельная пачка.

### F-01-156 — перепроверил живьём, дефекта не нашёл
Код на месте и однозначен: единственная кнопка `data-f="F-01-156"` — плитка в `JournalSidebar.tsx`,
вызывает `onOpenWaitlist` → `setWaitlistOpen(true)` в `JournalScreen.tsx`, панель — `WaitlistPanel.tsx`
(`data-f="F-01-156 F-01-162"`). Никакой ссылки на склад/`/biz/stock` рядом с этим data-f в коде нет. Замер
`scripts/measure.mjs --routes /biz/journal` (см. ниже) — 0 ошибок, кнопка на месте. Похоже на артефакт
одного прогона (сам измеритель это и предполагал — падение dev-сервера в то же окно времени, см. лог
demo-q3: «В 10:49–10:55 экран падал… к 10:55 уже работал»). Изменений не вносил.

### F-01-033 — перепроверил, дефект реальный, но не в моих путях (см. просьбу)
Прочитал `src/mock/db.ts` и `src/api/request.ts` целиком (фундамент): запись в `localStorage` дебaунсится
на 400 мс — этого достаточно для ожидания измерителя, значит дело не в задержке записи. Дело в чтении:
`persist(useDb, { skipHydration: true, … })` нигде не перечитывается по событию `storage`, и `useApiQuery`
не ревалидирует по фокусу/интервалу — во второй открытой вкладке новая запись физически не появится, ни
через 2.5 с, ни позже, пока вкладка не перезагрузится сама. Подробный разбор и формулировка просьбы — в
`qa/requests/journal.md` (раздел «g3-1 fix1»), правку в `src/mock/db.ts` не делал — чужой путь.
