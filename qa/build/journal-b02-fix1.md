## Исправлено

### F-01-048 (major) — дублирование закреплённого поля «Комментарий»
- Файл: `src/areas/journal/components/booking-window/ExpandedFieldsPanel.tsx`.
- Причина: панель «Расширенные поля» рисовала комментарий/категории/цвет/доп. поля безусловно,
  не глядя на `pinnedFields` — а закреплённые поля уже выведены в левую зону (`LeftZone` →
  `renderPinnedField`). При закреплённом по умолчанию `comment` он был виден дважды одновременно.
- Правка: каждый блок («Комментарий» F-01-050, «Категории записи» F-01-051, «Цвет записи»
  F-01-052) теперь оборачивается `!isPinned(...)`; список `customFieldDefs` фильтруется тем же
  способом (`visibleCustomFieldDefs`). Если закреплены абсолютно все поля — вместо пустой панели
  показывается строка-подсказка (`window.expanded.allPinned`, добавлен ключ в ru/en/hy).
- Проверено: снимок `qa/shots/journal-b02-fix1/…__expanded-fields.png` — «Комментарий» в открытой
  панели больше не дублируется, виден только в закреплённой зоне сверху.

### F-01-037 (major) — нет стрелки для сворачивания окна без потери введённого
- Файл: `src/areas/journal/components/BookingWindow.tsx`.
- Правка: `Sheet` получил `headerActions` — кнопка со стрелкой (`ChevronRight`, `IconButton`,
  подпись `window.collapseHide`) рядом с крестиком; по клику окно закрывается тем же путём, что и
  крестик/Escape. Так как черновик уже переживает закрытие (F-01-040, и его гонка исправлена ниже),
  «скрыть стрелкой, не теряя введённое» теперь выполняется буквально — есть отдельный элемент-стрелка,
  и данные не пропадают.
- Ключи добавлены: `window.collapseHide` в ru/en/hy `journal.json`.
- Проверено: снимки b02-fix1 (десктоп и телефон) — стрелка видна в шапке окна рядом с ✕.

### F-01-040 (minor) — гонка автосохранения черновика при мгновенном переоткрытии
- Файлы: `src/areas/journal/components/BookingWindow.tsx`, `src/api/journal.ts`.
- Причина: автосохранение черновика делает `setTimeout(…, 400)`; при закрытии окна (unmount) React
  выполнял cleanup эффекта, который просто гасил этот таймер — последняя правка, введённая меньше
  чем за 400 мс до закрытия, никогда не попадала в стор. Даже если бы cleaup досылал `saveDraft`
  как раньше, `saveDraft` идёт через `request()` с искусственной сетевой задержкой 150–400 мс — при
  мгновенном переоткрытии `loadDraft` мог успеть прочитать стор ДО того, как запись долетит.
- Правка: `latestSnapshotRef` хранит самый свежий снимок черновика; отдельный `useEffect` без
  зависимостей от полей формы делает `return () => flushDraftSync(...)` — при размонтировании окна
  черновик пишется в стор синхронно, в обход `request()`/её задержки. Новая функция
  `flushDraftSync` в `src/api/journal.ts` — та же мутация `mutateArea`, что и у `saveDraft`, но без
  обёртки `request()`.
- Проверено логикой (гонка была именно в cleanup + искусственной задержке — оба источника устранены);
  живого стенда с управляемым таймингом under test нет, воспроизвести численно («2 из 4») сборщик
  не может — полагаюсь на устранение обоих механизмов гонки. Отмечаю в `partial`, т. к. многократный
  живой прогон (открыл → напечатал → Escape → сразу открыть) не выполнял скриптом с точным таймингом.
