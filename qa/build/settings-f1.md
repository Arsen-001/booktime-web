# settings-f1 — достройка непомеченных F-id (без тестов, решение пользователя 26.09.2026)

Задача: 30 F-id из списка задания, которые скрипт `fids.mjs --area settings` показывал непомеченными
до начала пачки. По каждому сначала искал в src — вдруг уже построено под другим именем; затем строил
по блоку ТЗ, если путь наш; иначе — записывал наблюдение в `qa/requests/settings.md` без правки чужого
файла. Тестов не гонял (measure.mjs/Playwright/снимки) по прямому указанию — только tsc + eslint по
своим путям (см. «Проверки» ниже).

## partial / не построено — и почему

- **F-00-028/029/030 (кошелёк клиента и 5%, платное клиенту, сторонняя реклама)** — в
  `00-our-decisions.md` это статьи-РЕШЕНИЯ, а не экраны: «Готово когда» дословно — «решение принято и
  записано». Строить интерфейс под непринятое решение значит придумать его самому — не стал, как и все
  предыдущие пачки (b01…b06) этого раздела.
- **F-00-154 (стартовые сферы)** — тот же случай: «Готово когда: решение принято», порядок волн не
  выбран.
- **F-15-095 (платные приложения маркетплейса)** — «Готово когда: решено, будут ли у нас сторонние
  платные приложения» — решения нет.
- **F-00-147 (несколько сфер у мастера)** — ядро уже хранит `Business.sphereIds`/`Staff.sphereIds` как
  массивы, `registerBusiness` пишет несколько сфер, но `useSphere()` (`src/demo/hooks.ts`, фундамент)
  читает ОДНУ сферу из демо-переключателя и не объединяет `features` по реальным `sphereIds` — критерий
  «мастер видит функции обеих сфер» технически не проверить. Эскалировано с b02, повторил в этой пачке
  без правки чужого файла.
- **F-00-149 (ресурсы), F-15-050/051 (лицензия/платный-бесплатный у сотрудника), F-15-092 (уведомление
  об окончании лицензии)** — построены (F-00-149) или готовы к подключению (F-15-050/051/092) в ЧУЖИХ
  путях (`resources`, `staff`, `notify`); наш вклад — движок (`previewPriceChange`,
  `subscriptionWarnings`-подобные данные) уже стабилен. Не метил чужой код, записал точечные просьбы.
- **F-00-150 (план лечения)** — повтор наблюдения из b06: экран нужен в карточке пациента
  (clients/journal), у нас только признак сферы `treatmentPlan`.
- **F-15-002/003/004/006/007/008/010/011/014/015/016** — регистрация, вход, подтверждение телефона,
  восстановление, добавление локации — либо файлы раздела **client** (`src/areas/client/**`, не наш
  путь — по F-15-002…008/010/011/015 отдельная просьба на теги отправлена ещё в b02, статус не
  изменился), либо упираются в тот же гостевой блокер `BizShell`/`WorkspaceShell` (эскалировано 5 раз).
  F-15-014/016 (вторая локация, доступ сотруднику без регистрации) технически возможны в наших путях
  (`previewPriceChange` уже даёт цену), но полноценный флоу «создать вторую локацию из кабинета» требует
  переключателя филиалов в общем каркасе (`src/shell/**`) — не строил заглушку без него, чтобы не выдать
  недоделанное за готовое.
- **F-15-125/126/127 (категории записи в окне записи, событий, клиентов)** — справочники, на которые
  ведут вкладки `CategoriesScreen.tsx` («Категории» → «Клиенты»/«События»), уже редиректят на
  `/biz/clients/categories` и `/biz/resources` — использование категорий в окне записи/событии/карточке
  клиента строят journal/resources/clients, не мы.
