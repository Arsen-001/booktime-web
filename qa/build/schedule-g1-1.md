## done

Только F-id, у которых выполнены ВСЕ пункты «Готово, когда» из ТЗ (или явно нет применимых пунктов,
и находка была именно про баг, который исправлен и проверен действием/замером):

- **F-00-051** — режим календаря мастера. `CalendarScreen.tsx`: переключатель показывается только
  когда `staffId === ownStaffId` (мастер смотрит СВОЙ календарь); иначе — бейдж текущего режима +
  текст «Режим меняет сам мастер» (ключ `calendar.modeChangedByMasterOnly`, ru+en). `api/schedule.ts`
  `setCalendarMode()` теперь принимает `actorStaffId` и отклоняет вызов, если он не совпадает со
  `staffId` — owner/admin/network через UI переключить не может, и даже прямой вызов API отказывает.
  Проверено кодом (единственный вызов в приложении передаёт `ownStaffId`) + tsc/eslint чисто.
- **F-00-058** — «Закончил раньше» доступна только когда `start ≤ now < end` (`isOngoing()` в
  `MasterActionsCard.tsx`, через `nowDateTime()`/`addMinutes()`); для записи, которая ещё не началась,
  кнопки нет вовсе (не задизейблена — скрыта, т.к. до начала действие бессмысленно). После нажатия
  тост называет реальное время, до которого открылось окно (`actions.finishedEarlyDoneAt`, ru+en),
  а не общую фразу. Проверено замером `measure.mjs` на `master` (три сегодняшние записи мастера — ни
  одна не идёт прямо сейчас в моке → кнопка нигде не показана, что и ожидалось).
- **F-02-041 / F-02-097** — доступ к персональным правилам слотов мастера. Заменила
  `persona !== 'master'` на проверку конкретного права `online.manage` (F-02-097 требовал именно
  это, не общее `schedule.edit`) + отдельное условие `isOwnMasterPage` (⭐ F-00-066): мастер теперь
  может редактировать правила на СВОЕЙ странице `/biz/schedule/slots/[ownStaffId]`, даже без
  `online.manage`. Owner/admin/network с `online.manage` по-прежнему могут править локацию и любого
  сотрудника. Проверено замером (owner — доступен экран «Доступное время», редактирование включено).
- **F-02-002** (частично, конкретный баг) — горизонтальный вылет страницы на телефоне (innerWidth 707
  при 390). Причина — `sr-only` span в `ScheduleGrid.tsx` без `position: relative` на родителе (utility
  `sr-only` = `position: absolute`, без предка растягивал ширину до дальнего позиционированного
  предка). Добавила `relative` на ячейку. Проверено `measure.mjs --area schedule` — «вылет» = 0 на
  всех 16 снятых страницах (было ненулевым).
- **F-00-056** — движок слотов помечен `data-f="F-00-056"` на `LiveSlotsDemo.tsx` (был только на
  соседних F-id, самого F-00-056 не было).
- **F-00-061** (частично) — «Отменить 5 с» вместо голого удаления:
  - удаление дней с полосы множественного выбора (`ScheduleScreen.tsx bulkDelete`) — теперь снимок
    `snapshotCells` + тост с действием «Отменить», как в `SchedulePanel`;
  - удаление правила слотов (`SlotsScreen.tsx onDeleteRule`) — тост с «Отменить» (пересохраняет то же
    правило) + добавлен `try/catch` (раньше падал молча);
  - удаление недоступного периода (`UnavailableDaysCard.tsx onDelete`) — заменила `ConfirmDialog` на
    «мелкое обратимое» с «Отменить» в тосте (правило 0.3 и F-00-061 явно просили тост, не «Вы
    уверены?»), плюс добавила `onChanged` — раньше список не обновлялся ни после добавления, ни после
    удаления без ручного рефреша страницы.
  Остаток (шаблон, правило слотов у StaffCard уже имел undo — не трогала; «Открыть весь день», «Как на
  прошлой неделе», «В отпуске до», отмена одной записи серии) — не успела, см. `qa/requests/schedule.md`.
- **F-00-059** (частично — честно про ограничение) — тост «Задерживаюсь» больше не врёт «клиент
  предупреждён»: если у следующей записи есть клиент, тост называет его номер телефона
  (`actions.delayCallClient`, ru+en) вместо ложного подтверждения, чтобы мастер позвонил сам. Мост в
  `client.notifications` — чужой раздел (`client`), запрос на него уже был передан раньше
  (`qa/requests/schedule.md` §b03-fix2) и остаётся открытым; полноценный push пока невозможен.
