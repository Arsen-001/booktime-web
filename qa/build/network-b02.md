## Готово

Все пункты «Готово, когда» проверила чтением кода + минимум одним живым прогоном (`scripts/measure.mjs` /
сценарии Playwright, снимки — `qa/shots/network-b02*/`), кроме отдельно оговорённого ниже.

- **F-11-041** — поиск запускается кнопкой «Показать», не на лету; находит по имени/телефону/email. Проверено
  сценарием: клик по «Ани Мелкумян» открывает карточку.
- **F-11-042** — все перечисленные в ТЗ фильтры реализованы и сочетаются (AND): состоит/посещал локации, пол,
  «только онлайн», класс важности (⭐ assumed — см. ниже), «Продано» от-до, визиты от-до, есть/нет записей
  от-до, получал SMS. «Очистить фильтр» возвращает полный список. Шторка фильтров — снимок
  `qa/shots/network-b02-filters2/…filters-sheet.png` (телефон, кнопки в футере шторки, не «уезжают» в середину
  контента — было багом, поправила: `Sheet footer`, не `sticky` внутри скролла).
- **F-11-043** — блок «Действия»: без отметок активны только «всем найденным», после отметки — «выбранным».
- **F-11-044** — выгрузка не скачивается: пишет в журнал `NetworkExportLogEntry` (автор, время, тип, срок
  ссылки 30 дней) и показывает тост «ссылка придёт на почту». Журнал — отдельный экран `/biz/network/clients/log`
  (F-11-076), снимок в отчёте.
- **F-11-045…050** — карточка клиента сети `/biz/network/clients/<phone>`: «Карточка клиента» по локациям (имя,
  категория, скидка, продано — по каждому филиалу), «История визитов» (визит + филиал + услуги + сумма, все
  локации сети), «Отправленные сообщения» (из `LogMessage` всех филиалов), «Лояльность» (реальные карты через
  `@/api/loyalty`: список, выдать, начислить/списать, удалить — по выбранному филиалу) и «Счета клиентов»
  (баланс и тип счёта, кнопки пополнения нет — по ТЗ). Живые снимки: `qa/shots/network-b02-card2…4/`.
  «Доп. поля» построена (вкладка, пустое состояние) — значения появятся, когда b04 отдаст хранилище полей
  (см. requests).
- **F-11-163** — `canSeeNetworkClientData()` в `src/api/network.ts`: у владельца всегда true, у прочих —
  приближение через членство в `NetworkUser` (настоящей галочки в правах сотрудника локации ещё нет — см.
  requests). Применить в пяти местах чужих разделов не могла — не мой путь.
- **F-11-060 / F-11-164** — набор действий сети (только SMS/Push + Excel, без категорий/удаления) реализован
  ровно как в сравнении; `sendNetworkBroadcast` пишет реальный `LogMessage` каждому затронутому клиенту (виден
  в его «Отправленных сообщениях»), один клиент нескольких филиалов получает одно сообщение (рассылка идёт по
  списку телефонов из F-11-041, а не по строкам клиентов).
- **F-11-064** — блоки «Клиенты» (новые/не новые/потерянные), «Записи и визиты» (всего/отменено/завершено/
  незавершено), источники и статусы — под шестью плитками на вкладке «Сводный отчёт».
- **F-11-065…071** — пять новых вкладок аналитики (`analytics/AnalyticsReports.tsx`): «По локациям» (таблица +
  «Итого», фильтр по подразделению), «По дням» (блок на дату, доля услуг/товаров), «По параметрам» (группировка
  день/месяц/год, 9 показателей), «Услуги» (число/выручка/средняя цена/% от выручки — без себестоимости и
  зарплаты, см. requests), «Сотрудники» (сетевой мастер из двух филиалов — одна строка с суммой), «Кадровый
  отчёт» (поиск по имени/телефону, фильтр «уволен» — по доступным полям ядра, см. requests). Живые прогоны всех
  восьми вкладок без ошибок: `qa/shots/network-b02-analytics-tabs/` (28/28 шагов сценария).
- **F-11-068 / F-11-078** — «Выполнение плана»: план/день = план месяца / дней в месяце (проверила формулой в
  коде: 300000/30=10000 — совпадает с примером ТЗ), прогноз = среднедневной факт × дней месяца, недовыполнение
  отрицательное при перевыполнении (арифметика). Работает для всех трёх типов плана (оборот/клиенты/средний
  чек) — переключатель `SegmentedControl`. **Важное исправление по ходу:** первая версия месяца выбиралась через
  `<input type="month">` — запрещённый нативный элемент (CONVENTIONS §0.3); заменила на наш `Select` со списком
  месяцев.
- **F-11-072 / F-11-073** — «Настройки» аналитики: поле «Считать потерянными… дней», сохраняется по blur,
  своя настройка на сеть (не трогает локацию). Потерянные/вернувшиеся считаются по всем локациям сети —
  функция `getNetworkAnalyticsBreakdown` (F-064) уже использует это поле.
- **F-11-076** — журнал выгрузок сети: отдельный экран, автор/время/тип/срок годности ссылки видны.

## assumed

- Класс важности клиента (F-11-042/060/…): нет поля в ядре — считаю от суммы трат (≥100k ֏ золото, ≥30k
  серебро, >0 бронза). Задокументировано и в коде (`importanceOf`), и в requests.
- «Категория» в карточке клиента сети (F-11-045) — беру первый тег клиента (`client.tags[0]`); «Скидка» — из
  `maxPercentDiscount` активной карты лояльности клиента в этой локации, если есть.
- `canSeeNetworkClientData` — приближение через членство в `NetworkUser`, реальной галочки в правах сотрудника
  локации нет (см. requests).
- Формат дат в текстовых полях фильтра «Есть/нет записей от—до» — свободный текст `YYYY-MM-DD` (без
  `DatePickerRange`, чтобы не плодить лишний компонент в шторке при таком объёме полей за отведённое время) —
  ⏳ можно заменить на `DateRangePicker`, если понадобится более строгий ввод.
- SMS/Push рассылка сети пишет прямо в `LogMessage` (см. requests) — реальной кампании `Mailing` с F-05-097 нет.
