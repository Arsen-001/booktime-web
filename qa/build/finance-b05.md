## Что построено

- **Домен** (`src/domain/finance.ts`): `PaymentPolicy` (режимы `none/deposit/cardGuarantee`, настройки
  депозита и гарантии картой, охват), `PaymentPolicyServiceOverride`, `BookingPolicySnapshot` + 4-состояния
  жизненного цикла (`clientAccepted → confirmedAtCheckout | creditedToBalance | appliedCharged | appliedWaived`,
  плюс `expired`), счёт «Payment Policy» (`PolicyAccountEntry`, `computePolicyAccountSummary`,
  `isPolicyDebtor`), `AdyenConnection`/`AdyenTransaction`. Чистые функции: `policyAmountValue`,
  `policyNoShowFee`, `policyApplies`, `policyFreeCancellationDeadline`.
- **Мок-срез** (`src/mock/slices/finance.ts`, version 9): `paymentPolicy`, `policyServiceOverrides`,
  `policyAccountEntries`, `bookingPolicySnapshots`, `adyenConnections`, `adyenTransactions`. Сид: первый
  демо-бизнес — активный режим «Депозит» 20% без Adyen (типичный армянский сценарий), второй — «Гарантия
  картой» с подключённым Adyen и 6 демо-транзакциями Adyen Dashboard; счёт «Payment Policy» с примерами всех
  сценариев (резерв+удержание, зачёт при закрытии, неудачное списание штрафа в минус — F-07-122).
- **API** (`src/api/finance.ts`): `getPaymentPolicy`/`savePaymentPolicy` (валидация: депозит≠0, окно 1–72 ч,
  гарантия картой требует Adyen), `listServicePolicyOverrides`/`setServicePolicyOverride`, `getAdyenConnection`/
  `startAdyenOnboarding`/`completeAdyenOnboarding` (только владелец, окно 1 час), `listAdyenTransactions`/
  `refundAdyenTransaction` (только владелец), `listPolicyAccountEntries`/`getPolicyAccountSummary`/
  `isClientPolicyDebtor`, `evaluatePolicyForBooking`/`createBookingPolicySnapshot`/`getBookingPolicySnapshot`,
  `applyPolicyDepositAtCheckout` (F-07-115: целиком, излишек — на баланс, пишет и операцию, и запись счёта),
  `resolvePolicyDecision` (F-07-117/118/121: charge/credit/waive, окончательно — повторный вызов бросает
  ошибку), `isPolicyActive` — для соседей (стабильные сигнатуры, описаны в `qa/plan/finance.md`).
- **Экраны:** `/biz/finance/policy` (`PolicyScreen.tsx`) — режим, депозит/гарантия картой, охват (услуги,
  сотрудники, клиенты, должники, минимальная сумма), своя политика услуги (модалка), карточка «Activated»;
  `/biz/finance/adyen` (`AdyenScreen.tsx`) — подключение (форма, только владелец), онбординг с часовым окном,
  Dashboard (StatCard-сводка, таблица транзакций с фильтром по типу/PSP, возврат только владельцем).
- **Вклады в чужие экраны:** `areas/finance/policy/PolicyBookingBlock.tsx` (в `extensions/BookingWindow.tsx`,
  вкладка «Оплата») — снимок, статус, календарь срока (зелёный/красный), баланс/доступно клиента, кнопка
  «Зачесть депозит», решения поздней отмены/неявки, пометка о финальности решения и о блокировке телефона.
  `areas/finance/policy/PolicyAccountSection.tsx` (в `extensions/ClientCard.tsx`) — Balance/Available/Top-ups/
  Fees и история счёта «Payment Policy».
- **F-07-111:** `/biz/finance/online/prepayment` теперь прячет старую форму предоплаты и показывает баннер
  «политика активна» со ссылкой на `/biz/finance/policy`, когда политика включена (мой единственный
  редактируемый путь из перечисленных в F-07-111 — карточки услуги/сотрудника мне не отданы, см. прошлые
  записи qa/requests/finance.md).
- Меню: `finance.nav.policy` добавлен в `src/areas/finance/nav.ts` и `messages/{ru,en}/finance.json`;
  новые ключи `policy.*` и `adyen.*` добавлены в оба словаря (en+ru, по правилу «только два языка в работе»).

## assumed (додумано)

- Разделение «поздняя отмена / неявка» в `resolvePolicyDecision` определяю по флагам `booking.cancelledLate`
  (ядро уже ставит его) и `booking.status === 'no_show'` — своих новых полей в `core` не заводил.
  Реальный источник «поздняя отмена мастером» из спеки (окно визита → статус) видно в моём расширении только
  как факт `cancelledLate`; отдельной кнопки «Отменить» в моей вкладке нет (она в журнале).
- Порядок проверок в `policyApplies` (сначала услуги/мастер, потом тип клиента/сумма) — по 360426/360429, как
  в самой спеке; порядок должников проверяется раньше типа клиента (F-07-108: тумблер «всегда» сильнее типа).
- «Штраф за неявку выше депозита» (`noShowFeeAboveDeposit`) хранится только при подключённом Adyen; при
  отключении Adyen во время активной политики (маловероятный кейс) поле обнуляется на сохранении —
  решение не описано в ТЗ явно, сделал по логике «без Adyen штраф = депозит».
- Демо-кнопка «смоделировать снимок» в `PolicyBookingBlock` (когда снимка ещё нет) — не из ТЗ, добавлена для
  проверки блока без ручного заполнения снимков на каждой записи; помечено как demo, не отдельная функция.
- Adyen онбординг — упрощённая форма (юрлицо/страна/shopper statement) вместо полного набора полей справки
  (документы, IBAN, PCI DSS) — сочтено достаточным для демонстрации «недоступно без Adyen» в остальном экране.
