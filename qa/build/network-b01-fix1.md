# network · b01-fix1 — починка дефектов пачки b01

Дата 25.09.2026. Чиню дефекты, найденные измерителем на пачке b01 (29 функций: каркас кабинета сети,
переключатель, управление сетью, главные экраны-списки). Пять пунктов из отчёта измерителя, два из них block.

## Что сделано

### F-11-002 / F-11-005 (block) — «Сети» ложно пустует у владельца

**Причина:** `SwitchScreen.tsx` читал сети через `listMyNetworks(businessId)` — простой фильтр по
`core.networks`, ничего не создавая. Собственная сеть владельца создаётся ЛЕНИВО, только когда открыт
`/biz/network` (`useNetwork()` → `ensureNetwork()`). Прямой заход на `/biz/network/switch` (или заход после
полной перезагрузки страницы — см. ниже про `localStorage`) находил ноль сетей и показывал «вас не добавили
в сеть» самому владельцу.

**Правка:** `src/areas/network/SwitchScreen.tsx` — добавлен `ensureNetwork(businessId)` через `useApiQuery`,
включённый только при `useCan('network.manage')` (у owner/network — есть, у admin/master — нет, так что
F-11-005 для них не регрессировал — проверила отдельным снимком). Результат сливается с `listMyNetworks` в
`networks` (дедуп по `id`), рендер и состояния загрузки/ошибки переведены на него.

Проверила: прямой заход владельца — сеть на месте; повторная перезагрузка страницы (когда `localStorage`
ничего не сохранил, см. ниже) — тоже, потому что `ensureNetwork` теперь вызывается тут же, а не полагается
на то, что кто-то уже открыл `/biz/network` раньше. Персона admin по-прежнему видит пустой блок с объяснением
(`qa/shots/network-b01-fix1-admin-check/`).

### F-11-024 (major) — в «Пользователях» сети вместо владельца — название бизнеса

**Причина:** `ensureNetwork()` в `src/api/network.ts` заполняла автосозданную строку пользователя
`name: business.name` вместо имени сотрудника-владельца.

**Правка:** берёт `readCore().staff.find(st => st.id === business.ownerStaffId)` и использует его `name`/
`phone` (с откатом на бизнес, если сотрудник почему-то не найден). Проверила снимком —
`/biz/network/settings/users` теперь показывает «Нарине Акопян», а не «Nuri Nail Studio».

### F-11-094 (major) — заголовок «Подразделения» перекрыт кнопкой «Добавить подразделение»

**Причина:** у страницы контейнер `max-w-2xl` (672px), а в шапку рядом с заголовком уместились 3 кнопки
(primary «Добавить…», «Связаться с нами» с текстом, «?»). «Подразделения» — одно слово без пробела, при
нехватке места ужимался бокс заголовка, но само слово переноситься не может — глифы рисовались поверх кнопки.
Не флейк: проверила `scripts/measure.mjs` дважды, пиксель-в-пиксель совпадает с замером измерителя.

**Правка:** `src/areas/network/NetworkPageHelp.tsx` — кнопка «Связаться с нами» стала иконкой (как «?» рядом,
`IconButton` + `label` для подсказки/доступности) вместо кнопки с текстом; плюс `flex-wrap` на строке действий
как вторая линия обороны. Освободившихся ~140px хватает с запасом — проверила снимком, заголовок и обе кнопки
не спорят за место; заодно проверила `/biz/network/services` (тот же паттерн `extra`) и `/biz/network` на
телефоне — нигде не поехало.

### F-11-077 (minor) — заголовки месяцев на английском

**Причина:** `PlansScreen.tsx` форматировал `dayjs(...).format("MMM YYYY")` без локали.

**Правка:** заменила на `useFormat().date(..., 'monthYear')` (тот же хелпер, что и везде в проекте) — теперь
«сентябрь 2026» и т. д. на ru.

## Частично / не мой путь

### F-11-077 (block) — план не сохраняется после перезагрузки

Само сохранение работает: значение уходит в `setNetworkPlanCell`, читается обратно `listNetworkPlans`, видно
сразу без нажатия кнопки — это я проверила отдельно (SPA-навигация, без полного reload). Пропадает оно после
**настоящей** перезагрузки страницы — и причина не в моих файлах: `src/mock/db.ts` пишет всю базу одним
`localStorage.setItem` на каждый сброс, а она уже у порога квоты браузера (`QuotaExceededError` — видела на
каждой странице, на чистом контексте, без единого предыдущего прогона). Это уже подтверждённая чужая проблема
(`qa/requests/journal.md`, `payroll.md`, `loyalty.md`, `finance.md`, `notify.md`, `stock.md`) — добавила
network седьмым подтверждением с той же точной причиной в `qa/requests/network.md`. Не правлю `src/mock/db.ts`
сама (не мой путь).

### F-11-003 (major) — подменю не докручивается до активного глубокого пункта

Все 13 пунктов в DOM, права прячут лишние — это работает. Не работает автопрокрутка к активному пункту,
когда он не верхнего уровня (например `/biz/network/staff` — сайдбар остаётся на «Обзор/Аналитика», реально
открытая «Сотрудники сети» не видна без ручной прокрутки). Нашла точную причину в
`src/shell/workspace/NavList.tsx` (не мой путь): эффект автопрокрутки ищет `[data-nav-active]`, но этот
атрибут расставлен только на ссылке ВЕРХНЕГО пункта раздела — вложенные дочерние ссылки его не получают
вовсе. Записала в `qa/requests/network.md` точный однострочный fix (добавить `data-nav-active={childActive ||
undefined}` на дочернюю ссылку) — сама не правлю общий файл.
