## Что построено

### Каталог прав — `src/areas/staff/permissions/`
- `catalog.ts` — 13 групп, **207 тонких прав** + 4 отдельных переключателя (F-10-089) + группа
  «Медицинские документы» (9 строк, только сфера `medicalRecords`/dental, F-10-160). Каждая строка
  сведена к одному из 28 грубых прав фундамента (`reduceToCoarse()`), зависимости — `requires` (родитель
  обязателен, F-10-073).
- `roleDefaults.ts` — `ROLE_TEMPLATE_COARSE`: грубый набор каждого из 8 шаблонов ролей (в фундаменте
  есть только owner/admin/master — остальные 6 составлены по описанию роли в ТЗ, **assumed**). Нужен
  для «сбросить к шаблону» и для набора прав по умолчанию нового администратора.
- `PermissionsEditor.tsx` — сам редактор: счётчик «n из N», группы (тумблер-корень с
  indeterminate/полностью, счётчик, раскрытие, «Дополнительные»), «⋯» группы (дать все / снять все / как
  в шаблоне), «⋯» всех прав (дать все / снять все / сбросить к шаблону), поиск с подсветкой (`<mark>`),
  «Скопировать права» (Combobox по сотрудникам бизнеса с доступом, кроме себя и владельца), «История
  изменений прав» (Modal + Timeline поверх общего журнала `listChanges`), значения «▾» у строки (период
  всегда/сегодня/неделя/месяц + «все/выбранные» через TagInput), «Кто может менять права» (F-10-075,
  реальный переключатель все/в пределах своего набора). «Сохранить» сводит тонкий набор к грубому и
  зовёт `setStaffRights()` → ядро `setStaffPermissions()` → `PermissionGate` во всех разделах видит
  изменение сразу (F-10-072/074), плюс пишет в общий журнал (`entity: 'staffRights'`).

## Готово, когда — по каждой F-id пачки

## assumed

- Грубый набор прав для 6 из 8 шаблонов ролей (`accountant`, `callCenter`, `manager`, `systemManager`,
  `viewer`, `specialist` уже был в фундаменте только частично) — фундамент даёт только owner/admin/
  master, набор каждого шаблона составлен по описанию роли из ТЗ Altegio (`roleDefaults.ts`).
  Компромисс сообщён в `qa/questions/staff.md`, если у владельца другое мнение о конкретных галочках —
  поменять одной строкой в `ROLE_TEMPLATE_COARSE`.
- 207 строк каталога прав — наш список (F-10-076…090 в ТЗ дают только названия групп и число строк, не
  сам список): составлены по смыслу группы и по тому, что реально есть в остальных разделах кабинета.
  Если раздел X появится с другим набором функций — строки каталога можно переименовать/добавить без
  переписывания редактора.
- «Кто может менять права» (F-10-075) хранится как `RightScope.target` под ключом `__manageScope__` —
  своя надстройка, не отдельное поле ядра (пока не было просьбы фундаменту).
- «Медицинские документы» — 9 строк, ТЗ явно число не называет (F-10-160 просит «построчно, только
  dental»).
- «Права, которые есть только в справке» (F-10-090) — по ТЗ это пункт-заглушка «появятся, когда
  появится функция»; сделан как поясняющий блок под группами, без выдуманных строк.
- «Скопировать права» переносит текущий сохранённый набор source-сотрудника; если у source ещё нет
  сохранённого набора — подставляется набор по умолчанию его роли (не пусто).
