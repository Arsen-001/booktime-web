# Починка b02 «API и вебхуки, MCP; кабинет разработчика» — integrations-b02-fix1

Дата: 2026-09-25. Пачка чинит дефекты измерителя `qa/measure/integrations/b02-m0.md` (пакет b02:
F-13-028…036, F-13-046, F-13-051…056, F-13-058…072).

## Что починено

### F-13-033 (block) + F-13-046 (major) — общая причина, общий фикс

Измеритель предположил гонку гидратации persist-стора. **Живая проверка (Playwright-скрипт: создать
приложение → сразу перейти по короткой ссылке `goto`) показала другую причину**, не гидратацию:

- `request()` (`src/api/request.ts`) уже ждёт `await dbReady()` перед любым чтением базы — гонки с
  localStorage тут нет.
- Настоящая причина: «Ссылка на приложение» (`/biz/integrations/e/<code>`) вела в `DirectLinkScreen`,
  который резолвил код **только** через `getAppByCode` — поиск по `apps` (опубликованный каталог
  витрины, F-13-013). Черновик/приложение на модерации/непубличное туда никогда не попадает, поэтому
  короткая ссылка из кабинета разработчика была нерабочей **всегда**, а не только «на прямом заходе»
  (клиентская навигация «работала» только потому, что попадала на уже открытую карточку по другому URL
  — `/biz/integrations/developers/apps/<id>` — не через `DirectLinkScreen`).

**Фикс:**
- `src/api/integrations.ts` — новая `getDevAppByCode(code)`: ищет код среди `devApps`, отфильтрованных
  по `ownerStaffId === currentActor().staffId` (чужой черновик по коду не открыть).
- `src/areas/integrations/DirectLinkScreen.tsx` — резолвер пробует каталог, не нашёл — пробует
  `getDevAppByCode`; при успехе редиректит на `/biz/integrations/developers/apps/<id>` (кабинет
  разработчика, где и живут обе вкладки со ссылками и рабочая кнопка «Проверить в своём филиале»).

Проверено скриптом (create → `goto` на короткую ссылку сразу после создания, без ожидания): открывает
карточку приложения, не «Ссылка не найдена». `testInstallDevAppAtOwnLocation` (кнопка F-13-046) сама по
себе не была сломана — она вызывается напрямую, без ссылки; дефект был только в самой ссылке, которую
описывает F-13-046 как способ теста черновика.

### F-13-052 (major) — `/biz/integrations/api` без `PermissionGate`

`master` без `integrations.manage` свободно открывал вкладки «Ключи и токены», «Вебхуки», «MCP и ИИ»,
видел существующие ключи/адреса и мог нажать «Выпустить» (мутация падала только на уровне `assertCan`,
фронт показывал общий тост).

**Фикс:** `src/areas/integrations/api/ApiWebhooksScreen.tsx` — три вкладки с мутациями обёрнуты в
`<PermissionGate permission="integrations.manage" fallback="message">` (как на `/developers`).
«Обзор»/«Идентификаторы»/«Документация» остались открытыми — справочные, без мутаций.
Проверено: `?demo=master` на `/biz/integrations/api?tab=keys` показывает «Нет прав на это действие».

### F-13-029 (major) — карточка «Руководство по интеграции» без ссылки

**Фикс:** `src/areas/integrations/developers/DeveloperHelpScreen.tsx` — добавлена ссылка «Перейти в
кабинет разработчика» (там начинается путь размещения: «Мои приложения» → создание → «Перейти к
публикации»). Ключ `developers.help.guideLink` добавлен в `messages/ru/integrations.json` и
`messages/en/integrations.json` (hy не трогаю — правило 0.4, только en+ru в работе).

### F-13-034 (minor) — не чинил, объясняю почему

Пункт «картинка < 1120×630 или > 12 МБ не принимается с понятной ошибкой» физически непроверяем и
нечинибелен в этой архитектуре: галерея — счётчик-плашки «N из 5» без реальной загрузки файлов
(осознанное упрощение проекта «только интерфейс», комментарий уже стоит в `AboutTab.tsx`). Не выдумывал
фейковую валидацию несуществующей загрузки — это было бы вредным контрафактом, а не починкой.
