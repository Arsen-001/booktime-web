## partial (не доделано, с причиной)

- **F-04-219, часть «проданный абонемент/сертификат виден на вкладке «Лояльность» покупателя»** —
  quick-sale в `SellMenu.tsx` продаёт из ОТДЕЛЬНОГО демо-каталога журнала (`GoodsCatalogItem`,
  временная система F-01-010, ещё до появления разделов stock/loyalty), а не настоящие
  `Membership`/`Certificate` из `src/api/loyalty.ts`. Продажа товара клиенту теперь честно попадает
  в его «Продано»/«Оплачено» — это проверил и это работает. Но абонемент/сертификат, проданные
  через «Продать ▾», НЕ появляются на вкладке «Лояльность» карточки клиента, потому что это две
  разные системы данных. Слияние демо-каталога журнала с настоящими типами лояльности — межраздельная
  правка (владелец «journal» и «loyalty» сразу), не стал делать это молча в чужом файле без
  владельца — оставляю как есть с точным описанием проблемы; настоящая продажа абонемента/сертификата
  клиенту 1:1 уже работает из loyalty (`MembershipsScreen`/`CertificateTypesScreen` → «Продать»), там
  клиент выбирается и лояльность обновляется сразу — просто это другой вход, не «Продать ▾» в
  журнале.
- **F-04-223, часть «переменная фамилии не подставляется при выключенном поле фамилии»** — во всём
  разделе notify переменные подставляются только в ПРЕДПРОСМОТРЕ тестовыми данными (`TEST_DATA`),
  реальной отправки/подстановки в живое сообщение нигде в проекте нет (ни у одной из 23 переменных) —
  это общий для всего notify предел мокового фронтенда, не специфичный для клиентских переменных;
  чинить это только для двух клиентских переменных было бы имитацией, которую тут же выдаст
  проверка. Не трогал.
- **F-04-230, часть «поиск клиента… по имени ИЛИ телефону»** — подключил существующий фильтр
  `search`, который ищет по `partyName`/`comment` операции (обычно это имя, как в форме «Новый
  платёж» — «Имя [телефон]» одной строкой). Отдельного индекса по телефону клиента у операции нет
  (`Operation` хранит только текст, не `clientId`) — если телефон не попал в `partyName` при
  создании операции, поиск по чистому номеру ничего не найдёт. Не стал заводить `clientId` на
  `Operation` (это домен `finance`, довольно инвазивная правка модели без владельца) — сузил задачу
  до того, что API уже поддерживал.
- **F-04-189 «карточка звонящего при входящем звонке»** — сама карточка (левый нижний угол при
  входящем) требует симуляции звонка (глобальное событие поверх `shell`), которой в проекте нет и
  строить её ради одного демо-попапа посчитал непропорционально пачке (плюс это не «клиенты», а
  общий shell-уровень уведомлений). История звонков и прослушивание (F-04-190) — уже полноценно
  демо в `CallsTab.tsx`, это осталось нетронутым. Вместо реальной карточки — описал приём на новом
  экране «Интеграции» (F-04-189 в тексте карточки «телефония»).
- **F-04-215 «Личный кабинет клиента в виджете»** — по нашему решению (⭐, F-00-032) вход клиента —
  код в WhatsApp/Telegram, это уже построено в клиентском разделе (`LoginScreen.tsx`,
  `GuestLogin.tsx`, не мой раздел, не трогал файлы) — не проверял отдельно «видит только записи
  через приложение, не заметки и суммы CRM», это глубже, чем один экран, и файлы принадлежат
  разделу `client`, не `clients`. Дал только ссылочную заметку на экране «Интеграции».

## assumed

- «Продано»/«Оплачено» клиента = сумма визитов + импорт + продажи вне визита (`standaloneSold`) —
  считаю продажу товара клиенту через «Продать ▾» ВСЕГДА оплаченной сразу (в `SellMenu` нет
  «оплатить потом»), поэтому прибавляю поровну и к «Продано», и к «Оплачено»; отмена (`cancelled`)
  исключает и то, и другое.
- Без кода абонемент/сертификат в «Продать ▾» теперь продаётся, если указан клиент (раньше код был
  обязателен всегда) — по аналогии с `sellCertificate`/`sellMembership` в loyalty, где «без кода
  обязателен клиент» (F-06-098). Не проверял `allowNoCode`-подобный флаг у демо-каталога журнала —
  такого поля там нет вовсе (упрощённая система), решил, что наличие клиента достаточно.
- Экран «Интеграции» — новый пункт меню раздела (`nav.ts`), а не вкладка внутри уже существующей
  страницы: показалось честнее, чем прятать 6 разных 🔒-функций внутри «Сводки» или карточки
  клиента, где им не место по смыслу ТЗ («Где: маркетплейс»/«Настройки журнала» — не карточка
  клиента).
- Иконка-ссылка «Перейти к транзакции продажи» в `ClientCard.tsx` — добавил как отдельную кнопку с
  `title` (не задизайнено в ТЗ визуально, там просто «ссылка под названием абонемента»); решил, что
  иконка `ExternalLink` рядом с существующими кнопками карандаша/заморозки достаточно понятна и не
  ломает уже собранный ряд действий.
