# Пачка b04 — «payroll»: права на зарплату, зарплата мастера с телефона, классическая модель, встроенное из AutoPayroll и редкое

Собрано 25.09.2026. Файлы ТЗ: `functional-map/09-payroll.md`. Наших F-00 у раздела нет.

## Что построено

**Права раздела (F-09-085…089).** Фундамент даёт только плоские `payroll.view`/`payroll.manage`
(запрошено ещё в b01 — `payroll.schemes`/`payroll.calculate`/`payroll.accrue`/`payroll.ownOnly`
до сих пор не заведены, см. `qa/requests/payroll.md`). Реализовал права раздела сам, поверх
существующих: срез `staffRightsByStaff` (`src/mock/slices/payroll.ts`), `resolvePayrollAccess()`
(`src/api/payroll.ts`), хук `usePayrollAccess()` (`src/areas/payroll/access.ts`). Владелец задаёт
права по сотруднику в новой секции «Права на зарплату» внизу `/biz/payroll/settings` (галочка
«Доступ к схемам», выпадающие «Доступ к расчёту»/«Доступ к начислению»: нет/только сегодня/без
ограничения, галочка «только свой расчёт»). Гейты подключены к: редактору схемы (`SchemeEditor.tsx`),
справочнику премий (`BonusesScreen.tsx`), `/biz/payroll/daily` и `/biz/payroll/period` (просмотр +
кнопки начисления, с запиранием даты на «сегодня»), классическим экранам (rules/criteria/charts),
`/biz/payroll/me`. Проверено скриншотами для owner/admin/master.

**Зарплата мастера с телефона (F-09-092…094).** Новый экран `/biz/payroll/me`
(`src/areas/payroll/MeScreen.tsx`) — вкладки «Расчёт» (период/рабочее время/оказано услуг/стоимость
услуг/итог, настоящий расчёт через `computeStatement` + новый `getStaffWorkedHours`) и «Выплаты»
(«Заработано»/«Выплачено»/«Осталось выплатить» = баланс взаиморасчётов, `getStaffBalance` поверх
`listSettlementEntries`/`settlementBalance` из finance). Владелец выбирает сотрудника, мастер видит
только себя (`ownOnlyStaffId`), «только текущий день» запирает календарь и период. Отдельно от
`/biz/apps/payroll` (раздел `client`, F-14-127/128) — та демо-симуляция считает зарплату как сырую
сумму услуг+товаров, не через движок; расхождение описано в `qa/requests/payroll.md`.

**Классическая модель (F-09-002, F-09-027, F-09-049…056).** Переключатель модели
(упрощённая/классическая) в `/biz/payroll/settings`. Новые сущности в `src/domain/payroll.ts`:
`PayrollRule` (те же блоки, что у схемы сотрудника + `serviceCostBasis` F-09-027),
`PayrollCriterion` (период/метрика/для кого/по чему/порог/скидки/категории),
`PayrollChart` (standard/planned, `pickRuleForChart` — первый выполненный критерий сверху),
`PayrollChartAssignment` (сотрудник + дата начала, `resolveActiveChartAssignment`). Экраны:
`/biz/payroll/rules` (+`/[ruleId]`, блоки переиспользуют компоненты схемы сотрудника один в один —
`PersonalServicesBlockCard` и т.д. — плюс блок «Учёт себестоимости услуги» с живым примером),
`/biz/payroll/criteria` (+`/[criterionId]`, живой пример «510 000 срабатывает / 490 000 не
срабатывает», категории для metric='count'), `/biz/payroll/charts` (+`/[chartId]`, вкладки
«Настройка»/«Сотрудники» — назначение с датой начала). Движок `computeDay`/`computePeriod` классику
не читает (см. requests) — все «Готово когда» классики проверены прямым вызовом функций, тем же
приёмом, что F-09-047/028…030 в b03.

**AutoPayroll и редкое (F-09-099…104, F-09-108).** F-09-099 — `resolveActiveChartAssignment` берёт
назначение с датой начала ≤ дата операции (смена схемы не трогает прошлые периоды), подсказка в UI.
F-09-100 — согласование ведомости: `StatementApproval` (`pendingReview → reviewed → approved →
sentToStaff → signed → paid`), переключатель в настройках, блок статуса + кнопки «Продвинуть»/
«Подписать» на `/biz/payroll/statement`; цепочка целиком проверена живьём (Playwright-сценарий,
14 шагов, 0 ошибок). F-09-101 — `/biz/payroll/analytics`: оборот, ФОТ, доля в обороте с целью и
предупреждением при превышении порога, средняя выплата, топ начислений, риски (без схемы,
неподписанные, неотмеченные выплаты). F-09-102 — сотрудник не открывает чужую ведомость (ownOnly).
F-09-103 — раздел без платных замков (проверено: ни одного paywall/lock, связанного с подпиской).
F-09-104 — `/biz/payroll/setup`: массовая настройка ставки за услуги всем ещё не настроенным
мастерам за один проход. F-09-108 — `packageServiceStaffBases()` (все три способа цены пакета из
справки), демо-карточка с примером в `/biz/payroll/rules/[ruleId]`.

## Известные ограничения (не мои пути, не правил — см. `qa/requests/payroll.md`)

- Права раздела **сужают, но не расширяют** базовые `payroll.manage`/`finance.edit`: override не
  откроет кнопку начисления администратору, у которого persona вообще не даёт эти права — нужна
  правка `src/config/permissions.ts` (не мой путь).
- `/biz/apps/payroll` (client) и `/biz/payroll/me` (payroll) — два разных пути к «моей зарплате» с
  разными числами; не унифицировал (client — не мой путь).
- Классическая модель не подключена к `computeDay`/`computePeriod` — работает как самостоятельный,
  проверенный напрямую движок (см. выше).
- `/biz/payroll/me`: «Зарплата за период» = 0 у сотрудников без настроенной схемы (легитимное «не
  настроено», но экран это явно не подписывает — мелкая находка, не успел).
