# journal · b01 «Каркас журнала» — отчёт сборщика

Дата: 2026-09-25. Маршрут: `/biz/journal`. Файлы: `src/areas/journal/**`, `src/domain/journal.ts`,
`src/mock/slices/journal.ts`, `src/api/journal.ts`, `messages/{ru,en}/journal.json`,
`src/app/biz/journal/page.tsx`.

Построен настоящий день/недельный журнал на моковых данных: левая панель со сворачиванием и
мини-календарём загрузки, шапка с переходом по датам/видом/фильтром статусов/масштабом, сетка дня по
сотрудникам или ресурсам с рабочими/нерабочими полосами, линией «сейчас», блоками записей (цвет по
статусу и источнику, категории клиента, метка «new», технический перерыв), всплывающая карточка
статуса с быстрой сменой и итогом по услугам, окно создания/редактирования записи с проверкой
пересечений и лимитов длительности, вид «Неделя» на одного сотрудника, ответственный отклик на
телефоне (390×844) и десктопе. Данные — только через `@/api/core` и `@/api/journal` поверх
`useApiQuery`/`useApiMutation`; записи и клиенты переживают перезагрузку (мок-база в localStorage).

## done — все пункты «Готово, когда» выполнены

- **F-01-003** Мини-календарь месяца: клик открывает день в сетке; у дней с записями — цветная точка загрузки, у пустых — нет.
- **F-01-004** Индикатор загрузки: пороги 50%/80% → жёлтый/красный, зелёный < 50%; перерывы между интервалами графика не входят в знаменатель (уже исключены самим `WorkSchedule`).
- **F-01-009** «Сегодня» / стрелки ‹›/ заголовок даты: в дне — ±1 день, в неделе — ±7 дней; «Сегодня» возвращает с любой даты.
- **F-01-012** «День ▾»: «Все должности» показывает колонку на каждого сотрудника с графиком в этот день; выбор должности фильтрует; выбор «Ресурсы» переключает сетку на колонки экземпляров ресурса.
- **F-01-014** Фильтр статусов (воронка): снятая галочка убирает записи этого статуса с сетки, остальные остаются; групповые события фильтр не трогает (их нет в рендере вовсе).

- **F-01-214** Категория клиента (VIP и т. п.): ярлык виден и на блоке записи в сетке, и во всплывающей карточке статуса.

## Допущено (assumed) — решения, которые пришлось принять самому

- Всплывающая карточка статуса (F-01-029) открывается **кликом**, не наведением — на телефоне наведения не бывает, а клик работает одинаково всюду; кнопка отделена от клика по всему блоку (`stopPropagation`), открытие записи не конфликтует.
- «new» у записи (нет явного поля в `Booking`) — эвристика: клиент создан в тот же день, что и запись, и статус не «не пришёл» (`src/areas/journal/lib/heuristics.ts`).
- Категории клиента (F-01-214) — сопоставление по словам сидовых тегов (`VIP`, `постоянный`, `по рекомендации`) вместо настоящего каталога категорий (его ещё нет у clients area) — см. `qa/requests/journal.md`.
- Разметка сетки сотрудника (F-01-021) хранится во временном срезе `journal.prefs.staffMarkupMin`, а не в карточке сотрудника (staff area её ещё не построил).
- Окно записи в этой пачке — минимальный каркас (мастер/время/длительность/одна услуга/статус/телефон+имя/комментарий): полные боковые зоны, повторы, скидки, оплата, товары — это пачка b02 (F-01-036…077 и соседние), в b01 их нет.
- «Оплата» во всплывающей карточке — заглушка (кнопки «Наличные»/«Карты» показывают тост «в разделе Финансы», отключены у «Не пришёл») — реальная оплата в записи (F-01-061) принадлежит finance area.
- Право на создание/перенос записи — использую общее `journal.edit` (в `permissions.ts` нет отдельных `journal.create`/`journal.reschedule` из F-01-178/179) — запрошено в `qa/requests/journal.md`.
- Сеть с несколькими филиалами («Все филиалы»): записи читаю по `businessId` без разбивки на филиалы одновременно — сети/филиалы как отдельная ось не в этой пачке (у `listBookings` есть `locationId`, но мультивыбор не поддержан).
- Один компонент `BookingWindow` используется и для «создать», и для «править» — валидация пересечения и рабочих часов одинаковая в обоих режимах.
