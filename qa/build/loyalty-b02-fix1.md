## Дефекты из отчёта измерителя — все 3 исправлены

### F-06-021 (major) — новая карта у сети создаётся с пустыми локациями
- **Файл:** `src/areas/loyalty/card-types/CardTypeFormScreen.tsx`
- **Причина:** `CardTypeFormBody` монтировался до ответа `locationsQ` (список локаций сети), т.к.
  loading-guard в `CardTypeFormScreen` стоял только под `isEdit &&`. Для НОВОГО типа тело формы
  монтировалось сразу, `useState(allLocationIds)` фиксировал `locationIds = []` навсегда.
- **Правка:** guard переписан так, что ждёт `locationsQ.isLoading` независимо от `isEdit` (плюс
  добавлен `ErrorState` на ошибку `locationsQ`), и только после этого монтирует
  `CardTypeFormBody` — умолчание «все локации отмечены» теперь приходит с первым рендером тела.
- **Проверено:** `measure.mjs` на `/biz/loyalty/card-types/new` под персоной `network` — чекбокс
  локации отмечен сразу (скриншот смотрен глазами), 0 ошибок консоли, 0 сырых ключей.

### F-06-030 (minor) — согласование в диалоге удаления
- **Файл:** `messages/ru/loyalty.json` (`cardTypeForm.deleteConfirmTextCount`)
- **Причина:** глагол «будет удалена» стоял хвостом ВНЕ ICU-плюрала, не согласуясь с формами
  few/many/other («они будет удалена»).
- **Правка:** местоимение+глагол перенесены внутрь каждой ветки плюрала: one → «она будет
  удалена», few/many/other → «они будут удалены».
- **Проверено:** сценарий `measure.mjs` — удаление типа карты «Постоянный гость» (44 карты,
  форма «few») через реальный диалог: «У 44 клиентов есть эта карта — они будут удалены вместе
  с накопленными бонусами» (скриншот смотрен глазами).

### F-06-030 (minor) — консольное предупреждение после удаления со страницы правки
- **Файл:** `src/areas/loyalty/card-types/CardTypeFormScreen.tsx`
- **Причина:** после `deleteCardType` точечная инвалидация будила ещё смонтированный `existingQ`
  (тот же типа-карт коллекция), фоновый `getCardType` на уже удалённую запись падал `not_found`
  в консоль до редиректа.
- **Правка:** добавлено состояние `deleted` в `CardTypeFormScreen`, `existingQ` получил
  `enabled: ... && !deleted`; `CardTypeFormBody.remove()` вызывает `onDeleted()` **до** записи
  в базу (не после) — так React успевает отключить запрос за время задержки `deleteCardType`
  (150–400 мс), прежде чем инвалидация после самой записи его разбудит.
- **Проверено:** тот же сценарий удаления — до правки в консоли было предупреждение `[api] запрос
  не удался … not_found`, после правки `warnings: 0` в отчёте `measure.mjs`.
