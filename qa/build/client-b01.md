# Отчёт сборки — client / b01

Пачка «Каркас приложения клиента: вход, главная, каталог и поиск, карточки мастера и места, связь».
Построено на моковых данных (без бэкенда), проверено `scripts/measure.mjs`, `scripts/fids.mjs`,
`tsc --noEmit`, `eslint` — все по путям раздела `client`.

## Что построено

Экраны (`src/areas/client/**`), подключены страницами `src/app/(client)/**`:

- `/` — `HomeScreen`: поиск сверху, ряд сторис (черновик-заглушка), место под рекламу, баннер входа
  для гостя, ближайшие записи, мои мастера (по истории записей через приложение), «свободно рядом»
  (каталог).
- `/search` — `SearchScreen`: строка «Что ищете?» с синонимами на ru/en/hy → сфера, фильтры (сфера,
  район, где, кого принимает, материал, «свободно сегодня»), «рядом со мной» (геолокация + Haversine,
  отказ → выбор района), счётчик найденного, пустой результат → форма «сообщить, когда появится».
- `/masters/[staffId]` — `MasterCardScreen`: аватар/имя/должность, «индивидуал»/«в салоне», принимает,
  места работы + ссылка на Яндекс.Карты, выезд по районам (без точного адреса), услуги с ценой и
  длительностью, до 6 фото, материалы, факты (постоянные клиенты, «в приложении с»), ближайшие
  свободные окна (ссылка на `/book`), блок связи: звонок (по часам/всегда/только сообщения),
  WhatsApp с готовым текстом, Telegram/Instagram (текст в буфер + переход), «Попросить перезвонить»
  (модалка → своя очередь в срезе).
- `/places/[businessId]` — `PlaceCardScreen`: сведения о месте, часы работы по дням недели, телефон
  (копирование + звонок), ссылка на карту, услуги по категориям, мастера места, факт «постоянных
  клиентов».
- `/login` — `LoginScreen`: имя + телефон → канал кода (WhatsApp/Telegram/SMS) → код (демо: `0000`) +
  согласие → вход (создаёт/находит `AppUser`, переключает демо-персону на `client`, уходит на `?next=`).

Данные и API раздела:

- `src/domain/client.ts` — `StaffContacts`, `CallMode`, `CallbackRequest`, `DemandLead`.
- `src/mock/slices/client.ts` — свой срез: каналы связи и режим звонка по мастеру (черновик до
  настроек в разделе staff), очередь «перезвоните мне», лиды «не нашли».
- `src/api/client.ts` — `listCatalog` (общий движок каталога для Home и Search), `getMasterCard`,
  `getPlaceCard`, `listBookedMasters`, `requestCallback`, `submitDemandLead`, `sendLoginCode`,
  `verifyLoginCode`.
- Тексты — `messages/{ru,en}/client.json` (полностью), `messages/hy/client.json` — пока пусто (по
  правилу проекта: hy можно позже, при отсутствии ключа падает на ru — так и проверено `measure.mjs`,
  армянский шрифт помечен `ok`).

  запасной канал SMS.

## partial — что не доделано и почему

- **F-00-001** — каталог и мгновенный показ окон построены; но «запись клиента закрывает окно» и
  «отметка "занято" мгновенно убирает окно» — механизм общий (мок-база одна на всех, `useApiQuery`
  тихо перечитывается по `rev`), но живьём это можно показать только вместе с записью (`/book`,
  пачка b02) и отметкой мастера (`journal`/`schedule`, чужие разделы). В этой пачке не создаётся ни
  одной записи через UI — механизм не продемонстрирован сценарием, только структурно.
- **F-00-003** — оба пункта «Готово, когда» про регистрацию мастера и скрытие пунктов меню кабинета
  бизнеса — это не экраны приложения клиента, у нашей пачки нет поверхности, чтобы их выполнить
  (относится к settings/staff).
- **F-00-005** — платных кнопок в наших экранах нет (проверено), но полный путь «нашёл → записался →
  получил напоминание» не пройти без `/book` (b02) и пушей (`notify`, чужой раздел).
- **F-00-031** — просмотр без входа полностью работает (каталог/поиск/карточка мастера — под guest,
  0 ошибок); а «кнопка "Записаться" без входа ведёт на ввод имени/телефона» зависит от `/book`,
  которого в этой пачке нет — ссылки на него уже расставлены.
- **F-00-032** — вход отдельным экраном полностью работает (WhatsApp/Telegram, код, согласие, вход);
  но сценарий из ТЗ «код входа при записи, без повторного ввода данных» относится к `/book` (там
  вход должен быть частью потока записи) — эта интеграция в b02.
- **F-00-105** — режимы «всегда» и «по часам» (`Staff.callHours`) полностью работают: вне часов
  кнопка «Позвонить» скрыта, показано «Написать». Режим «не во время записей» реализован упрощённо —
  сейчас смотрит только на `callHours`, не на текущую активную запись мастера в реальном времени (в
  ядре нет живого «сейчас у мастера запись» без прогона журнала) — отмечено в коде комментарием.
- **F-00-106** — просьба «перезвоните» сохраняется в срез `client.callbackRequests` (с номером и
  временем) и подтверждается тостом клиенту; но фактическая доставка мастеру уведомлением зависит от
  раздела `notify`, которого ещё нет — срез задокументирован как источник для будущей интеграции.
- **F-00-112** — лид «не нашли» сохраняется; вторая часть критерия («при регистрации такого мастера в
  районе клиент получает пуш») требует `platform` (заявки/модерация) и `notify` — не в этой пачке.
- **F-14-007** — вход по номеру+коду и запасной канал работают; автоподстановка кода из SMS (WebOTP)
  не реализована — в демо нет реальных SMS, подставлять неоткуда.
- **F-14-010** — на главной есть ближайшие записи и мои мастера с переходом «Все»; блока карт
  лояльности/абонементов/сертификатов нет — это раздел `loyalty`, не наш.

## Снятое (00 «Снято») — не строилось нарочно

- Встроенная карта, «Вызвать такси» — только ссылка на Яндекс.Карты (`Location.yandexMapsUrl`).
- Мастер не появляется в «Моих мастерах» по номеру из CRM — только после записи через приложение
  (`listBookedMasters` строго по `appUserId`).
- Закрытая оценка 1–5, плохие отзывы — не строились; звёздочка/отзывы вообще не в этой пачке
  (F-00-116, F-14-013/014 — b03).
- Звонки внутри приложения, скрытие номера — не строились; номер, увиденный клиентом, — «не наше
  дело» (как решено).

## F-00-036 — не решено, не построено

Помечено в ТЗ как ❓ «не решено» (один вход клиента/мастера или переключатель), «Готово, когда» —
«решение принято и записано». В интерфейсе строить нечего до решения; сейчас гость видит «Войти»
(клиент) и отдельно «Мой бизнес» (для персон с кабинетом) — два независимых входа, как и требуют
остальные решённые пункты. Оставлено как есть, ждёт ответа пользователя.

## assumed — что пришлось додумать

- У мастера нет полей для Telegram/Instagram/режима звонка в ядре (`domain/core.ts`) — временно
  завели их в своём срезе `client.contacts` (ключ — id мастера), детерминированно заполнили сидом
  (по индексу сотрудника). Когда раздел `staff` даст мастеру эти настройки по-настоящему — надо будет
  перенести (написано в `qa/requests/client.md`).
- Синонимы поиска (F-00-110) — список слов на ru/en/hy собран как черновик (в ТЗ решения нет), покрыт
  пример «ногти», не все сферы одинаково богаты синонимами.
- «Постоянный клиент» (F-00-117) считается от 3 визитов без отмены — порог не решён в ТЗ, взят как
  черновик.
- Иконка Instagram — в установленной версии `lucide-react` нет `Instagram`, использован `AtSign`
  (сама функция канала не менялась).
- «Позвонить» на карточке мастера моделирует режим «не во время записей» через `Staff.callHours`
  вместо реальной текущей записи (см. partial по F-00-105).
