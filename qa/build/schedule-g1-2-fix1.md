# schedule — g1-2-fix1 (починка дефектов измерителя)

Разбор списка из 15 пунктов измерителя. Для каждого — что реально в моих путях (`src/app/biz/schedule/**`,
`src/areas/schedule/**`, `src/domain/schedule.ts`, `src/mock/slices/schedule.ts`, `src/api/schedule.ts`,
`messages/*/schedule.json`), а что физически лежит в чужих файлах (не трогаю по правилу CONVENTIONS.md §1).

## Починено в этой пачке

### F-02-085 · Права журнала на расписание — «ограничение истории» (major)
Третий пункт «Готово, когда» («при ограничении «7 дней» старшие даты не открываются») нигде не был построен —
ни хранилища, ни enforcement. Первые два пункта («мастер видит только себя», «без права на правку нет пунктов
изменения») уже были готовы раньше (`useCan('schedule.edit')`, `restrictedToSelf` в `ScheduleScreen`/`HistoryScreen`/
`ScheduleGrid`/`TemplatesScreen`) — просто без общего вывода измерителя это было не видно.
- `src/mock/slices/schedule.ts` — новое поле `historyLimitDays: Record<staffId, number>` (версия среза 4 → 3).
- `src/api/schedule.ts` — `getHistoryLimitDays`, `setHistoryLimitDays`, `isDateBeyondHistoryLimit`.
- `src/areas/schedule/ScheduleScreen.tsx` — кнопка «назад» по неделе/месяцу гасится (`disabled`), когда начало
  видимого диапазона старше лимита у мастера (`persona === 'master'`); подпись «Прошлые даты вам недоступны».
- `src/areas/schedule/history/HistoryScreen.tsx` — записи истории, целиком про даты старше лимита, у мастера
  из списка убираются (было `data-f="F-02-102 F-02-085"` уже проставлено раньше, теперь код реально фильтрует).
- `src/areas/schedule/extensions/StaffCard.tsx` — новый блок «Доступ к истории графика и записей» (Select:
  «Не ограничивать» / 1 / 7 / 30 / 90 / 180 дней), виден владельцу/администратору/сети, `data-f="F-02-085"`.
  Поле логически принадлежит вкладке «Доступ» карточки сотрудника (у staff её пока нет) — когда появится,
  контрол переносится туда без переделки хранения (см. запись в `qa/requests/schedule.md`).
- Тексты — `messages/{ru,en}/schedule.json` (`table.beyondHistoryLimit`, `staffCard.historyLimit*`).
- Проверено `scripts/measure.mjs` на `/biz/schedule` и `/biz/schedule/history` (owner/master, тел/деск) и
  `/dev/ext/staffCard/schedule` — 0 ошибок консоли, 0 сырых ключей; снимок нового контрола — глазами.

## Подтверждено-но-не-моё (без изменений, причины те же, что в прошлых отчётах — g1-1-fix1/fix2)

### F-02-079 / F-02-078 (major) — «Любой специалист» и «время раньше услуги» в виджете
Инженерная часть в моих путях полностью готова и работает: `getAnySpecialistSlots`, `getSkipStaffSelection`,
`computeAnySpecialistSlots`, `computeFreeSlots` — всё в `src/api/schedule.ts`, тумблеры в
`src/areas/schedule/extensions/{StaffCard,SettingsHub}.tsx` реальны и сохраняются (это подтвердил сам
измеритель). Единственное, чего не хватает, — `src/areas/online/**` (чужой путь) эти функции не вызывает.
Это НЕ мой файл, чинить нельзя (CONVENTIONS.md §1). Не дублирую предложение в `qa/requests/schedule.md` — оно
там уже есть и актуально.
- Дополнительно по F-02-078: наше решение F-00-092/F-00-056 (`00-our-decisions.md`) фиксирует порядок записи
  клиентом как «мастер → услуга → окно» БЕЗ варианта «время раньше услуги» — то есть сценарий, который описывает
  F-02-078, у нас как продукт не существует в принципе (это Altegio-специфика, ⭐ по нашему решению). Пункт
  «Готово, когда» неприменим, пока порядок остаётся фиксированным; если владелец решит иначе — вопрос уже
  зафиксирован в самом F-02-078 (❓) и в F-00-092 (❓ «можно ли начинать с времени»), пересматривать не мне.

`src/areas/journal/components/StaffScheduleModal.tsx` — чужой файл (раздел `journal`). Функция работает

компоненте — не мой путь, чиню только через `qa/requests/schedule.md`.

## Не мои функции вовсе (переадресация)

Список `F-02-021, F-02-022, F-02-058, F-02-059, F-02-060, F-02-063, F-02-066, F-02-074, F-02-081, F-02-082,
F-02-090, F-02-018, F-02-035, F-02-036` — все 14 проверены по ТЗ (`02-slots-schedule.md`, поле «Где»):
- F-02-021, F-02-022 — колонка/логика платности в списке сотрудников → раздел `staff`;
- F-02-058, F-02-059, F-02-060, F-02-063 — длительность/техперерывы услуги → раздел `services` (форма услуги,
  Excel-операции с услугами);
- F-02-066, F-02-074 — «Цифровой журнал» и часовой пояс в системных настройках → раздел `settings`;
- F-02-081, F-02-082, F-02-090 — базовые поля вкладки «Настройки» карточки сотрудника (не через хост
  `staffCard`, куда `schedule` контрибьютит только графиком/пулом/недоступными днями — см. `AREAS.md`) →
  раздел `staff`, его собственная реализация карточки;
- F-02-018 — шаг графика в быстром старте регистрации → раздел `settings` (`/biz/onboarding`);
- F-02-035, F-02-036 — мобильный вид журнала (правка графика/перерыв из ячейки в приложении) → раздел `journal`.

Ни одна из этих функций не строится в `src/areas/schedule/**` — у `schedule` там нет ни экрана, ни точки
расширения. Пометить их в моих файлах нечем: 0 меток `data-f` для этих id в моём разделе — не дефект, а
следствие того, что «Где» этих F-id физически не пересекается с путями `schedule` (AREAS.md). Прошу
измерителя/оркестратор перепривязать эти 14 пунктов к владеющим разделам (`staff`, `services`, `settings`,
`journal`) — с моей стороны чинить нечего и ничего не сломано.

## assumed
- Набор шагов ограничения истории упрощён до 1/7/30/90/180 дней (Altegio: от 1 дня до 6 месяцев, с полным
  запретом смотреть прошлое) — «полный запрет» реализован через отдельное значение (0 не входит в список,
  можно добавить, если владелец попросит именно «запретить совсем»; сейчас интерпретирую «не выбрано» как
  «не ограничено», а сам лимит хранится как число дней).
- Enforcement по лимиту истории применяется только для `persona === 'master'` (свой график) — карточка
  сотрудника хранит лимит per-staff, но зритель-мастер видит собственное ограничение; ограничение
  просмотра ЧУЖОГО графика владельцем/администратором не трогала (у них своих ограничений в ТЗ не описано).
- Контрол лимита истории временно живёт в моём вкладе `StaffCard.tsx` (а не на вкладке «Доступ», которой пока
  нет) — помечено в коде комментарием, чтобы `staff` мог перенести его без потери данных.
