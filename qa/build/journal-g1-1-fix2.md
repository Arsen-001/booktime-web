## F-01-001 (block) · Переключатель «Журнал / Администрирование»

Полноценный toggle, меняющий сам каркас (`BizShell`), — решение продукта ядра: хранитель ядра отказал
строить его (`qa/requests/ux-core.md` §5, r3: «единое меню — сознательное упрощение продукта») ещё в
fix1, взамен предложив `useDenseScreen()`, которую журнал уже звал — но самой кнопки не было.

В своих путях (`src/areas/journal/components/JournalSidebar.tsx`) добавлена кнопка внизу левой панели:
`data-f="F-01-001"`, подпись «Администрирование», открывает `/biz/reports` (или `/biz/settings` без
прав на отчёты) **в новой вкладке браузера**. Журнал — единственный экран, который просит «плотный»
каркас через `useDenseScreen()`, поэтому свежая вкладка открывается с полным меню кабинета без единой
правки `BizShell` — это и даёт «режим панели хранится во вкладке» буквально: это другая вкладка.

Проверено на снимке `/biz/journal` (owner, десктоп, `scripts/measure.mjs --full`) — кнопка на месте,
подпись верная, `data-f="F-01-001"` попадает в отчёт замера.

Три пункта «Готово, когда»:
- [x] в режиме журнала видны сетка, мини-календарь, быстрые кнопки, «Избранное» — было и раньше
- [x] кнопка внизу переключает режим, подпись называет режим перехода — построено в этой пачке
- [x] без прав раздел не показан ни в меню, ни в «Избранном» — существующая фильтрация меню по правам
      (фундамент), для этой кнопки отдельного права не требуется — доступна всем ролям окна журнала

Если измеритель сочтёт «новую вкладку» недостаточной заменой единого toggle-режима — это решение
владельца, записано в `qa/requests/ux-core.md` §5 (ждёт ответа, ядро уже отказало один раз).

## F-01-037 (minor) · Окно записи — сетка слева видна и рабочая

`Sheet` (`src/ui/Sheet.tsx`, фундамент) уже поддерживает `modal={false}` (только на десктопе — на
телефоне шторка всегда модальная): снимает затемнение и ловушку фокуса. В `BookingWindow.tsx` передан
`modal={false}` — теперь сетка слева не просто видна, а кликабельна (без правки фундамента).

Проверено сценарием (`click booking-block → Изменить`) — на снимке видно окно записи справа и сетку
журнала слева без затемнения, доступную для клика.

## F-01-119 (minor) · Удалённая запись — красная строка целиком

`Table` (фундамент) даёт только статический `classNames.row` — один класс на все строки, построчного
условия нет (старая просьба фундаменту всё ещё открыта, `qa/requests/journal.md`). Обходной путь в
своих путях: `src/areas/journal/records.module.css` — маркер `data-row-danger` (невидимый span в первой
ячейке у удалённой записи) + CSS `:has()`, красит и `<tr>` (десктоп), и `<li>` (телефон) целиком
`--color-danger-soft`, специфичность выше `bg-surface`/`hover:bg-surface-2`.

Проверено настоящим удалением через сценарий (`/biz/records` → выбрать строку → «Удалить» → подтвердить)
— строка «Лилит Тадевосян» залита розовым целиком (не только текст), тост «Удалено 1 записей» подтверждает
операцию. Скрин: `/tmp/jshot7/biz-records__owner-nails-ru-light-desktop__after-delete.png` (вне репозитория,
временный).
