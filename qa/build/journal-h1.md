## Сделано

### F-01-033 · Совместная работа и мгновенное обновление

ТЗ (`01-journal-records.md`) требует два «Готово, когда»:
- запись, созданная в одном браузере, появляется в другом без перезагрузки;
- два одновременных сохранения одного визита не затирают друг друга — второе получает ошибку.

Обоих не было: `src/mock/db.ts` синхронизировал вкладки только через `beforeunload`/`visibilitychange`
(закрыл/свернул вкладку), а не «прямо сейчас», и `updateBooking` ничего не проверял — вторая правка молча
затирала первую.

**Что построено** (точечная правка общих файлов — по правилу второго прохода, ради своей функции,
без переформатирования):

1. `src/mock/db.ts` — слушатель `window.addEventListener('storage', …)`: другая вкладка меняет
   `localStorage` (её же debounce на 400мс) → это событие видят ВСЕ остальные вкладки → подхватываю
   точечно тот же ключ (`core:<коллекция>` / `area:<раздел>` / `access`) и кладу в `useDb` через
   `setState`, пометив `markNextFlushAsDerived()` (тот же приём, что уже был у сида — не пишем на диск то,
   что и так только что оттуда прочитали). Дальше это идёт по уже готовому пути: `useDb.subscribe` в этом
   же файле сам находит изменившиеся теги и будит `request.ts` — экран перечитывает без вмешательства.
2. `src/api/core.ts` — `updateBooking`/`txUpdateBooking` получили необязательный третий параметр
   `expectedUpdatedAt`. Если передан и не совпадает с текущим `updatedAt` записи — `ApiError('conflict')`
   до применения патча. Параметр необязательный — все остальные вызовы `updateBooking` по кодовой базе
   (drag&drop в WeekGrid/DayGrid, `changeBookingStatus`, `src/api/journal.ts`) не меняли поведение.
3. `src/areas/journal/components/BookingWindow.tsx` — сохранение правки существующей записи передаёт
   `booking.updatedAt` третьим аргументом; в `catch` теперь различаю `ApiError('conflict')` от прочих ошибок
   и показываю свой текст, а не общее «не получилось».
4. `messages/ru/common.json`, `messages/en/common.json` — добавлен ключ `bookingErrors.conflict` (ru/en, по
   правилу «сейчас только ru+en»); показывается тем же уже существующим паттерном
   `tc(\`bookingErrors.${code}\`)`, каким уже пользуются `QuickBookingModal`/`RescheduleScreen`/`BookFlow`.
5. `src/areas/journal/JournalScreen.tsx` — `data-f="F-01-033"` добавлен на корневой узел экрана.

**Не проверено на снимках/браузере** — по прямому указанию задания «СЕЙЧАС БЕЗ ТЕСТОВ»: не запускал
Playwright/measure.mjs, снимки не смотрел. Логика прослежена по коду (`useDb.subscribe` → `onDbChange` →
`request.ts`), но живого межвкладочного прогона не делал.
