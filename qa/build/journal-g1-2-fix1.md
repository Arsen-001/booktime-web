# journal — доделка g1-2, починка 1 (25.09.2026)

Почин восьми дефектов из повторного измерения g1-2 (блок/major). tsc/eslint по своим путям — чисто;
`scripts/measure.mjs --area journal` (десктоп + телефон, ru) — 0 ошибок консоли, 0 сырых ключей,
0 пропавших переводов на всех 5 маршрутах раздела. Скрины — `qa/shots/journal-g1-2-fix1/`.

## Готово

- **F-01-046 · Ресурсы в записи.** Новое поле «Ресурсы» в левой зоне окна записи
  (`ResourcesField.tsx`): блока нет, если у локации нет ресурсов; услуга с привязанным ресурсом
  подставляет свободный экземпляр сама; занятый экземпляр не даёт себя выбрать (новая
  `listOccupiedResourceInstanceIds` в `api/journal.ts`, поверх уже готовой `hasResourceOverlap`).
  Сохраняется в `Booking.resourceIds` (ядро уже поддерживало поле).
- **F-01-059 · Ассистенты в услуге.** Строка услуги (`ServiceLineRow.tsx`) — «+ Добавить ассистента»
  серая с подсказкой, пока не включена настройка журнала «Оплачивать помощь в оказании услуги»
  (новая `JournalSettings.assistantPayEnabled`, тумблер в `JournalSettingsScreen.tsx`); при
  нескольких ассистентах доля делится поровну и правится вручную. Данные — в
  `BookingServiceLineExtra.assistants` (свой домен), переживают перезагрузку.
- **F-01-072 · Блок лояльности клиента в окне.** `LoyaltyBlock.tsx` в правой зоне (`ClientZone.tsx`)
  — карты/абонементы/сертификаты клиента с балансом, читает `@/api/loyalty` (чтение чужого раздела,
  без правки его файлов — тот же приём, что уже был в `JournalSettingsScreen.tsx` для
  `@/api/clients`).
- **F-01-070 · Поиск по примечанию клиента.** Баг в `searchClientsForBooking` (`api/journal.ts`):
  искал только по телефону/имени/email, примечание не проверялось вовсе. Добавлена проверка
  `clientNoteOverrides[id] ?? client.note`; поиск в правой панели журнала (F-01-163) и в окне записи
  теперь находит клиента по тексту примечания.
- **F-01-156…162 · Лист ожидания.** Раньше плитка «Лист ожидания» вела на `/biz/waitlist` (чужая
  заглушка, раздел `resources`). Построена панель ВНУТРИ журнала (`WaitlistPanel.tsx`, открывается
  поверх сетки, не модальная на десктопе) — свои домен/срез/API (`WaitlistEntry` в
  `domain/journal.ts`, `mock/slices/journal.ts` v11 с демо-заявкой на бизнес, полный CRUD в
  `api/journal.ts`): фильтры (статус / дата / сортировка) и поиск работают вместе, статус считается
  сам (активная/срок истёк/закрытая), панель помнит открыта/закрыта по сотруднику
  (`getWaitlistPanelOpen`/`setWaitlistPanelOpen`), форма проверяет имя/телефон/услугу и не создаёт
  заявку без них, поддерживает несколько дней и несколько интервалов на день, «Записать» открывает
  окно новой записи (клиент — по телефону заявки, услуги и комментарий — предзаполнены через новые
  `initialComment`/`initialServiceIds` у `BookingWindow`) и закрывает заявку только по реальному
  сохранению записи (закрытие окна без сохранения — заявка не меняется).

Пересмотр раннего решения «не строю — это вкладка resources/loyalty» и подробности упрощений —
`qa/requests/journal.md` (запись 2026-09-25 «fix1»).

## Не доделано

- **F-01-108/193/194/216…218 (групповые события).** Окно события целиком стоит на чужом маршруте
  `/biz/groups` (раздел `resources`, до сих пор заглушка). Со стороны журнала уже готово: клик по
  свободному времени → «Запись/Событие» → редирект на `/biz/groups?new=1&staff=…&start=…&date=…`
  (`MixedTypeChoice`). Строить чужой маршрут не стал — это подменило бы недостающий экран разделом
  `journal`, а не построило его. Нужен `resources`.
- **F-01-221 (формат даты/времени и часовой пояс).** Страница `/settings/system` — маршрут раздела
  `settings`, её нет вовсе. `useFormat()` (общий) уже готов читать сохранённый формат/пояс, как
  только `settings` заведёт поле — правок в `journal` тогда не потребуется.

## Assumed (додумано)

- Доля ассистента по умолчанию делится поровну (100 % / N) — правило «если в ЗП "каждый получает
  часть" — доля нередактируема» не подключено (раздел «Зарплата» не наш; своей настройки
  «оплачивать помощь» тоже нет в ЗП — временно в `JournalSettings`).
- «Доступен для ассистирования» у сотрудника не проверяется (поля пока нет в `Staff`) — в список
  ассистентов попадают все сотрудники локации, кроме основного мастера строки.
- Блок лояльности показывает «Остаток N визитов» вместо «N из M» — `MembershipRow` не отдаёт общее
  число визитов абонемента.
- «Записать» из заявки листа ожидания ищет клиента по телефону и сразу открывает заполненное окно
  записи — без «режима наведения на сетку» (тот трогал бы `DayGrid`/`JournalScreen.tsx` чужого
  файла глубже, чем эта пачка). Если клиент с таким телефоном не найден, окно открывается пустым по
  клиенту — в демо-данных такого не бывает (заявки всегда от существующего клиента).
- Ресурсы в записи выбираются по экземпляру резервирования (весь экземпляр целиком), без разделения
  записи «по ресурсам построчно» (F-01-114/132 — уже отдельная функция, не трогал).
