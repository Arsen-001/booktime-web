## Что исправлено

### F-04-126 (major) — .xls/.xlsx реально не парсились
`.xlsx` теперь разбирается по-настоящему: `src/areas/clients/lib/xlsx.ts` — свой минимальный ZIP-ридер
(центральная директория, локальные заголовки) + `DecompressionStream('deflate-raw')` браузера для
инфлейта + `DOMParser` для листа и `sharedStrings.xml`. Никаких npm-пакетов не ставил (запрещено
правилами) — только встроенные API браузера.
- `.xlsx` — полный разбор первого листа (`xl/worksheets/sheet1.xml`), общие строки, inline-строки,
  числа/строки.
- `.xls` — если это на самом деле Open XML под старым расширением (сигнатура `PK\x03\x04`), парсится тем
  же путём. Если это обычный текст под .xls (без control-байтов) — парсится как вставленный текст. Если
  это настоящий бинарный BIFF (Excel 97-2003, сигнатура OLE `D0 CF 11 E0`) — честно показывает
  `legacyXlsUnsupported` («пересохраните как .xlsx/.csv»), не притворяется, что распознал.
- Лимит 500 строк и «за раз — 1 файл» сохранены (`IMPORT_MAX_ROWS`, уже был в `api/clients.ts`).
- Проверено живьём: собрал руками валидный .xlsx (ZIP method 0 + sharedStrings), загрузил через
  `input[type=file]` — шаг «Сопоставление колонок» получил правильные заголовки `Name`/`Phone` из файла.
  Скриншот: `qa/shots/…` (временный, не сохранён — см. лог сессии), README ниже.
- Новые ключи `importPage.import.legacyXlsUnsupported`, `importPage.import.tooManyRows` — en+ru (hy не
  пишем, по правилу «В работе только en+ru»).

### F-04-137 (major) — удаление не было «видно в журнале изменений» нигде в интерфейсе
Раньше `ChangeLogCard` жил только внутри карточки самого клиента — а после удаления карточка становится
недоступной (обманчивый общий `ErrorState` «проверьте соединение»), и посмотреть, кто и когда удалил, было
негде. Сделал два дополнения:
1. Новый экран `/biz/clients/log` — «Журнал изменений» (весь бизнес, не один клиент): API
   `listClientChangeLog(businessId)` без `clientId` уже возвращал полный список, просто не было экрана.
   Добавлен пункт меню (`src/areas/clients/nav.ts`), страница `src/app/biz/clients/log/page.tsx`, экран
   `src/areas/clients/ChangeLogScreen.tsx`. Имя клиента — ссылка на `/biz/clients/[id]` (для живых
   открывает карточку; для удалённых — корректно попадает в состояние №2 ниже).
2. `ClientCardScreen`: при `ApiError('not_found')` (клиент удалён) вместо обманчивого «проверьте
   соединение» — честное «Этот клиент удалён» + кнопка «Открыть журнал изменений».
   Вынес общий текст строки журнала в `src/areas/clients/lib/changeLog.ts` (переиспользуют и
   `ChangeLogCard`, и новый `ChangeLogScreen`).
- Проверено живьём сквозным сценарием: открыл клиента → удалил → зашёл по старому URL → увидел «Этот
  клиент удалён» с кнопкой → нажал → в журнале видна строка «Клиент удалён · Кто: Вы».

### F-04-073 (minor) — `[mock-db]` предупреждение вне request()
`recalcClientLoyalty` в `src/api/clients.ts` читал `readArea`/`mutateArea` до входа в `request()`. Вынес
тело в `recalcClientLoyaltyImpl` и обернул публичную функцию в `request()`. Заодно нашёл и почини ту же
причину у **слияния** (F-04-135, `mergeClients`) — оно тоже не было обёрнуто в `request()` и печатало то
же предупреждение при каждом объединении дублей (в тексте дефекта это тоже упоминалось: «и слиянии»).
Обернул целиком.
Важно: `recalcAllClientsLoyalty` (пересчёт ВСЕХ клиентов при сохранении программы лояльности, вызывается
уже внутри чужого `request()`) теперь зовёт `recalcClientLoyaltyImpl` напрямую, а не публичный
`recalcClientLoyalty` — иначе у бизнеса с ~90 клиентами (реальный демо-сид «nuri») каждый пересчёт получил
бы свою задержку «сети» (150–400 мс), и сохранение программы растянулось бы на 15–25 секунд вместо одной
операции. Проверил tsc — типы и вызовы согласованы.

### F-04-111 (minor) — нативный `<input list>`/`<datalist>` вместо своего компонента
Не трогал `src/ui/TagInput.tsx` — это фундамент, им пользуются `online`, `platform`, витрина `/dev/ui`
(правка общего — не мой файл). Вместо этого сделал свой `src/areas/clients/components/CategoryTagInput.tsx`

подсказки — собственная стилизованная выпадашка в теме проекта (как у `Combobox`), с клавиатурой
(стрелки/Enter/Escape) и явным пунктом «Добавить «…»» для новой категории. Проверено живьём: список
подсказок кликается, ввод текста фильтрует список, Enter по подходящему варианту добавляет его чипом и
держит поле открытым для следующего тега (мульти-выбор, F-04-111 «Готово когда»).

## Допущено (assumed)

- **F-04-126**: настоящий бинарный BIFF-формат .xls (Excel 97-2003, до Open XML) не разбирается — без
  npm-библиотеки это нереалистичный объём работы (формат записей, разные кодировки строк). Файл с такой
  сигнатурой получает честное сообщение «пересохраните как .xlsx/.csv» вместо попытки разбора. Реальные
  файлы с расширением .xls сегодня почти всегда либо Open XML под старым именем, либо обычный
  текст — оба случая покрыты.
- **F-04-126**: для .xlsx беру строго первый лист по имени файла в архиве
  (`xl/worksheets/sheet1.xml`, иначе — наименьший номер); лист, который выбран в Excel как «активный»,
  не ищу через `workbook.xml`/`workbook.xml.rels` — усложнение не оправдано для сценария «выгрузили список
  клиентов, дальше сразу импорт».
- **F-04-137**: наш общий бизнес-журнал изменений — это НАШЕ дополнение (⭐, уже было решено раньше,
  «У нас» в ТЗ), просто раньше был виден только с одной стороны (внутри карточки). Разместил как ещё один
  пункт подменю `clients` (я — хозяин этих путей), а не встраивал в чужой раздел `staff` (у него есть свой
  «Журнал изменений» сотрудников по правам — это другая сущность, F-03).
