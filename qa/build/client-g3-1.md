# Отчёт сборщика — раздел client (сессия g3-1)

Честно: очередь пропусков в задании — на много полноценных сессий (переустройство
записи/отмены/переноса через ядро, видимость каталога, лист ожидания между разделами,
лента уведомлений, сторис/цены из platform, покупка абонементов через заявку, и т.д.),
а бюджет этой сессии был мал. Сделал не «по чуть-чуть везде», а довёл до конца
несколько самых опасных архитектурных нарушений — там, где расхождение с ядром реально
бьёт по деньгам и правам доступа — и проверил их компиляцией. Остальное осталось
несделанным, без апломба.

## done (доведено до конца, проверено tsc + eslint)

Ни один F-id из списка пропусков не закрыт целиком по своему «Готово, когда» (каждый
требует UI-работы, которую в этой сессии не трогал). Ниже — то, что закрыто на уровне
API/ядра (без этого доводить UI не имело смысла — он бы стоял на неверном основании):

- Нарушение «Правила мастера подменены своими копиями» (F-00-066/067/097/098) —
  устранено полностью в `src/api/client.ts`: `cancelWindowHours ?? 24` (было в трёх
  местах) заменён на `effectiveBookingRules()`/`freeCancelUntil()` из
  `@/domain/rules/booking-policy`. `getBooking`, `getCancelWindowHours`,
  `cancelBookingByClient` теперь читают правило мастер←бизнес по-настоящему.
- F-00-092, F-00-093, F-00-099 (частично, на уровне API) — `bookAppointment`
  переписан на `placeBooking()` из `@/api/core` (единый поток
  `@/domain/rules/booking-flow`): статус/место/предоплата/окно решает ядро ОДНОЙ
  транзакцией, вместо трёх последовательных обращений к базе. `cancelBookingByClient`
  и `rescheduleBookingByClient` переведены на `cancelBookingAsClient()` /
  `rescheduleBookingAsClient()` ядра — своя копия логики удалена.
- F-00-097 (частично) — `releaseExpiredPrepayments` в client.ts был дублем без
  `cancelReason`; заменён на вызов `@/api/core.releaseExpiredPrepayments()`
  (проставляет `cancelReason: 'prepayment_expired'`, как и требовалось).
  `markPrepaymentPaid` упрощён, своя область `prepaymentDeadline` больше не пишется —
  `BookingDetail.prepaymentDeadline` теперь читается из `booking.prepayment.holdUntil`
  (посчитан ядром при создании записи).
- Нарушение «Видимость мастера (F-00-065/108)» и «Замороженный бизнес по прямой
  ссылке» (F-00-024) — устранено в `getMasterCard`/`getPlaceCard`:
  `getMasterCard` теперь возвращает `undefined`, если `isStaffBookableOnline()` не
  пропускает (неактивен, бизнес заморожен, модерация, онлайн-запись выключена);
  `getPlaceCard` проверяет `business.status === 'active'` и фильтрует список мастеров
  через `isStaffBookableOnline()` + исключает `role === 'admin'`.

Верификация: `npx tsc --noEmit --incremental` по всему проекту — 0 ошибок;
`npx eslint src/api/client.ts` — 0 ошибок (3 старых предупреждения `_comment`,
не мои). `node scripts/fids.mjs --area client` после правки: **client 246 / 151 = 61.4%**
— не изменилось: правки этой сессии не UI, новых `data-f` не добавлял.

`scripts/ensure-dev.sh` не перезапускал (сервер уже поднят другой сессией — правило
«работающий сервер не убивать» соблюдено); `scripts/measure.mjs` и снимки в этой
сессии не гонял — бюджет ушёл на архитектурный слой, а не на подтверждение экранов,
и гонять measure по экранам, которые не менялись, только тратил бы его впустую.
Экраны, которые правки этой сессии физически затрагивают в рантайме (BookScreen,
BookingDetailScreen, MasterCardScreen, PlaceCardScreen, WaitlistScreen), **не
переизмерены — это дыра, а не подтверждённый факт**: следующая сессия должна прогнать
`scripts/measure.mjs` по ним первым делом, прежде чем считать API-слой безопасным.
