# clients · b04 — «Категории, программа лояльности локации (автоправила), импорт и выгрузка, дубли и удаление»

Раздел: **clients** («Клиенты и CRM»). Пачка **b04**, 26 F-id из `booking-research/functional-map/04-clients-crm.md` + `00-our-decisions.md`.

## Что построено

**Программа лояльности локации (F-04-114…122, 158, 073) — новый экран `/biz/clients/loyalty`.**
Новый пункт меню «Программа лояльности», 4 вкладки:

- «Правила для скидок» — ступени «Продано/Оплачено/Визитов от … → N %», добавление/удаление ступеней;
  при пересчёте несколько подходящих ступеней дают наибольшую скидку (F-04-115).
- «Правила для классов важности» — три класса (Бронза/Серебро/Золото), у каждого три независимых
  порога (продано/оплачено/визитов); при нескольких подходящих — побеждает старший класс (F-04-117).
- «Правила для категорий» — «Автодобавление» и «Автоудаление» отдельными списками правил; условие —
  продано/оплачено/визитов/не посещал N дней/статус «пришёл»/статус «не пришёл» (последнее — авто-
  категория за неявку, F-04-158) → категория (комбобокс с созданием новой на лету).
- «Настройки» — «Отмена скидки» и «Отмена класса» по числу дней без визита (F-04-116), предупреждение
  «за N дней» до сброса скидки — по нашему решению пушем, не SMS (F-04-120).

Движок пересчёта — новые функции в `src/api/clients.ts` (`recalcClientLoyalty`, `recalcAllClientsLoyalty`,
`saveLoyaltyProgram`): подходит несколько скидок → большая; несколько классов → старший; несколько
категорий → присваиваются все (F-04-121). Три момента пересчёта на месте: ручная кнопка «Пересчитать
автоправила» в карточке клиента (F-04-073, меню «⋯»), сохранение программы (пересчитывает всех клиентов
локации сразу — проверено живьём: «Сохранено — пересчитано 82 клиента») и сохранение записи в статусе
«Клиент пришёл»/«Не пришёл» — подключено прямо в `markVisitArrived`/`markVisitNoShow`, которые уже
существовали в этом файле. Правила выключены по умолчанию у новой локации (F-04-114), пример порогов
у демо-бизнеса заполнен, но не активен, пока не включат тумблер.

**Импорт и выгрузка (F-04-126…130, 132, 133, 107, 177) — экран `/biz/clients/import` вместо заглушки.**

- «Загрузить из Excel»: вставка текста или файл (.csv/.txt разбираются полностью; .xls/.xlsx честно
  показывают, что бинарный разбор в демо не поддержан — сохраните как .csv). Автоопределение
  разделителя (`,`/`;`/Tab), лимит 500 строк (501-я блокирует загрузку целиком с понятной причиной).
  Сопоставление колонок — автодогадка по заголовку + ручной выбор; «Имя»/«Телефон» обязательны, иначе
  кнопка «Загрузить» недоступна (F-04-127). Построчная проверка формата: телефон только цифрами
  (`37493000000`), email вида `x@y.z`, пол `M/F/1/2`, дата `ДД-ММ` или `ДД-ММ-ГГГГ` — со внятной
  причиной у каждой отклонённой строки (F-04-128). «Продано»/«Оплачено» (и загруженный «Остаток счёта»,
  F-04-177) **прибавляются** к уже существующим суммам через новое поле `ClientProfile.importedSold` —
  видное предупреждение над формой объясняет, что повторная загрузка того же файла удвоит суммы
  (F-04-129). Проверено живьём: загрузка одной строки → «1 клиент загружен», счётчик базы вырос
  90→91, карточка «Операции с данными» показала «создано 1, обновлено 0, отклонено 0».
- «Выгрузить в Excel»: кнопка с счётчиком найденных клиентов, неактивна на пустой базе и без права
  `clients.export`; каждая выгрузка пишется в журнал под кнопкой (F-04-130) — как уже было в списке
  клиентов, туда тоже добавлен вызов журнала.
- «Перенос базы командой» (F-04-132, 🔒 вне кабинета) — статичный блок с описанием и кнопкой «Скачать
  шаблон файла» (CSV с нужными колонками).
- «Телефонная книга» (F-04-133, F-04-107, 🔒 демо — веб-кабинета там нет): демо-модалка со списком
  контактов, галочками, «Выбрать все», уже существующие в базе номера — задизейблены с пометкой «уже в
  базе» (проверено живьём — импорт добавил ровно нового клиента, дублей не создал). Контакт с раздельными
  полями имя/фамилия раскладывается в «Имя Фамилия» — так же, как раскладка при импорте из телефонной
  книги в реальном приложении (F-04-107).

**Дубли и удаление (F-04-135…137)** — в меню «⋯» карточки клиента новый пункт «Объединить с...»:
модалка с поиском второй карточки, предупреждением «карта лояльности/абонемент/счёт НЕ переносятся»
(F-04-136), подтверждением («нельзя отменить»), после чего визиты и суммы дубля переезжают на карточку
с бОльшим числом визитов, дубль удаляется (F-04-135, F-04-137), экран возвращается к списку. Проверено
живьём полным сценарием: открыл модалку → выбрал клиента → «Продолжить» → диалог подтверждения →
«Объединить» → вернулся на клиентскую базу, 0 ошибок.

**Категории (F-04-109…111, 113)** — «Справочник» и «Создание/правка/удаление» были готовы с прошлой
пачки; в этой пачке помечены data-f и добавлено F-04-111 (назначение категории в форме карточки —
уже работало через `TagInput`, просто не было отмечено) и F-04-113 (мобильное создание категории,

нет).

Везде: три состояния (загрузка/пусто/ошибка), `data-f` на корневых узлах, `EmptyState`/`ErrorState`/

- **Право «Настройка программ лояльности» (F-04-114)** не заведено в `src/config/permissions.ts` —
  экран `/biz/clients/loyalty` временно гейтит через `useCan('settings.manage')`. Просьба записана в
  `qa/requests/clients.md`.
- **Общий журнал «Операции с данными» (F-04-126/130/206)** не существует в фундаменте — импорт и
  экспорт пишут в свой срез раздела (`importRuns`/`exportLog`) и показывают его прямо под своими
  кнопками, а не в общем месте. Просьба записана в `qa/requests/clients.md`.
- **F-04-135 «Объединить»**: ТЗ прямо говорит, что кнопки объединения у Altegio нет (только ручная
  процедура через смену клиента у каждой записи) — наше решение (F-00-128) явно предлагает добавить
  кнопку «Объединить», поэтому она построена. Какая карточка остаётся «главной» при объединении решает
  код автоматически (у кого больше визитов — вероятнее старая, основная карточка), а не сам пользователь
  выбором — в ТЗ этот шаг не описан отдельно.
- **F-04-107/113/133**: в проекте нет мобильного приложения для бизнеса — вся «телефонная книга» и
  «категория с телефона» показаны демо-модалкой на веб-экране с тем же результатом (создаётся клиент /
  категория), а не отдельным мобильным экраном.
- **F-04-121** «в какое время суток срабатывают правила „не посещал N дней“» (❓ в ТЗ) — у нас это не
  крон, а часть пересчёта при явном триггере (кнопка/сохранение программы/статус визита); отдельного
  ежедневного крона нет, т.к. в проекте вообще нет фоновых заданий (только пользовательские действия).
- **F-04-129/177** «Comment» при импорте (❓ в ТЗ, куда именно пишется) — решил в примечание карточки
  (`Client.note`), дописывается через перенос строки, если примечание уже было.
- **Импорт .xls/.xlsx**: библиотека для разбора бинарного формата Excel не подключалась (правило —
  «не ставьте пакеты»), поэтому файлы этих двух расширений принимаются кнопкой выбора, но показывают
  понятную ошибку с советом сохранить как .csv или вставить данные текстом. Вставка и .csv/.txt
  работают полностью — это и proверено сценарием.
