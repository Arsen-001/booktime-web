## Починенные дефекты (все 7 из пачки b04)

- **F-08-116 (block)** — `StockCatalogScreen.tsx:189`: `perm.manageGoods && <LinkButton>…</LinkButton>` не
  был обёрнут в `{}` — на экране был виден буквальный текст `perm.manageGoods &&`, а кнопка «Добавить
  товар» показывалась всем независимо от права. Обернул в `{}`. Проверено `measure.mjs` (0 сырых ключей) и
  сценарием под `master` — кнопки нет, текста нет (скриншот в отчёте сессии).
- **F-08-101 (block)** — экран `/biz/stock/reports` был одним сводным отчётом «Остатки» без переключателя.
  Переписал `ReportsScreen.tsx`: добавил Select «Отчёты ▾» с шестью пунктами (F-08-102…107,
  data-f у каждого), общий `DateRangePicker` для отчётов, которым нужен период, и «Выгрузить в Excel» у
  каждого отчёта. «Заказ товаров» в переключателе ведёт на уже готовый `/biz/stock/order`
  (⭐ F-00-137 с WhatsApp) — добавил туда `F-08-103` в `data-f`, отдельного дублирующего экрана не строил.
  Источник данных — `listGoods` (остатки) и `listOperations` (продажи/расход/списание/приход) по типам
  `sale` / `writeoffService` / `writeoffProduct` / `income`, которые в домене уже различены. Отчёт
  «Анализ оборачиваемости» считает средний запас упрощённо — `(остаток на начало + остаток на конец) ÷ 2`
  за период, без ежедневных срезов остатка (по ТЗ формула требует срез на каждую дату периода, у нас такой
  истории нет) — это explicitly отмечено подсказкой на экране и в assumed. Проверено сценарием
  переключения (11 шагов, 0 ошибок консоли) — см. описание в сессии.
- **F-08-109 (block)** — мелкие права склада (`StockStaffPermissions`, 15 полей) были только читаемой
  моделью без UI для назначения. Владелец не мог реально дать права конкретному сотруднику. Построил
  `/biz/stock/settings/access` (`StockStaffPermissionsScreen.tsx`): список сотрудников (из
  `listStaffRows`, чужой api читается, не пишется) с поиском, у каждого — модалка со всеми полями
  (доступ к складам — переключатель «все/выбранные» + список складов, себестоимость, срок просмотра
  операций, 4 права на операции, выгрузка в Excel, 4 права на инвентаризацию, доступ к управлению
  товарами, правки в окне записи и техкартах), сохраняет через уже готовый `setStockPermissions`. Идеально
  это должно быть вкладом в карточку сотрудника (`staffCard`), но пары `staffCard`/`stock` нет в
  `src/extensions/pairs.ts` — запрос фундаменту дописан в `qa/requests/stock.md` (раздел «Пара расширения
  `staffCard`/`stock`»); пока экран живёт в путях `stock` и уже реально работает. Починил попутно найденную
  консольную ошибку вложенных `<button>` (строка была кликабельной И содержала кнопку «Настроить» — на
  телефоне `Table` рисует строку как `<button>`) — убрал `onRowClick`, оставил только кнопку в колонке.
- **F-08-012 (major)** — `CategoryFormModal` инициализировал `useState` из `editing` только при первом
  монтировании: сам компонент не размонтируется между открытиями (размонтируется только его внутренний
  `<Modal>`), поэтому редактирование второй категории подряд открывало форму с полями от первой (или
  пустыми, если до этого была форма создания). Исправил через `key={editing?.id ?? 'new'}:{modalOpen}` в
  родителе (`StockCatalogScreen.tsx`) — React пересоздаёт компонент с чистым состоянием на каждое открытие,
  без `useEffect` (первая версия чинилась эффектом, но `react-hooks/set-state-in-effect` в eslint не
  пропустил — ключ проще и идиоматичнее). Проверено сценарием: открыл «Гель-лаки», отменил, открыл
  «Расходники для маникюра» — второе поле показывает верное название (скриншоты в сессии).
- **F-08-029 (major)** — переключателя «Не добавлять / Добавлять [Восстановлено] в название» не было
  вообще. Добавил параметр `markRestored` в `restoreGoods` (`src/api/stock.ts`) — при включённом
  переключателе суффикс ставится всем восстановленным, при выключенном (по умолчанию) — только при
  реальном конфликте имени, как было. В `ArchiveScreen.tsx` — `Switch` над таблицей архивных товаров.
  Проверено сценарием: архивировал 6 товаров → включил переключатель → «Восстановить выбранные» → у всех
  шести в названии добавился `[Восстановлено]` (скриншот в сессии).
- **F-08-031 (major)** — «Быстрое управление» на телефоне (390×844) оставалось широкой таблицей с обрезанными
  колонками (Штрихкод, Нетто, Брутто) — нарушение CONVENTIONS §0 «Телефон — первым». Добавил в
  `MassEditScreen.tsx` отдельную карточную вёрстку `<640px` (по товару — заголовок + сетка 2×3 подписанных
  полей), таблица со скроллом осталась только `≥640px`. Проверено `measure.mjs --device phone` и снимком.
- **F-08-028 (minor)** — счётчик «Все товары (N)» в сайдбаре не обновлялся сразу после массовой архивации
  (список и тост — обновлялись). Добавил явный `treeQ.refetch()` после `archiveMutation.mutate()` в
  `StockCatalogScreen.tsx` — автоинвалидация по тегам чтения (`areas.stock.goods`) должна была это сделать
  сама, но раз измеритель поймал задержку — явный refetch надёжнее и дешевле, чем разбираться в
  фундаментном `src/api/request.ts`. Проверено сценарием: после «Восстановить выбранные» счётчик сразу
  показал «Все товары (6)» без перезагрузки (тот же скриншот, что и для F-08-029).

## assumed

- F-08-109: пока нет пары `staffCard`/`stock`, экран назначения прав живёт в Товары → Настройки, а не на
  карточке сотрудника — сознательное временное решение, см. requests выше.
- F-08-105 (расход материалов) в новом отчёте показывает факт (сумма списаний `writeoffService` за период)
  без сравнения с расчётной нормой по техкартам — сама F-08-105 не входила в список дефектов этой пачки;
  подсказка на экране прямо говорит, что полное сравнение «факт против нормы» ждёт своей пачки.
- F-08-107 (оборачиваемость): средний запас считается как `(начало + конец) ÷ 2` за выбранный период —
  упрощение против формулы ТЗ (среднее по срезам на каждую дату), потому что ежедневных срезов остатка в
  сторе нет; отмечено подсказкой на экране.
- F-08-029: переключатель — глобальный чекбокс над таблицей архива (влияет на всё выбранное при
  восстановлении), а не отдельная настройка на строку — так проще и это совпадает с формулировкой ТЗ
  («Восстановление из архива: Не добавлять / Добавлять…» — один переключатель окна, не на товар).
