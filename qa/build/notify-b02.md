## assumed (додумано)

- **Язык уведомлений ≠ язык интерфейса.** `NotifyLanguage` (`ru|hy|en`) — отдельная настройка бизнеса (F-05-010),
  не связана с `useLocale()` кабинета: заголовки/подписи каналов на странице типа показываются на языке
  интерфейса владельца (`uiLocale`), а редактируемый текст шаблона — на выбранном языке уведомлений клиенту.
  Сначала перепутал эти два языка (шаблонная строка `` `F-05-005 ${…}` `` тоже не давала `fids.mjs`, статическому
  разборщику текста, найти метки — пришлось заменить на литеральные `data-f="F-05-0NN"` по каждому `code`) — само
  смешение языков поймал и исправил свежим прогоном `measure.mjs --lang en`, где заголовки и подписи каналов
  неожиданно остались русскими.
- **`smsVariants()` — полный/средний/короткий вариант вычисляется алгоритмически** (полный = как в реестре,
  средний = без упоминания мастера, короткий = только дата/время), а не 2–3 отдельных текста, набранных вручную
  под каждый из 29 типов по образцу Altegio — иначе пришлось бы вручную писать ~80 строк текста. Он всё равно
  свободно редактируется после выбора варианта.
- **Вставка переменной/эмодзи — по последнему сфокусированному textarea** (`ref` на канал + курсор), не через
  richtext/contentEditable — простое и надёжное решение для мока; вставленный токен встаёт по позиции курсора.
- **Форматирование доп. информации в Email** — markdown-подобные маркеры (`**жирный**`, `_курсив_`,
  `__подчёркнутый__`, `~~зачёркнутый~~`), которые кнопки вставляют вокруг выделения; в «Предпросмотре письма»
  эти маркеры действительно рендерятся как `<strong>/<em>/<u>/<s>`, не остаются видимым текстом.
- **Имя отправителя (F-05-012)** — показываю `Business.name` напрямую: поля «Бренд → название компании» в
  ядре ещё нет, так что ветку «пусто → берём название локации» продемонстрировать не на чем; когда поле
  появится, здесь читать его вместо `business.name` с тем же фолбэком.
- Реестр (`TYPE_REGISTRY`) — единственное место правки: `conditionsDefault` спутал местами при первой попытке
  сгенерировать патч скриптом (типы 1/4/72/6/16/17/55/85 получили значения друг друга) — заметил по дублям в
  выводе и переправил все 9 записей вручную, перепроверил `grep` на отсутствие повторных ключей в одном объекте.
