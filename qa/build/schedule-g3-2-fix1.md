## Почему 16 block не почищены

`AREAS.md`/`docs/areas.json` жёстко разводят «где живёт ТЗ-файл» (`02-slots-schedule.md`, отсюда F-02-*)
и «где живёт экран» (`routes` в `docs/areas.json`). Все 16 отмеченных block-функций по тексту самого ТЗ
(`### F-02-NNN` → поле «Где») открываются на экранах, которые `docs/areas.json` закрепляет за другими
разделами:

- F-02-036 → журнал (веб-эквивалент; мобильного приложения в проекте нет вовсе)
- F-02-022 → сотрудники (staff) — лицензия
- F-02-058, F-02-060, F-02-063 → услуги (services)
- F-02-018 → настройки/быстрый старт (settings/onboarding)
- F-02-074, F-02-088 → настройки (settings)
- F-02-011 → сеть (network) — сам файл ТЗ прямо пишет «строится разделом network»
- F-02-040 → уведомления (notify)
- F-02-084, F-02-104 → отчёты (reports); F-02-104 отдельно неприменима — мобильного приложения нет
- F-02-096 → зарплата (payroll)
- F-02-093, F-02-101 → интеграции (integrations)
- F-02-094 → в самом ТЗ «У нас: если решим; решения нет» — строить нечего, пока владелец не решил

`CONVENTIONS.md §1` прямо запрещает писать в чужие пути — параллельно у каждого из этих разделов работает
свой сборщик. Я перепроверила файловую систему заново (не поверила прошлым выводам на слово):
`find src/areas/{services,settings,notify,reports,payroll,network,integrations,staff,journal} -type f`
и точечный `grep` по каждому F-id/ключевому полю в соответствующем разделе — совпадений по-прежнему нет,
экраны либо заглушки, либо ещё не читают уже готовые поля в ядре (`Staff.hiddenInJournal`,
`Staff.journalMarkupMin`, `Staff.includeInFillRate`, `Location.timezone`). Это пятая по счёту фиксация
одного и того же (g1-2-fix2 → g1-3-fix1 → g2-2-fix1 → g2-2-fix2 → g3-2-fix1).

Со своей стороны в `src/api/schedule.ts` для всех 16 готовы и не трогались рабочие точки
(`getScheduleEnd`, `getWorkDays`, `addWorkDays`, `getBufferMin`/`setBufferMin`, `getFreeSlots`,
`DayTypeId` с зарезервированным форматом `custom:<id>`) — таблица «F-id → готовая точка» в
`qa/requests/schedule.md`. Просьба записана туда же (не правлю чужое сама): забрать эти 16 F-id
соответствующим разделам, либо снять F-02-104/F-02-094 с плана раздела (нет мобильного приложения; нет
решения владельца).
