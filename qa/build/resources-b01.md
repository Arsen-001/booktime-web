- Удаление ресурса — «Отменить» 5 с восстанавливает ТЕМ ЖЕ id (`restoreResource`), т.к. у `Resource` нет
  `deletedAt` (в отличие от `Client`/`Booking`).
- Вкладки события «Детали/Повтор/Расписание/Присоединиться/Уведомления/История» — каркас (переключаются,
  не пустой экран без объяснения), содержимое — F-16-039/043/066…094 и дальше, вне списка функций b01.
- `AddParticipantSheet`/форма заявки листа ожидания — минимальные (имя, телефон, места/услуги, комментарий);

## Правки по замечаниям измерителей (CONVENTIONS §0.1)

Файлы `qa/measure/resources/` на момент сборки — все в списке исключений CONVENTIONS §0.1 (`arch-*`,
`core-*`, `onboarding-*`, `a11y-*`, `e2e-*`, `ux-best-*`): дизайн-измерителя по разделу ещё не было (это
первая пачка). Прочитал их всё равно ради контекста (архитектура ресурсов, границы с journal) — из них взял
две правки: businessId события берётся из самого события, а не из текущего контекста кабинета (владелец сети
видит чужой филиал не пустым), и лист ожидания/занятость ресурса не заводят вторую копию данных `journal`
там, где это возможно избежать.

- **major** — дубль primary-кнопки (шапка + пустое состояние) на `/biz/resources` и `/biz/waitlist» —
  правило «один главный путь» (CONVENTIONS §0.1); убрал кнопку из шапки, пока список пуст.
- **major** — маленькая зона нажатия (36px) у «Добавить ресурс» в блоке ресурсов окна записи — `min-h-10`.
- **minor** — групповые услуги были видны в пикере услуг листа ожидания (F-16-033) — отфильтровал.
