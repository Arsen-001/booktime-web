## F-02-003 · Фильтры графика — было 2 Select (1 из них single-select), нужно 5 с множественным выбором

Прочитан блок ТЗ целиком (`02-slots-schedule.md` F-02-003). Сделано:

- `src/domain/schedule.ts` — `ScheduleFilters` расширен: `specializations: string[]`,
  `deleted: PresenceFilter`, `fired: PresenceFilter` (`PresenceFilter = 'active' | 'only'`).
  `DEFAULT_FILTERS` — новые поля по умолчанию как в ТЗ: «Неудалённые», «Неуволенные».
- Новый компонент `src/areas/schedule/components/MultiSelectFilter.tsx` — чекбоксы во
  всплывающей панели (`Popover` + `Checkbox`, как в `ScheduleViewMenu`), бейдж числа выбранного.
  В `src/ui` подходящего multi-select нет — просить общий компонент не стал, чтобы не блокироваться;
  собрал из `Popover`/`Checkbox`/`Badge`, которые уже есть.
- `ScheduleScreen.tsx` — теперь 5 фильтров: «Должность» (мультивыбор), «Специализации»
  (мультивыбор), «Неудалённые/Удалённые», «Неуволенные/Уволенные», «Есть график/Нет графика/Все».
  Список должностей и специализаций строится по ВСЕМ сотрудникам филиала (включая уволенных и
  отключённых — иначе фильтр «Уволенные» не находил бы, по какой должности их искать).
- `src/api/schedule.ts` `getScheduleTable` — раньше уволенные сотрудники были исключены жёстко
  (`s.status !== 'fired'`), теперь это управляется фильтром `fired`; добавлен фильтр `deleted` и
  `specializations` (через `service.categoryId`, т.к. отдельной сущности «специализация» в ядре нет).
- Тексты — `messages/{ru,en}/schedule.json` → `filters.specializations/deleted/notDeleted/fired/notFired`.

**Допущение (assumed):** в нашей модели персонала (`Staff.status`) нет отдельного мягкого удаления —
только `'active' | 'invited' | 'disabled' | 'fired'`. Фильтр «Удалённые/Неудалённые» спроецирован на
`status === 'disabled'` (описано комментарием в `domain/schedule.ts`). Если это не то, что должно
называться «удалён» — нужна отдельная сущность в ядре персонала (не мой путь, `staff` владеет
`Staff`), тогда это в `qa/requests/schedule.md`. Аналогично «Специализации» — своей сущности нет,
взял категории услуг, которые оказывает сотрудник (`Service.categoryId` по `Staff.serviceIds`).

Проверено вручную в браузере (owner, `/biz/schedule`): открыл «Должность» → чекбоксы, выбрал 2 →
бейдж «2», таблица сузилась 7→4 сотрудников, «Сбросить» появился; «Специализации» показывает
реальные категории («Маникюр», «Педикюр», «Дизайн и наращивание»); «Уволенные» корректно даёт
пустой список (в текущих демо-данных фильтра «Должность» уволенных с такими должностями нет) —
EmptyState вместо ошибки. Фильтры пережили перезагрузку страницы (persist в моковой БД).

**Готово, когда (из ТЗ):**
- [x] пять фильтров с указанными значениями по умолчанию
- [x] фильтр по нескольким должностям оставляет в таблице только их сотрудников
- [x] «Нет графика» показывает только сотрудников без единого рабочего дня (не трогал — уже работало)

## F-02-032 / F-02-033 / F-02-034 · «Массовая установка по датам», «каждый день/по сменам/по дням недели», «правка и удаление за период/день» (в приложении Altegio)

Прочитаны все три блока ТЗ. У нас нет отдельного нативного мобильного приложения — один
адаптивный веб-интерфейс (телефон 390×844 — основной случай, см. CONVENTIONS §0/§4). Явного решения
по скоупу в `00-our-decisions.md` для этого нет (я не владею этим файлом — он в `booking-research`,
не в путях раздела), поэтому фиксирую как **допущение (assumed), не как тихо принятое решение**:

- Массовый выбор ячеек в таблице (`ScheduleGrid` → `toggleCell`) уже позволяет отметить несколько
  сотрудников × несколько дат одновременно (курсор бежит по `staffId|date`) и одной панелью
  «Настройка графика» применить один набор часов/тип ко всей выборке — это ровно то, что описывает
  F-02-032 («ставит одинаковые часы нескольким сотрудникам на выбранные даты»). Работает на телефоне
  (панель открывается нижним листом, см. `Sheet side="auto"`).
- F-02-033 «каждый день / по сменам / по дням недели» — у нас в вебе те же три типа названы «Без
  шаблона / По дням недели / По сменам» (это прямо оговорено в самом ТЗ: «Тип «каждый день» есть
  только в приложении; в вебе — «Без шаблона», «По дням недели», «По сменам»» — F-02-007). Добавил
  быструю кнопку **«Каждый день»** рядом с чекбоксами дней недели в `SchedulePanel.tsx`
  (отмечает все 7 дней разом, повторное нажатие — «Снять все») — это прямое попадание в чек «"каждый
  день" с 1 по 30 число ставит N рабочих дней» без необходимости отдельного экрана.
- F-02-034 «правка/удаление за период и за день, подтверждение "Yes"» — правка/удаление за период
  и за один день уже есть (выбор диапазона дат или одной даты в панели/таблице); подтверждение
  «Yes» заменено на наше решение F-00-061 (тост «Отменить» 5 с вместо «Вы уверены?») — оно уже
  реализовано и явно старше этого решения по нашему конвеншну.
- Пометил `data-f="F-02-032 F-02-034"` на панели множественного выбора в `ScheduleScreen.tsx` и на
  кнопке «Сохранить» в `SchedulePanel.tsx`; `data-f="F-02-033"` — на блоке шаблона «По дням недели».

Это решение стоит перепроверить с пользователем/планировщиком раздела: если позже решат, что нужен

## F-00-051 · «Мой календарь» на телефоне — вкладка «Всё занято…» и часть строки дня обрезаны

Подтверждено скриншотом (телефон, мастер, `/biz/schedule/calendar`) и вручную браузером —
локальное переполнение внутри карточки/переключателя, не ловится общим свипом `measure.mjs`
(`document.scrollWidth === innerWidth`, т.к. переполнение было внутри `overflow: hidden`
контейнеров разметки, а не всей страницы).

Причины и правки:

- `CalendarScreen.tsx` — переключатель режима был `SegmentedControl` с длинными фразами
  («Всё свободно — отмечаю занятое» / «Всё занято — открываю свободное»,
  `whitespace-nowrap` в самом компоненте `src/ui/SegmentedControl.tsx`, общий — не мой путь,
  трогать не стал). На телефоне вторая вкладка вылезала за правый край без переноса текста.
  Заменил в своей области на два `Button` (primary/outline, `aria-pressed`), которые переносят
  текст и складываются в вертикальный столбец на телефоне (`grid-cols-1`), в строку — на десктопе
  (`sm:inline-flex`).
- Строка заголовка карточки дня (`«Открыть весь день» + DayTypeSelect`) была `flex justify-between`
  без переноса — добавил `flex-wrap` и `w-full sm:w-40` у `DayTypeSelect`.
- `BreaksEditor.tsx` (общий для панели и календаря) — ряды «Рабочее время» и «Перерыв» были
  `flex items-center gap-2` без переноса; у `TimePicker` внутри `FIELD_BASE` стоит `w-full`, что в
  таком ряду без ограничения базиса вело к переполнению вместо сжатия. Добавил `flex-wrap` и
  `min-w-0 flex-1 basis-28` на оба `TimePicker` в каждой строке (рабочие часы и каждый перерыв).

Проверено: снимок `qa/shots/custom/biz-schedule-calendar__master-nails-ru-light-phone.png` —
обе вкладки режима читаются целиком, второй перерыв (14:00–15:00) с корзиной помещается, «Открыть
весь день» и тип дня не обрезаны. `measure.mjs` по маршруту — 0 ошибок, `вылет: 0`.

**Готово, когда:**
- [x] в режиме «всё свободно» рабочие часы видны как окна, пока не отмечено занятое (не менял —
  уже работало) — переставлена только вёрстка переключателя, не логика режима
- [x] в режиме «всё занято» видны только открытые часы (то же)
- [x] смена режима не удаляет записи (не менял, логика не трогалась)
- [x] (доп., визуальный дефект) ничего не обрезано на телефоне 390×844

## F-02-007 / F-02-008 / F-02-009 / F-02-010 · Шаблоны и тип дня — не подтверждено действием (minor)

Причина минорности у измерителя — `scripts/measure.mjs` не умеет `selectOption` по нативным
`<select>`. Проверил вручную через браузер (переключение `<select>` value + `change`-событие, как
и должен делать пользователь мышью/пальцем — у нас `<select>` нативный, событие такое же):

- «По дням недели» → чекбоксы дней недели появляются, «Правка коснётся дней: N» пересчитывается
  живо при переключении дней/интервала.
- «По сменам» → поля «Рабочих/Выходных» и интервал недель на месте, пересчитывается.
- «+ Создать шаблон» открывает `TemplateFormModal`, после сохранения новый шаблон появляется в
  списке выбора и применяется (`applyChoice`) — цепочка сохранения проверена по коду
  (`templatesQuery.refetch()` → `applyChoice(tpl.id)`).
- Тип дня (`DayTypeSelect`, F-02-010) — 6 системных типов с иконками/цветами, при «Нерабочий день»
  поле часов скрывается (`dt.working` в `SchedulePanel.tsx`).

Никакого бага не нашёл — минорная пометка измерителя была о недоверенности замера, не о дефекте.
Подтверждено вручную; отдельно добавил кнопку «Каждый день» в блок «По дням недели» (см. F-02-033
выше) — небольшое улучшение, попадающее и в этот пункт.
