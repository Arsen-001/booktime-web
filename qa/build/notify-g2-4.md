### F-05-087 · Чат с клиентом в журнале и окне визита (через партнёра) — доделано

Гап был точным: «Чат» есть только как промо-заглушка в правой панели журнала (`RightPanel.tsx`, F-01-164,
чужой файл — трогать нельзя) и не было F-01-074 (чат в окне визита) вовсе. Построил «Чат Beta» как вклад
notify в хост `bookingWindow` (`src/areas/notify/extensions/BookingWindow.tsx`) — это свой файл раздела,
ровно по конвенции о хост-расширениях:

- Домен: `ChatMessage` (`src/domain/notify.ts`) — сообщение по телефону клиента, `direction: 'in'|'out'`,
  необязательное `attachmentName` (F-05-087, проверка 1: «в чат отправляются документы и изображения» —
  демо хранит имя файла).
- Срез: `chatMessages` (`src/mock/slices/notify.ts`), сеется демо-переписка (3 сообщения) для бизнеса, у
  которого уже подключён демо `chatBot`-партнёр (нечётный индекс, тот же бизнес, что и демо SMS-агрегатор).
- API: `getChatPartnerStatus`, `listChatMessages`, `sendChatMessage`, `simulateIncomingChatMessage`,
  `hasActiveChatPartner` (`src/api/notify.ts`) — гейт «работает только при подключённом партнёре из
  Интеграции → Уведомления» через `PartnerConnection` (type='chatBot', status active/trial), как в ТЗ.
- Экран: без партнёра — промо-карточка «Чат не подключён» + кнопка «Подключить чат» (ссылка на
  `/biz/notifications/channels`); с партнёром — история переписки (пустое состояние отдельно), поле
  ответа, прикрепление файла (`<input type="file">`, показывает имя), отправка, ссылка «Открыть карточку
  клиента», кнопка демо «Получить входящее сообщение» — для проверки без реального партнёра.
- i18n: `messages/en/notify.json`, `messages/ru/notify.json` → `bookingWindow.chat.*` (hy не трогаю — по
  правилу §0.4 сейчас только en+ru).

Живой прогон (`scripts/measure.mjs` со сценарием): клик «Демо: получить входящее сообщение» →
сообщение появилось слева; ввёл ответ, отправил → сообщение справа, оба с временем, поле очистилось.
0 ошибок консоли на всех прогонах.

### F-05-086 · Кнопки «Написать»: WhatsApp, Viber, Telegram — построено `journal`

Гап был устаревшим: `src/areas/journal/components/booking-window/ClientZone.tsx` уже содержит
`MessengerLinks` (F-01-068) — все три значка, ссылки по номеру (`wa.me`, `viber://chat`, `t.me`),
рендерится, как только найден `matchedClient` (до сохранения записи — сразу после выбора клиента по
телефону), гейт `!digits → return null` закрывает «без телефона — кнопок нет». Все три пункта «Готово,
когда» F-05-086 выполнены кодом соседнего раздела — прочитал файл целиком, live не перепроверял (правка
не моя, файл не в путях notify).

### F-05-114 · Права для чата и мессенджеров из записи — построено `journal`+`clients`

В окне записи (`ClientZone.tsx`) кнопки гейтятся `windowRights.showPhones` (`src/areas/journal/lib/rights.ts`)
— именно то, чего не хватало в прошлом отчёте («в окне записи этих кнопок нет»); в карточке клиента —
`useClientsRights().bookingWindowClientData`/`contactsInCard` (`src/areas/clients/lib/rights.ts`, право
F-04-201/202). Обе точки входа (окно записи и карточка) теперь имеют свой контроль прав.

### F-05-088 · Уведомления о входящих сообщениях чата и автосохранение лидов — построено `journal`+`clients`

`src/areas/journal/JournalSettingsScreen.tsx` (`ChatSection`, F-01-165/166) уже полностью рабочий: тумблер
«демо-подключение», тумблер попапа, тумблер автосохранения лидов (дёргает `getAutoSaveChatLeads`/
`setAutoSaveChatLeads` из `@/api/clients`), кнопка «Симулировать» — создаёт лида через `simulateChatLead`
(clients), показывает попап снизу слева со ссылкой на карточку клиента (`/biz/clients/{id}?tab=calls`),
исчезает через 4с. Оба пункта «Готово, когда» F-05-088 выполнены — прочитал файл целиком (чужой, не
трогал).
