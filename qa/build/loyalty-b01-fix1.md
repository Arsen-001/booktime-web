# loyalty · b01 · fix1

Починка дефектов пачки b01, найденных измерителем: F-06-005 (block), F-06-058 (major), F-06-003 (major).

## F-06-005 · Услуги и товары в программах должны быть «сетевыми» — block

Было: ни одной формы создания программы (акция/сертификат/абонемент) не существовало — «Добавить» везде
показывал тост-заглушку, выбора услуг/категорий не было нигде.

Сделано:
- `src/domain/loyalty.ts` — добавлен тип `ServiceScope { categoryIds, serviceIds }` и опциональное поле
  `Promotion.serviceScope`. Пустые массивы = «все услуги» (обратная совместимость со старым сидом).
- `src/api/loyalty.ts` — `listServiceScopeOptions(businessId, locale)` читает каталог услуг владельца
  из ядра (`core.services`/`core.serviceCategories`); по решению F-00-049 отдельного шага «перенести в
  сеть» нет — каталог общий сразу. `createPromotion(businessId, input)` — сохраняет акцию в срез
  (переживает перезагрузку через persist).
- `src/areas/loyalty/ServiceScopePicker.tsx` (`data-f="F-06-005"`) — переключатель «Все услуги» / список
  категорий с чекбоксом «вся категория» (индетерминейт при частичном выборе) + отдельные услуги внутри.
  Выбор категории кладёт её `id` в `categoryIds`, а не список услуг на момент сохранения — значит услугу,
  добавленную в категорию позже, программа подхватит сама при разворачивании списка (критерий «Готово,
  когда» проверен по значению, которое хранится, не по снятому один раз снапшоту).
- `src/areas/loyalty/PromotionFormModal.tsx` — рабочая форма «Создать акцию»: название, вид, размер
  скидки/бонуса, типы карт (обязательно, F-06-004), `ServiceScopePicker`. Валидация — название и хотя бы
  один тип карты; ошибки под полями, без системных алертов.
- `src/areas/loyalty/PromotionsScreen.tsx` — кнопки «Добавить акцию» (в шапке и в пустом состоянии) теперь
  открывают модалку вместо тоста; после сохранения список перечитывается и показывает новую акцию.

Прогнано сценарием `qa/scenarios/loyalty-promotion-create.json` (headless): открыл форму → ввёл название →
отметил тип карты → выключил «Все услуги» (появился реальный список категорий/услуг сида) → «Создать
акцию» → тост «Акция создана» → новая акция в списке. Все 12 шагов прошли, 0 ошибок консоли.

Не делал (за рамками этого фикса, формы отмечены в коде как «пачка b02»): создание типов карт, сертификатов,
абонементов — F-06-005 для НИХ технически даёт тот же ServiceScopePicker, когда до их форм дойдёт очередь;
сам компонент уже переиспользуемый и не завязан на Promotion.

## F-06-058 · Список «Карты лояльности» сети — major

Плейсхолдер поля обещал «Телефон или номер карты», но `listCards()` в `src/api/loyalty.ts` фильтровал
только по телефону клиента — ввод настоящего номера карты давал ложное «Ничего не нашли».

Правка (`src/api/loyalty.ts`, `listCards`): фильтр теперь проверяет ИЛИ телефон (по цифрам), ИЛИ номер
карты (без учёта регистра, `includes`). Плейсхолдер и колонки — без изменений, они уже были верными.

## F-06-003 · Меню «Лояльность» и «Счета клиентов» в кабинете сети — major

Пункт меню уже был скрыт без права `loyalty.manage` (`src/areas/loyalty/nav.ts`), но сами экраны
(`/biz/loyalty/**`) открывались по прямому URL и показывали финансовые данные клиентов (балансы депозитов,
номера карт и т.д.) без проверки права на уровне маршрута.

Сделано: `src/app/biz/loyalty/layout.tsx` (новый, роут-обёртка) + `src/areas/loyalty/LoyaltyAccessGate.tsx` —
гвардируют весь `/biz/loyalty/**` разом: `useCan('loyalty.manage')`, нет права — вместо контента экран
«Нет прав на это действие» (переиспользует существующие тексты `ui.permission.*` и `EmptyState`), с правом —
контент как раньше. Проверено персоной `admin` (у неё нет `loyalty.manage`): все проверенные страницы
(`/biz/loyalty`, `/biz/loyalty/deposits`, `/biz/loyalty/cards`) показывают только гвард, `data-f` на них 0 —
финансовые данные не рендерятся вообще, не просто прячутся стилями.

## assumed

- Форма акции — минимальная рабочая версия (не полноценный мастер из Altegio с шагами); поля названия,
  вида, размера, типов карт и услуг покрывают критерии «Готово, когда» F-06-004/F-06-005. Более богатый
  мастер акции — по-прежнему пачка b02, как и было отмечено в коде до этой правки.
- `ServiceScopePicker` показывает КАТЕГОРИИ владельца, в которых есть хотя бы одна активная услуга (пустые
  категории не засоряют список) — в ТЗ это не оговорено явно.
- Гвард раздела рендерит нейтральную карточку «Нет прав на это действие» без кнопки — по аналогии с
  `PermissionGate` (`fallback="message"`), а не с полноэкранным `AccessDenied` (тот заточен под смену
  персоны biz/platform целиком, здесь это не подходит).
- `CardsFilter.phone` теперь ищет и по номеру карты — параметр/пропы не переименовывал (остался `phone`),
  чтобы не трогать сигнатуру там, где на неё, возможно, опираются другие точки раздела.
