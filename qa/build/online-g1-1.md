# online-g1-1 · Сборка по пропускам (25.09.2026)

## Что сделано

Из-за очень ограниченного бюджета этого захода (экономная модель, общий лимит токенов) успел
закрыть только блок «нарушения наших решений» — он был сформулирован конкретнее всего и выше
по цене ошибки (приватность). Ни один из 30 пунктов из списка проверяющего (F-03-036…F-03-024)
не тронут — см. `partial`.

### Нарушения наших решений — исправлено

1. **F-00-077 / F-00-010 — точный домашний адрес мастера уезжал наружу.**
   `getPublicBusinessData` (`src/api/online.ts`) отдавал `Staff` целиком в списке для публичной
   страницы /b/[slug] — `homeAddress`, `login` администратора и `callHours` были видны в сетевом
   ответе (devtools → Network → response), даже если ни один экран их не рендерил напрямую.
   Добавлена `sanitizePublicStaff()`, срезающая эти поля перед возвратом; `homeDistrict` (только
   район) остаётся — по решению это можно видеть до записи.

2. **F-00-080 — адрес клиента на выезд видели все с `online.manage`, а не мастер записи.**
   `listOnlineRequests()` получил параметр `viewerStaffId`: точный адрес (`address`) отдаётся,
   только если запись принадлежит именно этому мастеру; иначе — только район, как остальным.
   `RequestsScreen.tsx` передаёт свой `staffId` этим параметром и на всякий случай дублирует
   проверку в рендере (`r.staffId === staffId`) — двойной пояс, но источник (API) теперь не
   отдаёт лишнего в принципе, а не только прячет в вёрстке. Добавлен ключ
   `requests.addressHiddenOtherStaff` (ru/en).

3. **CONVENTIONS §0.3 / F-00-067 — необратимое «Отклонить» без подтверждения.**
   `RequestsScreen.tsx`: клик «Отклонить» теперь спрашивает через `useConfirm()` (наш
   `ConfirmDialog`, tone `danger`) с текстом «Отклонить заявку? Клиент увидит, что запись
   отклонена, и ему придётся записываться заново — отменить это действие нельзя»; «Подтвердить»
   не трогал — оно не разрушительное. Проверено сценарием `measure.mjs` (скриншот диалога).

### Не тронуто (нашёл, но не успел)

- **F-00-065** («Только мои клиенты» полностью скрыт) — самая крупная из нарушений: чтобы сделать
  по решению (свои клиенты видят окна и бронируют сами, чужие подают заявку), нужно опознавание
  «это мой клиент» в `BookingWizard` (сверка по телефону/демо-персоне) и отдельная ветка UI —
  это не точечная правка, а фича на несколько экранов. Не начинал.
- **F-00-120 / Снято №11** (обещание SMS-напоминания «за N минут» в веб-записи, хотя канал только
  пуш) и **F-00-145** (minor: «Питомец» в «Для кого» у сферы маникюра) — не смотрел файлы.
- Цвет по умолчанию `#060f07` вместо токена `primary` (`mock/slices/online.ts:82,168`,
  `LinkSettingsScreen.tsx:536`) — не трогал.
