## Что построено

Новые экраны и маршруты:
- `/biz/network/services/categories/[categoryId]` — форма сетевой категории услуг (создание/правка)
- `/biz/network/services/[serviceId]` — форма сетевой услуги (создание/правка, запреты цены/описания)
- `/biz/network/services/migration` — расширена: выбор строк, «Добавить/Удалить из филиалов»,
  «Синхронизировать» (с предпросмотром, откуда уберётся), «Объединить»
- `/biz/network/services` — расширена: «Добавить категорию», раздел «Пакеты услуг» + окно создания пакета
- `/biz/network/staff/new`, `/biz/network/staff/[staffId]` — форма сетевого сотрудника + увольнение/удаление/восстановление
- `/biz/network/staff` — расширена: перетаскивание порядка (@dnd-kit), значок «Сеть» у сотрудника в 2+ филиалах,
  ссылки на должности/нерабочие дни/зарплаты/миграцию
- `/biz/network/staff/positions` — сетевые должности (список + окно формы: требования, «Только в сети»,
  филиалы, услуги должности)
- `/biz/network/staff/off-days` — типы нерабочих дней (системные + свои, цвет-токен, филиалы)
- `/biz/network/staff/payroll` — запуск расчёта по периоду и филиалам + история запусков
- `/biz/network/staff/migration` — перенос сотрудников филиала в сеть («Перенести всех»/выбранных) + объединение
- `/biz/network/goods/categories/[categoryId]` — форма сетевой категории товаров (+ вкладка «Филиалы»)
- `/biz/network/goods/[productId]` — форма сетевого товара (создание через `stockApi.createGood` +
  `copyGoodToLocationsNetworked`, F-08-135)
- `/biz/network/goods` — расширена: ссылка на новый товар, «Добавить все товары в филиал», архивирование выбранных
- `/biz/network/goods/migration` — перенос категорий/товаров филиала в сеть + объединение с сетевым
- `/biz/network/goods/archive` — архив («Восстановить» только если товар остался сетевым, иначе подсказка)
- `/biz/network/goods/stock` — таблица остатков сетевого товара по филиалам (через `stockApi.computeLevels`)

Новый общий компонент `src/areas/network/lib/LocationsPicker.tsx` (чеклист филиалов с «Выбрать все/Снять все») —
переиспользован во всех формах пачки.

Домен/API/срез: `src/domain/network.ts` (+`NetworkServiceLock`, `NetworkPosition`, `NetworkOffDayType`,
`NetworkPayrollRun`, `NetworkGoodsArchiveEntry`), `src/mock/slices/network.ts` (версия 4, сид системных типов
нерабочих дней), `src/api/network.ts` (+~35 функций).

## Архитектурная правка по ходу работы

Первая версия всех write-функций пачки оборачивала `await coreCreate/coreUpdate/coreRemove` внутри собственного
`request(async () => {...})` — нарушение arch-a1 («внутри без await coreCreate/updateBooking»). Нашла это не
измерением, а собственной проверкой на живых данных (создание категории не появлялось в списке сразу после
сохранения). Переписала все ~19 функций на плоскую последовательность отдельных `request()`-вызовов (как в
уже готовых `addLocationToNetwork`/`reorderNetworkLocations` b01). Проверено заново Playwright-пробой (создание
категории услуг, услуги, сотрудника, категории и товара склада — каждое видно сразу в списке в той же сессии).

## Проверено вживую (не только измерением)

Playwright-пробой (не сохранён в репозитории — разовый скрипт, результаты см. ниже):
- сетевая категория услуг создаётся, видна в списке сразу после сохранения (SPA-переход, без reload);
- сетевой сотрудник создаётся с 2 филиалами;
- сетевая категория товаров и сетевой товар создаются (`stockApi.createGood` + раздача по филиалам).
- Переживание **настоящей перезагрузки страницы** — не проверяется положительно: это тот же
  общий баг `localStorage`-квоты (`QuotaExceededError`), что уже подтверждён 7 разделами в своих
  `qa/requests/*.md` (включая network b01-fix1/fix2) — не мой путь, чужой файл `src/mock/db.ts`.
