  стоит дописать, если повторится в другом разделе.

  (кириллица остаётся `%D0%B0...`) — раньше Next декодировал сам. Добавил `decodeURIComponent` в `page.tsx`.
  Записал в `qa/requests/integrations.md` — грабля общая для любого раздела с не-ASCII в динамическом сегменте.

  не настоящие бренды-конкуренты один в один), цены — правдоподобные для рынка Армении. Разбивка по категориям:
  notifications 7, telephony 4, marketing 5, social 4, widgets 4, analytics 3, accounting 3, maps 2, payments 2,
  fiscal 1, other 2, chatbots 2 (скрытая), tips 1 (скрытая) = 40.
- «Скрытые категории» (chatbots, tips) не показываются в чипах/обзоре — открываются только прямым адресом
  `/biz/integrations/category/chatbots` (по описанию F-13-004); заходил и проверял руками.
- «Системный пользователь» при активации (F-13-018) — храню только `systemUserId` (синтетический) в своём
  `AppInstall`; настоящая запись в `staff.systemUsers` требует функции записи в чужом API — оставил просьбу
  (F-13-019 не в списке этой пачки).
- Лист подключения — не буквальный «степпер по шагам», а один Sheet с тремя секциями (Разрешения / Филиалы /
  Регистрация) друг под другом: короче по кликам, тот же набор полей и тот же порядок, что в плане; учёл правило
  §0 «длинные формы — по шагам ИЛИ секциями», здесь секций хватает (3 коротких блока, не 30 полей).
- Прямая ссылка `mp_<номер>_<имя>` — «имя» получается из кириллического названия (slug на кириллице:
  `mp_1_арм-смс-шлюз»`), а не транслитерацией на латиницу — решил, что это нормально для рынка с русскими
  названиями (сам URL корректно работает, браузер percent-encode делает сам).
- API `getAppByCode` не различает «неверный код» и «код есть, но 4xx от бэкенда» — оба случая ведут в один
  `EmptyState` «Ссылка не найдена» без кнопки «Повторить» (это осознанное решение — «не найдено» не ретраится),
  а не забытый `ErrorState`.
