- Тип записи для «Запись/Событие» (F-01-025) — по функции сферы, без настройки (решение из b01, не менялось).

  `paidAmount`), поэтому «Наличными» = все поступления, «Безналом» и «Лояльность» = 0 до раздела «Финансы».
- Пакет: только 2 режима — «параллельно» (разные мастера) и «последовательно одним мастером» — по самой ТЗ,
  «последовательно несколькими мастерами» противоречиво даже в источнике Altegio (F-01-134).
- Перенос пакета (F-01-113) двигает связанные записи на разницу МИНУТ в пределах суток (не учитывает перенос
  на другую дату целиком) — типовой случай «подвинуть на 15 минут» работает, редкий «перенести на завтра
  вместе с пакетом» — нет.
- Импорт/выгрузка Excel — без файла: текстовое поле «вставьте строки» вместо `.xlsx` (в проекте нет библиотеки
  парсинга таблиц — не ставлю npm-пакет сам, заявка в requests).
- История изменений (F-01-096) хранит короткую сводку (время + «К оплате»), а не полный дифф всех полей — ради
  скорости показа; события создания/сохранения фиксируются, у записей из сида (созданных до этой пачки) истории
  нет — это ожидаемо, не баг.
- Импорт кладёт визиты в первую активную локацию текущего пользователя, мастера выбирает первого из списка
  бизнеса (без ID/имени сотрудника в разборе строки — упрощение демо-формата).
