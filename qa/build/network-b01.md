# Отчёт сборщика — network, пачка b01

Каркас кабинета сети, переключатель, управление сетью и главные экраны-списки. 16 маршрутов, 16 экранов,
типы/срез/api раздела, nav.ts, ru/en тексты.

## Что построено

- Ядро: сеть (`Network`) и филиалы (`Business`/`Location`) читаются и пишутся через generic
  `coreList/coreGet/coreCreate/coreUpdate` (arch-a1) — не пришлось просить фундамент под сами сущности.
  Своим срезом (`src/mock/slices/network.ts`) закрыла то, чего в ядре нет: порядок филиалов, мягкое удаление
  сети, демо-срок подписки филиала, пользователей сети, планы, подразделения, телефонию.
- `ensureNetwork()`: у любого бизнеса без сети она создаётся сама при первом заходе в `/biz/network`, из его
  единственной локации (F-11-001) — без раздутия ядра лишними сидами.
- Экраны: обзор, переключатель, создание сети, управление сетью (название, филиалы с drag&drop через
  @dnd-kit, главный филиал, выход филиала, удаление/восстановление по прямой ссылке `?net=`), пользователи,
  планы (таблица «филиал × месяц», автосохранение по blur), доп. поля (каркас с двумя вкладками), сводная
  аналитика (6 плиток, период, дельта к прошлому периоду той же длины, подсказка-формула у каждой), записи
  сети (фильтры: филиал / отменённые / онлайн), клиентская база сети (склейка по телефону, число локаций),
  сотрудники сети (фильтры по должности/статусу/увольнению), услуги сети (категории со счётчиком), подразделения
  (создание), миграция услуг (обзорная таблица по реальным данным), товары сети (категории + поиск по реальному
  складу филиалов), телефония (токен, копирование, подключение).
- У каждого экрана: skeleton-загрузка, `ErrorState` с повтором, `EmptyState` с иконкой и фразой (и «Сбросить
  фильтры» у поиска/фильтра), наши `ConfirmDialog`/`Modal`/`Toast` — никаких `alert/confirm/<select>`.
- `data-f` — на корневой узел каждой из 29 функций пачки (несколько функций на одном экране размечены
  раздельно).
- ru/en тексты — все строки через `useT('network')`, hy не трогала (§0.4: пока выключен, не пишем и не
  проверяем).

  оригинальный текст про «права на объединение» в ТЗ помечен ❓ (не сохранён при обходе Altegio) — текст

- **F-11-077** (планы) — ввод и автосохранение по каждой ячейке «филиал × месяц» работает и переживает

- **F-11-079** (сетевые категории услуг) — список и счётчик услуг настоящие (из core.serviceCategories/

  филиале» — вывод, а не настоящий флаг «создана в сети», потому что раздача сетевых категорий по филиалам

  в `qa/requests/network.md`, чтобы b03 не удивился.
- **F-11-087** (миграция услуг) — таблица «услуга × филиалы» построена на реальных данных и корректно
  показывает наличие. Кнопки «Настроить в локациях» / «Объединить услуги» не сделаны — само распределение
  и объединение услуг между филиалами это b03; ставить недоделанные кнопки, которые ничего не делают, было
  бы хуже, чем не ставить (§0 «никаких мёртвых кнопок»).

## assumed (додумано)

- Цветовая подсветка меню «жёлтый — локация / фиолетовый — сеть» (справка Altegio) — не строила: тема меню
  задаёт фундамент (`src/shell/biz`), а не раздел; различие кабинета сети сейчас — через заголовок «Сеть
  <имя>» и полностью отдельное меню (это тоже соответствует F-11-001 «цвет ИЛИ шапка»).
- Срок подписки филиала в переключателе — в проекте нет модели биллинга филиала; сделала демо-срок в своём
  срезе (детерминированно от индекса бизнеса), подробности — в `qa/requests/network.md`.
- «Пользователи сети» (F-11-024) — список и карточка построены на реальных данных, но раздача 71 права и
  приглашение нового пользователя — не в этой пачке (план относит это к b04); сейчас у сети всегда один
  пользователь-владелец с полными правами (соответствует Altegio: «владелец автоматически стоит в списке со
  всеми правами»).
- «Сеть» = `Network` ядра целиком, без переноса `Business.networkId` для одиночных салонов — чтобы не задеть
  чужие предположения о том, что `networkId` означает «филиал многофилиальной сети» (искала использование
  этого поля в других разделах перед решением).
- Прямой URL `/biz/network` не режется по праву на уровне страницы (только пункт меню скрыт) — проверила,
  это общий паттерн приложения (staff/payroll так же), не придумывала свой; записала как вопрос фундаменту
  в `qa/requests/network.md`, сама не чинила в одиночку.
- Отчёт «Записи» сети (F-11-075) без кнопок «изменить»/«удалить» у строки — в ТЗ сам составитель пометил ❓
  «открывают ли они окно записи локации прямо из сети»; вместо мёртвых кнопок ничего не поставила.
