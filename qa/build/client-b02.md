# client — пачка b02: запись клиентом и «Мои записи»

Собрано 25.09.2026. Экраны: `/book` (переработан из b01), `/bookings`, `/bookings/[bookingId]`,
`/bookings/[bookingId]/reschedule` (все три — новые). Плюс дополнения на уже построенных экранах
b01: `/masters/[staffId]` (кнопка «Сообщить, если освободится» + модалка листа ожидания) и
`/places/[businessId]` (кнопка «Записаться» и блок «Мои записи здесь»).

## Поток записи (`/book`)

Полностью переписан под порядок F-00-092: **услуга → окно → оттенок → для кого/комментарий → вход →
подтверждение**, шагами через `Stepper` (`src/ui/Stepper.tsx`). Шаг пропускается, если параметр уже
пришёл с предыдущего экрана (клик по ближайшему окну на карточке мастера даёт готовые `staff+slot` —
шаг «окно» не показывается вовсе, F-00-004 «запись за секунды»). «Для кого» и комментарий сведены на
один экран с подтверждением/входом, а не в отдельный шаг — иначе для постоянного клиента с уже
известным окном запись раздувалась бы на лишний шаг сверх цели «в несколько нажатий».

Новое:
- Шаг «Оттенок» (F-00-094…096): палитра — `Service.materials`, статусы «в наличии» / «под заказ,
  через N дней» / «нет», плюс «мастер подберёт» и «принесу свой». Обязательность (F-00-095) —
  `required`/`preferred` из своего черновика; при недостижимом обязательном оттенке — предупреждение
  и явная альтернатива (не сдвигать шаг, а показать текст «выбрать другой / перенести / отменить без
  штрафа» непосредственно на месте, так как перенос/отмена доступны только у уже созданной записи).
- Шаг «Для кого» (F-00-125): я / ребёнок / питомец, имя для не-себя.
- Повторная проверка окна перед созданием записи (`computeFreeSlots` внутри `bookAppointment`) —
  «окно уже заняли» (часть F-00-092) кидает `slot_taken`, экран показывает тост с понятным текстом.
- Источник записи (F-00-093) — `source: 'app'`, уже был в ядре, теперь виден в деталях записи.
- Ручная предоплата (F-00-097): если у мастера есть `PrepaymentPolicy` (черновик своего среза, см.
  `qa/requests/client.md`), запись создаётся со статусом `awaiting_prepayment` и дедлайном; не оплатил
  вовремя — `listMyBookings`/`getBooking` сами переводят её в `cancelled_by_client` при следующем чтении
  (без фонового таймера, что соответствует «моковый бэкенд в браузере»).

## «Мои записи» (`/bookings`)

Три вкладки (F-14-011): предстоящие / прошедшие / отменённые, счётчик на вкладке «Предстоящие».
Каждая карточка — общий `BookingCard` (переиспользуется и на карточке места). Отдельная секция «Мой
лист ожидания» (F-00-102) с удалением записи и меткой «Окно освободилось!», когда `notifyWaitlist()`
пометила совпадающую запись после чужой отмены/переноса. Гость видит `EmptyState` со входом
(записи привязаны к номеру телефона).

## Детали записи (`/bookings/[bookingId]`)

- Подтверждение клиентом (F-14-057) — кнопка видна только в статусах, ждущих подтверждения.
- Перенос (F-00-099/F-14-016) — отдельный экран `/reschedule`: окна того же мастера/услуги тем же
  `SlotPicker`, один клик переносит и возвращает на карточку записи.
- Отмена (F-00-098/F-14-015) — `ConfirmDialog` с текстом, который зависит от того, прошёл ли срок
  бесплатной отмены (`freeCancelUntil = start − cancelWindowHours`); отмена позже срока пишет статус
  `no_show`, а не `cancelled_by_client` — ровно то, что требует «Готово, когда».
- Ручная предоплата (F-00-097): реквизиты, копирование, таймер до дедлайна, «Я оплатил».
- Групповое событие (F-14-023/017): цена за место × число мест, каждая запись на своё событие —
  отдельная карточка со своими кнопками отмены/переноса (общих полей с другими записями серии нет).
- «Повторить»/«Записаться снова» (F-00-118/F-14-012) — на прошедшей и отменённой записи, ведёт в
  `/book` с тем же мастером и услугой.
- Отмена мастером (F-00-100) — статус и бейдж видны клиенту, «Повторить» заменяет «выбрать другое
  время у того же мастера». Пуш с той же кнопкой — за разделом `notify` (не построен, вне b02).

## Каталог места (`/places/[businessId]`)

## Лист ожидания на карточке мастера (`/masters/[staffId]`)

Кнопка «Сообщить, если освободится» (F-00-102) открывает модалку: услуга, «любой день» / конкретная
дата. `notifyWaitlist()` вызывается при отмене (`cancelBookingByClient`) и переносе
(`rescheduleBookingByClient`) клиентом — F-00-101 «освободившееся окно» в части листа ожидания.

## Найденный и исправленный баг

Выбор другой услуги на шаге «Услуга» сбрасывал уже выбранное окно (`setSlotStart(undefined)`)
безусловно — включая случай, когда шага «Окно» в потоке вообще нет (окно пришло заранее с карточки
мастера). Экран подтверждения тогда рендерил пустую секцию без кнопки «Подтвердить запись» — гонка
без ошибок в консоли, поймана Playwright-сценарием (`client-b02-book-flow.json`, шаг 6 падал на
несуществующем поле формы). Исправлено: сброс — только если шаг «Окно» есть в потоке.

## assumed (додумано, решения в ТЗ нет)

- Порядок предложил ⭐-но-неявный: «для кого» и комментарий — на экране подтверждения, а не отдельным
  шагом (обоснование — «запись за секунды», см. выше).
- `ShadeOption.availability` для «под заказ» — каждый третий материал услуги, ETA `2 + (i % 4)` дней;
  реального склада ещё нет ни у одной услуги в сиде.
- `cancelWindowHours` — 2/3/4/6/12/24 часа по кругу демо-мастеров; `PrepaymentPolicy` — каждый 4-й
  мастер, 3 000–7 000 ֏, 15 минут. Оба — временные числа до настоящих настроек (см.
  `qa/requests/client.md`).
- «Записаться» с карточки места (F-14-029) открывает `/book` первого мастера места, у которого есть
  услуги — черновик до решения о «основной ссылке онлайн-записи» одного места.
- Подтверждение прихода (F-14-057) доступно в статусах `awaiting_confirmation`/`scheduled` — в ТЗ
  явного списка статусов нет, взял по смыслу «отправляется, только если статус "Ожидание клиента"».
