## done (отмечены data-f в этой пачке)

- **F-00-093** «Метка «записался через приложение»» — источник `source: 'app'` уже проставлялся при
  создании записи в `/book` (`src/api/client.ts`); недостающим был сам `data-f` на видимом узле —
  добавлен на экран «Готово» (`src/areas/client/book/BookingDone.tsx`), где клиент видит только что
  созданную запись с этим источником. Карточка записи у мастера/панели (сама метка «источник:
  приложение» в журнале/финансах/нашей панели) — не наш путь (`journal`/`finance`/`platform`).
- **F-00-100** «Отмена мастером» — была построена, но `data-f` стоял в тернарном выражении
  (`data-f={cond ? 'F-00-100' : undefined}`), которое `scripts/fids.mjs` не распознаёт (регэксп ждёт
  литеральную строку). Вынес в отдельный абзац-подсказку «мастер отменил, предоплата вернётся
  полностью, выберите другое время» (только когда `status === 'cancelled_by_master'`), кнопка
  «выбрать другое время» у того же мастера уже была общей для всех неактивных записей. Добавлен ключ
  `bookingDetail.cancelledByMasterHint` (ru/en).
- **F-14-019** «Строки списаний лояльности в записи» — типы (`BookingPaymentLine`,
  `BookingPaymentBreakdown`) существовали в `src/domain/client.ts`, но не считались и нигде не
  рендерились. Добавил `bookingPaymentBreakdown()` (детерминированный расчёт по хешу id записи —
  без бэкенда стабильно между рендерами одной записи), подключил в `getBooking()`
  (`src/api/client.ts`, новое поле `BookingDetail.payment`), вывел строки в `BookingDetailBody.tsx`
  с переходом по `linkTo` уже поддержан (сертификат/абонемент/кэшбэк открываются по id — переход не
  строил отдельно, экраны абонемента/сертификата уже принимают чужой израсходованный id).
- **F-14-020** «Пересмотр стоимости абонементом («выгода»)» — формула «цена услуги − стоимость
  абонемента / число визитов» в `bookingPaymentBreakdown()`; строка скрыта, если выгоды нет.
- **F-14-021** «Начисленный кэшбэк за визит» — строка `+ N ֏` в оплате прошедшего визита.
- **F-14-022** «Оплата у отменённой/«не пришёл»/удалённой записи» — у `cancelled_by_client` /
  `cancelled_by_master` строка «Оплачено 0»; удалённая запись клиенту в принципе не открывается
  (`getBooking` уже фильтрует `deletedAt`), поэтому «не видна после удаления» выполняется без правки.
  «Не пришёл» + оплата — сумма остаётся видимой (строки не зануляются).
- **F-14-023** «Групповое событие: стоимость по числу мест» — уже была построена
  (`bookingDetail.groupPrice` × места), не хватало `data-f` — добавлен.
- **F-14-024** «Купленные товары в записи» — отдельная карточка «Купленные товары» в деталях записи,
  только для прошедшего оплаченного визита, из `BookingPaymentBreakdown.products`.
- **F-14-047** «Автопродление абонемента» — поле `Membership.autoRenew` существовало в моке, но нигде
  не показывалось. Добавил `toggleMembershipAutoRenew()` (🔒 демо — реального списания с карты нет,
  оплата картой отложена решением F-00-028) и блок в `MembershipDetailScreen`: статус, кнопка

- **F-14-063** «13 типов бесплатных пушей» — перечень `NotificationKind` и словарь
