# Пачка b01 «Онлайн-запись» — исправление дефектов (fix2)

Собрано 25.09.2026. Правки трёх дефектов, найденных измерителем на пачке b01.

## Что исправлено

### F-03-088 (major) — вложенные `<label>` ломали клик по строке услуги

`src/ui/Checkbox.tsx` (фундамент) уже сам рендерит `<label htmlFor=…>` вокруг флажка. В
`ServicesStep` (`src/areas/online/booking/BookingWizard.tsx`) этот `Checkbox` был обёрнут ещё в один
`<label>` — браузер не активирует вложенный `<label>` кликом по внешнему, поэтому срабатывал только
клик точно по квадрату 20×20, хотя `min-h-16 cursor-pointer` визуально обещал всю строку.

Правка: внешний `<label>` заменён на `<div onClick={() => onToggle(s.id)}>`; клик по самому
чекбоксу останавливает всплытие (`stopPropagation`), чтобы не переключалось дважды. Чекбоксу добавлен
`aria-label` с названием услуги (раньше у него не было доступного имени вообще).

Проверено сценарием `measure.mjs` на `/b/nuri-nail-studio/book`: клик по тексту «Маникюр
классический» отмечает чекбокс, кнопка внизу переходит в «Продолжить · 1» — 0 ошибок консоли.

### F-03-027 (minor) — двойной знак продукта в подвале

`src/app/b/[slug]/layout.tsx` (наш файл) рендерил `PoweredByMark` («Работает на Azat») поверх
собственного `<footer>Azat</footer>` фундамента (`src/shell/public/PublicShell.tsx`, `src/shell/**` —
общий путь, сами не правим). На каждом экране `/b/[slug]/**` было два одинаковых знака подряд.

Правка: убрали свой рендер из `layout.tsx`, оставили один знак — из `PublicShell`. Подано в
`qa/requests/online.md`: `PublicShell` сейчас выводит голый текст без ссылки, а по ТЗ («проверкой 1»)
слово должно быть подчёркнутой ссылкой — просьба дать `PublicShell` слот/проп либо самому стать
ссылкой; `PoweredByMark.tsx` (готовый вариант со ссылкой и i18n) оставлен в дереве раздела, подключится
сразу, когда просьба будет закрыта. До этого «Готово, когда» (сам факт показа знака) закрыт частично —
знак виден один раз, но не как ссылка.

### F-03-009 (minor) — копирование ссылки падало без Clipboard-разрешения

`navigator.clipboard.writeText` без выданного разрешения (headless-браузер, страница без фокуса,
часть версий Safari) всегда уходит в `catch` — кнопка «Копировать» в `LinkCard.tsx` не копировала и не
давала способа подтвердить, что копирование вообще может сработать.

Правка: добавлен `src/areas/online/links/copyText.ts` — сначала пробует Clipboard API, при ошибке
или отсутствии API падает на `document.execCommand('copy')` через скрытый `textarea` (работает без
разрешения, синхронно из клика). `LinkCard.copy()` переписан на этот хелпер. Других мест с
`navigator.clipboard` в разделе online не найдено (адрес формы/скрипт копируются той же кнопкой).
