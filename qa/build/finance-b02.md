## Что построено

**Экран `/biz/finance/methods` (F-07-025)** — `src/areas/finance/MethodsScreen.tsx`:
- «Наличные» (F-07-026): касса по умолчанию + режим «всегда дефолтная / выбрать при оплате / недоступно».
- «Банковская карта» (F-07-027/028): общая комиссия или по брендам (Visa/Mastercard), касса, срок зачисления
  в календарных днях; для Армении — один карточный метод (по умолчанию `perBrand: false`).
- «Рассрочка» (F-07-029): тумблер + два плана (3 и 6 мес.) с комиссией каждого.
- «Свой способ оплаты» (F-07-030): добавление (имя + %), список с «Подключено/Отключено» и переключателем —
  реквизиты мастера для ручной предоплаты (Idram) заведены этим способом (⭐ F-00-097).
- «Кто платит комиссию банка в зарплате» (F-07-035): пять вариантов, читает `payroll` (не построен здесь).
- «Сохранить» сохраняет всё сразу и сразу действует на новые оплаты (старые не пересчитываются — F-07-025/033).
- Касса по умолчанию для быстрой оплаты (F-07-032) — не отдельная страница (в армянском кабинете её нет),
  как решено в `qa/plan/finance.md`: кассы методов из этого экрана и есть «кассы по умолчанию».

**Вклад в окно записи, вкладка «Оплата»** — `src/areas/finance/extensions/BookingWindow.tsx`
(хост `bookingWindow`, смотреть `/dev/ext/bookingWindow/finance`):
- Статус оплаты визита (F-07-045) с суммой к оплате/оплачено, у «Не пришёл» оплата скрыта.
- «Оплатить» переводит визит в «Клиент пришёл» при первой оплате (F-07-036) — через `changeBookingStatus`.
- Быстрая оплата (F-07-037) — плитки способов оплаты, один клик закрывает весь остаток.
- Раздельная (детализированная) оплата (F-07-038) — сумма по каждому способу, сумма ограничена остатком
  (решение по открытому вопросу спеки: сумма больше остатка не проходит, «безопасный вариант» по QUESTIONS.md).
- Оплата по строкам визита (F-07-181) — на каждую оплаченную строку отдельная финансовая операция с общим
  номером документа (как в примере CYCLE-07: «500 и 234, № …»); отмена одной не трогает другие.
- Итог и список платежей (F-07-039) — каждая строка со способом/суммой, комиссия эквайринга списывается
  отдельной операцией и привязывается к первой строке платежа (F-07-033/034, упрощённая связка «создание»,
  без полного пересчёта при правке исходной — см. partial).
- Подсказка «сначала лояльность/счета, потом деньги» (F-07-040) и скидка по акции строкой оплаты (F-07-041).
- Удаление (отмена) платежа (F-07-042) — корзина у строки, возвращает остаток, деньги со счёта клиента
  при отмене возвращаются на счёт.
- Детали оплаты (F-07-043) — ссылка «Открыть операцию»/«Распечатать чек» на страницу операции (b01).
- Примечание к оплате (F-07-047) — сохраняется и проставляется в поле «Комментарий» её операций.
- Личный счёт клиента (F-07-061) и оплата в долг (F-07-062) — ⭐ демо-минимум: баланс счёта, предупреждение
  и лимит долга 5000 ֏ (полные типы счетов и их лимиты — b03), долговая оплата помечена `debt: true` (красный
  бейдж «В долг» в списке платежей).

## assumed

- Разнесение частичной оплаты по строкам визита (F-07-181, открытый вопрос ТЗ) — «по порядку строк»: первая
  неоплаченная строка получает деньги первой. Записано в `allocateAmountToLines()` (`src/domain/finance.ts`).
- Сумма раздельной оплаты больше остатка — не принимается (кнопка выключена, сумма частей ограничена сверху
  видимым остатком); переплата/сдача не реализованы — соответствует «безопасному варианту» из QUESTIONS.md.
- Лимит долга по счёту клиента (F-07-062) — фиксированные 5000 ֏ на демо (`CLIENT_ACCOUNT_DEBT_LIMIT`), так
  как типов счетов с собственными лимитами (F-07-058) ещё нет — это b03.
- Комиссия эквайринга при раздельной/быстрой оплате считается от суммы КОНКРЕТНОГО платежа (не от всей суммы

- «Открыть операцию» — минимальная зона нажатия 44×44 + `Tooltip` вместо `title=` (общее правило 0.3).
- «Мобильное приложение для бизнеса» (F-07-049) — своего экрана нет, окно оплаты одно на оба масштаба.
- Своей странице «Настройки оплаты» (F-07-032) не быть — кассы по умолчанию только в «Методах оплаты»
  (решение уже в `qa/plan/finance.md`, не моё новое допущение).
