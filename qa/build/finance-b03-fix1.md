## Что сделано

### F-07-067 · Частичный возврат за услугу — **done**

Раньше на всё («полный» и «частичный» возврат) была одна кнопка «Полный возврат». Добавлена отдельная кнопка
«Частичный возврат» (иконка ↺, `data-f="F-07-067"`) у каждой денежной строки платежа визита
(`src/areas/finance/extensions/BookingWindow.tsx`) — открывает модалку с полями «Скидка» и «Сумма, которая
должна остаться оплаченной» (двусторонне синхронизированы — как требует ТЗ 174913), выбором способа повторной
оплаты и одной кнопкой «Оформить частичный возврат», которая сама выполняет три шага справки: отменяет старую
строку платежа → заводит скидку по акции на возвращённую часть (уже готовый `addBookingPromoDiscount`,
F-07-041) → проводит быструю оплату остатка выбранным способом (уже готовый `payBookingQuick`). После операции
в кассе остаётся только новая сумма, скидка видна в истории визита строкой «Скидка по акции».

### F-07-068 / F-07-069 / F-07-071 / F-07-072 · Возврат товара/абонемента/сертификата — **partial** (денежная часть done)

Общая причина всех четырёх: денежная сторона возврата — finance, а «куда» физически делся товар/остаток
посещений/баланс сертификата — домены `stock` и `loyalty`, не finance (путей туда нет, править чужое запрещено
правилом 1 `CONVENTIONS.md`). Построено:

- Новая функция `refundSaleOperation(businessId, operationId, { amount, mode, comment })`
  (`src/api/finance.ts`) — общий «Возврат» для операций-продаж по статьям `goodsSale` / `membershipSale` /
  `certificateSale`. Два варианта по справке 174913:
  - `cancel` (полный) — отменяет операцию целиком, касса дня **продажи** меняется задним числом;
  - `expense` (по умолчанию) — заводит отдельную расходную операцию статьёй «Возврат» **датой возврата**, сама
    продажа остаётся — касса дня продажи не искажается (F-07-072, вариант 2). Работает и частично (сумма меньше
    полной), копит `Operation.refundedAmount`.
- UI — кнопка «Возврат» в `/biz/finance/operations/[id]`
  (`src/areas/finance/operations/OperationDetailScreen.tsx`), видна только у непогашенных продаж этих трёх
  статей; `data-f` на кнопке и в модалке подставляется по контексту: `F-07-071` (абонемент), `F-07-072`
  (сертификат), `F-07-068` (товар с `refId` — продан в визите), `F-07-069` (товар без `refId` — вне визита).
- Демо-данные: в сид (`src/mock/slices/finance.ts`, version 5→6) добавлены 4 операции — товар в визите, товар
  вне визита, абонемент, сертификат — иначе функцию было не на чем показать (ни одной такой операции раньше не
  создавалось вообще, ни ручным вводом в сиде, ни из stock).
- Что осталось невыполненным из «Готово, когда» (домен не finance, см. `qa/requests/finance.md`, запись
  2026-09-26 «stock/loyalty: подключиться к общему возврату продажи»):
  - F-07-068: «товар вернулся на склад» — нет;
  - F-07-069: «товар... на склад» — нет («деньги из кассы» — есть);
  - F-07-071: «абонемент больше нельзя применить» / «остаток посещений обнулён» — нет (расход на сумму
    возврата — есть);
  - F-07-072: «сертификат с нулевым остатком не применяется» — нет; при этом первая строка критерия («при
    варианте 2 касса дня продажи не меняется, расход стоит датой возврата») **выполняется полностью** и
    проверяема на моках прямо сейчас.
