## Дефект 1 — F-08-050 — ПРОВЕРЕНО, уже не воспроизводится

Перечитал `src/areas/stock/operations/OperationDocScreen.tsx`: `save()` собирает `date` как
`dateVal && timeVal ? combine(dateVal, timeVal) : doc.date` — оба стейта (`dateVal`/`timeVal`) остаются
`null`, пока пользователь не трогает сами пикеры даты/времени; `DatePicker`/`TimePicker` вызывают
`onValueChange` только по явному выбору пользователя (руками проверил `src/ui/DatePicker.tsx`,
`src/ui/TimePicker.tsx` — нет автозапуска на маунте/ре-рендере). То есть в текущем коде правка одного
только комментария/чекбокса «Оплачено» не должна трогать время.

Перепроверил действием (Playwright, `?demo=owner&sphere=nails`, документ прихода № 100005,
`op_gd_loc_nuri_0_3_income`): открыл документ, время «19:49» → поправил комментарий → подождал 2.5 с
(имитация задержки измерителя) → «Сохранить изменения» → SPA-переход назад → открыл документ заново —
время осталось «19:49» (не «19:51»/подобное). То же для чекбокса «Оплачено» — время осталось «19:50».
Дефект не воспроизведён на текущем коде; похоже, был устранён по пути в одной из более ранних правок
раздела (fix1 его не касался — см. `qa/build/stock-b02-fix1.md`). Изменений в код не вносил — они бы
ничего не чинили и рисковали сломать рабочую логику.

## Дефект 2 — F-08-059 — ПОЧИНЕНО (`src/areas/stock/operations/MoveFormScreen.tsx`, `src/api/stock.ts`)

Корень был глубже одного текста тоста: форма показывала **суммарный остаток по всем складам**
(`good.totalStock`) как «Доступно», а не остаток НА выбранном складе-источнике — отсюда и ложное
ощущение, что операция пройдёт, и провокация ошибки при сохранении.

- `MoveFormScreen`: добавлен пересчёт остатка **по каждой строке на выбранном `fromId`**
  (`goodStockAt` из `@/api/stock`, эффект на смену `fromId`/строк) — «Доступно на складе: N» теперь
  показывает правду для текущего источника, а не сумму по складам; при недостатке строка подсвечивается
  красным (`Input invalid`) ещё ДО попытки сохранить.
- Автоподбор склада-источника: когда добавлен первый товар и пользователь ещё не выбирал «Со склада»
  сам (`fromTouched`), форма ищет склад, где товар реально лежит (`goodStockAt` по всем складам,
  берёт склад с наибольшим остатком), и переключает `fromId` на него — вместо жёсткого первого склада
  списка. Если пользователь выбрал склад руками — автоподбор больше не трогает выбор.
- `src/api/stock.ts` (`createMoveOperationMulti`, `createMoveOperation`): при `insufficient_stock`
  `ApiError` теперь несёт структурированные данные (`JSON.stringify({ goodName, warehouseName, available })`
  в `message`) — это защита на случай гонки/обхода клиентской проверки, а не основной путь.
- `MoveFormScreen.save()`: при поимке `insufficient_stock` показывает
  `t('moveForm.saveFailedInsufficient', { good, warehouse })` = «На складе «{warehouse}» нет товара
  «{good}»» вместо немого «Не удалось сохранить перемещение»; при неожиданном формате падает на прежний
  общий текст.
- Новый ключ `moveForm.saveFailedInsufficient` добавлен в `messages/ru/stock.json` и
  `messages/en/stock.json` (hy не трогал — по правилу 0.4 сейчас работаем только en+ru).

Проверено действием (Playwright, `?demo=owner&sphere=nails`, `/biz/stock/operations/new/move`):
- Добавил «Гель-лак «Розовый нюд»» без ручного выбора склада — «Со склада» сам переключился с
  «Расходники» (первый в списке) на «Товары» (где товар реально лежит), «Доступно на складе: 3 флак.»
  — верно.
- Довёл операцию до конца: выбрал «На склад» = «Расходники», «Переместить» → документ создан
  (`/biz/stock/operations/op_muh5ep1xy8civr`), 0 ошибок консоли.
- Отдельно проверил обратный сценарий: выбрал «Со склада» = «Расходники» руками (до добавления товара,
  трогая автоподбор), затем добавил тот же товар — «Доступно на складе: 0 флак.» видно сразу, поле
  количества подсвечено красным; клик «Переместить» блокируется клиентской проверкой количества (общий
  текст `qtyInvalid`, т.к. до сервера дело не доходит — сама возможность промаха теперь видна на экране
  до отправки, что и было целью замечания).
- Снимок телефона 390×844 (`Расходники` выбраны руками, товар без остатка) — красная рамка поля
  количества видна без скролла.

`MoveGoodsModal.tsx` (одиночное перемещение со страницы «Склады») уже показывал живой остаток на
складе-источнике через `goodStockAt` — не трогал, только добавил структурированные данные в
`ApiError('insufficient_stock', …)` в `createMoveOperation` для единообразия (модалка это не использует,
у неё превентивная проверка `qtyExceeds` раньше сабмита).
