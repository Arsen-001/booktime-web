# journal · b04 · fix1 — починка дефектов из измерения b04

Пачка b04 (сводка дня, «Продать», график из журнала, правая панель, несколько услуг и пакеты,
посетитель, список «Записи»). Ниже — починка 7 дефектов, найденных измерителем.

## done (все пункты «Готово, когда» выполняются)

- **F-01-010** — «Продать → Товар/Абонемент/Сертификат» теперь открывает продажу **во всплывающем
  окне внутри журнала**, а не уводит на `/biz/stock`/`/biz/loyalty` (оба «скоро появится»). Новое
  окно: выбор позиции из демо-каталога, количество и остаток для товара, код (с генератором) для
  абонемента/сертификата с проверкой `requiresCode`, способ оплаты, итог, подтверждение тостом. Без
  типов абонемента/сертификата — прежнее приглашение создать тип. Продажа списывает демо-остаток и
  пишется в новый журнал продаж (`quickSales` в срезе `journal`, переживает перезагрузку).
  Проверено сценарием: товар продан (тост «Продажа оформлена», остаток на складе уменьшился),
  абонемент без кода — кнопка «Продать» задизейблена с пояснением.
- **F-01-020** — в меню по имени сотрудника добавлены недостающие «Добавить рабочие дни» и «Удалить
  рабочие дни» (новый `WorkingDaysRangeModal.tsx`): диапазон дат + часы работы для добавления;
  удаление предупреждает о задетых записях (как уже было у «Отменить рабочий день») и не трогает
  сами записи. Пишет через `setCells()`/`deleteCells()` раздела schedule (свой срез не заводили).
- **F-01-128** — короткий/новый блок записи в сетке (⩽45 мин на стандартном масштабе) больше не
  показывает только время и бейдж «new»: приоритет деталей внутри блока пересмотрен — услуга и
  клиент (F-01-128) теперь важнее декоративного бейджа «new»/категорий, так что при нехватке места
  первым пропадает бейдж, а не имя клиента. Раньше было наоборот — клиент был в DOM, но визуально
  обрезан фиксированной высотой блока раньше, чем скрывался бейдж. Проверено на живом снимке.
- **F-01-134** — в режиме «Последовательно, один мастер» второй (задизейблленный) select мастера
  теперь всегда синхронизирован с первым: смена мастера в первом select мгновенно применяется ко
  всем шагам пакета (и на уровне `steps`, и defensively в `planSteps`), поиск слотов больше не
  пересекает графики двух разных людей. Проверено сценарием: смена мастера на «Ани Саргсян» —
  второй select сразу показал «Ани Саргсян», нашлись свободные слоты (12:05/12:10/12:15).
- **F-01-005** — под мини-календарём появился блок «Избранное» (сворачивается стрелкой, пустое
  состояние с подсказкой, открытый сейчас раздел подсвечен, порядок = порядок добавления через уже
  существующий `toggleFavorite`). Добавлен недостающий ключ перевода `sections.journal`, из-за
  отсутствия которого список раньше не мог бы вывести подпись раздела вовсе.
- **F-01-011** — статус «Клиент пришёл» на самом деле сохранялся не всегда: причина — обязательное
  «при статусе Клиент пришёл» демо-поле `consentDate` (namespace journal.ts, добавлено нарочно как
  тестовый сценарий для custom fields), которое живёт только в свёрнутой панели «Расширенные поля».
  Общий тост «Не получилось. Попробуйте ещё раз.» не называл поле — тестировщик резонно решил, что
  статус не сохраняется вовсе. Теперь: тост называет поле по имени («Заполните обязательные поля:
  Дата согласия на обработку данных»), панель раскрывается автоматически, а сам `DatePicker`
  получает `invalid` (раньше не передавался) — красная рамка и текст «Обязательное поле» под ним.
  После заполнения поля статус сохраняется и «Выполнено на сумму» может быть посчитано и проверено.
  Проверено сценарием до места открытия датапикера с подсвеченным полем (см. `qa/shots/journal-arrived-probe5`); клик по
  конкретному дню календаря в автоматическом прогоне не удалось надёжно смодировать чужим
  универсальным `Calendar.tsx` (дни там без `aria-label="25"`, есть второй `role=grid` у
  мини-календаря позади модалки) — сама починка (текст тоста, `invalid`, автораскрытие) видна и
  верна по коду и по снимку.

## partial

- **F-01-132** (разделение записи по услугам с разными ресурсами) — добавлена **только сама
  настройка**: галочка «Делить запись по ресурсам» в шапке журнала (там же, где уже временно живёт
  `breakCombineMode` до появления `/biz/journal/settings`), поле `splitByResourceEnabled` в
  `JournalPrefs`, мутатор `setSplitByResourceEnabled`, переживает перезагрузку. **Не сделано**:
  сама логика «ресурс занят только на время своей услуги» — `Booking.resourceIds` в ядре общий на
  всю запись, назначения ресурса ПО КАЖДОЙ услуге визита нет нигде в проекте (вклад раздела
  `resources` в `bookingWindow` — пустой `ExtensionStub`, 0 совпадений по репозиторию). Без этого
  основания реализовать «раздельные записи на каждую услугу» нельзя, не выдумывая чужую модель
  данных за раздел `resources`. Записано в `qa/requests/journal.md`.

## assumed

- Список «Избранное» показывает только раздел «Журнал» — звёздочка есть только у заголовка журнала
  (другие страницы кабинета свою пока не подключили, `FavoriteSection`/`toggleFavorite` из
  `api/journal.ts` рассчитаны на них заранее). Бывший пункт «Готово, когда» про исчезновение при
  потере прав проверить некому вторым разделом — сам «Журнал» виден, только если раздел вообще
  открыт, так что условие тривиально выполняется для единственной реальной записи.
- Продажа без визита (F-01-010) — демо-логика в своём срезе (журнал продаж, списание остатка), как
  и весь остальной каталог `GOODS_CATALOG` — настоящий склад/касса принадлежат разделам
  «Склад»/«Финансы», которых ещё нет.
- «Добавить/удалить рабочие дни» (F-01-020) не показывают отдельно список задетых по именам записей
  (только счётчик) — тот же уровень детализации, что уже был у «Отменить рабочий день».
- Пороговые высоты блока записи (30/80/96 px) в F-01-128 подобраны под текущий масштаб сетки
  (`pxPerMin` 1.4/1.8/2.4) так, чтобы конкретно сообщённый случай (~45 мин, зум 15 мин) показывал
  клиента, но не бейдж; для экстремально коротких записей (<20 мин) блок по-прежнему показывает
  только время — это физический предел, не эта починка.
