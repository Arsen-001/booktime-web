# План раздела network — Сеть и филиалы

Составлен 24.09.2026 планировщиком раздела. ТЗ: `booking-research/functional-map/11-network-branches.md` (все блоки «### F-11-…»);
наших функций F-00 у раздела нет (в `docs/areas.json` поле ours = «—»). Снятое из `00-our-decisions.md` задевает раздел в двух
местах: встроенной карты выбора филиала нет — только ссылка на Яндекс Карты (п. 1, это F-11-122 у online), звонков внутри
приложения нет (п. 12) — телефония остаётся интеграцией, только интерфейс. Решения «У нас: ⭐ …» действуют: один аккаунт владельца,
внутри несколько салонов, владелец видит всё вместе и каждый салон отдельно (F-00-049); у каждого салона всё раздельно (F-00-050);
деньги — целые драмы (F-00-002); администраторов создаёт владелец с логином и паролем, права — галочками (F-00-034, F-00-038, F-00-039).

## Как строить (общее для всех пачек)

- Кабинет сети — страницы `src/app/biz/network/**` (тонкие обёртки), экраны и шторки — `src/areas/network/**`. Меню кабинета сети —
  `src/areas/network/nav.ts` (на каждый href — страница). Лояльность и счета клиентов сети живут в `/biz/loyalty/**` (раздел loyalty) —
  наше меню только ссылается туда. Адреса ниже предлагаемые; исполнитель пачки может переименовать, сохраняя охват.
- Модель: филиал = `Business` (салон) со своей `Location`; сеть = `Network` ядра (`businessIds`). В демо — сеть `NET.manana` из двух
  филиалов (Нор-Норк, Шенгавит), персона `network`. `Business.networkId` — «главная сеть» филиала; вхождение в другие сети — через
  `Network.businessIds`. Активная сеть кабинета выбирается на `/biz/network/switch` и хранится в своём срезе (подменю статичное).
- Данные: срез `src/mock/slices/network.ts` — свойства сетей (порядок и главный филиал, удалена/восстановлена, активная), пользователи сети
  и их права (71 галочка по группам), планы, настройка потери клиента, подразделения, сетевые категории и услуги и их привязки к услугам
  филиалов, пакеты, сетевые сотрудники, должности, типы нерабочих дней, сетевой каталог товаров и архив, доп. поля (запись/клиент),
  телефония (токен, маршруты, правила, звонки), журнал выгрузок. Типы — `src/domain/network.ts`, API — `src/api/network.ts`.
- Общая база клиентов: клиенты ядра хранятся по бизнесу (ключ — телефон), база сети склеивает их по телефону; визиты — `listBookings`
  по всем филиалам сети. Аналитика — чистые функции в `src/areas/network/analytics/*` поверх записей со статусом «пришёл».
- Чужие данные — только чтение через свои api-функции (`readArea('loyalty' | 'stock' | 'payroll' | 'notify')`); писать в чужое — только через
  api того раздела. Флаги, которые нужны другим (сетевая ли услуга, запрет цены и описания, сетевой ли сотрудник или товар, может ли
  сотрудник видеть данные клиента по сети), отдаём стабильными функциями из `src/api/network.ts` и описываем в `qa/requests/network.md`.
- Вклад: только `extensions/SettingsHub.tsx` — карточка «Сеть и филиалы» со ссылками на настройки сети, пользователей, доп. поля, планы.
- Необратимое (сделать сетевым, объединить услуги, сотрудников, товары) — `useConfirm` с текстом «отменить нельзя»; обычное удаление —
  `useConfirm` (⭐ F-00-061 — отмена 5 секунд, предложение).
- Персоны для замеров: `network` (главная), `owner` (салон из одного филиала — сеть из одного), `admin` (не добавлен в сеть → пустой
  блок «Сети», F-11-005), `master`. Сферы — хотя бы `nails` и `dental`. У каждого экрана загрузка / пусто / ошибка; `data-f` — на корень
  того, что реально работает.
