## Стыки с другими разделами (что даёт наша сторона)

- **journal:** рисует события в сетке (F-01-035) и выбор «Запись / Событие» (F-01-025) → ведёт на `/biz/groups/events/new?staff=&start=` и `/biz/groups/events/[eventId]`; плитка «Лист ожидания» → `/biz/waitlist`; окно записи открывается по адресу с `waitlist=<id>` — после сохранения journal зовёт нашу `markWaitlistBooked(requestId, bookingId)`. Ресурсный вид журнала и пакетная запись — у journal, читают `listResources`, `getResourceBusy`, `listPackages`.
- **schedule:** окна `getFreeSlots` учитывают ресурсы (F-02-070) и техперерыв (F-02-064) — читают наш `getResourceBusy(locationId, date)`; сигнатуру держим стабильной.
- **online:** виджет читает `listPublicGroupEvents`, бронирует места через `bookGroupSeat`, пакеты — `listPackages`, клиент встаёт в лист — `addWaitlistRequest({ source: 'client' })`.
- **client:** `/bookings` — брони событий (отмена одной брони не трогает остальные), лист ожидания клиентом (F-00-102) — через `addWaitlistRequest`.
- **reports:** отчёт «События» читает ядро + наш срез (`listEventStats`), удаление — `deleteGroupEvents(ids)`.
- **payroll:** читает доли ассистентов `listAssistantShares(bookingIds)` и участников событий.
- **stock / finance / loyalty:** продажа, оплата, абонемент внутри события — зовём их api; расходники участника рисует stock через `bookingWindow` (F-08-045) — договориться, как это попадёт в окно события (см. просьбы).
- **notify:** пуш об отмене события, ссылка онлайн-занятия, «окно освободилось» для листа ожидания — через api notify.
- **staff:** галочки прав (F-10-076, F-10-077, F-10-081), журнал изменений (F-16-171), «Доступен для ассистирования» (F-10-037) — читаем.
- **settings:** страница «Категории» (F-15-126) ведёт на `/biz/groups/categories`.
- **services:** пакет в каталоге услуг со значком «Пакет» и «Добавить → Пакет услуг» → наш `/biz/resources/packages/new`.

- Фундаменту: ключи прав `resources.view`, `services.resources`, `groups.create|edit|delete|move`, `waitlist.view|manage`, `bookingWindow.assistants` в `src/config/permissions.ts` (сейчас есть только `resources.manage`).

- journal: вызвать `markWaitlistBooked` после сохранения записи из заявки; ссылка «Событие» на наш адрес.
- stock: как показать расходники участника в окне события (новый хост `groupBooking` или вклад `bookingWindow` в режиме участника — решает фундамент).
- finance / loyalty / notify / staff: функции записи оплаты, списания абонемента, пуша и строки журнала изменений, если их нет в их api.
- services: показ пакетов в каталоге и вход «Добавить → Пакет».
