# Вопросы владельцу — раздел finance

### Перенос оплаченного визита и снижение цены после оплаты (F-07-184)
Суть: по ТЗ (справка Altegio) переезжает ли дата операций визита при переносе уже оплаченного визита —
неясно; и напрямую снизить цену/скидку у уже оплаченной строки, похоже, нельзя — сначала нужно отменить
оплату услуги, потом поставить скидку/сумму, потом оплатить заново. Нам нужно решение для своего продукта,
не «как у них дословно».
- **а)** дата операций финансов НЕ переезжает при переносе визита (день фактической оплаты остаётся днём
  операции) — проще для кассы, отчётного периода и зарплаты, но дата операции расходится с датой визита.
- **б)** дата операций переезжает вместе с визитом — совпадает с интуицией «когда был визит», но может
  задним числом менять уже закрытый отчётный период/зарплатную ведомость.
- **в)** снижение цены/скидки у оплаченной строки запрещено в UI напрямую (кнопка неактивна с подсказкой
  «сначала удалите оплату») — 1:1 с Altegio.
**Что сделал по умолчанию:** «цена/скидка/состав визита без прав» правит строки визита в journal (не мой
путь, `notOurs` — см. `qa/requests/finance.md`), в этой пачке НЕ построено. Дата операции при переносе в
`finance` не пересчитывается сама (равна дате исходной оплаты, F-07-011) — де-факто вариант (а), т.к. никто
её не двигает; вариант (в) не проверен сценарием (нет вызывающего экрана в journal).
**F-id:** F-07-184, F-07-011, F-07-119
