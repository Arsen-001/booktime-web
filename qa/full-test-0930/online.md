## Цепочка «клиент → мастер → клиент» (проверено действием)

- Отмена раньше срока: окно заранее пишет «Предоплата 2 100 ֏ вернётся». Отмена → `refundDue 2100`, в журнале «Верните клиенту 2 100 ֏ · Вернул».

- Время на оплату истекло → «Запись отменена · Снята: предоплата не поступила вовремя» (`prepayment_expired`).
- Мастер не ответил вовремя → «Снята: мастер не ответил вовремя» + 3 окна → запись **одним нажатием** (тост «новое время отправлено мастеру»).
- «Другое время»: мастер отметил 2 окна → клиент видит их кнопками → одно нажатие → новая запись «Вы записаны». Исходная заявка снята и исчезла из «Заявок». Старая ссылка ведёт на новую запись.

- Работают: ссылки (создать / QR / удалить), публичная страница, «О салоне», кабинет /me, embed, «запись не найдена», неверный адрес, «скоро откроется» у черновика, `api=error` (ErrorState с «Повторить»), `api=slow`, пустой салон, переключение на en.

## Починено (всё в файлах online; tsc и eslint по своим путям чистые)
1. `api/online.ts` releaseExpiredPrepayments: своя петля ставила «Отменена» без причины. Теперь одно правило ядра (`prepayment_expired`, событие клиенту). Проверено действием (C1).
2. Отмена, окно отмены и перенос по ссылке идут через ядро: `coreTx.cancelByClient` / `rescheduleByClient`, правила `effectiveBookingRules` (бизнес + мастер), время по Еревану. Стало:
   - неявка +1 при поздней отмене;
   - нельзя отменить прошедшую или завершённую запись;
   - оплаченную запись клиент не переносит, если мастер не разрешил.
   Проверено (B4, G1). В окне отмены добавлено `allowCancelPrepaid`, запрет виден до нажатия (B5).
3. `BookingConfirmedScreen`:
   - причина снятия записи словами; «Мастер отклонил» больше не показывается, когда время ответа просто истекло;
   - у ждущих статусов иконка песочных часов;
   - у пришедших и прошедших записей нет «Отменить» и «Перенести»;
   - в истории вместо сырого `time_offered` — «Мастер предложил другое время»;
   - объясняется, почему оплаченную запись нельзя перенести;
   - таймер оплаты по Еревану (`parse` + `nowYerevan`);
   - после отмены, оплаты и переноса данные перечитываются (`invalidates`, для api).
4. Запись в предложенное окно одним нажатием: `bookAlternativeTime` (только мок; в api — прежняя форма записи). Время, которое предложил сам мастер, не ждёт второго подтверждения. Исходная заявка снимается, в `meta.replacedBy` — ссылка на новую запись.
5. Отзывы по ссылке с `?h=`: `online.server.ts` (addReview/hasReviewed), мок проверяет хэш, ключ запроса с hash. Действием не проверено: звёздочки появляются только после визита.
6. Срок ответа мастера (`confirmDeadline`) — правка в ядре (`src/api/core.ts` txUpdateBooking, по поручению координатора). Когда запись заново попадает в «ждёт подтверждения» («Деньги пришли» у мастера с подтверждением, перенос клиентом), срок = min(сейчас + 2 ч, начало − 1 ч), а не от создания. Своя копия в `confirmPrepaymentReceived` убрана. Проверено (sI):
   - заявка создана 3 ч назад, «Деньги пришли» → `awaiting_confirmation`, deadline 05:00;
   - после перечитывания журнала и «Заявок» запись не снята и видна в «Заявках».
7. TelegramRemindersCard:
   - в api ссылку на бота запрашивает только по нажатию и перечитывает статус, когда клиент вернулся на вкладку;
   - ошибка → тост;
   - мок без телефона → `phone_required`, карточка скрыта.
8. «Кого позвать» (`slotCandidatesOf`):
   - «Пора снова» по правилу dueAtOf: последний визит «Пришёл» + интервал услуги; без интервала срока нет; будущая запись в салоне — не звать;
   - «Обычно ходит» — только визиты «Пришёл» за 90 дней;
   - один клиент — одно окно (было «Арман Егиазарян» в 4 окнах подряд, снимок A5);
   - дни считаются по Еревану.
9. Публикация черновика: на /biz/online карточка «Страница ещё не открыта клиентам · Опубликовать» (`publishBusiness`, только из draft). Пока записаться не к кому, кнопка неактивна и сказано, что добавить. Проверены показ и блокировка (E1, D5); сам клик не удалось пройти (см. ниже).
10. Приглашённые, но не принявшие приглашение («Ева Карапетян»): подсказка в «Правилах записи» и на /biz/online (проверено, E6). Скрытые активные мастера отмечены «Не видно клиентам» с причиной и ссылкой «Задать график / Добавить услуги / Включить» (проверено, G2: 1 метка в Kaytsak).
11. SlotPicker: длинная кнопка «Ближайшее свободное — …» переносится по словам и не вылезает за карточку (правка в коде, нужное состояние на снимке не удалось получить).
12. WidgetScreen: адрес сайта через `useSyncExternalStore` — ушла ошибка гидратации.

13. Решение 01.10: исходная заявка при взятии предложенного окна — `cancelReason: 'rescheduled'` + новое поле `Booking.rescheduledTo` (добавлены в `src/domain/core.ts`, также в `BookingEvent.reason`). Статус остаётся «Отменил клиент», неявки нет. Подписи ru/en/hy:
   - `common.bookingCancelReason.rescheduled` и `rescheduledTo`;
   - `client.bookings.status.rescheduled`;
   - `online.confirmed.status.rescheduled`.
   Показ:
   - страница записи по ссылке: метка «Перенесена», «Перенесена на 6 октября, 10:00», в истории «Перенесена»;
   - окно записи в журнале: «Перенесена на …»;

   Проверено (sI): `cancelled_by_client / rescheduled / 2026-10-06T10:00`, без `cancelledLate`; в журнале «Перенесена на 6 октября, 10:00». В приложении клиента — только по коду: у записей по ссылке нет пользователя приложения.

## Не починено / вне раздела
- **services:** шаблонные услуги у «Нового мастера» (individual-empty) не назначаются ему самому («Нет мастеров 7»). Опубликовать новый бизнес можно только после ручного назначения каждой услуги (E2). Предложение: в индивидуальном бизнесе при добавлении из шаблона сразу назначать владельца.
- **client / journal:** склонение имени — `client.json:369 «Запись к {name}»`, `:35`, `:549`, `journal.json:1325/1349/1393 «У {name} …»`. Заменить на «Мастер: {name}» / «{name} — свободно …».
- **journal:** отменённую запись с «Верните клиенту» видно только в окне записи. В «Требует внимания» есть строка «Вернуть предоплату N клиенту» (G1), но в «Записях» фильтр «Отменённые» пуст (сценарии №9).
- **Бэкенд (api):**
  - `cancel-window` не отдаёт `allowCancelPrepaid`;
  - нет записи в предложенное окно одним нажатием (`bookAlternativeTime`) и снятия исходной заявки;
  - `public.controller.ts:163-178` — принять `?h=` у отзывов;
  - «Кого позвать» на сервере — то же правило dueAtOf;
  - `publishBusiness` в api не нужен: там нет черновиков.
- **Стенд:** next-server зависал до 12 ГБ и дважды перезапускался; `GoodPicker.tsx:189` (stock) временно не компилировался и ронял /me.
