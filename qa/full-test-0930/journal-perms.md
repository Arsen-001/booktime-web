# Журнал: права мастера (утечки из journal-2.md) — 01.10.2026

Правило владельца: мастер без права видеть чужие записи (`journal.others` + тонкое «Просматривать расписание и записи
сотрудников» = «Все») видит и меняет **только свои** записи. Телефоны скрыты без `clients.phones`, действует ограничение
истории (у мастера по умолчанию 7 дней), выручка видна только с правом «Показывать статистику».
Все проверки в интерфейсе идут через те же хуки прав (`useCan`, `useJournalBlockRights`, `useWindowRights`), поэтому в
режиме api они работают так же: права приходят с сервера (`identity.permissions`, `getStaffJournalRights`).

Проверка: `journal-perms/verify.mjs` и `journal-perms/foreign.mjs` (Playwright через pw-slots), персоны master/owner/admin,
телефон 390×844 и десктоп 1440×900. Логи — `journal-perms/verify.log` и `journal-perms/foreign.log`, снимки — `journal-perms/*.png`.

## Починено
1. **Поиск «Найти клиента»** (`components/JournalSearchResults.tsx`): только свои записи (новый хук `useJournalStaffScope` в
   `lib/rights.ts`, то же правило, что у сетки), без записей за окном истории, телефон через `maskPhone`.
   Проверено: у мастера по «Мане» 0 записей (все записи Мане — у Мариам и Гаяне), телефон `+3749XXXXX71`
   (`master-*-B-search.png`). У владельца и администратора по-прежнему 10 записей.
2. **Чужая запись по ссылке** (`components/BookingWindow.tsx`): по модели прав `can('journal.view', {actor, target})` без
   `journal.others` = нет, поэтому показываем замок «Это запись другого мастера», а не данные. Имя мастера в шапке и
   «Дублировать» скрыты, «Сохранить» выключено, удаления нет. Проверено: `?booking=bk_4287` (запись Мариам) — у мастера
   только замок (`master-*-A-foreign.png`), у владельца и администратора окно открывается целиком.
   Mock api: `deleteBookingWithAuthor` (и через него массовое удаление) проверяет `assertCan('journal.edit', {targetStaffId})`,
   `duplicateBooking` — `journal.create` с targetStaffId. Смена статуса (`changeBookingStatus`) уже проверяла право в ядре.
3. **«Записи»** (`RecordsScreen.tsx`):
   - телефоны маскируются без права;
   - «Выручка» видна только с правом «Показывать статистику»;
   - соблюдается ограничение истории: у мастера было 133 записи, стало 54;
   - галочки массового удаления есть только с правом «Удалять записи», а какие строки можно выбрать, решает `canDeleteBooking`;
   - в «Операциях с Excel» загрузка требует `clients.edit` и права создавать записи, выгрузка — `clients.export`. У мастера меню нет;
   - «Демо: запись от бота» видно только тем, кто создаёт записи всем мастерам.

   В mock api: `importBookingRows` проверяет `clients.edit`, `exportBookingsToEmail` — `clients.export` (`master-*-C-records.png`).
4. **«⋯ Ещё»** (`components/JournalToolbar.tsx` → `JournalGridSettings`): «Технический перерыв» и «Делить запись по
   ресурсам» видны только с `settings.manage` (как страница «Цифровой журнал»). Статусы и шаг сетки — личные, остались.
   Mock api: `setBreakCombineMode` и `setSplitByResourceEnabled` проверяют `assertCan('settings.manage')`.
   Проверено: у мастера и администратора этих пунктов нет, у владельца есть (`*-D-more.png`).
5. **Выручка в журнале без права статистики:** сверх списка тестировщика нашлась строка итогов дня «23 500 ֏ выручка» у
   мастера. Теперь её прячут `DayTotals.tsx`, выручка в шапках колонок «Обзор» (`DayOverview.tsx`) и «Лента»
   (`DayTimeline.tsx`). Проверено: у мастера строка «7 записей · 1 свободное окно» (`master-desktop-A-foreign.png`).

Тексты: `window.foreignTitle` и `window.foreignText` в ru, en и hy. tsc по `src/areas/journal` и `src/api/journal`
ошибок не даёт, eslint по изменённым файлам чист.

## Не починено / вне раздела
- **`src/api/core.ts` `updateBooking` (фундамент) не проверяет права.** Сохранение окна идёт через него, поэтому прямой вызов
  от мастера по чужой записи mock не отклонит. Интерфейс это закрывает замком. Как чинить: в `updateBooking` добавить
  `if (current) assertCan('journal.edit', { targetStaffId: current.staffId })`. Сначала нужно проверить, что его не
  вызывают клиентские персоны.
- **Удалённая запись по ссылке** (`?booking=bk_2385`, её удалили в тестах journal-2): журнал переходит на её день, но окно
  не открывается, и тоста «Запись не найдена» нет. Причина в `JournalScreen.tsx:261-289`: `coreGet` находит удалённую запись,
  а в `bookingsQuery` её нет, поэтому `windowBookingResolved` навсегда false. Это не утечка, файл параллельно правит другой агент.
- **Ошибка гидратации (Hydration failed) в консоли у мастера** (и на телефоне, и на десктопе). Мои правки её не касаются:
  они работают только на клиенте после загрузки. Источник не искал.
- Режим api: запрет на правку чужих записей сервер должен проверять сам (`journal.edit` + `journal.others` по staffId).
  Интерфейс от mock-фильтров не зависит.

## Для владельца
- Администратор по умолчанию без `settings.manage`, поэтому теперь тоже не видит «Технический перерыв» и «Делить по
  ресурсам» в «Ещё». Это соответствует странице настроек («меняет только владелец»). Если админу это нужно, владелец
  включает ему «Настройки».
