## Главное: предложение окна из журнала НЕ доходит до заявки /biz/waitlist (блокер, чинить не в моём разделе)
- Шаги (s1-offer.log): на /biz/waitlist создал заявку «QA Ожидание» (Снятие покрытия, любой мастер, любое время),
  потом открыл журнал. «Свободно сегодня» (8 окон у 3 мастеров) → «Пока некому предложить — в листе ожидания пусто».
  «Найти окно» → «Снятие покрытия» → «Предложить окно 10:00» → то же. После этого `resources.waitlistNotified` = null,
  в журнале уведомлений 0 строк, на заявке нет «Уведомлён». Снимки: `s1-04-freetoday.png`, `s1-07-offer-preview.png`, `s1-08-entry-after.png`.
- Причина: листов ожидания два. `src/api/journal-offers.ts:93` `collectRecipients` читает только `journal.waitlistEntries`
  (панель в журнале), `online.waitlistRequests` и `client.waitlist`. Срез `resources.waitlist` (экран /biz/waitlist, пункт меню) он не читает.
- Как чинить (journal-offers.ts): добавить четвёртый источник `readArea('resources').waitlist`:
  `!closedBookingId`, `serviceIds.includes(t.serviceId)`, `staffIds` пуст или включает мастера окна, желание `!w.date || w.date===t.date`
  плюс время внутри `intervals`/`time`, если они заданы. Канал — `waitlist`, ref `{kind:'resources'}`. В `offerSlots` отметить
  `s.waitlistNotified[id].push(now)` через `mutateArea('resources')`. Правильнее — слить два листа в один (просьба уже с 25.09
  лежит в `qa/requests/resources.md` b01). Решает координатор journal/resources.
- Там же: «Записать» с /biz/waitlist передаёт в журнал `waitlist=<id>`, а журнал этот параметр не читает. Заявка из
  /biz/waitlist после записи **никогда не становится «Закрытой»** (F-16-163): `closeWaitlistEntry` из `api/resources` в UI
  никто не вызывает. Как чинить: JournalScreen/BookingWindow `onSaved` → `closeWaitlistEntry(params.waitlist, booking.id)` из `@/api/resources`.

## Починено (мои файлы; tsc и eslint по ним чистые)
1. `src/api/resources.ts` `notifyWaitlistForFreedSlot`: окно на дату X «уведомляло» всех, у кого есть любое будущее
   желание (`w.date >= today()`). Теперь уведомляются только «любое время» и желания ровно на X; прошедшая дата — никого. Проверено по коду.
2. `WaitlistScreen.tsx` `slotsToWishes`: один интервал «12:00–15:00» сохранялся как «12:00», а при правке открывался как «12:00–12:00».
   Теперь интервал хранится целиком, а подпись `from===to` показывается одним временем. Проверено по коду и tsc.
3. Форма заявки: если снять «Любое время», сразу добавляется интервал 09:00–18:00. Если задано время без дня, сохранить
   нельзя, под датой появляется подсказка «Выберите день для этого времени» (ключ `waitlist.form.dateRequired`, ru/en).
   До этого время без дня молча превращалось в «любое время»: s3 создал заявку с `wishes: []`.
4. «Записать» на /biz/waitlist: окно журнала теперь открывается с именем, телефоном, услугами и временем заявки.
   Проверено действием: `s3-10-journal-from-waitlist.png`, телефон и имя подставились. Если в заявке «любой специалист»,
   подставляется первый мастер, который делает эту услугу. Иначе окно открывалось на владельце без услуг, и услуга
   пропадала (видно на том же снимке). Этот мастер после правки не проверен действием: не дождался слота браузера.
5. «Уведомить лист ожидания»: если под окно никто не подходит, показывается честный тост «уведомлять некого» вместо
   «Уведомление отправлено» (`waitlist.notifiedNobody`). Для кнопки берётся ближайшее будущее желание, а не прошедшее.
   В строке заявки тоже показывается ближайшее будущее желание.
6. На телефоне плашка статуса заявки растягивалась на всю ширину карточки (`s2-_biz_waitlist-owner-phone-ru.png`),
   теперь стоит по размеру (`self-start`).
