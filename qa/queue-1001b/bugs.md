## 2. Поиск «стрижка» ведёт на «Укладку»

В моке частично исправлено раньше (№9). Ошибка оставалась в трёх местах:
- **Сервер** (`catalog.service.ts`): если слово совпадало со сферой («стрижка» → барбер), услуги по названию не
  искались. Поэтому выбиралась самая короткая услуга мастера, то есть «Укладка». Теперь название ищется всегда:
  по основе слова, на всех языках.
- **Ранжирование** (мок и сервер): раньше сортировка шла только по времени окна. Теперь сначала идёт точное
  совпадение с названием услуги, потом слово в названии, потом совпадение только по сфере, имени или салону.
  Внутри каждой группы — по времени. Реклама («выше в поиске») не обгоняет более точное совпадение. Если у мастера
  несколько найденных услуг, показывается та, что он делает чаще за 90 дней. При равенстве — с названием ближе к
  запросу, потом более короткая («Мужская стрижка», а не «Детская стрижка до 12 лет»).
- **Карточка мастера из поиска** показывала окна под самую короткую услугу (та же «Укладка»). Теперь ссылка
  `/masters/<id>?service=<найденная>`, и окна считаются под эту услугу. Это сделано в `getMasterCard(staffId, viewer,
  serviceId)`, на сервере — `GET /v1/public/masters/:id?service=`.
- Попутно на сервере: у «Свободно завтра» `tomorrowIso` равнялось сегодняшней дате. Исправил на следующий день.
- Проверено: `bugs/n2-engine.mjs` — «стрижка», «Стрижки», «маникюр», «укладка»: совпадения выше остальных ✓.
  `bugs/n2-browser.mjs` в моке и в api — «Укладки» в выдаче нет, на карточке мастера «Свободное время для услуги
  «Мужская стрижка»» (в api — «Стрижка и борода», её этот мастер делает чаще). Снимки
  `n2-search-*.png`, `n2-master-*.png`, `api-n2-*.png`.
