  функции раздела «Интеграции» самим этим фактом (мутации в памяти работают, тосты корректны), но не могу
  подтвердить persist-after-reload нигде, пока это не почищено или не увеличен лимит (например IndexedDB вместо

## 2026-09-27 · [дизайн-пачка] Дубликат `install.id` в сидере — React варнинг «two children with the same key»

- Зачем: `node scripts/measure.mjs --routes /biz/integrations/installed` (owner/nails) ловит на КАЖДОМ прогоне
  `Encountered two children with the same key` на телефоне и десктопе. Причина — не в моём рендере: в
  `src/mock/slices/integrations.ts` (`seed()`, ф-ция сидинга подключений) `app2`/`app3` берутся как
  `pool[(bi + 5) % pool.length]` / `pool[(bi + 11) % pool.length]` — при небольшом `pool.length` для некоторых
  `bi` это тот же индекс, что и `app1 = pool[bi % pool.length]`, и в `installs` для одного `locationId` дважды
  пушится запись с одним и тем же `id: iai_${locationId}_${app.id}`.
- Что именно: у себя (`InstalledScreen.tsx`) я не могу поправить сидер (`src/mock` — чужой путь), поэтому
  подстраховался дедупликацией по `install.id` при рендере списка (`useMemo` + `Set`) — варнинг с экрана ушёл,
  но правильное решение — не сидировать дубль изначально: в `seed()` при выборе `app2`/`app3` пропускать индекс,
  уже занятый `app1` (например `pool.filter((a) => a.id !== app1.id)` перед вторым/третьим выбором).
- Пока жду: ничего не блокирует — экран рендерит правильный список (лишняя строка отфильтрована), просто на
  будущее, если кто-то будет трогать `seed()` в integrations-срезе `src/mock/slices/integrations.ts`.
