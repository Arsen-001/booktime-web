## 1. Четвёртый срез подряд: `argsIgnorePattern`/`varsIgnorePattern: '^_'` не настроен в `eslint.config.mjs`
- Серьёзность: **major**
- Где: `eslint.config.mjs` (правило `@typescript-eslint/no-unused-vars`).
- Что не так: разделы пишут код по конвенции проекта «неиспользуемое — с `_`», eslint всё равно
  светит warning на каждое такое место. Поднято в q2 и q3 (`qa/requests/build-q3.md`, пункт 1 — тогда
  было 20 из 26 warning'ов; сейчас 24 из 27, почти все места — те же файлы `src/api/client.ts`,
  `src/api/online.ts`, `WidgetScreen.tsx`, `NewsScreen.tsx`, `StoriesGeneratorScreen.tsx`, только
  список чуть подрос: `src/api/online.ts` теперь на одну строку больше). Три среза без движения.
- Как исправить: в `eslint.config.mjs`, в блоке `@typescript-eslint/no-unused-vars`, добавить
  `{ argsIgnorePattern: '^_', varsIgnorePattern: '^_', destructuredArrayIgnorePattern: '^_' }` — уберёт
  24 из 27 текущих warning'ов разом, без единой правки в разделах.

## 2. Наблюдение (не открытый баг): расширение без готового `LOADERS`-файла роняет ЧУЖИЕ страницы 500-й
- Серьёзность: **major** (как защита на будущее — сейчас уже само разрешилось)
- Где: `src/extensions/registry.ts:30` (`'clientCard:client': () => import('@/areas/client/extensions/
  ClientCard')`) — статический импорт компонента вклада.
- Что не так: во время этого среза `src/areas/client/extensions/ClientCard.tsx` какое-то время не
  существовал (раздел client его ещё писал) — из-за этого сборка отдавала 500 на восьми маршрутах
  ЧУЖИХ разделов (`/biz/finance/**`, `/biz/payroll/**`, `/biz/reports/**`, `/biz/services`,
  `/biz/staff`, `/biz/loyalty/deposits/**` — всё, что рендерит хост `clientCard` где-либо в дереве),
  а не только страницы раздела client. Раздел client досоздал файл до конца замера, повторный прогон —
  чисто; открытого бага на сдаче нет. Полные детали и список из 17 упавших комбинаций —
  `qa/build-health/q4.md`, пункт 3.
- Как исправить (предложение, не срочно): обернуть `import()` в `LOADERS` в try/catch на уровне
  `lazy()` или дать `EXTENSIONS` схлопывать несобранный модуль в пустой компонент с `console.error`
  вместо падения всей страницы — тогда недостающий вклад ломает только свой блок хоста, а не всю
  страницу целиком (сейчас так уже сделано для «нет пары в `LOADERS`» — строка 62-64, `if (!loader)`
  — но не для «пара есть, а модуль не собирается»). Решение не срочное: ситуация возникает только
  когда раздел ещё не досдал заявленный в `pairs.ts` файл вклада, то есть сама по себе временная.

## 3–4. `src/app/layout.tsx:50-51`, `src/app/manifest.ts:21-22` — готовая замена `THEME_META` не подставлена (повтор с q2/q3, теперь без причины ждать)
- Серьёзность: **major**
- Где: `src/app/layout.tsx:50-51` (`themeColor: [{ color: '#f7f7fb' }, { color: '#0f0f1a' }]`),
  `src/app/manifest.ts:21-22` (`background_color: '#f7f7fb'`, `theme_color: '#4f46e5'`) — сырые hex
  вместо констант.
- Что не так: то же самое замечание третий срез подряд (q2 → q3 → q4), но с q3 изменилось важное:
  `src/config/theme-meta.ts` **уже существует** и уже помечен `tokens-ok` (`THEME_META.lightBackground
  = '#f7f7fb'`, `.darkBackground = '#0f0f1a'`, `.primary = '#4f46e5'`) — кто-то («ядро k4», судя по
  пометке в `qa/requests/build-q3.md`) уже сделал константу именно для этого случая. Осталось только
  подставить импорт в двух файлах — это уже не «завести константу», а буквально две замены строки.
  В q3 обе находки получили отметку «❌ не мой файл — помощник «приложение для телефона»», то есть
  фундамент считает эти два файла зоной ДРУГОГО помощника (не ядра), но они не входят ни в один из 18
  разделов (`docs/areas.json`) — по правилу 1 CONVENTIONS.md `src/app/layout.tsx` прямо в списке
  фундамента, `src/app/manifest.ts` рядом (не раздел, не путь ни одного раздела). Если у фундамента
  внутри есть отдельная роль «PWA/мобильное приложение» — пусть эта роль сделает замену; со стороны
  хранителя сборки различить это не могу, оставляю пункт открытым третий срез подряд, потому что
  никто из видимых мне владельцев его не забрал.
- Как исправить: в `src/app/layout.tsx` — `import { THEME_META } from '@/config/theme-meta'`, заменить
  `'#f7f7fb'` → `THEME_META.lightBackground`, `'#0f0f1a'` → `THEME_META.darkBackground`. В
  `src/app/manifest.ts` — тот же импорт, `background_color: THEME_META.lightBackground`,
  `theme_color: THEME_META.primary`. После замены `check-tokens.mjs` больше не найдёт эти 4 строки
  (значения строковые литералы исчезнут, идентификатор константы — не hex).
