# Просьбы раздела staff к фундаменту и другим разделам

Заведено сборщиком b01 (25.09.2026).

## К фундаменту (src/domain/core.ts, src/config/permissions.ts)

1. **Поле `positionId` у `Staff`** — сейчас должность хранится как `Staff.position: LocalizedText`, свободным
   текстом, совпадающим с именем в каталоге `staff.positions` (наш срез). Это работает для группировки
   списка (F-10-008), но переименование должности в каталоге не переименовывает её у уже назначенных
   сотрудников — обновляем только новых. Просьба: `Staff.positionId?: Id`, ссылка на наш каталог.
2. **API цен подписки (billing/settings)** — до сих пор нет `src/api/settings` с ценой за место. Пока
   пользуемся временной константой `src/areas/staff/pricing.ts` (MASTER_SEAT_PRICE=4000, ADMIN_EXTRA_SEAT_PRICE=2000).
   Когда settings/billing заведёт свой api — заменить импорт в `pricing.ts` и `qa/build/staff-b01.md` можно закрыть
   этот пункт.
3. **Права `notify.mailings`, `notify.log`, `online.own`/`online.manage`** уже добавлены в `src/config/permissions.ts`
   (см. `qa/measure/staff/core-k2.md`, `core-k4.md`) — раздел staff их прочитал, галочки для администратора
   в редакторе прав (b04) выставит следующий сборщик.

## От staff другим разделам

1. **`logChange()` / `listChanges()`** теперь есть в `src/api/staff.ts` (⭐ F-00-040, общий журнал изменений,
   срез `staff.audit[]`). Пишите из journal/clients/services/stock: `import { logChange } from '@/api/staff'`.
2. **`readCore().staff`** — список сотрудников бизнеса без сортировки/фильтров; для готового списка с
   лицензией и порядком берите `listStaffRows()` из `@/api/staff`.
3. **Порядок сотрудников** — `staff.order` (map `staffId → number`), меняется `reorderStaff()`. Календарь
   (schedule) и запись клиента должны сортировать колонки этим же ключом, а не своим — иначе порядок
   разъедется с тем, что сотрудник настроил на вкладке «Специализация» (F-10-009).

## Добавлено сборщиком b02 (25.09.2026)

1. **F-10-050 «Где используются должности»** — фильтр «Должность» в staff (список, `positionName`) готов, но
   ТЗ требует его и в журнале (вид «День» → «Должности»), графике (фильтр «Сотрудники и должности»), отчётах
   («Продажи по сотрудникам», «Основные показатели») и виджете онлайн-записи (показывать должность вместо
   специализации). Это фильтры экранов journal/schedule/reports/online — staff не может их построить в чужих
   путях. Просьба: когда journal/schedule/reports/online заводят фильтр по сотруднику, добавьте туда же фильтр
   по `listPositions(businessId)` (или `Staff.position?.ru`), это закрывает F-10-050 полностью.
2. **F-00-045/046 «мастер в салоне и сам по себе» / «домашняя запись видна администратору»** — данные уже
   поддерживают несколько мест (`Staff.workplaces` может содержать `'salon'` и `'home'` одновременно,
   переключатель «принимаю и дома» построен в карточке, F-00-048). Но «запись в салоне в 15:00 закрывает
   15:00 дома, и наоборот» и «в календаре салона это время подписано „дома", без имени и суммы» — это движок
   календаря/пересечения слотов, который живёт в schedule (сетка занятости) и journal (сама сетка записей),
   не в staff. Staff подготовил только модель данных и своё поле в карточке; просьба schedule/journal добавить
   в расчёт свободных окон мастера объединение по всем его местам работы (собственный бизнес мастера — это
   отдельный `Business`, если у мастера `role==='individual'`-подобный сценарий уже есть в ядре, свяжитесь по
   `qa/requests/schedule.md` — вопрос выходит за рамки b02).
3. **Переименование должности теперь каскадится** — `renamePosition()` (b02) переносит новое имя на всех уже
   назначенных сотрудников (`Staff.position.ru`), а не только на новых. Пункт 1 из просьб b01 про
   `Staff.positionId` остаётся открытым (это упрощение работает, но ссылка по id была бы надёжнее совпадения строк).
