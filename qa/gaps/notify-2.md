## Нарушения

1. **⭐ F-00-114 и Снято №3 (по смыслу), F-00-130: бесплатная пуш-рассылка уходит всей CRM-базе, у кого есть приложение, а не подписчикам ❤.**
   - Где: `api/notify.ts:318–337`, функция `audienceClients` фильтрует только по `onlyWithApp && appUserId`.
   - Подписка (`favorites`) и приглушение (`newsMuted`, `domain/client.ts:115`) нигде в notify не проверяются. `grep favorit|newsMuted` по разделу пуст.
   - Отправленная новость не попадает в ленту клиента.
   - В `qa/requests/notify.md` (g1-1) сборщик пишет, что рассылка «фильтрует подписчиков». В коде этого нет. Ядро k3 ответило, что client может сам читать `readArea('notify').mailings`.
2. **⭐ F-00-120 «напоминания — только пуш»: правка напоминания для одной записи сделана как у Altegio.**
   - В окне записи (`extensions/BookingWindow.tsx:141–175`) выбор только между SMS и Email.
   - Умолчание — `smsEnabled: true` «за 1 ч» (`api/notify.ts:106–111`). Строки «Пуш» нет.
   - Это расходится даже с собственным умолчанием типа 1: `CLIENT_DEFAULT = { push: 'always' }`, `registry.ts:44`.
3. **⭐ F-00-032: код входа клиента (тип 7) шлётся только по SMS.**
   - `registry.ts:294`: `availableChannels: ['sms']`, `defaultScenario: { sms: 'always' }`.
   - Решение: код идёт в WhatsApp или Telegram, SMS только запасной канал.
4. **⭐ F-00-121: кнопка «Напомнить через WhatsApp» в журнале отправок открывает чат с номером МАСТЕРА, а не клиента.**
   - `LogScreen.tsx:149–153`: `waLink(staffPhone, …)`.
   - Решение: «открывает WhatsApp мастера с номером клиента и готовым текстом». Кнопка должна вести на номер клиента, а сейчас она пишет самому сотруднику. В окне записи эта ссылка сделана верно.

Из «Снято» в разделе ничего не построено. Нет звонков из приложения, нет оценки 1–5, нет продажи SMS, нет «напоминаний за монеты».

Граничный случай, в нарушения не внесён: статус журнала «Отклонено оператором связи» почти дословно совпадает с Altegio («Отклонено оператором»).
