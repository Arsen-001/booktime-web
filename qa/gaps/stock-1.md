## Главное (block / major)

1. **F-00-138 · продажа не попадает в выручку.** `createSaleOperation` (`src/api/stock.ts:1951`) пишет только складскую операцию.
   `recordOperation` из finance (`src/api/finance.ts:321`, «соседи зовут её из своих api») не вызывается ни при продаже, ни при
   оплате прихода (F-08-057), ни при отмене продажи (F-08-073). Остаток при этом считается верно: в этом прогоне квоты нет, так что
   block из b03-m2 надо проверить заново одной сессией с перезагрузкой.
2. **F-08-028 · товар из техкарты архивируется** (major из b04-m2, не исправлен). В `archiveGood` и `archiveGoods`
   (`src/api/stock.ts:953`, `:968`) нет проверки `state.techCards`, хотя в `deleteGood` она есть (`good_in_use`). Нужно так же
   бросать ошибку и показывать причину в диалоге.
3. **F-08-059 · «На склад» сбрасывается после добавления товара** (major из b02-m2, не отмечен). Эффект автоподбора в
   `MoveFormScreen.tsx:77` ставит склад-источник равным уже выбранному `toId`. Нужно пропускать `best.id === toId` или
   сохранять `toId` и предупреждать.
4. **F-08-092 / F-08-076 · поле «Код» подписано «необязательно», а без кода сертификат не продаётся** (major из b03-m2). В
   `SaleFormScreen.tsx:425` стоит `optional`, а в `:399` — `codeRequired`. Нужно одно поведение: либо код генерируется сам,
   либо поле обязательное.
5. **F-00-137 / F-00-140 / F-00-141 · владельцу не приходят уведомления** о «заканчивается», сроке годности и замене
   оборудования. Подпись поля обещает «вы получите уведомление» (`goodForm.criticalStockHint`), но в `src/api/stock.ts` нет
   ни одного события для notify. Колокольчик (`src/shell/workspace/NotificationsBell.tsx`) ждёт api notify. Просьбу №8 из плана
   в `qa/requests/notify.md` так и не завели.

   `OperationsScreen.tsx:127`: пока журнал операций не открыли, каталог и карточка показывают завышенный остаток. core-rules

7. **core-rules №1 / arch-a1 №1–3 · склад не отдал соседям свои api.** Нет `listProducts(businessId)`, `listProductSales({clientId|bookingId})`
