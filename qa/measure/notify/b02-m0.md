# Раздел «Уведомления» — измерение пачки b02 (формы и детали: шаблоны/переменные, клиентские типы)

Измеритель, не сборщик — код продукта не правил. Дата: 25.09.2026. Дев-сервер: `bash scripts/ensure-dev.sh`
(порт 3710, чужой, не трогал; один раз он на минуту упал 500-кой из-за чужой правки в
`src/mock/slices/client.ts` — не моё, отвалилось само после того, как его починили).

**Правило языков обновилось во время работы** (см. `CONVENTIONS.md` §0.4, отметка 25.09.2026): сейчас
пишутся и проверяются **только ru и en**, hy — не проверяю (выключен, но код его поддерживает). Замер
сделан на ru+en, phone (390×844) и desktop (1440×900), персона `owner`, сфера `nails`, плюс отдельная
проверка прав персоной `master`.

**Оговорка по масштабу.** Проект — только интерфейс без бэкенда: настоящего движка отправки по таймеру
нигде в разделе нет (это явно зафиксировано в `qa/build/notify-b02.md`, и это осознанное решение проекта,
а не дыра b02). Поэтому пункты «Готово, когда», которые по факту описывают исход реальной доставки
(«клиент получает сообщение»), я читаю как «настройка сохраняется правильно и включена в правильный канал
по каскаду `previewDelivery()`» — это то немногое, что вообще можно проверить действием в интерфейсе без
бэкенда. Это НЕ занижает планку: где интерфейс явно обещает интерактивную возможность (например, ручную
правку времени на уже созданной записи, F-05-009), я проверял именно её и нашёл, что её нет.

## Главные находки (по убыванию серьёзности)

1. **[major] F-05-009 — обещанная ручная правка настроек на старой записи не существует.** Подсказка в
   каждом типе с условиями («Условия отправки») прямо обещает: «Время для уже созданной записи меняется в
   её карточке, в плитке «Уведомления о визите»». Открыл вклад раздела в окно записи напрямую —
   `/dev/ext/bookingWindow/notify` — это пустая заглушка `ExtensionStub` (0 функций, 0 `data-f`).
   Снимок: `qa/shots/notify-b02-m0-ext/dev-ext-bookingWindow-notify__owner-nails-ru-light-desktop.png`.
2. **[major] F-05-011 — смена формата даты/времени не меняет ни один предпросмотр.** Тестовые значения
   переменных `{date}`/`{time}`/`{dateTime}` в `VARIABLES`/`TEST_DATA` (`src/areas/notify/lib/registry.ts`)
   — статичные строки («26 сентября», «14:00»), не зависящие от `NotifySettings.dateFormat`. Переключил
   формат на 12-часовой, сохранил, перезагрузил страницу (`settings-after-reload.png`) — надпись у поля
   сменилась на «12-часовой — 7:32 вечера», но ЛЮБОЙ текст шаблона/предпросмотра как показывал «14:00», так
   и показывает. Пункт «Готово, когда» не выполнен ни для одного канала/типа.
3. **[major] Гонка при быстрой смене двух полей условий одного типа теряет первое значение без ошибки.**
   Воспроизвёл на типе 1 (`/biz/notifications/types/1`): выбрал «3 ч» в «Отправлять за», сразу (через
   500 мс) поставил галочку «Другое время для Email» → после перезагрузки «Отправлять за» откатилось на
   «1 ч» (дефолт), тост оба раза лживо показал «Условия сохранены». С паузой 1200 мс между действиями —
   всё сохраняется верно. Причина — `saveConditionsPatch` мержит патч поверх `conditions` из замыкания
   рендера, а не поверх свежих данных с сервера; второй вызов, ушедший до `refetch()` первого, стирает его
   правку. Живому владельцу достаточно кликнуть два select подряд, чтобы тихо потерять первую настройку.
   Снимки: `qa/shots/notify-b02-m0-pair/…step2-after-email-toggle.png` (потеряно),
   `qa/shots/notify-b02-m0-pair2/…step3-after-reload.png` (с паузой — сохранилось).
4. **[minor→major по строгости] F-05-012 — фолбэк «пусто в Бренде → название локации» непроверяем и, судя
   по коду, не реализован.** `senderName` в `TypeDetailScreen.tsx` читает только `businessQ.data?.name`
   напрямую; отдельного поля «Бренд» в ядре ещё нет, так что ветку «пусто» показать не на чем — сам
   сборщик отметил это как допущение в `qa/build/notify-b02.md`. Читаю строго по ТЗ: пункт не выполнен.
5. **[minor] Подсказка F-05-009 показывается на всех типах с условиями, включая те, где она не имеет
   смысла.** Типы 3 (день рождения), 17 (сгорание скидки), 55 (повторный визит), 72 (недошедшие) —
   вообще не про изменение времени визита в календаре, но подсказка про «плитку «Уведомления о визите»»
   всё равно висит над их полями («когда», «за N дней», «через N дней») — сбивает с толку, тем более что
   самой плитки не существует (находка №1). Снимки: `type3-before.png`, `type17-before.png` в
   `qa/shots/notify-b02-m0-conditions/`.
6. **[minor] Каталог переменных и «Сохранить» показаны и на полностью системных типах (7 basic-режим SMS,
   19, 43), где вставлять переменную некуда** — активного поля нет, поповер покажет «нет активного поля».
   Не ломает, но лишняя кликабельная зона без смысла. Снимок:
   `qa/shots/notify-b02-m0-locked/biz-notifications-types-43-templates__owner-nails-ru-light-desktop__full.png`.
7. **[minor, вне раздела notify] F-05-026/F-05-028 — «Подтвердить запись» нигде не существует.** Grep по
   всему `src/` не нашёл ни кнопки подтверждения на стороне клиента (F-05-028), ни отдельного экрана
   отчёта «Визиты» с подтверждением администратором (F-05-026) — это зависит от online/journal и, по
   собственному отчёту сборщика, отложено на b03. Подтверждаю: действительно ничего нет.
8. **[minor, косметика]** 3 карточки (типы 6, 3, 85, desktop) — кнопка «‹ Уведомления» в шапке измерена
   как 135×40 px, ровно на границе порога 40 px; общий для всего раздела компонент шапки, не новое в b02.
