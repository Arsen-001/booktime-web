# notify — измерение доделки g2-2 (m1, после `qa/build/notify-g2-2-fix1.md`)

Проверял живыми действиями через `scripts/measure.mjs` (32 базовые стр. ru/en + 8 hy + 4 собственных
сценария с кликами) под персонами `owner`/`admin`/`master`/`network`, сфера `nails`, телефон 390×844 и
десктоп 1440×900, ru/en, hy — только сырые ключи/шрифт. Браузеры закрыты (headless, через `pw-slots`).
Цель прогона — перепроверить то, что `fix1` заявил починенным или перепроверенным: F-05-061/062 (клик
по строке), F-05-059/111/112 (гейты по правам), F-05-097 (дедуп по сети); остальные пункты из m0
(block-хосты, вне-путей) не поменялись и не перепроверялись заново по существу — их статус подтверждён
чтением кода/файловой системы, без повторного полного прогона.

**Baseline** (`g2-2-m1-area-report.json`, 32 стр.) и **en** — 0 ошибок консоли, 0 4xx/5xx, 0 сырых
ключей, 0 вылетов по ширине, 0 зон нажатия < 40px, 0 «висит загрузка», data-f 37. Отдельно замечено:
баг `loyalty.ts` (`defaultCardTypeNotify is not defined`), который `fix1` фиксировал как ломающий 5
страниц `/dev/ext/*`, в этом прогоне **не воспроизводится** — все 5 `/dev/ext/*` страниц (`bookingWindow`,
`clientCard`, `settingsHub` × ru/en × телефон/десктоп) загрузились с 0 ошибками. Похоже, `loyalty` уже
починил свой файл отдельно от notify — не дефект notify, фиксирую как факт среды.
**hy** (`g2-2-m1-hy-report.json`, 8 стр.) — 0 ошибок, 0 сырых ключей, армянского текста на экране нет
(ожидаемо, hy выключен по правилам проекта, не дефект).
