# notify · сквозные сценарии e2e-q3

Дата: 2026-09-25. Цепочки C24 (новая), C13, C17, C19 (`qa/e2e/scenarios.md`, итог `qa/e2e/report-q3.md`). Код раздела не правил.
Повторить: `node qa/e2e/run.mjs --only C24,C17,C19`.

**Работает хорошо:** «Журнал отправок» строится из событий ядра: запись клиента из приложения → строка «Клиент записался
онлайн · Пуш в приложение · Вы записаны: Маникюр классический к Сона Григорян 26.09.2026 в 12:00»; отмена салоном → «Отмена
записи · Пуш в приложение» (C24.S2, S5 ✅). Клиенту с приложением — пуш, не SMS/WhatsApp (решение «только пуш»).

## major

1. **Центр уведомлений не говорит, какая запись** (C24.S3). Строка — «Новая онлайн-запись · 25 сентября, 11:17»: время
   создания, но ни клиента, ни мастера, ни времени визита. Администратору не понять, куда смотреть. Как: «Новая онлайн-запись
   · Ани Мелкумян → Сона Григорян · завтра, 12:00», нажатие открывает запись в журнале.
2. **Отмена в центре уведомлений не видна** (C24.S6). События выводятся из самих записей по `source` и `updatedAt`
   (`InboxScreen`), поэтому отменённая запись остаётся «Новой онлайн-записью». Как: строить из `listBookingEvents`
   (созданa / статус from→to / перенесена / удалена) — как уже делает ваш `liveLog`.
3. **Ключ кэша чужого вида** (архитектура §18 п. 1, 11): `InboxScreen` читает `listBookings` под ключом
   `['journal', 'bookings', businessId]` — тот же ключ у журнала с другой функцией/фильтром; кэш общий. Как: `useCoreList`
   / `coreKeys` или свой ключ `['notify', 'inbox', businessId]` поверх `listBookingEvents`.
4. **Колокольчик в шапке пуст** (C17.S6, C19.S3–S4, повтор q2): новая запись клиента, просьба перезвонить — «Новых
   уведомлений нет». Шапка ждёт от вас `countUnreadInbox` / `listInboxPreview` (комментарий в `NotificationsBell.tsx`) —
   отдайте их из того же источника, что центр уведомлений; фильтр по мастеру для персоны `master`.
5. **«Доставлено» клиенту, которого клиент не видит** (C24.S7, вместе с client): журнал отправок показывает «Прочитано»
   для пуша об отмене, а в приложении клиента уведомления нет. Пока клиентская лента не читает события ядра, статус
   «Прочитано» вводит в заблуждение.
