языки ru/en (проверено сценариями ниже — см. «Как проверял»).

## Как проверял

1. `node scripts/fids.mjs --area notify` — раздел `notify`: всего меток 139, размечено 88 (63.3%); все 30 id
   пачки g2-3 — в списке «Не помечены в коде».
2. `grep -rln "<F-id>" src/app/biz/notifications src/areas/notify` для каждого из 30 id — 0 совпадений (ни разу,
   ни в коде, ни в комментариях-ссылках на F-id, которые разработчики оставляют у соседних функций).
3. `node scripts/measure.mjs --routes /biz/notifications,/biz/notifications/channels,/biz/notifications/channels/sms,/biz/notifications/channels/email --persona owner --lang ru,en --device phone,desktop`
   — 16 страниц (все существующие экраны раздела), снимки в `qa/shots/notify-g2-3-m0/`. 0 ошибок консоли,
   0 сырых ключей, 0 вылетов по ширине, 0 мелких целей, 0 «висящих» загрузок — но список найденных `data-f`
   на всех 16 страницах: `F-05-001, 002, 003, 004, 043, 058, 059, 065, 066, 067, 068, 077, 079, 110, 116` —
   ни одного id из проверяемой пачки.
4. Прочитал ТЗ каждой из 30 функций (`booking-research/functional-map/05-notifications.md`) и раздел
   «Снято (не делаем)» в `00-our-decisions.md` — прямого «снято» для этих id нет (кроме общего пункта №11:
   платные WhatsApp/SMS-напоминания клиенту сняты, что бьёт по логике F-05-071/073/075/076, но сама карточка
   подключения канала как «1:1 механизм» ТЗ всё равно требует). Значит это не «намеренно не строим», а
   недоделка — законный предмет измерения, не вопрос владельцу.
5. Посмотрел снимки экрана `/biz/notifications` и `/biz/notifications/channels` (телефон и десктоп, ru/en) —
   глазами: раздел показывает только вкладки «Типы» и «Каналы» с уже помеченными функциями (email, SMS,
   Altegio.me пуш, чек-лист команды); ни каталога партнёров/провайдеров, ни баланса, ни WebHook-настроек,
   ни баннеров-напоминаний в кабинете нет — экран заканчивается там же, где заканчиваются размеченные F-id.

## Что уже посмотрено вживую (не выдумано)

- Существующие экраны раздела (`/biz/notifications`, `.../channels`, `.../channels/sms`, `.../channels/email`)
  открываются без ошибок под owner, ru/en, телефон/десктоп — но это не относится к пачке g2-3: на них нет ни
  одного из 30 нужных `data-f`.
- Проверка через `/dev/ext/<host>/notify` не применялась — все 30 функций по ТЗ живут не в хостах-расширениях
  (bookingWindow/clientCard/staffCard/serviceCard/settingsHub/clientProfile), а в собственных экранах раздела
  notify (интеграции/каналы/баланс/маркетплейс/абонементы), которых просто нет.
- Отдельно проверил соседний раздел `integrations` (`docs/areas.json`, id `integrations`,
  `src/app/biz/integrations/**`) — предположил, что часть карточек (SMS-каталог, WhatsApp-партнёры) могла уехать
  туда по смыслу «Где: Интеграции» из ТЗ. Но по `AREAS.md`/`docs/areas.json` весь файл `05-notifications.md`
  закреплён за `notify`, поэтому смотрю как недоделку notify, а не как чужой вклад.

## Вывод для сборщика

Пачка g2-3 по этим 30 id не начата: 0 из 42 пунктов «Готово, когда» выполнено. Рекомендую при следующей
сборке начать с малых по объёму и не завязанных на внешние API пунктов, которые можно замокать полностью в
браузере: F-05-081/100–106 (шаблонные уведомления лояльности/абонементов — используют уже существующий движок
`src/areas/notify/lib/engine.ts` и типы уведомлений), F-05-135 (служебные баннеры — чисто UI), F-05-115
(баланс — тоже чисто UI + мок-состояние). Крупный интеграционный блок (069–076, 119–128, 127, 136) требует
сначала завести раздел «Интеграции/каналы-партнёры» внутри notify (или получить экран из integrations) — без
него все эти пункты структурно невозможно выполнить.
