## Найденные дефекты

1. **major** — `/biz/schedule/calendar` (Мой календарь), роль мастер, телефон 390×844: вкладка «Всё занято — …» и часть строки дня («Открыть весь день», тип дня, вторая пара полей времени перерыва) обрезаны за правым краем экрана без видимого скролла/подсказки — `qa/measure/schedule/shots-master/biz-schedule-calendar__master-nails-ru-light-phone.png`. Общий sweep не поймал это как «вылет», похоже элементы лежат в контейнере с горизонтальной прокруткой без визуальной подсказки (не проверял свайпом — **инференс**, не подтверждено кликом/свайпом).
2. **major** — F-02-003 «Фильтры графика»: ТЗ требует пять фильтров («Сотрудники и должности», «Специализации», «Удалённые/Неудалённые», «Уволенные/Неуволенные», «Есть график/Нет графика»); в коде реализовано два («Есть график», «Должность»), и должность — single-select, хотя ТЗ явно требует «выбрать несколько». Подтверждено чтением `ScheduleScreen.tsx`.
3. **major** — F-02-032/033/034 (пачка ТЗ отмечена 🔒 мобильное приложение): нет размеченного `data-f`, нет явного отдельного UI под «массовая установка графика по датам для нескольких сотрудников»; непонятно, покрывается ли пункт существующей веб-панелью — см. таблицу выше, нужно решение по скоупу.
4. **minor** — не удалось средствами `scripts/measure.mjs` (только click/fill/press/expectText/expectVisible/wait) надёжно переключить нативный `<select>` кликом по тексту опции — потребовалась ручная комбинация click+ArrowDown+Enter, и даже она не всегда меняла значение с первого раза. Это ограничение инструмента измерения, а не обязательно продукта, но из-за него шаблоны «По дням недели» / «По сменам» / «Свой шаблон» (F-02-007/008/009) и переключение типа дня (F-02-010) **не подтверждены действием до конца** — только визуально (поля на экране есть, форма разумная).
5. **minor** — не проверил hover-подсказки (тип дня и часы при наведении, F-02-002) и точный смысл цифры в шапке дня («сколько сотрудников работает») headless-снимком — нужен отдельный замер с tooltip.
