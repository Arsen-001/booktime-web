### [block] F-00-058 — «Закончил раньше» обрезает запись, которая ещё не началась, и открывает её время клиентам
✅ исправлено (fix-schedule): «Закончить раньше» — только у идущего визита (MasterTodayBooking.ongoing), finishEarly в api бросает not_ongoing; тост «Визит закончен в 11:40 — время до 13:00 снова свободно». C18.S2–S3 ✅.
- **Где:** `/biz/schedule/calendar` (master) → «Действия по сегодняшним записям» → «Закончил раньше».
- **Что:** кнопка есть у всех сегодняшних записей, в том числе у будущих. В 05:59 нажал её у записи
  `bk_1616` (11:00, 120 мин, клиентка Милена Гаспарян, ещё не пришла). Длительность в базе стала **5 мин**,
  тост «Остаток времени стал свободным окном». У клиента на `/book?staff=st_nuri_ani` появились окна
  **11:05, 11:30, 12:00** — поверх живой записи. Итог: двойная запись одного и того же времени.
  Причина в `MasterActionsCard.tsx`: `elapsed = max(5, diffMinutes(start, now))` — у будущей записи разница
  отрицательная и превращается в 5 мин. «✅» в b03-m0 поставлен по тосту, окна клиента после нажатия не смотрели.
- **Как исправить:** показывать кнопку только у записи, которая уже идёт: `start <= now < end`, статус не
  отменён и не «не пришёл». При `now <= start` кнопку не показывать совсем. Если нужна отметка «клиент не
  придёт», это другое действие. После нажатия показывать, какое окно освободилось: «11:40–13:00 открыто клиентам».
- Скрипт: `s3.mjs`, снимок `s3-finish-early.png`.

### [major] F-00-059 — «Задерживаюсь» ничего не отправляет следующему клиенту
✅ исправлено (fix-schedule): событие ядра reportDelay; тост — «Следующий клиент получил уведомление» или «У клиента нет приложения — позвоните: номер». ⏳ показ у клиента — раздел client.
- **Где:** та же карточка, кнопка «Задерживаюсь».
- **Что:** тост «Клиент предупреждён о задержке». В базе появилась только запись
  `schedule.delayNotices[bk_1616] = { nextBookingId: bk_1617 }`. Следующей клиентке (Мариам Есаян, cl_053)
  ничего не пришло. Её `appUserId` пустой, так что пуш дойти не мог. При этом `delayNotices` никто в
  проекте не читает, кроме самого графика: нет ни ленты клиента, ни журнала отправок notify. Пункт «Готово,
  когда» — «следующий клиент получает пуш» — не выполнен, а тост вводит в заблуждение.
- **Как исправить:** писать уведомление в ленту клиента (`client.notifications`, вид `master_delay`), если у
  клиента есть приложение, и строку в журнал отправок notify. Если приложения нет — тост «У клиента нет
  приложения — позвоните ему: +374 …» с номером. Нужна пара с notify/client (просьба в `qa/requests`).
- Скрипт: `s3.mjs`.

### [major] F-02-102 — в «Истории» неверное время (UTC вместо Еревана) и чужая правка подписана «Вы»
✅ исправлено (fix-schedule): время — nowDateTime() (Ереван), автор — actorStaffId, «Вы» только своему; тип дня и часы — из словаря («10:00–19:00 → 10:00–20:00»).
- **Где:** `/biz/schedule/history`.
- **Что:** в 06:00 по Еревану добавил рабочий день через «Быстрый доступ → + рабочий день». В истории
  показано **«Вы · 25 сентября, 02:00»**, то есть время по UTC, на 4 часа раньше. Тот же браузер в журнале
  «Записи» показывает время удаления правильно («06:07»). Автор сохранён строкой `actorName: "Вы"`,
  `actorStaffId: null`: администратор видит правку владельца тоже как «Вы». Значение подписано как
  «Тип «work»» — служебное слово на экране.
- **Как исправить:** хранить `actorStaffId` и имя из `useCurrent()`, «Вы» показывать только когда
  `actorStaffId === staffId` смотрящего. Время выводить через `useFormat().time(...)` в поясе Еревана, как в
  `/biz/records`. Тип дня — через словарь («Рабочий день»).
- Скрипты: `s4.mjs`, `s5.mjs`, снимок `s4-history.png`.

### [major] F-00-063 — черновик из фразы теряет день и услугу
✅ исправлено (fix-schedule): «Записать фразой» в окне записи заполняет день (поле «День»), время, клиента и услугу (matchServices).

  если несколько — открыть список с ними сверху.
