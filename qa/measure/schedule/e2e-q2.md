Что работает: «Мой календарь» → «Отметить занято» закрывает окно у клиента (C14.S2–S3 ✅); «Закончил раньше» укорачивает

следующего клиента (C18.S5 ✅).

## major

1. **«Задерживаюсь» не доходит до клиента** (C18.S6, F-00-059): тост «Клиент предупреждён о задержке», а у клиента ни в
   «Уведомлениях», ни в карточке записи ничего — `sendDelayNotice` пишет только `schedule.delayNotices`. Как: событие
   записи в ядре (просьба e2e-q2 №3); до тех пор не писать «Клиент предупреждён».
      ✅ исправлено (fix-schedule) (schedule): событие ядра; тост честный — «получил уведомление» / «позвоните: номер». ⏳ лента клиента читает listClientEvents — раздел client (C18.S6 ❌ на стороне client).
2. **«Закончил раньше» доступно у визита, который ещё не начался**: в 6 утра у записи 11:00 кнопка активна, нажатие
   укорачивает визит до 5 минут (`Math.max(5, elapsed)` при отрицательном `elapsed`). Как: кнопка только для идущих визитов
   (`start ≤ сейчас < конец`), остальным — «Задерживаюсь» / ничего.
      ✅ исправлено (fix-schedule): в меню только у идущего визита; finishEarly в api отвечает not_ongoing для не начавшегося.
3. **Домашний график мастера не виден в графике** (C07.S2, из q1): у Ани в воскресенье клиенту предлагаются окна «дома у
   мастера» 11:00–12:30, а в `/biz/schedule` воскресенье «—». Как: вторая строка / метка «дома» из `WorkSchedule
   workplace: 'home'`.
      ✅ исправлено (fix-schedule)
4. **Две реализации серий** (C08, просьба e2e-q2 №7): журнал зовёт свою `createRecurrenceSeries`, ваша `createSeries` не
   используется окном записи — договориться с journal об одной.
      ⏳ позже (fix-schedule) — журнал зовёт свою createRecurrenceSeries (путь journal); наша createSeries — одним запросом через placeBooking. Договорённость — просьба в qa/requests/schedule.md.
