## Найденные дефекты

1. **[major] F-00-127 / F-04-156 — нет уведомления о неявке/неотмеченном визите.** Отметка «пришёл/не
   пришёл» реализована только как ручной поход на `/biz/clients/summary`; ни push, ни колокольчик,
   ни другое уведомление на неё не ведёт (`grep -rn "pendingMark" src/areas/notify/` — пусто). ТЗ
   прямо требует «прямо из уведомления». Аналогично не нашёл уведомления мастеру о неявке
   (F-04-156, «сотруднику сразу уходит уведомление»).
2. **[minor] `text-q4.md` не синхронизирован с кодом.** Major №1 и №2 из этого файла уже исправлены в
   `messages/{ru,en}/clients.json`, но строки в самом файле не помечены `✅ исправлено` — следующий
   проверяющий рискует чинить то, что уже починено, или, наоборот, не заметить расхождение.
3. **[minor] Разовый hydration-error на телефоне.** Первый прогон сценария (`cl_001`, owner, ru,
   phone, через «Ещё → Изменить») дал 2 console-error («Hydration failed…», «Can't perform a React
   state update on a component that hasn't mounted yet»); повторный идентичный прогон — 0 ошибок. Не
   смог воспроизвести стабильно за отведённое время — не блокер, но стоит на заметке: похоже на гонку
   при открытии Sheet сразу после клика по «⋯» на холодном рендере.
4. **[minor] F-04-206 в демо не проверяется импортом.** Реальная проверка требования (импорт тоже
   попадает в журнал) не была сделана ни мной, ни, судя по пустому `runsQ`, никем на этом наборе
   демо-данных — только экспорт. Не блокер (код общий, `coreTx.logDataOperation()` вызывается из обеих
   веток по комментарию в файле), но пункт остаётся формально непроверенным действием.
