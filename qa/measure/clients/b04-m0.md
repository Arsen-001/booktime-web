## Найденные дефекты

1. **[major] F-04-107** — демо телефонной книги (`PhoneBookImportModal`) не разбирает контакт на «Имя»/«Фамилию», хранит одну строку. Критерий не выполняется даже в веб-приближении.
2. **[major] F-04-111** — не подтверждена видимость категории клиента в «Окне записи» (вклад `clients` в `bookingWindow`): вкладка «Клиент» показывает имя/телефон/визиты/баланс/лояльность, но не теги-категории. Либо функция не докинута в этот вклад, либо вклад не читает `row.tags`.
3. **[major] F-04-137** — удаление клиента не пишется в «Журнал изменений» (наше собственное ⭐-решение по этому же F-id) — не нашёл такой записи; при удалении карточки Нуне Нерсесян никакого журнала изменений в карточке клиента нет вообще (это не то же самое, что «Операции с данными» у импорта/экспорта).
4. **[minor] F-04-130** — у персоны без права «Выгружать список клиентов» кнопка выгрузки остаётся ВИДИМОЙ (задизейблена + пояснение), а не отсутствует, как требует спецификация («без права выгрузки пункта нет — это главный способ запретить вынос базы»). По сути защищено (клик недоступен), но буква ТЗ про полное отсутствие кнопки не соблюдена.
5. **[minor] F-04-177** — нет отдельной загрузки остатков счетов таблицей; наше же предложение из `00-our-decisions.md` («сделать загрузку остатков в импорте клиентов — обсудить») висит нереализованным.
6. **[minor, вне пачки]** Поиск клиентской базы (`ClientsListScreen.tsx:129`, F-04-002 — другая пачка) ищет `r.phone.includes(q)` по ОТФОРМАТИРОВАННОМУ номеру («+374 93 777 888»): запрос цифрами без пробелов («777888») не находит клиента, хотя номер реально содержит эти цифры подряд с пробелом между «777» и «888». Указываю для раздела на будущее, в свой checked/passed пачки b04 не включаю.
7. **[minor]** В сид-данных бизнеса `Nuri Nail Studio` есть категории-дубли с разным регистром: «постоянный» (12 клиентов) и «Постоянный» (0 клиентов) — похоже на артефакт сидирования, а не пользовательское поведение; стоит почистить сид.
8. **[minor, известно]** Периодический hydration-mismatch/console-warning («Can't perform a React state update on a component that hasn't mounted yet») при взаимодействии со страницей после того, как localStorage уже содержит данные из прошлой сессии (SSR рендерит сид, клиент гидрирует персистентными данными). Не смог воспроизвести стабильно (повторный прогон — чисто); это известная кросс-командная проблема, уже упомянутая в отчётах других разделов (`qa/measure/*/…`), не специфична для `clients`.
