## Находка не из списка задания, но на проверяемом узле F-04-206

Живой прогон нашёл, что «Готово, когда» F-04-206 выполнено не полностью: способ загрузки (`paste`/
`file`) в строке журнала есть и верный, но поле «автор» — это буквально `persona` (`owner`, `admin`,
`master` — слово роли демо-персоны), а не имя сотрудника. Пример со скриншота
(`qa/shots/clients-g2-2-m2/import-flow/…step3-journal-ru.png` и `…phone-journal-scrolled.png`):

> 25 сентября, 19:52 · **owner** · вставка из таблицы: создано 0, обновлено 0, отклонено 1

Ожидалось имя сотрудника (как в других разделах — `src/api/loyalty.ts:1927` берёт
`author?.name` через `core.staff.find(...)`, не персону). В коде раздела:
`src/areas/clients/ImportExportScreen.tsx:278` — `authorName: persona` (импорт),
и та же строка в `exportAll()` для F-04-208 (экспорт, не в списке этой пачки, но тот же узел и тот же
баг). `useCurrent()` уже отдаёт `staffId` — просто не используется для поиска имени.

Это нарушает и «Готово, когда» («с автором» — не с ролью), и правило CONVENTIONS.md §0 «понятные
слова, без терминов разработчика»: `owner`/`admin`/`master` — системные слова, не то, что видит
пользователь нигде больше в кабинете. → **major**, не minor, потому что это единственный пункт этой
пачки, который вообще имел код для проверки, и весь смысл правки был «показывает автора».

## Снимки

- `qa/shots/clients-g2-2-m2/import-flow/` — сценарий загрузки на `/biz/clients/import`: форма →
  сопоставление колонок → результат и строка журнала (ru десктоп 1440×900,
  `…step3-journal-ru.png`; ru телефон 390×844, `phone-journal-scrolled.png`; попытка на en упала на
  шаге клика — не критично, тексты ICU-строки уже сверены по коду `messages/en/clients.json:693,697`).
- `qa/shots/clients-g2-2-m2/import-langs/` — `/biz/clients/import` под ru/en/hy × телефон/десктоп,
  свежая (не импортированная) персона: 0 ошибок консоли, 0 сырых ключей, 0 вылетов по ширине, 0 зон
  нажатия < 40px во всех шести комбинациях; hy без армянского текста на экране — ожидаемо (§0.4
  CONVENTIONS.md, hy не пишется и не проверяется по содержанию), не дефект.
- `qa/shots/clients-g2-2-m2/spotcheck/` — `/biz/clients` и `/biz/waitlist` под owner и network: обе
  страницы открываются без ошибок, но не несут никаких из 50 F-id пачки (0 совпадений в `data-f`),
  подтверждает вывод `grep`/`fids.mjs` живым просмотром, а не только статикой.

## Права (owner / network)

`/biz/clients` под `owner` и `network` — идентичный набор `data-f` (20 у обоих), т.е. ни один из
сетевых F-id пачки (F-04-180…185, F-04-205) не даёт network-персоне ничего, чего не видно владельцу
локации — совпадает с «block»: сетевая клиентская база (F-04-180) не построена, различать права
нечем.

## Браузеры закрыты

`chromium.launch()` через `acquireBrowserSlot()`/`measure.mjs` закрывает контексты по завершении;
ручной Playwright-скрипт для скролл-скриншота (`b.close()`) — тоже. Полосы `lsof`/`ps` после прогона
не проверялись отдельно (measure.mjs сам это гарантирует).
