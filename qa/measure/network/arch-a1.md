Дата: 2026-09-25. Ревьюер архитектуры (код не правил).
Раздел ещё заглушка (код фундамента ~10–80 строк), поэтому замечаний к коду нет — ниже то, что уже построено соседями
на вашей территории и что нужно учесть с первого файла, чтобы не завести второй источник правды. Общие правила —
docs/ARCHITECTURE.md и CONVENTIONS.md §16; проверка — `node scripts/arch-check.mjs --area network`.

Первым делом (для всех новых разделов):
- данные среза — по `businessId` (никаких «общих на всех» настроек), ключи — фабрика `networkKeys` с `['network', …]`;
- одна бизнес-операция = одна функция `src/api/network.ts` = один `request()`, внутри без `await coreCreate/updateBooking`;
- правила (суммы, сроки, остатки, статусы) — чистые функции в `src/domain/network.ts`;
- права — `useCan('network.*')` в экране и проверка в api, не `persona ===`;
- записи — `useApiMutation` + try/catch + тост; списки > 100 — фильтр и пагинация в api.

## Что учесть

1. Филиал выбирается в верхней полосе, `useCurrent().activeLocationIds` — его учитывают только journal и schedule.
   Ваши сводки по сети — функции api с `businessIds`/`locationIds` на входе; агрегаты считаются в api, а не в компоненте.
2. Сотрудник сети в каждом филиале — отдельный `staffId` (docs/backend/README.md вывод 1). Не стройте связи «человек → филиалы»
   в своём срезе, пока ядро не решило (просьба `qa/requests/arch-a1.md` №12).
