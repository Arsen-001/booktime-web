## 🔴 Главная находка — БЛОКЕР для всего раздела (и, похоже, всего приложения)

**Данные не переживают перезагрузку страницы.** На каждой из 44 страниц раздела консоль пишет предупреждение:

```
[mock-db] не удалось сохранить в localStorage QuotaExceededError: Failed to execute 'setItem' on 'Storage':
Setting the value of 'bp-mock-db' exceeded the quota.
```

Проверено действием: создан склад «Витрина тест QA» (F-08-007) — появился в списке с тостом «Склад создан»; после `page.reload()` склад исчез, остались только два стандартных. Создан товар «QA Персист Товар» (F-08-017) — сохранён, открыта карточка; после `page.reload()` на той же странице — экран «Товар не найден» (пустое состояние, не крах, но данные потеряны). Проверено на **свежем контексте браузера** (localStorage пуст, 5 байт, 0 ключей) — то есть **само сохранение единого блока `bp-mock-db` уже превышает квоту localStorage** ещё до того, как что-либо создано пользователем: весь мок-снапшот (данные всех 18 разделов) сериализуется в одну строку и не помещается в ~5–10 МБ лимита браузера.

Это не баг конкретно кода склада — запись ведёт общий `src/mock` слой, — но бьёт по каждому пункту «сохранение после перезагрузки» из чек-листа измерителя для ЛЮБОЙ функции склада: F-08-007, F-08-008, F-08-011, F-08-017, F-08-027 и т. д. Отмечаю один раз здесь как общий блокер и ссылаюсь на него в таблице вместо повтора на каждой строке.

## Пустые состояния и права — что проверено отдельно

- **owner-empty** (пустой бизнес): все 8 маршрутов раздела открылись без ошибок, 0 предупреждений сверх стандартного quota-варнинга, пустые состояния с текстом и кнопкой — на Товары, Склады (0 товаров, но сами склады есть), Складские операции, Оборудование. На Техкарты и Инвентаризация — экран открывается, но без `data-f` (эти подстраницы вне пачки b01, замечены как «пока не построено» отдельным пунктом выше).
- **master** (ограниченная персона): открыл /biz/stock и /biz/stock/warehouses — обе страницы отдаются без ошибок и без вылета за права (403/белый экран), т.е. базовый доступ есть; тонкую проверку по конкретным правам (F-08-116…119, видимость себестоимости и т. п.) в этой пачке не проходил — она относится к другой группе функций (не входит в список из задания на b01).
- **hy**: на всех проверенных маршрутах ни одного сырого ключа `namespace.key` или «⋯» на экране не найдено; армянского текста не найдено вовсе (полный fallback на ru) — это ожидаемое поведение по правилу проекта («в работе только ru+en»), не дефект.
