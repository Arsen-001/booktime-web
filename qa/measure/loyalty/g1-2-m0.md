# g1-2 — измерение доделки (loyalty), заход m0

Раздел «Лояльность» (loyalty). Проверял действием в браузере: `scripts/measure.mjs` (owner, сфера nails,
ru/en, phone+desktop, 5 экранов раздела) + свои сценарии Playwright `qa/scenarios/loyalty/g1-2/*.mjs`
(клики по окну записи → вкладка «Лояльность», поиск по коду, оплата сертификатом/абонементом/бонусами,
отмена оплаты, удаление оплаченной записи, переход из хаба, справочные списки сети). hy — отдельно,
только на сырые ключи и армянский шрифт (правило CONVENTIONS §0.4: hy сейчас не пишем и не проверяем на
перевод — фолбэк на английский это НЕ дефект).

Персона везде — owner (Азат / Нарине Акопян, «Nuri Nail Studio», сфера nails). Браузеры за собой закрывал
(headless Playwright через `acquireBrowserSlot`, каждый прогон — свой процесс/контекст).

**checked = 24** пунктов «Готово, когда» (по 17 F-id) · **passed = 13** подтверждено действием ·
**5 дефектов** (2 major подтверждены действием, 1 структурный дефект мока, 2 уже известных фундаменту) ·
**6 пунктов не проверено действием в этом заходе** (нехватка времени на 390×844+en для каждого, отмечено
отдельно).

## Итог по важному

1. **Известный фундаментный дефект — подтверждён действием ещё раз.** Каждая мутация мока
   (`localStorage.setItem('bp-mock-db', …)`) бросает `QuotaExceededError` — воспроизвёл на КАЖДОЙ странице
   раздела (`g1-2-main-report.json`, поле `console.warnings`) и отдельно на живом сценарии: полностью оплатил
   визит подарочным сертификатом чужого клиента (см. п.2) → тост «Оплата лояльностью проведена» → твёрдая
   навигация (`goto`) на `/biz/loyalty/certificates` → сертификат **как будто не трогали**: баланс
   15 000/15 000, владелец прежний. Это тот же дефект, что в `g1-1-m0.md` («Персистентность») — не завожу
   заново, отмечаю у конкретных F-id ниже как причину, почему «сохранение после перезагрузки» не проходит.

2. **F-06-097 — перенос сертификата к плательщику НЕ подтверждён.** Живьём: запись клиента «Мариам Петросян»,
   код `CERT-1003` (владелец — Гаяне Аветисян) найден по коду, «Оплатить сертификатом» → «Провести оплату
   лояльностью» → тост успеха, панель показывает «Оплачено лояльностью: 8 000 ֏ · Списание с сертификата»
   (скриншот `cert-transfer2/1-after-full-pay.png`) — **до этой точки всё верно**. Но: (а) список
   «Транзакции» после этого не получает новую строку «Списание с сертификата» вообще (верхняя строка
   осталась от 22.09, сегодня 25.09) — то есть операция не пишется в журнал транзакций даже в рамках одной
   сессии, не только из-за квоты; (б) список «Сертификаты» после навигации не отражает переноса (см. п.1).
   (а) — самостоятельный дефект (не объясняется квотой localStorage, раз данные в первую же секунду не
   появились ни разу за 4 прогона). major.

3. **F-06-074, второй заход (доделка) — критерий «удаление оплаченной абонементом записи возвращает
   посещение на абонемент» НЕ подтверждён, подтверждено обратное.** Клиент Нелли Симонян (телефон
   `+374 95 965 289`), абонемент «Маникюр × 5», остаток 2 из 5 (список `/biz/loyalty/memberships`, живой
   снимок `lists/2-memberships.png`). Открыл её будущую запись (09.10, Ани Саргсян) → вкладка «Лояльность» →
   «Списать визит» → «Провести оплату лояльностью» → визит закрыт полностью (5 000 ֏, скриншот
   `membership3/2-after-full-pay.png`). Затем удалил саму запись через 🗑 у шапки записи → тост «Запись
   удалена» + «Вернуть» — но правая колонка карточки записи в тот же момент (без перезагрузки, чистое
   состояние React) показывает «Лояльность → Маникюр × 5 · Остаток **1** визит» (скриншот
   `membership4/2-after-delete-click.png`) — то есть списанный визит НЕ вернулся на абонемент (ожидалось
   «Остаток 2»). Это внутрисессионный дефект, не следствие квоты localStorage. **major.**

4. **F-06-123/F-06-124 — «чужой абонемент по коду» структурно непроверяемо: у моковых абонементов нет
   кода.** `src/mock/slices/loyalty.ts:333-345` создаёт `Membership` без поля `code` — у сертификатов есть
   `code: 'CERT-1000+ci'`, у абонементов такого поля нет вообще. Список «Абонементы» сети (`/biz/loyalty/
   memberships`, скриншот `lists/2-memberships.png`) не показывает колонку «Код» (у «Сертификатов» она
   есть). `findLoyaltyByCode` (`src/api/loyalty.ts:1859`) ищет `m.code && m.code.toLowerCase() === …` — при
   отсутствующем `code` условие всегда ложно, поиск абонемента по коду **не может найти ни один абонемент
   ни при каком вводе**. Проверил действием: поиск `MEMB-1000` и `lm_biz1_3` в поле «Сертификат или
   абонемент по коду» — оба «не найдено» (без ошибок в консоли, поведение штатное — просто данных для
   успеха нет). Второй пункт «Готово, когда» F-06-123 («чужой абонемент по коду оплачивает визит и
   переходит к этому клиенту») и единственный пункт F-06-124 непроверяемы, пока в моке нет кода у
   абонементов. major (блокирует проверку двух F-id целиком).
