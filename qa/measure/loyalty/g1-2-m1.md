ru, phone), `node scripts/arch-check.mjs --area loyalty`, чтение источников (`grep`/`Read`) для проверки,

(headless Playwright через `acquireBrowserSlot`).

3. **🔴 Новый block — `arch-check.mjs` находит ERROR A2 в `src/api/loyalty.ts:11`**:
   `import type { AreaStates } from '@/mock/slices'` — чекер помечает любой импорт из `@/mock/slices`
   ошибкой «прямой доступ к моковой базе — только через src/api/*», независимо от того, что импорт
   **типовой** (`import type`) и используется только как generic-параметр (`AreaStates[typeof AREA]`,
   строки 36, 956), реального обращения к данным в обход `readArea`/`mutateArea` здесь нет. По CONVENTIONS
   §16 «ошибки A1–A4, A6 — сдавать нельзя»: `node scripts/arch-check.mjs --area loyalty` завершается кодом
   `1`. Технически безопасно (тип, не значение), но формально не проходит проверку — отмечаю как **block**
   по букве правила, с пометкой, что фактического обхода API нет (вероятно, ложное срабатывание чекера на
   `import type`, а не настоящий A2). Раздел `loyalty` сам это правит (это его файл), не «чужое».

4. **Фундаментный дефект квоты localStorage — переподтверждён живым прогоном ещё раз, теперь и на

   F-06-152 (см. п.6) тем же способом, что F-06-097/076 в m0 — не завожу как новый дефект, отмечаю как ту же
   причину у нового F-id.
