## 2. Мастер создания акции: у шагов есть названия, итог перед сохранением (major)
- **У них [видел]:** Altegio «Создание акции»: 5 шагов показаны **номерами без названий** (1···2···3···4···5), тип акции — две
  карточки «Скидки / Бонусы» с иконкой; последний шаг — галочки «по каким картам» и «в каких локациях» (`c-09-promo-step1.jpg`, `c-09-promo-step5.jpg`).
  Ловушка у них: **акция работает только у клиентов с картой** — без карты скидка молча не применяется (`CYCLE-09-loyalty.md`).
- **Сделать:** Stepper с подписями («Что даём · Кому · Когда · Где · Проверка»); последний шаг — сводка человеческими словами:
  «Скидка 10% на маникюр · всем клиентам с картой „Бронза“ (14 человек) · по будням до 31 окт». Если у 0 клиентов есть нужная
  карта — предупреждение warning «Сейчас акция никому не применится».
- ✅ исправлено (b02) — Stepper подписан на каждом шаге («Название и тип» / «Вид» / «Способ расчёта» / «Правила» /
  «Уведомления и область действия», видно и в шапке шага, и при переходе; подписи — свои по смыслу шага ТЗ, не «Что
  даём · Кому · Когда · Где», это не подошло бы описанию функций из functional-map). Шаг 5 получил блок «Итог»:
  вид акции · число отмеченных типов карт (или «ни один тип карты не отмечен») · число локаций (или «все локации»);
  при 0 типов карт — warning «Пока не отмечен ни один тип карты — акция никому не применится». ⏳ позже — «14 человек»
  у типа карты: нужен подсчёт клиентов по типу карты (своя агрегация в `src/api/loyalty.ts`), решил не тянуть в b02,
  чтобы не разрастить пачку; текущий «Итог» уже ловит главную ловушку Altegio (0 карт → акция не сработает).
