# client · сквозные сценарии e2e-q2

Дата: 2026-09-25. Проверка: сквозные цепочки `qa/e2e/` (сценарии — `qa/e2e/scenarios.md`, итог — `qa/e2e/report-q2.md`).
Повторить: `node qa/e2e/run.mjs --only C01,C03,C05,C06,C15`. Снимки — `qa/shots/e2e/`. Код раздела не правил.
Что работает: «Свободно рядом», «Рядом со мной», окно из карточки → сразу запись, оттенок, «Мои записи», связь с CRM
по номеру, отмена до срока и лист ожидания «Окно освободилось!», перенос, ❤ подписка и приглушение новостей, «Мои
мастера», «Повторить запись», звёздочка после «пришёл» (число на карточке растёт), просьба перезвонить, «Никого не
нашли» → просьба, покупка абонемента.

## block

1. **Клиенту показываются выдуманные оплаты и товары** (C01, снимок `qa/shots/e2e/C01-S18-fail.png`, F-14-018…025).
   Визит, который в журнале никто не оплачивал: «Списано с сертификата −2 700 ֏ · Оплачено 6 300 ֏ · Начислен кэшбэк
   +500 ֏», у других — «Товары: Уходовое средство для дома 4 500 ֏». Строки выбираются по хэшу id
   (`getBookingPaymentBreakdown`, `getBookingCashbackEarned`). Как: пока нет finance/stock/loyalty — только «Итого»
   (`booking.total`) без «Оплачено», списаний, кэшбэка и товаров; потом — из их api (просьба `qa/requests/e2e-q2.md` №5).
2. **После входа новым номером — чужие «Мои записи»** (C02.S4, из q1). Нужна правка демо-контекста (просьба e2e-q1 №1);
   на вашей стороне — после `verifyLoginCode` запоминать вошедшего (`apply({ persona: 'client', appUserId })`).

## major

3. **Запись, отмена, перенос, просрочка — свои копии правил вместо команд ядра** (C01.S6, C06.S5, C15.S5, C05.S2, C03.S7).
   Мастер «сразу» (Ани, Гаяне): по ссылке запись «Записан», из приложения «Ждёт подтверждения»; после переноса — снова
   «Ждёт подтверждения». Срок бесплатной отмены берётся из `client.cancelWindowHours` (24 ч), а мастер поставил 72 ч в
   «Правилах записи» — клиент за 48 ч отменяет «без последствий». Просроченная предоплата пишется «Отменена вами».
   Как: `bookAppointment` → `placeBooking` (`@/api/core`), отмена → `cancelBookingAsClient` (исход `clientCancelOutcome`:
   поздно = «Отменил клиент» + неявка), перенос → `rescheduleBookingAsClient`, просрочка → `releaseExpiredPrepayments` ядра;
   удалить из среза `cancelWindowHours`, `prepaymentDeadline`, `prepaymentPolicy`. Предупреждение в записи «засчитается как
   неявка» — от `freeCancelUntil(booking, effectiveBookingRules(...))`.
4. **Всё «от клиента салону» остаётся в вашем срезе** (C16.S3, C19.S3, C21.S3–S4, C04.S8). Просьба перезвонить
   (`callbackRequests`), «сообщить, когда появится» (`demandLeads` — наша панель читает `platform.demandEntries`),
   купленные абонементы и сертификаты (`memberships`, хозяин — loyalty), лист ожидания (хозяин — resources) никто в
   кабинете не видит. Как: звать api владельцев (`reportSearchDemand` из `@/api/platform` на «Сообщить, когда появится»
   и на пустой поиск; остальное — по просьбе e2e-q2 №4), свои копии удалить.
5. **Поиск не находит салон по названию** (C11.S2, регрессия: в q1 новый салон находился). «Nuri» и «E2E Салон …» →
   «Никого не нашли» — а клиент чаще всего ищет место, название которого ему сказали. Как: искать и по
   `Business.name`/`Location.name`, показывать место отдельной строкой «Места».
6. **Администратор показан клиенту как мастер** (`/places/biz_nuri` → «Лилит Мкртчян · Администратор», карточка с
   «Позвонить / WhatsApp» и «Свободных окон пока нет»; F-00-014, F-00-072). Как: список мастеров места и каталог — через
   `isStaffInCatalog` / `staffClientVisibility` из `@/domain/rules`.
7. **Ближайшие окна в карточке мастера и в «Свободно рядом» не совпадают с записью** (C18.S4). После «Закончил раньше» у
   Ани запись (/book) предлагает 11:20, 11:30, 12:00, а карточка — только «вс, 27 сентября», «Свободно рядом» Ани не
   показывает. Как: карточка и каталог берут окна тем же `getNearestSlots`/`nearestSlots`, что и шаг «Время».
8. **Запись на «домашнее» окно создаётся как салонная** (C07.S3b): окно из графика `workplace: 'home'`, запись —
   `workplace: 'salon'`. Как: передавать место окна в `placeBooking` (`workplace`).
9. **Модалки «Кого принимает мастер» нет в приложении** (C15.S6, F-00-069): по ссылке у Ани («только женщин») модалка
   есть, в приложении — только бейдж. Как: та же модалка при выборе мастера/окна.
10. **Шаг «Оттенок»: «Выбор желателен, но необязателен», а «Продолжить» без выбора не нажимается** (C17.S4, F-00-095).
    Как: при `requirement: 'preferred'` кнопка активна; либо явный вариант «Мастер подберёт» выбран по умолчанию.
11. **Абонемент «куплен» без оплаты** (C21.S2): «Купить» → тост «Куплено — оплатите по реквизитам мастера при визите»,
    абонемент сразу активен, салон о продаже не знает. Нужен вопрос владельцу (как платит клиент в приложении, кошелёк
    отложен F-00-028) — предлагаю «заявка на абонемент» до подтверждения салоном.
12. **Публичные «Отзывы о месте»** (`/places/…`, «Оставить отзыв о месте») — по решению «пока только звёздочка», текстовые
    отзывы — открытый вопрос №26 (F-00-116), и всё видимое — только после нашей проверки (F-00-168). Как: убрать до решения
    владельца или спрятать за выключенный флаг; вопрос — в `qa/questions/client.md`.
13. **Реквизиты предоплаты — телефон мастера, а не реквизиты из правила** (C03.S2, из q1): правило «Idram · +374 90000012»,
    на экране — номер мастера. Как: `Staff.prepayment.requisites`.

## minor

14. **«Шенгавит · Шенгавит»** в каталоге и на главной (C09.S7): имя филиала уже содержит район.
15. **Просьба перезвонить у вошедшего клиента — номер вводится заново** (C19.S2b, F-00-004 «за секунды»): подставлять
    номер `AppUser.phone`, имя — из профиля.
16. **На главной клиента видна заглушка «Здесь будет реклама салонов»** — служебный текст людям. Пустой слот не рисовать.
17. Тексты: «В приложении с август 2025» (нужен родительный падеж: «с августа 2025»); «Абонемент скоро закончится ·
    «Абонемент «5 массажей спины»» — …» — кавычки в кавычках, «Абонемент» дважды; в «Покупках» места сертификат без
    названия — только «20 000 ֏» (C21.S1); на карточке администратора раздел «Услуги» говорит «Свободных окон пока нет».
