# journal — измерение g3-2-m0

**Раздел:** «Журнал записей и окно записи» (id `journal`). **Дев-сервер:** :3710 (уже работал —
не трогал). **Сфера:** nails (владелец «Nuri Nail Studio»), fitness — не удалось переключить через
`--sphere` (персона `owner` осталась на Nuri Nail Studio даже с `--sphere fitness`; это ограничение
демо-персон/фундамента, не проверял дальше — вне бюджета этого прогона). **Устройства:** десктоп
1440×900 и телефон 390×844 (в общем замере). **Языки:** ru, en — полно; hy — только сырые ключи
(0, чисто) и шрифт (см. ниже, ожидаемо).

## Контекст задания

Из `qa/plan/journal.md` (таблица владения функциями) все шесть проверяемых F-id **не построены в
разделе journal** — раздел `journal` отдал их другим срезам ещё в раунде g1-2 (см.
`qa/requests/journal.md` §g1-2, §g1-2 fix2, «это НЕ мой раздел»):

| F-id | Кому отдано | Что реально в journal |
|---|---|---|
| F-01-097 | staff (`/biz/staff/log`, дубль в reports) | ничего — журнал только «создаёт» записи, которые туда попадают |
| F-01-108 | resources (`/biz/groups`, F-16-064…067) | плитка выбора «Запись / Событие» (F-01-025) → `router.push('/biz/groups?new=1…')` |
| F-01-153 | stock (`/biz/stock`) | плитка «Каталог товаров» в левой панели журнала → `href="/biz/stock"` |
| F-01-193 | services (фильтр `kind` в апи) | окно записи journal — куда фильтр ДОЛЖЕН применяться (services ещё не дал `listServices({kind})`) |
| F-01-201 | staff (карточка сотрудника → «Внедрение» → Google Календарь) | ничего |
| F-01-202 | integrations (F-13-093, всплывающая карточка звонка) | ничего |

Поэтому для F-01-097/108/201/202 «Готово, когда» из ТЗ **физически проверяется на чужом экране**, не
в срезе journal — я проверил только (а) что вклад journal (плитка/переход) есть и не сломан, и (б)
что целевой экран открывается без падения (без проверки его внутренней функциональности — не мой
раздел). Для F-01-153 плитка ведёт на уже построенный `/biz/stock` — проверено действием полностью.
Для F-01-193 сам фильтр в апи ещё не появился нигде (ни у services, ни у journal) — проверил, что
journal передаёт групповые услуги в обычное окно записи БЕЗ фильтрации (код), т.е. пункт не
выполнен со стороны journal тоже, если/когда фильтр появится в апи — вызывать его должен journal.

## Не проверено (честно)

- F-01-097/201/202 — внутренняя функциональность чужих экранов (staff, integrations) не
  проверялась вовсе, только что они открываются без падения — это НЕ входит в раздел journal.
- F-01-108 — «Готово, когда» невозможно проверить: экран-хозяин (`/biz/groups`) сам ещё заглушка
  «скоро появится», это ограничение resources, не journal.

  у персоны `owner` не переключил бизнес (остался Nuri Nail Studio, услуг типа `group` там нет).
  Вывод сделан по коду, не по клику — стоит перепроверить действием в следующем раунде, когда
  найдётся способ открыть fitness-бизнес.
- state (память фильтров после перезагрузки), onboarding, finance-source, arch-size — не пройдены
  отдельными сценариями в этом раунде, бюджет ушёл на 6 назначенных F-id.
- Права (чужая персона не видит) для этих 6 F-id — не проверялись: 5 из 6 не имеют своего UI в
  journal, F-01-153 — не проверял видимость плитки без прав `canGoodsCatalog` в этом раунде.

## Итог

Из 6 назначенных F-id **пять принадлежат другим разделам** (staff ×2, resources, integrations,
services) — journal либо не участвует вовсе, либо вносит только маленький, рабочий кусок (переход/
плитка), который проверен. Единственный пункт, реально решаемый в коде journal, — **F-01-193, и он
не выполнен**: групповые услуги не фильтруются при построении списка для индивидуального окна
записи. Блокирующих находок (`block`) в самом срезе journal нет — F-01-108 «не готово» целиком
из-за resources (чужая заглушка), не из-за journal.
