## Главная проверка этого захода: жив ли BLOCK из m1 (override прав не читался для master)?

**По коду — похоже, исправлено.** `src/areas/journal/lib/rights.ts` сейчас:
```ts
const isOverridable = persona === "admin" || persona === "master";   // было: persona === "admin"
```
и в `useJournalBlockRights`/`useWindowRights` запрос персонального override включён (`enabled: ...
&& isOverridable`) для **обеих** ролей — раньше было только для admin. `JournalScreen.tsx:79`
(`canReschedule = canCreate && journalRights.reschedule`) читает именно этот результат, то есть
DayGrid должен теперь видеть выключенное право у мастера так же, как у админа.

**Живым действием довести до конца в этом заходе не успел** — попытка выключить «Перенос записи»
для Ани Саргсян в Настройках → Права доступа (persona=owner) и тут же проверить drag под
persona=master не сработала технически: переключатель в UI не переключался кликом Playwright
(`aria-checked` до и после клика — оба `true`, скрин `qa/shots/journal/b05-m2/drag2-reschedule-off.png`
и `drag3-saved.png` показывают прежнее состояние) — либо хрупкий селектор с моей стороны, либо
реальная проблема самого переключателя в этом ряду; не разобрался, на что именно, за отведённое
время. **Это не «баг снят» и не «баг жив» — статус открыт, отмечаю как ⏳ для следующего захода**,
с кодовым указанием (see above) как основанием для оптимизма, а не как подтверждение.

## Прочее, не входящее в саму таблицу

- Ошибок консоли/страницы за весь заход не поймано ни на одном шаге (все сценарии печатали `console:
  errors: []` там, где я это логировал).
- Технический вывод: в этом заходе часть Playwright-кликов по переключателям в
  `JournalSettingsScreen.tsx` (право «Перенос записи», чекбокс «Делить запись по ресурсам» в
  тулбаре) не производила видимого эффекта на скриншотах несмотря на "успешный" клик без ошибки —
  тогда как m0/m1 успешно кликали похожие переключатели в той же форме. Не берусь утверждать баг
  продукта — с высокой вероятностью хрупкость именно моих селекторов (регэкспы по тексту,
  многострочные лейблы) в условиях, когда параллельно с другими агентами браузеров и общая нагрузка
  выше обычной. **Рекомендация следующему заходу**: переоткрыть именно F-01-115/178/179 (жив ли
  BLOCK m1 для master) с более надёжным сценарием — искать `button[role="switch"]` по соседству
  `getByText(...).locator('xpath=./ancestor::div[1]//button[@role="switch"]')`, а не по
  `aria-labelledby`/`preceding`, и подтвердить драг под persona=master скриншотом курсора.
