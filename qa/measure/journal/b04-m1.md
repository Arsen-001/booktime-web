# Пачка b04 — измерение (m1)

Раздел: journal. Роль тестирования — измеритель (код не правил). Проверка — реальными действиями в
браузере: `scripts/measure.mjs` (24 отдельных прогона + сценарии) и Playwright-сценарии в
`qa/scenarios/journal/*.json`. Персона `owner` (админ-права те же экраны), сфера `nails`, телефон
390×844, десктоп 1440×900, языки ru/en (hy — проверка на сырые ключи/шрифт отдельным прогоном).

Стартовый замер `measure.mjs --routes /biz/journal,/biz/records --persona owner,admin --lang ru,en
--device phone,desktop`: 16 страниц, 0 ошибок консоли, 0 4xx/5xx, 0 сырых ключей i18n, 0 горизонтальных
вылетов. Найдено 112 зон нажатия < 40px (в основном узкие блоки «Технический перерыв» высотой 14–21px
и кнопки имени сотрудника F-01-020 высотой 20px — общая для сетки журнала проблема, не специфична для
пачки b04, отмечаю отдельно ниже).

**Важная методологическая находка по ходу проверки**: `measure.mjs` без `--scenario` открывает КАЖДУЮ
комбинацию в новом изолированном контексте браузера (без общего localStorage) — поэтому сравнение
«сохранил в одном прогоне → перечитал в другом прогоне» **не проверяет персистентность**, это два разных
браузера. Первая проверка F-01-127/F-01-096 так и ошиблась (решил, что данные теряются) — переделал
внутри ОДНОГО сценария (открыл → сохранил → закрыл → открыл снова в той же странице) и вывод изменился.
Отчёт ниже — по перепроверенным, single-session результатам.

Снимки: `qa/shots/journal-b04/**` (report.json там же). Сценарии: `qa/scenarios/journal/*.json`.

## Общие замеченные проблемы (сквозные по пачке)

1. **❌ BLOCK, мобильная версия: F-01-010, F-01-011, F-01-016, F-01-017, F-01-152 полностью недоступны
   на телефоне 390×844.** Все пять обёрнуты в `{!isMobile && …}` в `JournalScreen.tsx` (и «Список услуг»
   лежит в левой панели, которая на телефоне не рендерится). Это прямое нарушение правила CONVENTIONS.md
   §0 «Телефон — первым»: функция должна быть достижима с телефона, а не только с десктопа. На телефоне
   у пользователя нет способа продать товар без записи, посмотреть кассу за день, добавить сотрудника в
   расписание на день, открыть панель клиентов/чата или посмотреть прайс — módulo hamburger-меню (только
   переход между разделами, не действия внутри «Журнала»). Нужно поднять как минимум как «ещё» (⋯) кнопку
   в шапке журнала на телефоне.
2. **major, F-01-096:** история изменений всегда пишет «время + сумма» вместо реального описания правки
   (проверено на добавлении посетителя — итог «10:00, 6000 ֏», хотя изменил не время и не цену). Не
   выполняет заявленный функционал «журнал правок» по сути, только фиксирует факт+автора+момент.
3. **major, F-01-098/окно записи:** вкладка «Источник» в окне записи — пустая, при этом реальные данные
   об источнике лежат на вкладке «Запись». Пустая вкладка с обманчивым названием — чинить или убирать.
4. **major, F-01-163:** нет кнопок «Создать запись»/«Расписание специалиста», обещанных ТЗ для найденного
   в панели клиента — реализован только поиск+история визитов.
5. **major, зона нажатия:** имя сотрудника над колонкой (F-01-020, вход в меню графика) — 20px по высоте,
   вдвое меньше минимума 40px, тестировал устройство телефон и десктоп.
6. **minor-major, архитектура:** сохранение записи (`updateBooking`/`flushDraftSync`) стабильно пишет в
   консоль `[mock-db] обращение к базе вне request()` — нарушение правила «один request() на операцию».
7. **minor:** панель «Клиенты» (F-01-163) и таблица «Записи» (F-01-181) не показывают телефон/услугу
   рядом с историческими визитами клиента — ТЗ просит «мастера, услуги, суммы, локации» / «имя и телефон».
