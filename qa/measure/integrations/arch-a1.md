# Архитектура integrations · arch-a1

Дата: 2026-09-25. Ревьюер архитектуры (код не правил).
Раздел ещё заглушка (код фундамента ~10–80 строк), поэтому замечаний к коду нет — ниже то, что уже построено соседями
на вашей территории и что нужно учесть с первого файла, чтобы не завести второй источник правды. Общие правила —
docs/ARCHITECTURE.md и CONVENTIONS.md §16; проверка — `node scripts/arch-check.mjs --area integrations`.

Первым делом (для всех новых разделов):
- данные среза — по `businessId` (никаких «общих на всех» настроек), ключи — фабрика `integrationsKeys` с `['integrations', …]`;
- одна бизнес-операция = одна функция `src/api/integrations.ts` = один `request()`, внутри без `await coreCreate/updateBooking`;
- правила (суммы, сроки, остатки, статусы) — чистые функции в `src/domain/integrations.ts`;
- права — `useCan('integrations.*')` в экране и проверка в api, не `persona ===`;
- записи — `useApiMutation` + try/catch + тост; списки > 100 — фильтр и пагинация в api.

## Что учесть

1. Только интерфейс, без настоящих подключений: состояние «подключено/нет» — в своём срезе по `businessId`.
2. Ключи API/вебхуков — сериализуемые записи, секрет показывается один раз (так будет на сервере); не храните «открытый»
   секрет в данных для повторного показа.
