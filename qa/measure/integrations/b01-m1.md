## Дефекты

### 1) major — F-13-007: новая/«пустая» локация не получает автоматически «Наше приложение для клиентов»
- **Где:** `/biz/integrations/installed`, persona `owner-empty` («Новый салон — пусто»)
- **Что видно:** страница «Установлено» показывает полный `EmptyState` «Пока ничего не подключено» — включая
  встроенное клиентское приложение, которое по ⭐ нашему решению (F-13-173) должно быть подключено всегда, в
  каждой локации. Снимок: `qa/shots/integrations/b01-empty/biz-integrations-installed__owner-empty-nails-ru-light-phone.png`.
- **Причина (код):** `src/mock/slices/integrations.ts`, функция `seed()` — построение начальных `installs` идёт
  только по `businessesWithLocations.slice(0, SEEDED_BUSINESSES)` (`SEEDED_BUSINESSES = 6`). Бизнесы за пределами
  первых шести (в т. ч. «пустые» демо-персоны) не получают install встроенного `ia_builtin_client`.
- **Нарушенный пункт ТЗ:** F-13-007 «Готово, когда: новая локация видит в «Установлено» наше клиентское
  приложение».
- Не мой код чинить (я измеритель), сборщику раздела нужно снять ограничение `.slice(0, SEEDED_BUSINESSES)`
  для builtin-инсталлов (они не зависят от объёма сидов остальных 40 карточек) — либо сидировать builtin для
  ВСЕХ `businessesWithLocations`, включая «пустые».

### 2) minor — F-13-011: рейтинг/число отзывов на карточке не совпадает со списком отзывов
- **Где:** карточка приложения → вкладка «Отзывы», любое приложение каталога кроме одного (специально
  засеянного в bi===0)
- **Что видно:** плашка справа и шапка вкладки показывают «4.9 · 56 отзывов», сама вкладка «Отзывы» —
  `EmptyState` «Пока нет отзывов». Снимок: `qa/shots/integrations/b01-tabs/…__reviews-tab.png`.
- **Причина:** `buildApp()` в `src/mock/slices/integrations.ts` генерирует `rating`/`reviewsCount` формулой,
  независимой от реального массива `reviews` (который засеян только для одного приложения одного бизнеса).
  Чисто демо-данные, не логика экрана — сам компонент корректно показывает пустой список.

### 3) ⚠️ инфраструктурное (не раздела «Интеграции», но мешает измерять «сохранение после перезагрузки» везде)
- `[mock-db] не удалось сохранить в localStorage QuotaExceededError` — на каждой без исключения странице
  раздела с первой же загрузки. Подтверждено действием: после «Сообщить о новых интеграциях» тост «Подписка
  оформлена» показывается, но полный `goto` того же адреса откатывает экран к состоянию «не подписан» —
  `qa/shots/integrations/b01-scen2` vs то же с `--force reload` дало откат в отдельном контрольном прогоне.
  Заявка ушла в `qa/requests/integrations.md` (общий `src/mock/db.ts`, не мой код).
