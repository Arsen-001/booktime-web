# online · перекрёстная перепроверка c1 (25.09.2026)

Проверял «✅» из `b01-m2.md` действиями в браузере (персоны `owner`, `guest`, `master`; телефон и десктоп, ru).
Важно для воспроизведения: база моковая и живёт в localStorage браузера, поэтому ссылку, созданную владельцем,
надо открывать **в том же браузере** (новый контекст её не знает и честно отвечает «Страница не найдена»).
Скрипты — `qa/recheck/scripts-c1/o*.mjs`, снимки — `qa/recheck/shots-c1/o*.png`.
Итог по разделу: **проверено 15, подтверждено 12, опровергнуто 3.**

## Опровергнуто

### [major] F-03-005 — ссылка для сотрудника не ведёт сразу к нему
- **Где:** `/biz/online` → «Новая ссылка» → «Ссылку для сотрудника» → Ани Саргсян → создать → открыть
  `/b/nuri-nail-studio/f/<formId>`.
- **Что:** открывается общая страница салона; «Записаться» ведёт на `/b/nuri-nail-studio/book` — обычный
  мастер записи из 4 шагов со страницей выбора специалиста. `bookHref()` в `PublicBusinessPage.tsx`
  теряет `formId`, а `staffId` ссылки нигде не применяется. Из-за этого такие записи ещё и пишутся с
  источником `widget`, а не `link`.
- **Как исправить:** со страницы `/f/<formId>` вести на запись с `formId`; для ссылки с `staffId` —
  пропускать шаг «Специалист» и подставлять мастера.

### [major] F-03-006 — параметры ссылки не действуют / не задаются
- **Что:** (1) «язык по умолчанию» и «сеть» при создании задать нельзя — в `NewLinkSheet.tsx` язык зашит
  `defaultLocale: 'ru'`, поля нет нигде в разделе; (2) ссылка с типом «Групповые» показывает клиенту все
  индивидуальные услуги (маникюр, педикюр…) и ведёт в общий мастер записи.
- **Как исправить:** добавить поля «Язык по умолчанию» (ru/hy/en) и «Сеть» (для сетей); фильтровать услуги
  на странице и в мастере записи по `link.bookingType`, передавая `formId` дальше.

### [major] F-03-093 — занятое за время заполнения окно всё равно записывается (и затирает чужую запись)
- **Где:** две вкладки одного браузера на `/b/nuri-nail-studio/book`, обе — Маникюр классический · Ани · сегодня 16:00.
- **Что:** вкладка Б записалась («Вы записаны»). Затем вкладка А, открытая раньше, нажала «Записаться» на
  то же время — тоже «Вы записаны». В базе после этого **одна** запись на 16:00 — от вкладки А; запись
  вкладки Б исчезла, хотя человеку показали «Вы записаны». Причина в фундаменте: `src/mock/db.ts` не
  слушает событие `storage`, каждая вкладка пишет своё состояние целиком поверх — последняя побеждает.
  То же грозит кабинету: владелец с журналом в двух вкладках теряет правки.
- **Как исправить:** просьба фундаменту — перед записью перечитывать состояние из localStorage (или
  `window.addEventListener('storage', () => useDb.persist.rehydrate())`); в `confirm` визарда проверять
  пересечение по свежим данным и показывать «окно уже заняли» + ближайшие окна.
