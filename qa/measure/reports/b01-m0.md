## Найденные дефекты

### 1. F-12-015 — «Потерянные клиенты» ведёт не в базу, а в настройки — major
`Потерянные клиенты` тайл на «Основных показателях» не открывает базу клиентов вовсе — ссылка `/biz/reports/churn`
(«Настроить период потери»). Спецификация требует «клик по плитке открывает клиентскую базу, отфильтрованную по
этой цифре и периоду» — сейчас так работает частично только тайл «Клиенты» (передаёт `range`), а «Новые клиенты» и
«Не новых клиентов» ведут на `/biz/clients` вовсе без фильтра (все 90 клиентов). Проверено живым кликом на
desktop/ru, owner. Файл: `src/areas/reports/DashboardScreen.tsx:174-221`.
Починка: либо провести реальный фильтр (`?segment=new|returning|lost&range=...`) на `/biz/clients` для всех
четырёх тайлов, либо (если сегментный фильтр ещё не готов в разделе «Клиенты») явно развести назначения ссылок:
у «Потерянные» — либо тоже в базу с фильтром, либо явно оставить «Настроить период потери» вторым действием, не
единственным.

### 2. F-12-030 — «было → стало» есть только для статуса, не для остальных правок — major
Лента активности по записи показывает настоящее «было → стало» только когда меняется статус (`e.kind === 'status'`).
Перенос времени, смена мастера/услуги (`updated`, `moved`) в UI видны только как факт «Автор — обновлено — время»,
без самих старых/новых значений — при этом строка `summary` для них жёстко равна словам `'updated'`/`'moved'`, и
именно поэтому такие правки скрыты явным условием в JSX, а не просто «слов нет». Проверено чтением
`src/api/reports.ts:393-408` и `src/areas/reports/VisitsScreen.tsx:243-256`; визуально в собранной ленте (снимок
`biz-reports-visits__owner-nails-ru-light-desktop.png`) все видимые записи в тестовых данных были создания без
правок, что скрыло проблему от поверхностного просмотра — найдено чтением кода, не глазами.
Починка: у `e.kind === 'moved'`/других видов правок формировать `summary` из реальных старого/нового значения
(время, услуга, мастер — что изменилось), как уже сделано для статуса.

### 3. F-12-001 — в подменю раздела нет пунктов «Записи» и «События» — major (по формулировке ТЗ), но осознанно
`src/areas/reports/nav.ts` содержит только `overview`/`visits`/`all` с явным комментарием «Записи и События — вне
пачки b01, откроются из витрины позже тем же generic-экраном» — то есть сами отчёты уже отвечают честной
заглушкой «Скоро» (см. F-12-002), но заходят на них можно только из витрины «Все отчёты», не из подменю слева.
Формально пункт «Готово, когда» («в кабинете есть раздел «Отчёты» с пунктами Основные показатели, Записи, События,
Все отчёты») не закрыт. Не чиню сама (измеритель), фиксирую по правилам отчёта.

### 4. F-12-004 — один аномально долгий загрузочный замер (17.7 с) на первой странице — minor / нужно перепроверить
Первый прогон `measure.mjs` в этой сессии (owner/ru/phone, `/biz/reports`) дал `loadMs: 17685` — выше требуемых
«быстрее 10 секунд». Все последующие прогоны той же страницы (7 штук, разные lang/device) — 1.6–7.5 с. Похоже на
разогрев Turbopack/dev-компиляции после запуска сервера, а не системную деградацию — но раз цель прямо называет
секунды, отмечаю формально; не переизмерял на «холодном» сервере намеренно (сломал бы чужие параллельные замеры).
