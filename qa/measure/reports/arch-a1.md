# Архитектура reports · arch-a1

Дата: 2026-09-25. Ревьюер архитектуры (код не правил).
Раздел ещё заглушка (код фундамента ~10–80 строк), поэтому замечаний к коду нет — ниже то, что уже построено соседями
на вашей территории и что нужно учесть с первого файла, чтобы не завести второй источник правды. Общие правила —
docs/ARCHITECTURE.md и CONVENTIONS.md §16; проверка — `node scripts/arch-check.mjs --area reports`.

Первым делом (для всех новых разделов):
- данные среза — по `businessId` (никаких «общих на всех» настроек), ключи — фабрика `reportsKeys` с `['reports', …]`;
- одна бизнес-операция = одна функция `src/api/reports.ts` = один `request()`, внутри без `await coreCreate/updateBooking`;
- правила (суммы, сроки, остатки, статусы) — чистые функции в `src/domain/reports.ts`;
- права — `useCan('reports.*')` в экране и проверка в api, не `persona ===`;
- записи — `useApiMutation` + try/catch + тост; списки > 100 — фильтр и пагинация в api.

## Что учесть

1. Отчёты — только агрегаты из api: `getReport({ businessId, from, to, groupBy })` → готовые строки/серии. Никаких
   `listBookings` за год в компонент и `reduce` в рендере (как сейчас в platform `OverviewScreen`).
2. «Активная запись», «пришёл», «отменена» — одно определение для всех (`domain/rules/booking-status.ts`, просьба №2):
   иначе ваша выручка разойдётся с журналом.
3. Деньги — операции finance, не `Booking.total`, когда finance появится; до того помечайте в отчёте источник.
