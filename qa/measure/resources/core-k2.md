# Замечания хранителя ядра — k2 (25.09.2026)

1. **major · «Окно освободилось» (F-00-101, e2e-q1 №3, C04.S7).** Лист ожидания — ваш (AREAS.md «Хозяева сущностей»). Источник
   освободившихся окон — журнал событий ядра: `listBookingEvents({ businessId, freedOnly: true, since })` → `e.freed =
   { staffId, locationId, start, durationMin }`; ядро пишет его при отмене салоном и клиентом, удалении, переносе, снятии
   неоплаченной записи. Как исправить: при чтении листа ожидания сверять заявки с `freed` после последней проверки (момент —
   в своём срезе) и отмечать «окно освободилось»; client читает это через ваш api, свой `client.waitlist` удаляет.

⏳ позже (b01-fix1) — вне пачки: `listBookingEvents(freedOnly)` ещё не подключён к `/biz/waitlist`; эта пачка чинила
занятость ресурса при записи и участников группового события. Учтено в `qa/requests/resources.md` (лист ожидания —
общая межразделная работа с client/notify).
